# 화면 스모크 체크

`pnpm typecheck` · `lint` · `build` 는 **화면이 뜨는지 모른다.** 실제로 그런 버그를 한 번 놓쳤다 —
`startMocks()` 가 워커보다 먼저 화면을 그려서 첫 요청이 목을 통과해 실서버로 나갔고,
00 로그인의 status prefetch 가 영구 `pending` 이 되어 **버튼이 계속 비활성**이었다.
세 명령 모두 통과했고 콘솔 에러 1건으로만 보였다. 이 스킬은 그걸 잡으려고 있다.

## 손으로 열어 볼 때

스크립트 없이 브라우저에서 직접 확인할 거면 [`docs/web/mock-screens-v1.md`](../../../docs/web/mock-screens-v1.md) 를 본다 — 시나리오별 주소,
저장소 초기화 스니펫, 화면별 진입 경로가 거기 있다.

## 무엇을 보는가

[`routes.json`](routes.json) 의 화면을 하나씩 열어서 아래를 본다.

| | 왜 |
| --- | --- |
| 최종 경로가 `expect` 와 같은가 | 리다이렉트가 **설계**인 화면이 있다 (`AuthGate` 튕김 · `/auth/callback` 되돌림) |
| 콘솔 에러 · 미처리 예외 · Next 에러 오버레이 | 렌더는 됐는데 안에서 터진 경우 |
| `mustSee` 문구가 실제로 보이는가 | 껍데기만 뜨고 데이터가 안 온 경우 |
| `mustBeEnabled` 버튼이 눌리는가 | **비활성 버튼도 글자는 보인다** — 위 버그가 정확히 그 모양이었다 |
| 목을 통과해 실서버로 나간 `/api/v1/` 요청 | **위 버그가 여기 걸린다** |
| 가로로 넘치는 요소가 있는가 | 390px 웹뷰라 **가로 스크롤이 생기면 그 자체가 버그**다 |

390×844 (웹뷰 폭)로 연다 — 이 화면들은 대부분 [`apps/mobile`](../../../apps/mobile) 안에서 보인다.

## 실행

```bash
node .claude/skills/web-smoke/smoke.mjs
```

- 개발 서버가 이미 떠 있으면 **그대로 쓰고**, 없으면 띄웠다가 끝나고 내린다 (`--keep-server` 로 유지).
- 눈으로 보려면 `--headed`. 포트는 `SMOKE_PORT`.
- 스크린샷은 `out/` 에 화면마다 한 장 (커밋 안 됨). **찍고 끝내지 말고 본다 — 바로 아래.**
- 통과하면 종료 코드 0, 하나라도 실패하면 1.

### 처음 한 번

- `apps/web/.env.local` 에 **`NEXT_PUBLIC_API_MOCKING=enabled`** 가 있어야 한다.
  백엔드 없이 화면을 보는 스킬이라 목이 필요하다. 없으면 멈추고 알려준다.
- `playwright-core` 는 apps/web 의 `@playwright/test` 가 데려온 것을 쓴다. 설치 전이면 스킬이 `.cache/` 에 받는다 (저장소에 안 들어간다).
- **크로미움 실행 파일은 알아서 받지 않는다** — 수백 MB 라 몰래 받지 않는다.
  없으면 `pnpm --dir apps/web exec playwright install chromium` 을 안내하고 멈춘다 (화면 규칙 테스트 `make web-e2e` 와 같은 브라우저다). `SMOKE_CHROME` 으로 직접 지정해도 된다.

## 🚨 PASS 가 "잘 그려졌다" 는 아니다

위 검사는 전부 **DOM 과 콘솔**을 본다. 문구가 있고 버튼이 눌리고 콘솔이 조용하면 PASS 인데,
그 상태로도 요소가 겹치거나 텍스트가 잘리거나 폰트가 안 붙거나 여백이 무너질 수 있다.
**규칙으로 옮길 수 있는 레이아웃 검사는 가로 넘침 하나뿐이고, 나머지는 사람이나 에이전트가 그림을 봐야 한다.**

그래서 **실행이 끝나면 `out/*.png` 를 열어 본다.** 한 장씩 보며 확인할 것:

- 잘린 텍스트 · 겹친 요소 · 화면 밖으로 나간 버튼
- 제목·본문 크기와 여백이 [`docs/web/design-system-v1.md`](../../../docs/web/design-system-v1.md) 와 어긋나지 않는지
- **빈 화면 · 껍데기만 있는 화면** — `mustSee` 가 정적 문구면 데이터 없이도 PASS 가 난다 (아래 🚨 참고)

스크린샷에서 **개발 전용 떠 있는 버튼(Next 개발 표시기 · Query devtools)은 일부러 숨긴다** — `position:fixed` 라
`fullPage` 로 찍으면 본문 위에 얹혀 찍히고, 실제로 소개 화면 "식사" 줄을 가렸다. 그림에 없는 게 정상이다.

장수가 많아 전부 읽기 부담되면 **이번에 건드린 화면 + 그 화면이 들어 있는 흐름**만 본다. 안 본 건 안 봤다고 말한다.

## 화면을 추가했으면

[`routes.json`](routes.json) 에 한 줄 넣는다. **이 파일이 "지금 살아 있어야 하는 화면 목록"이다.**

```json
{
  "name": "05 제안 후보",
  "path": "/child/c1/suggestions",
  "auth": true,
  "expect": "/child/c1/suggestions",
  "mustSee": "추천 이유"
}
```

| 키 | 뜻 |
| --- | --- |
| `path` | 열 주소. `?scenario=` 를 붙여 목 시나리오를 지정할 수 있다 |
| `expect` | **최종** 경로. 리다이렉트가 설계면 도착지를 적는다 |
| `auth` | `true` 면 목의 refresh 쿠키 표식을 심고 들어간다 (`localStorage` 의 `icatch.mock.refresh` · 화면이 켤 때 refresh 로 토큰을 받는다) |
| `seed` | 그 화면에 들어가려면 있어야 하는 `sessionStorage` 값 (예: 가입 대기표 `consent_code`) |
| `mustSee` | 그 화면이어야만 나오는 문구. 렌더 완료를 기다리는 기준이기도 하다 |
| `mustBeEnabled` | 그 이름의 버튼이 **눌릴 수 있는 상태**여야 한다. 비활성 버튼도 글자는 보이므로 `mustSee` 로는 안 잡힌다 |

🚨 **`mustSee` 는 되도록 "데이터가 와야 나오는 문구" 로 고른다.** 정적 제목으로 잡으면 쿼리가 끝나기 전에 통과하고, 스크린샷에도 빈 화면이 찍힌다 — 02 화면을 정적 제목으로 잡았다가 발달 문항이 안 온 상태로 통과한 적이 있다.

## 한계 — 이걸로 대신하지 말 것

- **눈으로 보는 것까지 대신하지 않는다.** 가로 넘침 말고는 레이아웃을 판정하지 않는다 — 위 🚨 대로 PNG 를 본다.
- **E2E 테스트가 아니다.** 폼을 채우거나 승인 게이트를 눌러 보지 않는다. `bind` 왕복·`Idempotency-Key` 재시도·`partial` 전환 같은 건 여기서 안 잡힌다 — 그건 별도 이슈의 E2E 몫이다.
- **CI 에서 안 돈다.** 사람이 손으로 돌리는 도구다.
- **실서버를 안 본다.** 목 위에서만 도므로, 계약이 어긋난 것은 못 잡는다.
- 🚨 **`smoke.mjs` 의 `IGNORED_CONSOLE` 에 뭔가 추가할 때는 "왜 무시해도 되는가" 를 같이 적는다.**
  이 목록이 길어지면 스크립트가 아무것도 안 잡는 상태로 조용히 썩는다.
- **가로 넘침이 오탐일 수 있는 경우가 하나 있다** — 화면 밖에 대기시키는 요소(`translate-x-full` 같은 오프캔버스 시트)는
  실제로 문서 폭을 늘린다. 그런 화면이 생기면 그 요소의 부모에 `overflow-hidden` 을 주는 것이 맞는 수정이고,
  검사를 끄는 게 아니다.
