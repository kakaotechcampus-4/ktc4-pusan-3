# 디자인 시스템 v1

**살아 있는 버전이 있다 — `pnpm dev` 후 [`/design-system`](../../apps/web/src/app/design-system/page.tsx).** 실제 토큰·컴포넌트를 렌더하고, **대비비와 높이를 지금 값으로 읽는다.** 토큰을 바꾸면 통과/미달이 바뀌므로 문서와 코드가 어긋나면 눈에 보인다.

문서 목적: 색·타이포·레이아웃·컴포넌트가 **왜 그 모양인지, 어디에 쓰고 어디에 쓰지 않는지**를 확정한다.

### 무엇이 어디에 있나

같은 값을 두 곳에 손으로 적으면 어느 쪽이 최신 결정인지 알 수 없게 된다. 그래서 종류마다 원본을 한 곳으로 정했다.

| 무엇 | 원본 | 이 문서에는 |
| --- | --- | --- |
| 디자인 의도 · 사용 조건 · 금지 예 | **이 문서** | 전부 |
| 여러 컴포넌트가 같이 쓰는 값 (색 · 타이포 · radius · **높이**) | [`globals.css`](../../apps/web/src/app/globals.css) 의 `@theme` | **토큰 이름**으로 부른다. 숫자는 결정의 근거를 설명할 때만 적는다 |
| 한 컴포넌트 안에서만 쓰는 치수 (버튼 좌우 여백 등) · 상태별 표현 · 키보드 · 포커스 동작 | [`components/ui/`](../../apps/web/src/components/ui) 코드와 `/design-system` | 그 치수가 **결정인 이유가 있을 때만** 이유와 함께 적는다 |

**아직 코드가 없는 컴포넌트**(`/design-system` 맨 아래 목록)는 이 문서가 유일한 사양이라 숫자를 그대로 둔다. 만들 때 위 표대로 옮기고 여기서 숫자를 뺀다.

🚨 **문서와 코드가 어긋나면 한쪽이 틀렸다고 가정하지 않는다. 먼저 바뀐 이유를 확인한다.** 구현 실수일 수도 있지만, 실기기 검증이나 접근성 때문에 코드를 먼저 고친 것일 수도 있다.

1. 어긋난 지점의 커밋·PR 에서 **왜 바꿨는지**를 찾는다.
2. 이유가 있으면 **같은 PR 에서** 이 문서의 근거를 고친다 (값만 바꾸고 근거를 두면 다음 사람이 되돌린다). [`DESIGN.md`](../../DESIGN.md) · `.impeccable/design.json` 사본도 같이 맞춘다.
3. 이유를 못 찾으면 구현 실수로 보고 코드를 되돌린다.

값을 바꾸는 PR 은 1~2 를 한 번에 담는다. 값이 바뀌었는데 문서나 코드 한쪽만 들어 있으면 리뷰에서 반대쪽을 요구한다.

## 1. 한눈에

웜 오프화이트 바탕 위에 **세이지 그린 하나**를 브랜드로 쓴다. 도메인 4색과 상태 2색이 있고, 그 밖의 모든 것은 뉴트럴이다. 그림자는 바텀시트 **한 단계뿐**이고 카드 경계는 테두리가 만든다. 단일 컬럼 고정 — 데스크톱 레이아웃이 따로 없다.

| | |
| --- | --- |
| 색 토큰 | **35개** (뉴트럴 8 · 브랜드 4 · 도메인 12 · 상태 7 · 외부 브랜드 3 · 오버레이 1) |
| 타이포 | **8단계** · 본문 16px / 1.6 · 학교안심 날개 R (문서는 Pretendard) |
| 간격 | 4px 배수 7단계 · 컨테이너 최대 폭 560px |
| radius | 4개 (10 · 14 · 20 · 9999) |
| 그림자 | **1개** (바텀시트) + 스크림 |
| 높이 | 토큰 **5개** (`touch` · `button` · `approve` · `field` · `chip`) · **전부 최소 높이** |
| 컴포넌트 | 버튼 6 · 입력 3 · 칩 4 · 카드 5 · 배너 2 · 시트 · 탭 · 진행 · 빈 상태 · 스켈레톤 |
| 브레이크포인트 | 3개 · 전 구간 1열 |

**성격** — 하루에 여러 번, 자주 밤에, 지친 상태로 여는 화면이다. 한 번 보고 감탄하는 화면이 아니라 100번째에도 안 피곤한 화면을 목표로 한다. 그래서 강조는 채도가 아니라 **명도**로 만들고, 색은 전부 "이 색 = 이 뜻" 이 1:1 이며, 예쁘라고 칠하는 색은 없다.

## 2. 색

전 항목 [WCAG 2.2 AA](https://www.w3.org/WAI/WCAG22/quickref/#contrast-minimum) 기준으로 계산했다 (본문 4.5:1 · 비텍스트 3:1). 괄호 안은 실측 대비비, 재현 방법은 §10.

### 2-1. 뉴트럴 — 화면의 90%

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-canvas` | `#FBF9F5` | 페이지 바탕. **웜 오프화이트** — 순백 대비 야간 글레어를 줄인다 |
| `--color-surface` | `#FFFEFB` | 카드·시트·입력. 바탕 위에서 1.04:1 로만 뜬다 |
| `--color-surface-muted` | `#F3F1EC` | 비활성 · 접힌 영역 · 실패 카드 · 스켈레톤 · **하단 크롬**(채팅바 알약 · 화면 이동 바) |
| `--color-ink` | `#221F1B` | 본문 (15.6:1). 순검정 아님 |
| `--color-ink-muted` | `#605A52` | 보조 텍스트 · 설명 (6.5:1) |
| `--color-ink-subtle` | `#6F6A61` | 메타 · 타임스탬프 · 건수 (5.1:1) |
| `--color-line` | `#E8E4DC` | 기본 구분선 · 카드 테두리 |
| `--color-line-strong` | `#969086` | 입력 테두리 · 점선 테두리 (3.0:1 — 비텍스트 AA) |

🚨 **`surface` 도 순백이 아니다.** 처음엔 `#FFFFFF` 였는데 색조가 아예 없어서 웜 캔버스 위에서 **혼자 차가웠다.** 카드가 읽는 면적의 대부분이라 야간 글레어(§2-1 이 `canvas` 를 웜으로 잡은 이유)는 바탕보다 카드에서 더 문제가 된다. `canvas` 와 같은 색조(OKLCh H 85)로 옮기고 밝기만 올렸다 — 리프트는 1.052 → 1.043 으로 사실상 그대로고, **어차피 카드 경계는 그림자가 아니라 `line` 1px 이 만든다**(§6).

> `ink-subtle` 도 4.5:1 을 넘긴다. **"흐린 회색 글씨" 를 만들지 않는다** — 기록 건수·날짜는 부모가 실제로 읽는 정보다.

### 2-2. 브랜드 — 세이지 그린

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-brand` | `#3A6B52` | 주 버튼 · 활성 탭 · 링크 · 포커스 링 (5.9:1 · 흰 글자 6.2:1) |
| `--color-brand-hover` | `#2F5943` | press / hover (흰 글자 8.0:1) |
| `--color-brand-soft` | `#E7EFE9` | 아이콘 타일 · ghost 아이콘 버튼 press · `chip-choice` 선택 |
| `--color-brand-ink` | `#26493A` | soft 위 텍스트 (8.6:1) |

성공 상태에는 별도 색을 두지 않는다. `brand` 를 쓴다 — 초록을 두 뜻으로 쓰면 브랜드가 "성공" 으로 읽힌다.

**브랜드색이 서는 자리는 정해져 있다.** 화면의 90%가 뉴트럴이라(§2-1) 브랜드를 어디에 둘지 정해 두지 않으면
화면이 회색 카드의 나열이 된다. 아래 다섯 곳에만 쓰고, 여기서 늘리지 않는다.

| 어디 | 무엇으로 |
| --- | --- |
| 섹션 라벨 (`오늘` · `눈여겨볼 것` · `저장 결과`) | `label` / `brand` |
| 화면에서 제일 먼저 읽는 숫자 (홈의 기록·일정 건수) | `display` / `brand` |
| 목록 줄 앞의 아이콘 타일 · 빈 상태 아이콘 | `brand-soft` 바탕 + `brand-ink` 아이콘 / `brand` 아이콘 |
| (제안이 앉는 색 면은 여기 없다 — 그건 **도메인 색**이다 · §2-3) | |
| 지금 눈여겨볼 카드 **한 장** (`card-accent`) | `brand` 테두리 |
| 주 버튼 · 보내기 · 활성 탭 · 링크 · 포커스 링 | `brand` 채움 또는 글자 |

🚨 **`brand-soft` 로 큰 면을 칠하지 않는다.** 아이콘 타일 · press 틴트 · 선택된 칩처럼 작은 면이 전부다.
**제안이 앉는 색 면은 브랜드가 아니라 그 제안의 도메인 색**이다 (§2-3) — 초록으로 통일하면 네 Agent 의
제안이 전부 같은 면이 되어, 이미 뜻을 정해 둔 도메인 4색이 칩 하나로만 쓰인다.

### 2-3. 도메인 4종

[`suggestion_agent`](../../CLAUDE.md) enum 과 1:1 이다. **여기 있는 색은 다른 용도로 쓰지 않는다.**

**뜻은 "어느 영역인가" 다.** 처음에는 "이 제안이 어느 Agent 에서 왔는가" 로 좁게 적었는데, 07 에서
쌓인 기록·기억을 훑는 목록이 생기면서 넓혔다 — 거기 서 있는 것은 제안이 아니지만 식사·놀이·교육·건강
넷은 똑같이 갈려야 하고, 그 색을 쓰지 않으면 같은 것을 두 벌의 언어로 말하게 된다.
🚨 **넓어진 것은 "무엇의 색인가" 뿐이고 "무엇이 아닌가" 는 그대로다** — 실행(브랜드)·상태(caution·danger)와
섞지 않는다.

| 도메인 | 주색 | soft 배경 | soft 위 텍스트 |
| --- | --- | --- | --- |
| 식사 `food` | `#9A4F22` 테라코타 (5.7:1) | `#F6EBE1` | `#7E3F1B` (6.8:1) |
| 놀이 `activity` | `#0F7084` 틸 (5.4:1) | `#E5EFF1` | `#055766` (7.0:1) |
| 교육 `education` | `#4E5AA0` 인디고 (6.1:1) | `#E9EAF5` | `#3B4680` (7.4:1) |
| 건강 `health` | `#8A4E74` 플럼 (5.8:1) | `#F3E9EF` | `#6E3B5B` (7.3:1) |

`activity` 로 통일한다 — 기획서·테크스펙의 `play` / `interest` 는 쓰지 않는다 (CLAUDE.md §5).

🚨 **`-soft` 는 칩 배경이자 열린 제안 줄의 바탕이다** (§7 `suggestion-row`). 칠하는 면이 커져도 뜻은
하나다 — "이 제안이 어느 Agent 에서 왔는가". 제안 줄은 한 번에 하나만 열리므로 화면에 큰 색 면은 항상
하나고, 그 면 위의 글자는 전부 그 도메인의 `-ink` 다 (soft 색과 비교해 6.8~7.4:1).
🚨 **고르는 버튼은 도메인 색을 따라가지 않는다** — 실행은 브랜드(`btn-primary`)다. 도메인 색은
"어디서 왔나", 브랜드는 "무엇을 하는가" 라서 둘을 섞으면 두 신호가 같은 색이 된다.

**네 색은 동급이어야 한다 — 그런데 틸만 흐렸다.** 도메인 사이에는 우열이 없다 (한 화면에 최대 2개가 나란히 뜬다). 그래서 명도는 넷 다 OKLCh L 49~51 로 이미 맞춰져 있었는데, 지각 채도는 `food` 0.115 · `education` 0.112 · `health` 0.095 인 사이에서 **`activity` 만 0.072** 였다. 같은 크기·같은 자리에 놓아도 놀이 칩만 한 단계 물러나 보이고, 하필 놀이가 넷 중 제일 생생해야 하는 자리다.

| | 옛 | 새 |
| --- | --- | --- |
| chroma | 0.072 (`food` 의 0.63배) | **0.086 (0.75배)** |
| `activity` on `canvas` | 5.3:1 | 5.4:1 |
| `brand`(세이지) 와의 거리 | 0.069 | **0.077** |
| `education`(인디고) 와의 거리 | 0.098 | 0.099 |

**0.086 이 끝이다.** 216° 는 sRGB 가 채도를 가장 못 내는 구간이라 그 명도에서 천장이 0.089 고, 그 위는 색이 뭉개진다. 넷을 완전히 같은 채도로 맞추려면 나머지 셋을 0.086 까지 **내려야** 하는데, 그러면 `danger` 가 도메인 최고치의 1.74배까지 벌어져 §2-6 이 맞춰 둔 서열이 무너진다. 그래서 **올릴 수 있는 쪽을 올려** 폭을 1.60배에서 1.29배로 줄였다. 남은 차이는 sRGB 의 한계지 취향이 아니다.

세이지와 틸은 원래 제일 헷갈리는 한 쌍인데, 채도를 올리면 오히려 **멀어진다** — 브랜드는 차분한 초록이고 놀이는 선명한 청록이라는 차이가 생기기 때문이다.

### 2-6. 외부 브랜드 — 카카오

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-kakao` | `#FEE500` | 카카오 로그인 버튼 배경 |
| `--color-kakao-hover` | `#F0D800` | 그 버튼의 hover / press (`kakao-ink` 10.5:1) |
| `--color-kakao-ink` | `rgb(0 0 0 / 0.85)` | 그 위 라벨 (16.4:1) |

🚨 **우리 팔레트가 아니다.** 카카오 로그인 버튼은 카카오가 정한 색·모양을 써야 해서 예외로 뒀고, **로그인 버튼 밖에서는 쓰지 않는다.** 노랑이 승인 게이트의 `caution` 과 가까워 보이지만 뜻이 겹치지 않는 이유는 이 색이 **로그인 화면에만 있고 `caution` 이 그 화면에 없기** 때문이다 — 두 색이 한 화면에 같이 나오면 규칙이 깨진다.

말풍선 심볼도 lucide 가 아니라 카카오 마크를 인라인 SVG 로 쓴다 (§7 아이콘 규칙의 예외).

**`danger` 는 두 번 옮겼다. 두 번째 기준은 색약이다.**

처음 값은 Material 기본 빨강(`#B3261E`)이었는데, 지각 채도(OKLCh chroma)로 재 보니 **0.178 로 도메인 최고치(food 0.115)의 1.55배**였다 — 혼자 다른 팔레트에서 온 색이라 `#A03641`(0.140 · 1.22배)로 당겨 가족 안에 넣었다.

그 값의 문제는 **테라코타(`food`)와 명도로만 갈렸다**는 것이다. 색조를 18°로 잡아 49°와 벌렸다고 봤지만, 적록색약으로 시뮬레이션하면 두 색의 거리가 **0.117** 밖에 안 된다. 하필 **알레르기 경고는 식사 화면에 뜨는 색**이라, 이 팔레트에서 제일 붙으면 안 되는 한 쌍이 여기다.

밝기를 올리면 색조를 더 파란 쪽(16°)으로 잡을 수 있어서 그 거리가 벌어진다.

| | 옛 `#A03641` | 새 `#B74351` |
| --- | --- | --- |
| 명도 L | 48.9 | **54.6** |
| chroma | 0.140 (1.22배) | 0.150 (1.30배) |
| `danger` on `canvas` | 6.4:1 | 5.1:1 |
| 흰 글자 on `danger` | 6.8:1 | 5.3:1 |

| `health` 와의 거리 | 0.086 | **0.097** |

**1.30배는 밝기를 고른 대가다.** 밝게 올리면서 채도를 그대로 두면 빨강이 **분홍**이 된다 — 후보 `#B74B5E`(1.22배 유지)를 실제 배너·삭제 버튼에 얹어 보니 경고가 아니라 라즈베리로 읽혔다. 채도 서열에서 `danger` 가 여전히 맨 위(도메인 최고치의 1.30배 · `caution` 의 1.34배)라는 점은 그대로다.

**대가 두 가지를 알고 고른 것이다.** ① `canvas` 대비가 6.4 → 5.1 로 얇아진다. 실제 용도는 1px 입력 테두리와 배너 바(비텍스트 3:1)뿐이라 여유는 남지만, `danger` 를 본문 글자로 쓰지 않는다는 규칙이 이제 **여유가 아니라 조건**이다. ② main 이 `danger-soft` 위에서 4.5:1 이라 배너 글자는 반드시 `danger-ink` 를 쓴다.

**비활성 상태에는 토큰을 만들지 않는다.** 어떤 컴포넌트든 `surface-muted` 배경 + `ink-subtle` 텍스트 (4.8:1) + `line` 테두리로 만든다. 브랜드색을 흐리게 만든 비활성 버튼은 "누를 수 있어 보이는데 안 눌리는" 상태가 되어 지친 사용자에게 제일 나쁘다.

## 3. 🚨 색 사용 규칙

[CLAUDE.md §2](../../CLAUDE.md) 와 [`apps/web/CLAUDE.md` §4](../../apps/web/CLAUDE.md) 가 색으로 떨어지는 지점이다. 어기면 스타일 문제가 아니라 **규칙 위반**이다.

- 🚨 **실패는 빨강이 아니다.** Agent 2개 중 1개만 성공해도 화면은 나가야 한다(NF-06). 그걸 빨강으로 칠하면 부모가 매일 빨간 화면을 본다. **실패 카드는 `surface-muted` + `ink-muted`**, 빨강은 알레르기에만 남긴다. `llm_unavailable`(503) 도 같다 — 실패했다고 말하되 경보로 말하지 않는다.
- 🚨 **일반 추천과 개인화 추천을 색으로 구분하지 않는다.** 개인화 = 도메인 색 면 + 근거 칩 N개, 일반 = `canvas` 그대로 + 점선 `line-strong` 테두리 + **"또래 기준 일반 추천" 라벨 + 쌓인 기록 건수**. 적록색약에서도 §2 가 지켜져야 하므로 **라벨이 본체이고 배경색은 거들 뿐이다** — 도메인 색이 뜻하는 것은 "어느 Agent" 이지 "개인화됨" 이 아니다.
- 🚨 **`caution` 은 승인 게이트 2곳에만.** ㉠ 캘린더 쓰기 ㉡ 건강·알레르기 기록 확정. 06 화면 상단 `prechecks` 배너가 여기다. 승인을 늘리지도 줄이지도 않는 규칙이라 **색도 늘리지 않는다.**
- 🚨 **도메인 색을 단독 신호로 쓰지 않는다.** 항상 아이콘 + 텍스트 라벨과 함께 나간다. 4색 중 `food`(테라코타) 와 `health`(플럼) 는 적록색약에서 가까워진다.
- **한 화면에 도메인 색은 최대 2개.** Agent 가 최대 2개(NF-01)라 자연히 지켜진다. 홈에 4색을 다 깔지 않는다.
  - **이건 제안 화면의 규칙이다.** 근거가 "Agent 가 최대 2개" 라, 화면에 제안이 서 있을 때만 성립한다.
  - **예외 ㉠ 로그인 전 소개 화면(00).** 추천이 없어서 도메인 색이 "어느 Agent 에서 왔는가" 신호로 쓰이지 않는다 — 거기서는 4개를 나열하는 것 자체가 설명이다.
  - **예외 ㉡ 07 기록·기억 목록.** 여기도 제안이 아니라 **쌓인 것을 훑는 화면**이고, 목록은 `?domain=` 없이 부르면 네 영역이 섞여 내려온다. 색을 빼면 영역을 가르는 것이 글자 하나뿐이라 목록이 통째로 회색 덩어리가 된다. 🚨 **색 면은 왼쪽 아이콘 타일 하나까지고, 영역 이름이 항상 글자로 함께 선다** (§3 "단독 신호 금지"). 🚨 `is_stale` 기억 카드만 뉴트럴 타일이다 — 카드 전체가 `surface-muted` 인데 그 위에 색 타일이 서면 "근거에서 빠져 있다" 를 화면이 되받아친다.
  - 그 밖의 로그인 뒤 화면에서는 예외를 만들지 않는다.
- **`is_stale` 근거 칩은 `ink-subtle` + 점선** 으로 눌러서 그린다. 6개월 넘은 기록은 단독 근거로 못 쓴다(NF-08) — 색으로도 대등해 보이면 안 된다.
- **컴포넌트에서 `#hex` 를 직접 쓰지 않는다.** Tailwind 토큰 클래스만 (`text-ink-muted` · `bg-brand-soft`).

## 4. 타이포

**서체는 두 벌이고, 쓰는 자리가 다르다.**

| | 서체 | 토큰 | 어디에 |
| --- | --- | --- | --- |
| **본문** | `학교안심 날개 R` | `--font-sans` (`font-sans`) | 기본값. 화면 대부분 |
| **문서** | `Pretendard Variable` | `--font-doc` (`font-doc`) | 이용약관 · 개인정보 처리방침 · 동의 전문 등 **읽고 동의해야 하는 긴 법률 문서** |

별도 디스플레이 서체는 두지 않는다 — 손글씨가 이미 그 자리를 겸한다. `--font-doc` 은 폴백이 아니라 **역할이 다른 자리**다. 손글씨에 없는 글자가 Pretendard 로 떨어지는 것(폴백)과는 다른 이야기이므로 헷갈리지 말 것.

**손글씨를 본문에 쓴다는 것은 가독성을 조금 내주고 온기를 사는 선택이다.** 이 서비스가 다루는 것이 아이에 대한 기록이라 그 교환이 성립한다고 봤다. 대신 아래 보정들을 걸어 §4 의 8단계가 의도한 크기로 읽히게 맞췄다.

🚨 **법률 문서는 그 교환을 하지 않는다.** 약관·처리방침은 온기를 주는 글이 아니라 **불리한 조항을 놓치지 않고 읽어야 하는 글**이고, 개인정보 동의는 그 이해를 법이 전제한다 (개인정보보호법 제22조 — 명확히 표시해 알아보기 쉽게). 손글씨의 단일 웨이트 합성 굵기와 낮은 자소 판별성은 그 자리에서 손해만 된다. **`font-doc` 을 쓰고, 그 화면에서는 §8 의 굵기 위계도 Pretendard 의 실제 웨이트로 나온다.**

⚠️ **한 화면 안에서 두 서체를 섞지 않는다.** 문서 화면은 통째로 `font-doc` 이다 — 제목만 손글씨로 두면 같은 문단 안에서 글자 크기감이 어긋난다 (아래 `size-adjust` 참고).

**둘 다 자체 호스팅 · 동적 서브셋이다** (§14 에서 열려 있던 결정). 두 폰트가 **같은 `unicode-range` 파티션**을 쓴다 — Pretendard 패키지의 92개 파티션이 한글 빈도순이라 그대로 가져다 본문 서체를 다시 뽑았다. 경계가 같아야 폴백이 블록 단위로 어긋나지 않는다.

| | 학교안심 날개 R | Pretendard |
| --- | --- | --- |
| 어디에 | `public/fonts/hakgyoansim/` (92개 · 540KB) | `public/fonts/pretendard/` (92개 · 3.1MB) |
| `@font-face` | [`src/app/hakgyoansim.css`](../../apps/web/src/app/hakgyoansim.css) — [스크립트](../../apps/web/scripts/build-hakgyoansim-subset.py)가 만든다 | [`pretendard.css`](../../apps/web/src/app/pretendard.css) — 패키지에서 뽑는다 |
| 원본 | `apps/web/fonts-src/` 에 커밋 (1.4MB) | 패키지 |
| 라이선스 | **SIL OFL 1.1** (저작권 KERIS · 제작 투게더그룹) · `public/fonts/hakgyoansim/LICENSE.txt` | **SIL OFL 1.1** · `public/fonts/pretendard/LICENSE.txt` |

**두 폰트 모두 SIL OFL 1.1 이다** — 수정(서브셋)·재배포·임베딩·상업적 이용이 모두 허용되고, 폰트 파일 자체를 파는 것만 금지다. 그래서 자체 호스팅과 저장소 커밋에 걸리는 것이 없다.

🚨 **OFL 이 요구하는 것은 하나 — 저작권 고지와 라이선스를 같이 배포하는 것이다.** `LICENSE.txt` 를 woff2 옆에 두고, **빌드 스크립트가 서브셋 92개마다 라이선스 레코드(name ID 13·14)를 심는다.** 원본 TTF 에는 그 레코드가 없어서, 우리 woff2 파일 하나만 따로 받아 가면 조건을 알 방법이 없기 때문이다. 폰트 폴더에서 `LICENSE.txt` 를 지우지 말 것.

**화면당 실측 — 00 로그인 13개 · 157KB** (그 화면 글자는 본문 서체가 전부 덮어서 Pretendard 는 0개). `unicode-range` 로 화면에 실제 쓰인 범위만 받는다.

🚨 **외부 CDN 을 쓰지 않는다.** 저장소가 public 이고 외부 리소스는 보안 검토 대상이다 (CLAUDE.md §9). 자체 호스팅이면 앱이 우리 오리진 밖으로 나가지 않는다 — 실측 외부 오리진 요청 **0건**.

> **폰트를 고를 때 라이선스를 먼저 본다.** 앞서 검토한 교보 손글씨 2024 박서우는 웹 사용은 허용인데 *"수정 및 변경(디지털 포맷 변경)"* 과 재배포를 금지해서, woff2 로 쪼갤 수도 저장소에 넣을 수도 없었다. 남은 길이 배포처 CDN 을 가리키는 것뿐이었고 그러면 단일 파일 1.25MB + 외부 오리진을 떠안아야 했다. **변환을 허용하는 폰트로 바꾸자 157KB · 외부 오리진 0건이 됐다** — 라이선스가 성능과 보안을 같이 결정한다.

**본문 서체에 건 세 가지 보정**

🚨 **본문 서체는 Regular 400 단일 웨이트다.** 아래 표의 600·700 은 브라우저 합성(faux bold)으로 나온다. 합성을 끄면 제목과 본문의 굵기 차이가 사라져 위계가 크기 하나에만 걸리므로, 합성을 켠 쪽을 골랐다.

⚠️ **그래서 선언한 굵기 4단계가 화면에서는 2단계로 붙는다.** 브라우저는 600 이상만 합성한다 — **`label`(500)은 `body`(400)와 똑같이 나온다** (크로미움 실측). 칩·탭·폼 라벨이 본문과 붙어 있는 자리에서 그 구분이 사라진다는 뜻이다. `font-doc`(Pretendard) 을 쓰는 문서 화면에서는 4단계가 그대로 나온다.

🚨 **`hakgyoansim.css` · `pretendard.css` 를 손으로 고치지 않는다.** 각각 [`scripts/build-hakgyoansim-subset.py`](../../apps/web/scripts/build-hakgyoansim-subset.py) 와 `pretendard` 패키지에서 뽑은 파일이고, 폰트를 올릴 때는 다시 뽑는다. prettier 대상에서도 빼 뒀다.

| 역할 | 크기 / 행간 | 굵기 | 자간 | 쓰는 곳 |
| --- | --- | --- | --- | --- |
| `display` | 24 / 1.3 | 700 | -0.02em | 화면 제목 (03 홈 인사말) |
| `title` | 20 / 1.35 | 700 | -0.01em | 카드 제목 · 시트 헤더 |
| `section` | 17 / 1.4 | 600 | -0.01em | 섹션 구분 |
| **`body`** | **16 / 1.6** | 400 | 0 | **본문 기본값** · 입력값 |
| `body-sm` | 14 / 1.55 | 400 | 0 | 보조 설명 |
| `button` | 15 / 1.2 | 600 | 0 | 버튼 라벨 |

| `caption` | 12 / 1.4 | 400 | 0 | 메타 · 타임스탬프. **이보다 작게 쓰지 않는다** |

🚨 **`display` 는 좁은 폰(< 380px)에서 `title` 로 낮춘다** (§9). 화면마다 손으로 쓰면 어긋나므로 [`components/ui/page-title.tsx`](../../apps/web/src/components/ui/page-title.tsx) 한 곳에 뒀다 — **화면 제목은 `<h1>` 을 직접 쓰지 말고 `PageTitle` 을 쓴다.**

한글은 라틴보다 행간이 더 필요해서 본문 1.6 을 잡았다. 크기가 커질수록 자간을 음수로 조여야 한글이 헐거워 보이지 않는다.

🚨 **화면에 보이는 글자에 이모지·기호를 쓰지 않는다.** `①②③` · `↓` · `★` · `▶` 같은 것으로 뜻을 나타내지 않는다.

- **스크린리더가 제각각으로 읽는다.** 순서를 나타내려던 `①` 이 "동그라미 일" 로 읽히거나 통째로 건너뛰어지고, `↓` 는 읽히지 않아 의미가 사라진다.
- **기기·폰트에 글리프가 없으면 두부(□)로 보인다.** 손글씨·Pretendard 서브셋에 모두 없는 문자면 시스템 폰트로 떨어져 크기·정렬도 어긋난다.
- **아이콘은 lucide 한 곳에서 관리하는데**(§7) 텍스트 기호는 그 관리 밖으로 샌다. 색 단독 금지(§3)를 아이콘에 걸어 둔 것과 같은 이유로, 뜻을 나르는 것은 한 곳에 모아야 한다.

대신 이렇게 한다 — **뜻은 글자로 쓰고**, 순서가 필요하면 `<ol>`, 목록 마커가 필요하면 CSS `list-*`/`marker:` 로 그린다(브라우저가 접근성 트리에 맞게 처리한다). 그림이 필요하면 lucide 아이콘 + 텍스트 라벨을 쓴다.

**문장부호는 이렇게 나뉜다.**

| | 규칙 |
| --- | --- |
| 줄표 `—` | 🚨 **화면 텍스트에 쓰지 않는다.** 괄호 · 쉼표 · 줄바꿈으로 바꾼다. 한국어에서 정상 부호이긴 하지만 **뜻이 애매해지는 자리에 아무 데나 들어가기 쉬워서**, 쓰지 않는 쪽이 문장을 또렷하게 만든다 |
| 붙인 가운뎃점 `수집·이용` | 그대로 쓴다. **병렬 합성어**를 만드는 한국어 정서법이지 구분자가 아니다 (`건강·알레르기`, `예약·발송·결제`) |
| 띄운 가운뎃점 ` · ` | **한 줄에 하나까지.** 메타 스트립 전용이다 (`아이 등록 · 1 / 2`). 문장 안에서 나열할 때는 쉼표를 쓰고, 항목이 셋 이상이면 목록으로 쪼갠다 |

⚠️ 코드 주석·마크다운 문서·[`/design-system`](../../apps/web/src/app/design-system/page.tsx) 은 대상이 아니다 — 앞의 둘은 화면에 안 나가고, `/design-system` 은 팀이 보는 내부 문서라 설명문의 리듬을 유지한다.

**줄바꿈은 `word-break: keep-all`** 로 어절 단위를 유지한다 — 좁은 웹뷰에서 단어가 잘리면 읽는 속도가 눈에 띄게 떨어진다. 한 줄은 **35자 안팎**에서 끊는다(컨테이너 폭이 그 역할을 한다).

⚠️ **입력 필드의 글자는 16px 미만으로 내리지 않는다.** iOS 웹뷰는 16px 미만 입력에 포커스가 가면 화면을 자동으로 확대하고, 확대된 채로 남는다.

🚨 **프로토타입은 11~13px 이 전체의 70% 였다** (11px 108곳 · 12px 68곳 · 13px 56곳). 데스크톱 브라우저에서 모바일을 흉내 내다 나온 크기고, 실제 기기에서 지친 눈으로 읽을 크기가 아니다. **그대로 옮기지 말 것.**

## 5. 레이아웃

### 간격

4px 배수만 쓴다.

| 토큰 | 값 | 기본 용도 |
| --- | --- | --- |
| `2xs` | 4px | 아이콘과 라벨 사이 |
| `xs` | 8px | 칩 사이 · 인라인 요소 |
| `sm` | 12px | **카드와 카드 사이** |
| `md` | 16px | **카드 안쪽 여백 · 화면 좌우 여백** |
| `lg` | 20px | 시트 안쪽 여백 |
| `xl` | 24px | **섹션과 섹션 사이** |
| `2xl` | 32px | 화면 상단 여백 · 빈 상태 위아래 |

### 컨테이너 · 그리드

- **콘텐츠 최대 폭 560px**, 그 이상에서는 가운데 정렬하고 양옆은 `canvas` 로 둔다.
- 화면 좌우 여백 16px. 폭 360px 미만 기기에서만 12px.
- **그리드는 1열 고정이다.** 제안 카드도, 기록 목록도, 도메인 칩 줄도 세로로 쌓는다. 2열이 필요해 보이면 정보가 많은 것이지 열이 부족한 게 아니다.
- **상하 여백 32px(`2xl`) 과 노치·홈 인디케이터는 [`components/ui/screen.tsx`](../../apps/web/src/components/ui/screen.tsx) 가 `calc` 로 함께 소유한다.** 웹뷰 안에서는 네이티브 셸이 safe area 를 이미 처리해서 0 이 되고, 모바일 브라우저 직접 접속에서만 값이 생긴다.
- 🚨 **safe-area 유틸은 여백을 함께 받는다 — `pt-safe-8` = safe area + 32px.** 예전에는 safe area 만 넣는 `pt-safe`/`pb-safe` 였는데, 같은 padding 속성이라 `py-8` 을 나란히 쓰면 **뒤에 오는 쪽이 이겨 한쪽이 조용히 죽었다.** 이 사고를 두 번 냈다 — 화면 5개의 상하 여백이 0 이었고(하단 문구가 모서리에 붙음), 바텀시트 닫기 버튼이 화면 맨 아래에 붙었다. 그래서 유틸이 `calc` 로 합쳐서 내보내고, **여백만 주는 `py-*` 를 그 위에 겹치지 않는다.**

### 바닥에 붙이는 것 · 붙이지 않는 것

화면 아래 버튼에 `mt-auto` 를 주면 **남는 높이가 한 군데로 몰린다.** 내용이 많으면 그게 자연스러운
바닥 고정이지만, 덩어리가 서넛뿐인 화면에서는 **가운데에 빈 화면이 한 폭** 생긴다.

- **붙인다** — 스크롤이 생기는 폼 (01 아이 만들기 · 가입 동의). 마지막 칸을 채우고 나면 버튼이 엄지 밑에 있다.
- **붙이지 않는다** — 한 화면에 다 들어오는 화면 (05 제안 후보 · 00-1 경로 고르기 · 초대 코드).
  버튼은 **내용 바로 뒤**를 따라가고 화면은 그냥 끝난다. 아래가 비는 것과 **가운데**가 비는 것은 다르게 읽힌다.
- 🚨 **빈 가운데를 글자로 채우지 않는다.** 그건 화면을 늘리는 것이지 고치는 것이 아니다.
  여러 화면이 계속 비어 보이면 **단계를 너무 잘게 쪼갠 것**이다 — 가입을 이름 화면과 동의 화면으로
  나눴다가 합친 것이 그 경우였다 (앞 화면에 입력칸이 하나뿐이었다).
- 🚨 **고르는 화면은 선택지가 본문이다.** 갈래를 바닥 버튼 둘로 세우면 `primary`/`secondary` 서열이
  생겨 **화면이 한쪽을 권하게 된다.** 00-1 에서는 그 권유가 정확히 막으려던 실수였다(잘못된 등록).
  줄로 세운다 (§7 설정 줄).

### 여백 철학

**위는 넉넉하게, 목록은 촘촘하게.** 화면 상단(인사말·상태)은 32px 을 쓰고 카드 목록은 12px 로 붙인다. 스크롤 한 번에 더 많은 카드가 들어오는 편이, 카드마다 숨 쉴 공간을 주는 것보다 이 서비스에 맞다 — 부모는 감상하러 온 게 아니라 확인하러 왔다.

## 6. 모양 · 높낮이

### radius

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--radius-field` | 10px | 입력 · 버튼 · 배너 |
| `--radius-card` | 14px | 카드 (프로토타입 지배값 유지) |
| `--radius-sheet` | 20px | 바텀시트 상단 |
| — (`rounded-full`) | 9999px | 칩 · 탭 · 아바타 |

직각(0px)은 화면 전체 바탕과 구분선에만 남는다.

### 높낮이 — 단 하나

| 단계 | 무엇 | 값 |
| --- | --- | --- |
| **평면** | 카드 · 배너 · 입력 · 목록 (화면의 95%) | 그림자 없음. 경계는 `line` 1px |
| **떠 있음** | 바텀시트 하나 | `--shadow-sheet: 0 -2px 16px rgb(34 31 27 / 0.08)` |
| **가림막** | 시트 뒤 | `--color-scrim` |

**단계를 늘리지 않는다.** 미세한 그림자가 여러 겹 깔린 화면은 저조도에서 뿌옇게 보인다. 무언가를 띄우고 싶으면 그림자 대신 배경색(`surface` vs `canvas`)이나 테두리로 구분한다.

## 7. 컴포넌트

값이 비어 있으면 §5 기본값(카드 안쪽 16px 등)을 따른다. 타이포 열은 §4 역할 이름이다.

**높이는 `globals.css` 의 `--height-*` 토큰 이름으로 적는다** (`button` = `min-h-button`). 숫자는 [`/design-system`](../../apps/web/src/app/design-system/page.tsx) 의 "높이" 가 지금 값을 읽어 보여준다. 🚨 **전부 최소 높이다** — 문구가 길거나 글자를 키우면 늘어난다 (§10).
좌우 여백처럼 한 컴포넌트 안에서만 쓰는 치수는 그 컴포넌트 코드가 원본이라 이 표에 옮기지 않는다 (머리말).

**구현은 직접 한다.** 별도 UI 라이브러리를 쓰지 않는다 — 토큰과 1:1 로 붙고 고치기 쉬운 쪽을 골랐다.
대신 접근성이 전부 우리 책임이 되므로, **직접 짜면 반드시 빠뜨리는 것은 이미 검증된 것 위에 얹는다.**

| 무엇 | 무엇 위에 | 왜 |
| --- | --- | --- |
| 바텀시트 | 네이티브 `<dialog>` | 포커스 트랩 · ESC · 바깥 `inert` · 스크림을 브라우저가 준다 |
| 달력 | [`react-day-picker`](https://daypicker.dev) | 그리드 ARIA · 방향키 이동 · 월 경계 처리 · 로케일. 이 넷을 손으로 짜면 어딘가 빠진다 |

🚨 **이 둘이 "UI 라이브러리를 쓰지 않는다" 의 예외 전부다.** `react-day-picker` 는 달력 하나만 하는 라이브러리라 자기 디자인을 들고 오지 않는다 — 기본 CSS 를 **불러오지 않고** `classNames` 로 우리 토큰만 입힌다. 버튼·입력·시트 같은 것을 주는 UI 킷은 계속 쓰지 않는다.

🚨 **얹는 범위는 자리마다 다르다.** 09 월 그리드는 라이브러리 머리줄(화살표 + 달 이름)을 그대로 쓰고, `date-field` 는 **머리줄만 우리가 그린다**(`hideNavigation`) — 거기서는 연월을 눌러 연도·달을 고르게 해야 하는데, 라이브러리가 주는 방법이 네이티브 `<select>` 뿐이기 때문이다 (아래 "날짜 고르기 달력"). **위 표의 넷은 어느 쪽에서도 우리가 가져오지 않는다** — 그 넷이 이 라이브러리를 얹은 이유 전부라, 하나라도 직접 짜기 시작하면 얹을 이유가 없어진다.

**아이콘은 [lucide](https://lucide.dev) 를 쓴다.** 크기 3단계(16 · 20 · 24)와 `strokeWidth: 1.75` 로 고정한다 — lucide 기본값 2 는 16px 에서 두껍게 보인다.
도메인 4종 매핑은 `apps/web/src/components/ui/icon.tsx` 한 곳에 있고, 그 컴포넌트는 **`aria-hidden`** 이다 — 아이콘이 단독 신호가 되는 것을 구조적으로 막는다 (§3).

🚨 **네 아이콘은 전부 집에 있는 물건이다** — 수저(`Utensils`) · 블록(`Blocks`) · 책(`BookOpen`) · 체온계(`Thermometer`). `health` 에 심전도(`HeartPulse`)를 쓰지 않는다: 그 기호는 **병원과 진단**을 뜻하는데 이 제품은 Health Agent 가 진단하지 않는다고 못박아 뒀다 (CLAUDE.md §2). 아이콘이 제품의 반대말을 하면 안 된다. 넷이 같은 층위의 사물이면 **색을 못 알아봐도 모양으로 구분된다** — §3 이 `food`·`health` 의 적록색약 근접을 걱정한 자리를 아이콘이 받쳐 준다.

### 버튼

| 이름 | 배경 | 글자 | 테두리 | 높이 | radius | 타이포 |
| --- | --- | --- | --- | --- | --- | --- |
| `btn-primary` | `brand` | `#FFF` | — | `button` | field | button |
| `btn-primary:active` | `brand-hover` | `#FFF` | — | `button` | field | button |
| `btn-approve` | `brand` | `#FFF` | — | **`approve`** · 전체 폭 | field | button |
| `btn-secondary` | `surface` | `ink` | `line-strong` 1px | `button` | field | button |
| `btn-tertiary` | 없음 | `ink-muted` | `line` 1px | `button` | field | button |
| `btn-danger` | `danger` | `#FFF` | — | `button` | field | button |
| `btn-kakao` | `kakao` | `kakao-ink` | — | `button` | field | button |
| `:disabled` (공통) | `surface-muted` | `ink-subtle` | `line` 1px | 그대로 | 그대로 | 그대로 |

- `btn-approve` 는 **승인 게이트 2곳 전용**이다. 다른 버튼보다 한 단계 키우고(`approve` > `button`) 전체 폭을 쓴다 — 되돌릴 수 없는 행동을 잘못 눌러서 실행하는 경로를 만들지 않는다.
- 🚨 **`approve` 와 `field` 는 지금 값이 같지만 다른 토큰이다.** 승인 버튼은 잘못 누르지 않게 키운 것이고 입력은 16px 글자에 여유를 준 것이라, 한쪽을 바꿀 때 다른 쪽이 따라 바뀌면 안 된다.
- 🚨 **승인 버튼은 문구가 길어져도 전부 보여야 한다.** 무엇을 승인하는지가 가려진 승인 버튼은 승인 게이트가 아니다 — 문구를 줄여 넣지 말고 버튼이 늘어나게 둔다 (§10).
- `btn-danger` 는 **파괴적 확정에만** (10 설정의 보호자 연결 끊기·탈퇴 확정·데이터 삭제, 11 의 알레르기·안전 정보 회수). 🚨 **화면이 아니라 뜻으로 정해진다** — §11 표의 "10 설정에서만" 은 설정이 유일한 자리이던 시절의 서술이었다. 승인 게이트의 "아니에요" 는 `btn-secondary` 다. 거절은 파괴가 아니고, 되돌릴 수 있는 삭제(11 측정 한 줄 지우기)도 파괴가 아니다.
  🚨 **같은 이유로 동의 철회가 이 목록에서 빠졌다.** 처음 이 줄을 쓸 때는 동의 4건이 전부 필수여서
  철회가 탈퇴에 가까웠다. 지금 화면에서 끌 수 있는 것(`location`)은 **되돌릴 수 있고** 기록도
  지워지지 않는다 — 같은 시트가 "설정에서 다시 켤 수 있어요" 라고 말하는데 버튼이 빨강이면 화면이
  스스로를 부정하고, 철회권을 돌려주려고 만든 구역이 철회를 말리는 것처럼 읽힌다.
  필수 4건에는 철회 버튼 자체가 없다.
- `btn-kakao` 는 **00 로그인 화면 전용**이다 (§2-6). 그 화면에 `btn-primary` 가 없어서 "한 화면에 primary 하나" 규칙과 부딪히지 않는다.
- 🚨 **목록 바로 아래에 전체 폭 `btn-secondary` 를 두지 않는다.** `secondary` 는 `surface` 바탕 + 테두리 + `radius-field` 라 **목록 상자와 실루엣이 같다.** 목록 밑에 붙이면 둥근 사각형이 둘 연달아 서고, 그런 구역이 두세 개면 화면이 §2-2 가 말한 **상자의 나열**이 된다 (11 에서 실제로 그랬다). 목록에 **더하는** 행동은 구역 머리줄 오른쪽에 `btn-tertiary`(compact) 로 올린다 — 상자가 사라지고 "무엇이 몇 건 · 여기서 더한다" 가 한 줄에 모인다.
- 🚨 **크기는 두 단계뿐이다.** `default`(높이 `button` 48)는 **화면이 소유한 행동**(다음 · 홈으로 · 제출),
  `compact`(높이 `touch` 44 · 좌우 16)는 **카드 안의 행동**이다. 카드 본문이 12~14px 인데 48px 짜리 상자가
  들어가면 버튼이 내용보다 커 보인다 — 실제로 그렇게 보였다. 44 는 터치 타깃 최소값이라 더 줄이지 않는다.
  `btn-approve` 는 이 축을 보지 않는다(항상 52 · 전체 폭).
- **카드 안의 버튼은 폭도 내용만큼만 쓴다.** 전체 폭으로 늘렸더니 세 글자짜리 라벨에 초록 판이 붙어 더 커 보였다 —
  서열은 크기가 아니라 **채움 대 빈 칸**이 낸다.
- 한 화면에 `btn-primary` 는 **하나**. 두 개면 무엇이 다음 행동인지 부모가 판단해야 한다.
  - **예외는 목록 항목이다.** 같은 종류의 행동을 항목마다 제공할 때(05 제안 카드의 "이걸로")는 항목마다 primary 를 둔다.
    이때 **화면의 다른 곳에는 primary 가 없어야 한다** — 05 의 "홈으로" 가 `btn-secondary` 인 이유다.
    항목 안에서 실행과 거절을 secondary + tertiary 로 뒀더니 **둘이 똑같아 보여서** 어느 쪽이 실행인지가 사라졌다.
- 🚨 **`btn-tertiary` 는 글자만 있는 버튼이 아니다.** 예전에는 배경도 테두리도 없었는데, 옆에 `btn-secondary` 가
  서면 한쪽만 상자가 있어 줄이 어긋나 보였고 카드 안에서는 버튼인지 문장인지 구분이 안 됐다. 셋의 실루엣을
  맞추고(높이 `button` · radius `field`) 서열은 **채움 → 옅은 채움 → 빈 칸**으로 낸다.
  글자를 `brand` 로 두지 않는 것도 같은 이유다 — 초록 글자를 두면 **거절 버튼이 실행 버튼보다 눈에 띈다.**

### 아이콘 버튼

글자 없이 아이콘만 있는 원형 버튼. 채팅바(03)처럼 라벨을 놓을 자리가 없는 곳에만 쓴다.

| 이름 | 사양 |
| --- | --- |
| `icon-button-ghost` | 배경 없음 · `ink-muted` · hover/press `brand-soft` + `brand-ink` · `touch` 정사각 · full |
| `icon-button-brand` | `brand` 배경 · 흰 아이콘 · press `brand-hover` · `touch` 정사각 · full |
| `:disabled` | ghost 는 배경 없이 `ink-subtle`, brand 는 **`surface`** + `line` 테두리 |

🚨 **`aria-label` 이 필수다.** 글자가 없으니 스크린리더에는 그것밖에 남지 않는다 (§10).
🚨 **brand 의 비활성 배경은 `surface-muted` 가 아니다.** 이 버튼이 앉는 채팅바가 `surface-muted` 라 같은 색이면 버튼이 통째로 사라진다 (실제로 안 보였다).
🚨 **여기에 `Spinner` 를 넣지 않는다.** `prefers-reduced-motion` 에서 스피너는 숨는데(§8) 글자가 없어 빈 원만 남는다 — 기다림은 비활성 상태와 `aria-label` 이 말한다.

### 아이콘 타일

`brand-soft` 바탕의 정사각 타일(radius-field) 안에 아이콘 하나. 목록 줄 앞에 서서 어떤 종류의 줄인지를 모양으로 알린다.
🚨 **도메인 색을 여기 넣지 않는다** — 도메인 색은 "어느 Agent 의 결과인가" 신호고(§3), 사실을 나열하는 줄에 쓰면 그 뜻이 흐려진다.

톤이 셋이다.

| 톤 | 색 | 어디에 |
| --- | --- | --- |
| `brand` (기본) | `brand-soft` + `brand-ink` | 03 홈 목록 줄 · 04 저장 결과 |
| `plain` | **호출자가 준다** (`domainField()`) | 07 기록 줄 · 기억 카드 — 그 영역의 도메인 색 |
| `neutral` | `surface-muted` + `ink-muted` | 색을 줄 수 없는 자리 (`is_stale` 기억 카드) |

🚨 **`plain` 은 primitive 가 도메인을 몰라야 해서 있는 톤이다** (`components/ui/` 는 토큰만 안다). 색은 호출자가 `className` 으로 넘긴다 — `cn()` 이 tailwind-merge 가 아니라서, 여기서 `bg-*` 를 깔아 두면 바깥 색이 덮이지 않는다.
🚨 **07 의 타일을 브랜드 톤으로 바꾸지 않는다.** 목록 여섯 줄에 초록 타일이 서면 브랜드가 장식이 되고, 타일 안에 든 것이 도메인 아이콘이라 "어디서 왔나" 와 "무엇을 하는가" 가 같은 색이 된다.

### 입력

| 이름 | 사양 |
| --- | --- |
| `input` | `surface` 배경 · `line-strong` 1px · radius-field · 높이 `field` · **body(16px)** · placeholder `ink-subtle` |
| `input:focus-visible` | `brand` 2px outline · offset 2 · 테두리는 그대로 |
| `input[aria-invalid]` | `danger` 1px 테두리 + 아래 `caption` / `danger-ink` 로 사유 한 줄 |
| `textarea` (03 입력) | 위와 동일 · 자동 증가 · 몇 줄까지 늘어나는지는 [`text-area.tsx`](../../apps/web/src/components/ui/text-area.tsx) 가 원본. 🚨 "한 줄" 이라고 부르지만 부모는 서너 줄을 쓴다 — 쓰는 동안 자기 글이 안 보이면 안 된다 |
| `date-field` | 값을 보여주는 트리거(입력과 같은 사양) + 달력을 담은 **바텀시트** · 연월을 누르면 **연도·달 그리드**(아래 "날짜 고르기 달력") · 오늘 이후 비활성 · 요일과 월 이름은 한국어. 🚨 트리거의 날짜 표기는 `formatDateWithYear`(**연도 있고 요일 없음**)다 — 생일을 받는 입력이라 어느 해인지가 본체고 요일은 군더더기다 |
| `checkbox` | 네이티브 `<input type="checkbox">` 를 `sr-only` 로 숨기고 표식만 그린다 · 표식 **20 × 20** · **`rounded-full`** · 선택 전 `line-strong` 1px / 선택 후 `brand` 채움 + 흰 체크 16 · 행 전체가 터치 타깃(`touch`) |

🚨 **`failed` 이벤트가 오면 `raw_text` 를 `textarea` 에 그대로 되돌려 놓는다.** 부모가 다시 타이핑하게 만들지 않는다.

**채팅바 (03 홈)** — `surface-muted` 알약(full) 하나 안에 `[사진] [마이크] [입력] [보내기]` 가 들어간다.
빈 상태의 높이는 **버튼 한 줄(`touch` 44) + 알약 안쪽 여백**이고, 글이 길어지면 알약이 같이 자란다(3줄에서 멈추고 그 안에서 스크롤).
🚨 **한 글자를 넣었다고 높이가 뛰면 안 된다.** `textarea` 의 `rows` 기본값이 **2** 라 자동 증가가 바닥을 두 줄로 잡고 있었다 —
한 글자만 쳐도 알약이 52 → 75px 로 튀었다. 바닥은 한 줄이고, 높이는 내용이 정한다.
자라는 동안 버튼은 **아래에 붙는다** — 가운데 두면 보내기 버튼이 긴 글 옆에 떠 있는 것처럼 보인다.

🚨 **placeholder 는 한 줄에 들어가는 길이여야 한다.** 버튼 3개가 132px 을 가져가서 입력에 남는 폭이 206px 뿐인데,
그보다 긴 문구를 넣었더니 **빈 입력창이 두 줄 높이(75px)로 섰다.** 전체 문구는 화면에서 숨긴 라벨이 진다.
입력은 테두리 없는 `bare` 변형이고, 상자처럼 보이는 것은 알약 쪽이다. 화면 아래에 고정되며
그 고정과 safe area 는 [`Screen`](../../apps/web/src/components/ui/screen.tsx) 의 `bottomBar` 가 소유한다 (§5).

부모는 이미 매일 아이 얘기를 하고 있다 — 입력이 폼이 아니라 **대화창 모양**인 이유다 (CLAUDE.md §1 "수신처만 바꾼다").
제안(`agent_prompts`)은 이 알약 **바로 위**에 **가로 한 줄**로 붙는다(위 제안 줄 `scroller`). 다음에 할 말을 고르는 자리라 입력과 멀면 의미가 없고, 세로로 쌓으면 그만큼 입력창이 밀린다.

**표식은 20px 이다.** 처음 24px 로 잡았는데 16px 라벨 옆에서 표식이 글자보다 커 보였다. 누르는 영역은 행 전체(44px)라 표식을 줄여도 터치가 나빠지지 않는다.

**체크박스에 새 radius 를 만들지 않으려고 `rounded-full` 을 골랐다.** 24px 사각형에 `radius-field`(10px) 는 과하고, 그 사이 값을 만들면 §6 의 radius 4개가 5개가 된다.

🚨 **동의 화면의 체크박스는 승인 게이트가 아니다.** `btn-approve` 와 `caution` 색을 쓰지 않는다 — 그 둘은 되돌릴 수 없는 2곳 전용이고(§3), 법적 동의는 그 2곳이 아니다. 제출은 `btn-primary` 다.

### 고르는 칸 (`choice-field`)

**둘~셋 중 반드시 하나**를 고르는 칸. 라벨은 상자 위 `caption`/`ink-subtle`, 칸은 `min-h-field` ·
`radius-field` · 똑같은 너비로 나눈다. 고른 칸은 `brand-soft` 배경 · `brand` 1px · `brand-ink` 글자 ·
**체크 아이콘**, 나머지는 `surface` · `line-strong` 1px · `ink-muted`.

🚨 **선택지가 둘이면 `select` 를 쓰지 않는다.** 드롭다운은 고를 것이 많거나 화면에 다 못 세울 때 쓴다.
두 가지뿐이면 그 상자는 있는 선택지를 한 번 **감췄다가** 탭 두 번으로 다시 보여주는 일만 한다.
🚨 **`chip-choice` 도 아니다.** 칩은 `aria-pressed` 토글 여럿이라 **둘 다 꺼진 상태가 정상**이고
(01 관심사가 그 자리다), 보조기술에 "둘 중 하나" 라는 관계가 드러나지 않는다. 이 칸은 반대로
**비어 있을 수 없는 값**이다 — 비워 둘 수 있으면 그건 `select` 자리다.
🚨 **네이티브 `<input type="radio">` 를 `sr-only` 로 숨기고 표식만 그린다** (`checkbox` 와 같은 처리).
같은 `name` 을 주면 그룹 · 방향키 이동 · 단 하나만 선택 · 폼 의미를 브라우저가 그대로 준다 —
직접 만든 `role="radiogroup"` 보다 언제나 정확하다. 손으로 만든 것은 `select` 하나뿐이고,
그건 네이티브로 **생김새를 못 정해서** 진 빚이다.
🚨 **`<fieldset>` + `<legend>`** 라 그룹 이름이 각 선택지에 저절로 붙는다 ("성별, 남자아이, 2 중 1").
🚨 **고른 것을 색 하나로 말하지 않는다** — 체크 아이콘이 같이 선다 (§3 · `select` 항목과 같은 언어).
🚨 **칸을 똑같이 나눈다.** 글자 길이에 따라 너비가 달라지면 한쪽이 기본값처럼 보인다 — 어느 쪽도 기본이 아니다.
🚨 **체크 아이콘 자리를 늘 차지하게 둔다.** 고를 때 아이콘이 생기며 글자가 밀리면 "색만 바꾼다"(§8)가
깨지고 칸이 들썩인다.
🚨 **`min-h-field` 다** — 같은 폼의 `input`·`date-field` 와 높이를 맞춘다. 한 칸만 낮으면 그 칸이
입력이 아니라 장식으로 읽힌다.

### 칩

| 이름 | 사양 |
| --- | --- |
| `chip-domain` | `{domain}-soft` 배경 · `{domain}-ink` 글자 · 아이콘 16 + 라벨 · 높이 `chip` · full · label |
| `chip-evidence` | `surface` 배경 · `line` 1px · `ink-muted` · 높이 `chip` · full · caption |
| `chip-evidence-stale` | 위와 같되 `line` **점선** · `ink-subtle` (`is_stale` 근거) |
| `chip-count` | 배경 없음 · `ink-subtle` · caption ("기록 12건") |
| `chip-choice` | 눌러서 고르는 칩. 선택 전 `surface` · `line` 1px · `ink-muted` / 선택 후 `brand-soft` · `brand` 1px · `brand-ink` · 높이 `chip` · full · label |

세 칩의 좌우 여백은 같고 [`chip.tsx`](../../apps/web/src/components/ui/chip.tsx) 가 원본이다. 도메인·근거 칩을 만들 때 거기서 가져간다.

`chip-choice` 는 `aria-pressed` 로 상태를 낸다 — 색만으로 "골랐음" 을 전달하지 않는다 (§10). 보이는 칩(`chip`)의 위아래에 투명 여백을 둬서 누르는 영역을 `touch` 로 채우기 때문에(§9) **칩 줄에는 가로 gap 만 주고 세로 gap 은 주지 않는다.**

칩 문구가 길면 칩 안에서 줄바꿈한다 — 말줄임(`…`)으로 자르지 않는다. 관심사 이름이 잘리면 무엇을 고르는지 모른다.

칩 줄은 가로 스크롤하지 않는다. 넘치면 줄바꿈하고, 4개를 넘으면 **"+N" 로 접는다** — 근거를 숨기는 게 아니라 카드에서 목록으로 옮기는 것이고, 누르면 07 화면으로 간다.

🚨 **이 규칙이 지키는 것은 "판단에 쓰는 정보를 가리지 않는다" 다.** 근거 칩과 관심 칩이 그렇다 — 밀어서 봐야 하면 부모는 안 민 것을 없는 것으로 친다. **들어가는 문은 여기 해당하지 않는다**: 03 채팅바 위의 제안 줄은 가로로 눕히고 넘치는 만큼 민다(아래 제안 줄). 밀지 않아도 잃는 정보가 없고(직접 적으면 된다), 세로로 쌓으면 부모가 제일 자주 여는 화면에서 **입력창이 두 줄만큼 아래로 밀린다**.

### 카드

| 이름 | 사양 |
| --- | --- |
| `card` | `surface` · `line` 1px · radius-card · 안쪽 16 · 카드 사이 12 |
| `card-accent` | 위와 같고 테두리만 `brand`. **한 화면에 한 장** — 그 화면에서 제일 먼저 읽어야 하는 한 덩어리에만 (03 눈여겨볼 것 · 04 적어주신 한 줄). 두 장이 되면 강조가 아니라 장식이다 |
| `suggestion-row` (05 개인화) | 카드가 아니라 **목록 한 줄**이다. 접히면 `surface` 에 도메인 칩 + 기록 건수 / 제안 문장(`body`) + 쉐브론, 열리면 **두 칸** — 위 **`{domain}-soft`**(제안 `title` · 이유 `body-sm` · 글자는 전부 `{domain}-ink` · 칩은 `surface` 바탕으로 띄운다) · 아래 **`canvas`**(**근거 칩 행 필수** · 고르는 버튼). 줄 사이는 `line` 1px, 목록 전체가 한 컨테이너. 누른 느낌은 **그 줄이 열릴 색**이다 |
| `card-general` (05 일반) | `canvas` 배경 · `line-strong` **1px 점선** · 머리줄에 `chip-domain` + "또래 기준 일반 추천" 라벨 + `chip-count` **필수** · 제안 문장 `body`/`ink` · 기준 문구 `body-sm`/`ink-muted`. **고르는 버튼이 없다** — 승인 게이트 ㉠ 은 되돌릴 수 없는 캘린더 쓰기인데 이 추천은 이 아이의 기록에서 나온 것이 아니다. 개인화 목록이 서는 자리에 **대신** 선다 |
| `card-failed` | `surface-muted` · 테두리 없음 · `ink-muted` · 재시도 `btn-tertiary` |
| `card-photo` (08) | **4:3 이미지가 위, `line` 1px 아래로 읽어낸 것이 이어 붙는 한 덩어리.** 안쪽 16. 확인 단계에서만 `accent`(그 화면의 한 장)이고 저장한 뒤에는 기본 테두리로 돌아온다. 사진이 없을 때도 같은 4:3 칸이고 `surface-muted` 면에 브랜드 아이콘 하나인데, 이건 **주된 경로가 아니다** — 사진은 03·09 에서 시트로 고르고 08 에는 이미 사진을 들고 들어온다(위 "고르는 시트"). 이 빈 칸은 직접 링크·새로고침으로 들어왔을 때만 선다. 🚨 점선 드롭존을 만들지 않는다(점선은 `card-general` 과 `chip-evidence-stale` 이 이미 가져간 뜻이다) |

🚨 **"승인 전에는 저장되지 않아요" 라벨에 `caution` 을 쓰지 않는다.** 이 표는 한동안 `caution` 계열을 적어 뒀는데, `caution` 은 **승인 게이트 2곳(캘린더 쓰기 · 건강 기록 확정) 전용**이고 (최상위 `CLAUDE.md` §2 · 아래 §11), 08 의 `commit` 은 `event` 를 **draft** 로만 만들어서 게이트가 아니다. 그 문구는 경고가 아니라 **사실**이라 중립 면(`surface-muted` + `ink-muted`)에 앉힌다. 게이트를 색으로 늘리면 세 곳이 된다.

🚨 **개인화(`suggestion-row`)와 `card-general` 은 같은 컴포넌트로 만들지 않는다.** 한 컴포넌트에 플래그를 넣으면 언젠가 근거 0건인데 개인화로 그려진다.
**타입도 응답 필드도 따로다** — `GeneralSuggestion` 에는 `evidence` 필드가 아예 없어서 개인화 목록에 넘기면 컴파일이 막고,
응답에서도 `suggestions` 와 `general` 로 갈려서 개인화 집계에 섞이지 않는다 (CLAUDE.md §2 하드 기준).
🚨 **둘이 한 화면에 같이 서지 않는다.** 일반 추천은 개인화 **대신** 나가는 것이라, 같이 그리면 무엇이 우리 아이 기준인지가 흐려진다.
🚨 **일반 추천이 위, 되묻는 질문이 아래다.** 부모가 이 화면에 온 이유는 "지금 뭘 할까" 고 질문은 "다음엔 더 맞추기" 다 — 순서를 뒤집으면 답부터 요구하는 화면이 된다.
🚨 **일반 추천을 그린 화면에서는 질문 카드 문구가 달라진다.** 또래 기준 추천을 이미 보여 준 화면이 "근거 없이 추천을 만들지 않겠다" 고 말하면 화면이 스스로를 부정한다.

🚨 **열린 줄의 제안 문구는 `title`(20) 이다. `section`(17) 으로 내리지 않는다.** 본문 서체가 단일 웨이트라
굵기가 브라우저 합성이고(§4), 위계를 사실상 **크기가 혼자 진다** — 17 대 14 로는 무엇이 제안인지 안 보인다.
같은 이유로 **고르는 버튼이 남는 폭을 가져간다.** 거절은 제 폭만 쓴다(반반으로 나누면 서열이 사라진다).

**왜 목록인가** — 05 는 **고르는 화면**이지 읽는 화면이 아니다. 후보를 카드로 전부 펼쳐 놓으면 부모가 둘 다
읽고 비교해야 하는데, 밤에 한 손으로 여는 화면에서 그 비교가 곧 인지 노동이다. 한 줄씩 훑고 **하나만 그 자리에서
연다**(항상 한 줄). 🚨 **접힌 줄을 끌고 가는 것은 제안 문장**이고(`body` · `ink`), 도메인 칩과 기록 건수는
그 위아래의 메타다 — 문장이 약해지면 목록에서 제일 약한 것이 목록의 내용이 된다.
🚨 **접힌 줄에도 기록 건수가 남는다.** 접힌 동안 "근거를 달고 나온 제안" 이라는 사실이 사라지면 구조가 약속을 깬 것이다.

🚨 **아래 칸이 `canvas` 인 이유는 후보 사이 경계가 줄 안의 경계보다 세야 하기 때문이다.** 접힌 줄이
`surface` 인데 아래 칸까지 `surface` 로 두면, 고르는 버튼이 **아래 후보와 한 덩어리로 묶여** 보인다 —
열린 줄이 색이 끝나는 데서 끝나는 것처럼 읽힌다. 열린 줄은 도메인 색 머리 + 웜 바닥 한 덩어리고,
접힌 줄은 흰 줄이다.

**왜 두 칸인가** — 한 배경에 제목 · 이유 · 근거 · 버튼을 쌓으면 넷이 같은 무게로 읽혀서, 이 제품의 차별점인
"근거를 달고 나가는 추천"이 본문에 묻힌다(초록으로 칠해도 마찬가지다). 근거와 버튼을 **영수증처럼 아래 칸**으로
내리면 위 칸은 제안만 말하고 아래 칸이 "그래서 무엇을 보고 말했나 · 어떻게 할까"를 받는다. 나누는 수단은 선이
아니라 **바탕색**이다 (그림자도 선도 늘리지 않는다 · §6). 아래 칸은 줄 가장자리까지 꽉 차서 **카드 속 카드가
되지 않는다.**

🚨 **`brand-soft` 위의 글자는 전부 `brand-ink` 다.** 회색 잉크를 얹으면 대비를 `canvas` 기준으로 잘못 계산하게 되고,
초록 카드 위에 회색 글씨가 얹힌 것처럼 보인다. 위계는 색이 아니라 크기가 만든다.

health 줄도 같은 규칙으로 자기 색(플럼)을 쓴다 — 면의 뜻은 "고를 수 있음" 이 아니라 "어느 Agent" 다.
다른 것은 **고르는 버튼이 없다**는 점과 이유 라벨(무엇을 봤나 / 참고할 점), 그리고 진단이 아니라는 문구다.

**접은 것을 말없이 지우지 않는다.** "안 할래요" 로 줄이 사라지면 무슨 일이 있었는지 알리고(`role="status"`)
되돌릴 길을 같은 자리에 둔다 — 누르던 버튼이 언마운트되므로 그 자리로 초점도 옮긴다. 전부 접었을 때 화면에
남는 설명도 이 줄이 진다.

### 제안 줄

"이 주제로 도와드릴까요" 한 줄. `surface` 배경 · `line` 1px · full · 높이 `touch` · 도메인 칩 + 문구.
누른 느낌은 **그 주제가 열릴 색**(`{domain}-soft`)이다 — 05 제안 줄과 같은 규칙이라, 누른 색과 다음 화면의 색이 같다.

**배치는 두 가지고, 자리가 정한다.**

| | 어디 | 왜 |
| --- | --- | --- |
| `list` | 04 저장 결과 | 화면에 자리가 있다. 세로로 쌓아 한눈에 다 보인다 |
| `scroller` | 03 채팅바 **위** | 세로가 비싸다. 가로 한 줄로 눕히고 넘치면 민다 — 바 높이가 183 → 133px 로 줄고 그만큼 입력창이 올라온다 |

`scroller` 는 좌우 여백을 상쇄해 **화면 끝까지** 흐른다(안쪽에서 잘리면 밀 수 있다는 게 안 보이고 마지막 줄이 잘린 것처럼 읽힌다), 상쇄값은 하단 바의 여백과 같아야 한다.
🚨 **`overscroll-behavior-x: contain` 을 건다.** 웹뷰에서 가로 스와이프가 끝까지 가면 네이티브 뒤로가기 제스처로 넘어간다 — 제안을 밀다가 화면이 뒤로 가면 안 된다.
🚨 **문구를 자르지 않는다.** 밀면 전부 보이므로 말줄임을 쓰지 않는다(§7 칩과 같은 규칙).

🚨 **제안을 버튼으로 쌓지 않는다.** 04 에서 `[제안][제안][아니요]` 3개를 같은 무게로 세웠더니 무엇이 다음 행동인지가
사라졌다. 고르는 것은 줄이고, **화면을 떠나는 것만 버튼**이다. "아니요" 는 버튼으로 두지 않는다 — 아무것도 고르지
않아도 저장은 이미 끝나 있고, 그 사실은 아래 문구가 말한다.

### 배너

| 이름 | 무엇을 알리는가 |
| --- | --- |
| `banner-caution` | **내가 확인해야 한다** — 승인 게이트 2곳 전용 (06 의 `prechecks`) |
| `banner-danger` | **막혔다** — 알레르기 저촉 · 건강 추천 중단 |

두 배너는 배경·왼쪽 바·글자만 색이 다르고 치수는 같다. 구현은 [`components/ui/banner.tsx`](../../apps/web/src/components/ui/banner.tsx) 가 원본이다.

배너는 화면 최상단 한 곳에만 둔다. 두 개가 동시에 필요하면 `danger` 가 이긴다.
guard 가 여러 건이어도 배너는 **하나**고 안에서 줄로 나눈다 — 배너가 쌓이면 그때부터 아무도 안 읽는다.

🚨 **승인 게이트가 시트가 아니라 화면이면 경고가 결정하는 자리에 없다.** 06 은 시트라 배너와
`btn-approve` 가 한 화면에 같이 서지만, 11-2 는 화면이라 배너가 맨 위에 있고 승인 버튼은 카드 열 장
아래다 — 누르는 순간에는 그 배너가 화면에 없다. 이때 **배너를 하나 더 세우지 않는다.** 대신 버튼 바로
위에 `caution` **글자 한 덩이**를 둔다: 이 화면이 게이트라 그 색을 쓸 수 있고(§3), `caution-soft`
배경이 아니라 카드 면 위라서 `caution-ink` 가 아니라 `caution` 이다(§5 — 이름이 곧 용도다.
`surface` 위 5.1:1). 🚨 **색이 단독 신호가 아니다** — 무엇을 왜 다시 봐야 하는지를 글자가 말한다.

🚨 **실패는 배너가 아니다.** `failed` · `partial` 의 실패 쪽은 `card-failed` 다 (§3).

### 고르기 상자

닫혀 있을 때는 `surface` · `line-strong` 1px · `full` · `min-h-touch` · `body-sm` + 쉐브론.
펼치면 바로 아래에 `surface` · `line-strong` 1px · `radius-card` 패널이 붙고, 고른 항목만
`brand-soft` + `brand-ink` + 체크 아이콘이다. 라벨은 상자 위 `caption`/`ink-subtle`.

⚠️ **네이티브 `<select>` 를 쓰지 않는다.** 그쪽은 키보드·포커스·스크린리더·바깥 클릭을 브라우저가
줘서 싸지만 닫혀 있을 때 말고는 생김새를 우리가 못 정한다. 직접 만들기로 한 이상
**그 넷이 전부 우리 책임**이다 (§7 머리말 "라이브러리를 안 쓰는 대신 접근성이 전부 우리 책임").

🚨 **ARIA 는 `combobox` + `listbox` 한 쌍이다.** 버튼이 `role="combobox"` · `aria-expanded` ·
`aria-haspopup` · `aria-controls` 를 지고, 목록이 `role="listbox"`, 항목이 `role="option"` +
`aria-selected` 를 진다. `role="combobox"` 가 없으면 "콤보 상자, 식사" 처럼 **고른 값까지** 읽히지 않는다.
🚨 **열 때 고른 항목으로 포커스가 들어가고, 닫을 때 버튼으로 돌아온다.** 안 돌아오면 닫는 순간
포커스가 `<body>` 로 떨어져 키보드 사용자가 자리를 잃는다 (09 달력에서 같은 사고를 냈다).
🚨 **ESC · 바깥 클릭 · Tab · 스크롤에 닫힌다.** 목록이 트리거에 붙어 있어서 페이지가 움직이면 자리가 어긋난다.
🚨 **다만 "여는 동작이 만든 스크롤" 에는 닫히지 않는다.** 그 규칙이 말하는 것은 **연 다음의** 움직임인데,
여는 것 자체가 스크롤을 만든다 — 버튼을 누르거나 항목에 포커스가 들어가면 브라우저가 그것을 보이게 하려고
스크롤되는 면(바텀시트 본문 등)을 움직이고, 그 스크롤이 같은 틱에 감시에 걸려 **방금 연 목록을 즉시 닫는다.**
화면에서는 **"눌렀는데 아무 일도 안 일어난다"** 로 보인다 (11 검사지 시트에서 실제로 났다 — 두 번 눌러야 열렸다).
막는 방법 셋: ㉠ 여는 포커스는 `focus({ preventScroll: true })` · ㉡ 스크롤 감시를 **한 프레임 뒤에** 건다 ·
㉢ **목록 자신이 스크롤한 것은 제외**한다(목록에도 `overflow-y-auto` 가 있어서 방향키로 내려가면 스스로 스크롤한다).
🚨 **방향키 · Home · End 가 항목 사이를 옮긴다.** Enter · Space 로 고른다.
🚨 **그림자가 없다** (§6). 떠 있는 면의 경계는 `line-strong` 1px 이 만든다 (토스트와 같은 처리다).
🚨 **등장 애니메이션도 쉐브론 회전도 없다** (§8). 상호작용 전환은 "색만 바꾸고 크기·위치는 건드리지 않는다" 라서,
펼침 방향은 아이콘을 갈아 끼워 말한다.
🚨 **라벨을 지우지 않는다** — 좁은 화면에서 상자만 남기면 무엇을 고르는 상자인지 사라진다.
🚨 **사유(`error`)는 상자에 붙인다** (입력과 같은 처리). `aria-invalid` + `aria-describedby` 를 함께 걸고
테두리를 `danger` 로 바꾼다. 상자 밖에 떠 있는 문단으로 두면 보조기술이 그 문구를 **어느 칸의 문제인지**
잇지 못하고, 색만 바꾸면 단독 신호가 된다 (§3) — "고르지 않음" 을 그대로 넘길 수 있는 칸에서 그건
**빈 값이 조용히 저장되는 길**이다 (11-2 검사지의 분류가 그 칸이다).

### 토스트

**화면 안에 자리가 없는 사실**을 잠깐 띄운다. `surface` 바탕 · `line-strong` 1px · radius-card · `body-sm`/`ink` ·
**위**에 붙는다 (`max-w-content` 안 · safe area + 8) · 6초 뒤 사라진다.

무엇을 띄우는지가 이 컴포넌트의 전부다. §14 가 "어떤 성공을 알려야 하는지가 안 정해졌다" 로 미뤄 두었던 자리이고, 정한 답은 아래다.

| | |
| --- | --- |
| **띄우지 않는 것** | **성공.** 이 제품의 성공은 이미 화면이 말한다 — 승인 결과는 화면 전환, 교정 결과는 시트 안의 `cascade`, 저장은 목록이 바뀌는 것. 토스트를 얹으면 같은 말을 두 번 하면서 지친 부모의 시선을 한 번 더 뺏는다 |
| 〃 | **되돌릴 것이 있는 일.** 05 의 "접어 둔 제안 N건 · 되돌리기" 처럼 화면 안에 자리를 만든다 — 토스트는 사라지므로 되돌릴 길을 담으면 길이 같이 사라진다 |
| **띄우는 것** | **조용히 되돌아간 실패** 하나. 준비물 체크처럼 낙관적으로 반영했다가 실패해 원래대로 돌아가는 경우, 화면에는 체크가 풀린 것만 보이고 **왜** 가 어디에도 없다 (체크박스 옆에는 문장이 들어갈 자리가 없다) |

🚨 **누를 수 없다.** 닫기 버튼을 달면 그 버튼이 무엇을 하는지 또 말해야 하고, 메시지 자체를 버튼으로 만들면 스크린리더가 "…버튼" 이라고만 읽는다. 시간이 지나면 사라지고 그 동안 클릭은 뒤로 통과한다(`pointer-events-none`).
🚨 **행동을 담지 않는다** (되돌리기·다시 시도). 사라지는 자리다.
🚨 **한 번에 하나다.** 쌓으면 390px 화면에서 본문이 묻힌다 — 새 메시지가 앞의 것을 덮어쓴다.
🚨 **그림자도 등장 애니메이션도 없다** (§6 · §8). 경계는 `line-strong` 이 만든다 (canvas 대비 3.0:1).
🚨 **라이브 리전은 빈 채로 늘 DOM 에 세워 둔다.** 메시지와 함께 나타나면 스크린리더가 리전이 생긴 것으로 보고 내용을 안 읽는 경우가 있다. `polite` 다 — 읽던 것을 끊을 만큼 급하지 않다 (§10).
🚨 **바텀시트 안에서 부르지 않는다.** 시트는 `<dialog>` 의 top layer 라 이 `fixed` 레이어가 시트 **뒤로** 깔린다. 시트 안의 실패는 시트 안에서 말한다.
🚨 **발화 원문을 싣지 않는다** (최상위 §2 개인정보).

### 접히는 질문 (10 › 고객센터)

`card` 안에 네이티브 **`<details>`/`<summary>`** 를 얹는다. **기본은 닫힘**이고, 질문만 보이는 목록이 먼저 읽힌다.

- 🚨 **`aria-expanded` 를 손으로 달지 않는다.** 펼침 상태·키보드·포커스를 브라우저가 준다 — 시트를 `<dialog>` 로, 달력을 `react-day-picker` 로 고른 것과 **같은 기준**이다 (§7 컴포넌트).
- 🚨 **기본 삼각형 마커를 지운다** (`list-none` + `::-webkit-details-marker`). 뜻을 나르는 그림은 lucide 한 곳에 모으기로 했고(§4), 브라우저마다 다르게 생긴 마커가 그 규칙 밖에 하나 더 서면 안 된다.
- 🚨 **여는 애니메이션이 없고 쉐브론도 회전하지 않는다** (§8). 방향은 아이콘을 갈아 끼워 말한다 — 고르기 상자와 같은 처리다.
- 🚨 **한 번에 하나만 열리게 하지 않는다** (`name` 속성 없음). 두 답을 나란히 비교하는 것을 막을 이유가 없고, 방금 연 것이 다른 것을 닫으면 화면이 제멋대로 움직인다.
- 🚨 **`summary` 의 여백을 카드 밖으로 네 방향 다 되민다** (`-m-4 p-4`). 글자만 누르게 하면 타깃이 44를 못 채우고, 아래만 남기면 카드의 `p-4` 와 겹쳐 **닫힌 카드 아래에 32px 빈 띠**가 생긴다. 펼친 답과의 간격은 답을 감싼 `div` 의 `mt-4` 가 진다.

### 바텀시트

- 상단 radius-sheet · `surface` · `--shadow-sheet` · 뒤에 `--color-scrim`
- 최대 높이 `88dvh`, 내용이 넘치면 시트 안에서만 스크롤
- 드래그 핸들 · `line-strong` · full
- 하단 버튼 영역은 **`pb-safe-4`** (safe area + 16). 🚨 `pb-safe` 와 `py-*` 를 나란히 쓰면 아래 패딩이 죽어 버튼이 화면 맨 아래에 붙는다 — 실제로 그렇게 났다
- **승인 시트는 스크림 탭으로 닫히지 않는다.** 명시적으로 닫아야 한다 — 실수로 닫혀서 draft 가 만료되는 경로를 만들지 않는다 (승인 없는 draft 는 24시간 뒤 만료된다).

- `showModal()` 이 바깥 조작은 막아 주지만 **배경 스크롤까지 막지는 않는다.** 컴포넌트가 `body` 를 `overflow: hidden` 으로 잠근다.
- 🚨 **제목 id 를 상수로 박지 않는다** (`useId()`). `<dialog>` 는 닫혀 있어도 DOM 에 남아서, 한 화면이 시트를
  여러 개 마운트하면(10 설정은 다섯) 같은 id 가 여럿이 되고 `aria-labelledby` 가 문서에서 먼저 나오는 것을
  집는다 — 연 시트가 다른 시트의 제목으로 읽히거나 이름이 통째로 빈다.
- **`variant="document"` 는 약관·동의 전문 전용이다.** 시트를 통째로 `font-doc`(Pretendard)으로 바꾼다.
  🚨 제목만 손글씨로 남기지 않는다 — `size-adjust` 때문에 같은 시트 안에서 글자 크기감이 어긋나고,
  "한 화면 한 서체"(§4)가 시트 머리에서 깨진다. 쓰는 곳은 10 설정과 가입 동의의 **전문 시트 둘**이다.

- **모든 시트에 닫는 버튼을 세운다** (`footer`). 웹뷰에는 ESC 가 없어서 스크림 탭 하나만 남으면 닫는 길이 화면에 안 보인다. 아직 시작한 것이 없는 시트의 문구는 "취소" 가 아니라 **"닫기"** 다 — 취소할 것이 없다.
- **고르는 시트 (08 사진)** — **두 단계**다. ㉠ **어떤 사진인가**(알림장·식단표 / 아이 활동 사진) → ㉡ **어디서 가져오나**(최근 사진 줄 + 촬영·앨범). 🚨 **한 화면에 쌓지 않는다.** 처음에는 셋을 한 화면에 세우고 ㉠ 을 고르기 전에는 나머지를 비활성으로 뒀는데, **부모가 할 일이 하나인 순간에 화면이 세 덩어리를 보여 주고** 꺼진 것들이 "왜 안 눌리지" 를 먼저 묻게 만들었다. 한 번에 한 가지만 묻는다.
  - **시트 제목이 지금 묻는 것**이다 — ㉠ 에서는 "어떤 사진인가요?", ㉡ 에서는 고른 종류의 이름. 두 단계가 같은 제목을 쓰면 넘어간 것이 화면에 안 보인다. 설명 줄은 ㉡ 에서 **고른 것이 무엇을 뜻하는지**(무엇만 읽는지)를 되짚는다.
  - ㉠ 은 **라디오가 아니라 길**이다 — 고르면 곧바로 ㉡ 이므로 확인 버튼이 없고, 그래서 오른쪽 **쉐브론**이 붙는다(누르면 무슨 일이 일어나는지가 모양에 있어야 한다). 되돌아가는 길은 ㉡ 맨 위 `btn-tertiary` "다른 종류로 바꾸기" 이고 **왼쪽 쉐브론**을 단다 — 나머지 줄이 전부 오른쪽 쉐브론이라 그 짝이다.
  - **최근 사진**은 **가로로 민다.** §7 의 "칩 줄은 가로 스크롤하지 않는다" 는 **근거 칩**의 규칙이고, 이 줄은 03 채팅바 위 제안 줄과 같은 **들어가는 문**이라 밀어도 잃는 것이 없다(안 민 사진은 "앨범에서 고르기" 로 그대로 간다). 🚨 **줄 자체가 없는 환경이 정상이다** — 웹은 기기 갤러리를 읽을 수 없어서 네이티브 셸이 있을 때만 선다. 빈 상자도 권한 안내도 띄우지 않는다.
  - **두 단계가 같은 줄 모양을 쓴다** (아이콘 타일 + 라벨 + 한 줄 설명 + 쉐브론 · 줄 사이 `line` 1px · 마지막 줄에 선 없음). 모양이 갈리면 넘어간 것이 아니라 다른 화면에 떨어진 것처럼 읽힌다. 🚨 카드로 만들지 않는다 — 시트 안에서 카드 안의 카드가 된다. 🚨 비활성은 **타일을 뉴트럴로** 바꾼다 (브랜드색을 흐리게 만들지 않는다).
  - 🚨 **화면을 하나 새로 만들지 않고 시트로 끝내는 기준**은 "고르고 나면 곧바로 다음이 오는가" 다 — 고르기만 하는 화면은 누른 뒤에 또 누르게 만든다. 시트 **안에서** 단계를 나누는 것은 이 기준을 깨지 않는다(한 번 열어 끝까지 간다).
### 돌아가기 화살표

**`PageTitle` 과 한 줄**에 선다 — 화살표가 왼쪽, 제목이 오른쪽이다. `IconButtonLink`(ghost) 안에 lucide `ArrowLeft`(20). 설정과 그 하위 화면이 쓴다.

```
<div className="-ml-3 flex items-center gap-1">  ← 줄 전체를 민다
  <IconButtonLink …><ArrowLeft/></IconButtonLink>
  <PageTitle>…</PageTitle>
</div>
```

- 🚨 **버튼이 아니라 링크다.** `router.back()` 은 어디서 왔는지에 따라 달라져서, 알림이나 링크로 바로 들어오면 돌아갈 데가 없다 — 가는 곳을 `href` 로 못박는다.
- 🚨 **`label` 에 "뒤로" 가 아니라 가는 곳을 적는다** ("설정으로 돌아가기"). 글자가 없어 스크린리더에 남는 것이 그것뿐이다.
- 🚨 **`-ml-3` 는 줄 전체에 건다.** 44px 원 안에 20px 아이콘이 가운데 있어 좌우 12px 이 비는데, 그대로 두면 화살표가 화면 왼쪽 기준선(16)보다 안쪽에 선다. 타깃은 44를 그대로 유지한다 — 여백을 밖으로 미는 것이지 줄이는 것이 아니다.
- ⚠️ **제목만 왼쪽이 안 맞는다** (화살표 16 · 제목 52 · 보조 문구·구역 머리줄·카드 16). 가로로 붙이는 한 피할 수 없다 — 터치 타깃 44가 좌우 여백 16보다 넓어서, 화살표를 기준선에 놓으면 제목은 그 폭만큼 밀린다. **세로 44px 을 아끼는 값으로 그 어긋남을 받기로 했다** (제품 결정 · #89). 헤더 높이 118 → 74.
  - 되돌리려면 제목을 화살표 **아래 줄**로 내린다(정렬은 맞고 세로가 는다). 상단을 별도 크롬 바로 만드는 선택지도 있었지만, 디자인 시스템에 상단 바가 없어 새 요소가 하나 생겨서 하지 않았다.
- 🚨 **한 화면에 같은 이름의 링크를 둘 두지 않는다.** 아래에 같은 이름의 돌아가기를 하나 더 두면 스크린리더 링크 목록에 같은 이름이 두 번 뜬다 — 다른 이름·다른 뜻일 때만 함께 선다(탈퇴 화면의 "그만두고 돌아가기").

### 설정 줄 (10 · 00-1)

**설정 전용 모양이 아니라 "누르면 다른 화면으로 가는 줄" 이다.** 00-1 경로 고르기의 두 갈래도
같은 줄을 쓴다 — 거기서 버튼 둘을 세우면 서열이 생기는데 그 화면은 어느 쪽도 권하지 않아야 한다
(§5 "바닥에 붙이는 것"). 고르면 곧바로 넘어가는 자리라 라디오가 아니라 쉐브론인 것도 같다
(08 사진 시트 1단계와 같은 판단).

`SettingsGroup` 한 덩어리 안에 줄을 `line` 1px 구분선으로 나눈다. 줄마다 왼쪽 **아이콘 타일**(brand),
가운데 **이름 + 지금 상태**, 오른쪽 **행동**이다.

- 🚨 **줄을 카드로 감싸지 않는다.** 구역이 넷이라 줄마다 상자를 두르면 화면이 상자의 나열이 되고,
  카드 속 카드가 된다. 상자는 구역당 하나다
- 🚨 **상태를 글자로 단다** (`동의함` · `동의하지 않음` · `엄마 · 아이를 만든 보호자`). 이 화면의 요지가
  "지금 어떻게 되어 있는가" 라서, 누르기 전에 읽히는 값이 없으면 구조가 무너진다. 색·아이콘으로 대신하지 않는다
- **두 종류뿐이다** — `SettingsLinkRow`(다른 화면으로 간다. **줄 전체가 링크**이고 오른쪽은 쉐브론) /
  `SettingsInfoRow`(줄은 정보, 행동은 오른쪽 버튼이 따로 가져간다).
  🚨 **한 줄에 오른쪽 버튼은 하나까지다.** 둘을 쌓으면 줄 높이가 내용의 두 배가 되고 왼쪽에 빈 띠가
  생기며, 오른쪽 열이 줄마다 하나와 둘을 오간다 — 구역 머리줄로 올려 걷어냈던 그 실루엣이 목록 안에서
  다시 생긴다. 읽으러 가는 길이 더 필요하면 **이름**에 건다 (`onTitleClick`)
  🚨 철회·연결 끊기처럼 되돌리기 어려운 행동이 달린 줄은 **줄 전체를 버튼으로 만들지 않는다** —
  줄 어디를 눌러도 실행되면 잘못 누르는 경로가 생긴다
- 구역 머리줄은 `label` + `brand`, 더하는 행동은 **머리줄 오른쪽 아이콘 버튼**이다 (목록 아래 전체 폭
  버튼으로 두면 `secondary` 실루엣이 목록 상자와 같아서 둥근 사각형이 연달아 선다 · 11 화면과 같은 규칙)
- 🚨 **이 화면에 `primary` 버튼이 없다.** 설정에는 "다음에 할 행동" 이 없다 — 하나를 세우면 화면이 그걸
  권하는 셈이 된다. `primary` 는 시트 안에만 선다
- 🚨 **위에서 아래로 "손대는 것 → 읽는 것 → 나가는 것" 이다.** 지금 켜고 끌 수 있는 동의가 위에
  서고, 읽기만 하는 **약관과 방침**이 그 아래, **계정**(로그아웃·탈퇴)이 마지막이다.
- 🚨 **설정에 동의 스코프를 늘어놓지 않는다.** 필수 동의 네 건은 *가입 화면이 받는 것*이고,
  그걸 설정에 다시 세우면 가입 화면을 한 번 더 그리는 셈이다. 설정의 **약관과 방침**이 드는
  것은 동의 스코프가 아니라 **읽는 문서 둘**(서비스 이용약관 · 개인정보 처리방침)이다.
- 🚨 **"이미 동의한 것" 이라고 부르지 않는다.** 그 이름은 *동의라는 행위*를 주어로 삼아 동의
  구역의 꼬리처럼 읽히는데, 부모가 거기 오는 이유는 이력 확인이 아니라 **약관을 읽으려는** 것이다
- 🚨 **문서 줄에 "동의함" 을 달지 않는다.** 이용약관은 가입 때 동의한 것이지만 처리방침은
  동의하는 글이 아니라 **알리는 글**이다 — 한 목록에 두고 상태를 나란히 붙이면 처리방침도
  동의 대상인 것처럼 읽힌다. 어느 판인지는 목록 아래 한 줄이 말한다
- **컴팩트한 설정 줄** — 아이콘 타일이 없고 상태가 오른쪽 끝에 `caption` 으로 붙는다.
  **문서 목록에만** 쓴다: 훑는 속도가 먼저고, 타일을 세우면 손대는 구역들과 같은 무게로 읽혀
  자리를 먹는다. 🚨 이름에 밑줄은 남긴다 — 거기서 누를 수 있는 것이 그것 하나뿐이다
- 🚨 **맨 위에 현황 요약을 두지 않는다.** 한동안 `card-accent` 한 장에 "함께 보는 사람 N명 · 켜 둔 선택
  동의 N/M · 로그인" 을 모아 뒀는데, 그 셋이 바로 아래 구역들이 이미 말하는 것이라 **같은 사실을 두 번**
  적는 꼴이었다. 요약이 본문과 어긋날 여지만 남기고 스크롤 한 번에 들어오는 줄 수만 줄인다

### 동의 목록 (10 · 가입)

🚨 **필수와 선택을 같은 컨트롤로 그리지 않는다.** 두 무리를 각각 머리줄(`label`/`ink-muted`)로 가른다 —
**켜고 끌 수 있는 동의**(선택)와 **끌 수 없는 동의**(필수).

- 선택은 상태 + `btn-tertiary`(`동의하기` / `철회하기`). 필수는 철회 버튼이 **없고** 대신 왜 못 끄는지가
  줄의 상태 자리에 글자로 선다
- 🚨 **스위치(토글)를 만들지 않는다.** 스위치는 "즉시 · 가볍게 · 되돌릴 수 있음" 을 뜻하는데, 철회는
  확인 단계를 거치는 행동이다. 그리고 상태 변화는 색으로만 일어나고 크기·위치는 움직이지 않는다(§8)
- 확인 시트는 **일어날 일만** 적는다. 끄는 쪽과 켜는 쪽에 **다른 목록**을 보여준다 (`blocks` / `enables`) —
  "없으면 멈추는 것" 을 켜는 시트에 돌려 쓰면 "동의하면 동작해요" 아래에 "이 기능이 멈춰요" 가 붙는다
- 확정 버튼은 양쪽 다 `btn-primary` + `btn-tertiary` 다. 🚨 **철회에 `btn-danger` 를 쓰지 않는다** (§7 버튼)
- 🚨 **전문으로 가는 길은 줄의 이름이다.** 별도 동의로 받아야 하는 것들이라 무엇에 동의하는지를 읽을
  수 있어야 하는데, 켜고 끄는 버튼만 두면 읽으려고 철회를 눌러야 한다. 이름에 밑줄을 주고 누르면
  전문 시트가 열린다 — 🚨 **오른쪽에 버튼을 하나 더 쌓지 않는다** (줄이 내용의 두 배로 늘고
  왼쪽에 빈 띠가 생기며, 오른쪽 열이 줄마다 하나와 둘을 오간다 · §7 설정 줄)
- 🚨 **끌 수 없는 동의 줄은 오른쪽이 비어 있다.** 거기엔 할 수 있는 일이 없고 그게 그 무리의 사실이다 —
  버튼을 세워 두면 오른쪽 열이 "무엇이든 할 수 있는 자리" 로 읽힌다
- 🚨 **필수 줄도 상태를 먼저 낸다** (`동의함`). 못 끄는 이유는 그 아래 줄이다 — 이유만 적으면 제목이
  "지금 이렇게 되어 있어요" 인 화면에서 그 셋만 지금 어떤지를 말하지 않는다
- 🚨 **바뀐 것을 `aria-live="polite"` 로 알린다.** 시트가 닫히고 줄의 글자가 바뀌는 것이 전부라,
  화면을 안 보는 사람에게는 아무 일도 안 일어난 것과 같다. 토스트는 쓰지 않는다(§7 토스트)
- 요약의 분수는 **선택 동의만** 센다. 필수까지 한 분모에 넣으면 "다섯 개를 다 끌 수 있다" 로 읽혀서,
  두 무리를 가른 이유가 요약 한 줄에서 사라진다
- 같은 행동에는 같은 말을 쓴다 — 전문을 여는 버튼은 10 설정도 가입 동의도 `내용 보기` 다
- 🚨 **승인 게이트가 아니다** — `btn-approve` 도 `caution` 도 쓰지 않는다 (게이트는 09 캘린더와 11 건강 기록 둘뿐)
- 🚨 **자물쇠 아이콘을 머리줄에 붙이지 않는다.** 열린 자물쇠와 닫힌 자물쇠는 16px 에서 거의 같은 모양이라
  두 무리를 가르는 대신 헷갈리게 만든다 — 뜻은 글자가 진다 (§4)
- 목록 줄에는 **짧은 이름**(`shortLabel`)을 쓴다. 법적 표기(`label`)는 그 줄에서 여는 전문 시트의 제목이다 —
  긴 라벨은 오른쪽 버튼에 밀려 두 줄로 접히고, 접힌 라벨은 읽히지 않고 자리만 먹는다

### 화면 이동 바 (하단 네비)

화면 아래에 붙는 4칸 — **홈 · 캘린더 · 기록/기억 · 아이.** 아이콘(20) + 라벨(`caption`)을 세로로 쌓는다.
🚨 **네 번째 "아이" 칸은 프로토타입에 없다** — 11 아이 프로필 화면이 들어오면서 생겼다. 앞의 셋이 "무슨 일이 있었나" 라면 이 칸은 **아이 자체**로 간다.
아이콘은 `Baby` 가 아니라 `UserRound` 다 — 대상 연령이 유아라 아기 아이콘은 사실과 다르고, "원색 캐릭터 키즈 앱으로 가지 않는다"(§1)와 같은 방향으로 어긋난다.
`touch` 는 **하한**이고 실제 높이는 아이콘 + 라벨 + 여백이 정한다 (지금 51px). safe area 는 이 바가 받는다.

**바닥은 면으로 만든다.** 바 전체가 `surface-muted`, 위에 선은 **없다.**
활성은 `brand` 아이콘 + `brand` 라벨 + 칸 위쪽 `brand` 2px, 비활성은 `ink-subtle`.
누른 느낌은 `surface` — 바닥보다 **밝은** 쪽이다. 🚨 **호버는 주지 않는다** — 대부분 웹뷰라 호버가 없고,
마우스에서만 칸이 밝아지면 커서가 지나갈 때마다 바닥이 들썩인다.

🚨 **선을 하나 더 긋는 것으로는 안 갈린다.** `line` 1px 은 `canvas` 위에서 1.21:1 이라
비텍스트 대비 기준(3:1)에 못 미치고, 03 홈에는 **같은 선이 27px 위에도** 있다 (고정 영역 시작선).
한 신호가 "여기부터 고정" 과 "여기부터 다른 종류" 두 뜻을 나눠 쓰면 하단 전체가 **줄 쳐진 슬래브 하나**로 읽힌다.
`surface-muted` 는 대비로는 1.07:1 이지만 **바 전체 면적**에 걸려서 훨씬 세고, 무게 기울기도 바로 선다
(본문 → 채팅바 → 바닥). 이전에 `line-strong` 3.0:1 로 세워 본 적이 있는데, 톤 문제를 굵은 크롬 선으로
덮는 것이라 반려됐다.

🚨 **활성 표시를 색 하나에 맡기지 않는다.** `brand` 와 `ink-subtle` 은 **휘도 차가 1.15:1** 이라
그레이스케일·적록색약에서 거의 같고, 본문 서체가 단일 웨이트라 굵기로도 못 만든다 (§4).
그래서 07 탭이 이미 쓰는 `brand` 2px 선을 칸 위쪽에 얹는다 — 새 언어가 아니다.
🚨 자리는 늘 차지하게 두께만 깔고 **색은 분기가 준다.** `border-transparent` 를 기본에 두고
활성에서 `border-brand` 로 덮으려 하면 안 덮인다 (`cn()` 은 tailwind-merge 가 아니고 둘 다
`border-color` 라 특정도가 같다 · apps/web/CLAUDE.md §3).

| | |
| --- | --- |
| **어디에 붙나** | 가는 곳 네 화면 + 설정 |
| **어디에 안 붙나** | 04 저장 결과 · 05 제안 후보 · 01·02 온보딩 · 로그인 |

🚨 **흐름 중인 화면에는 붙이지 않는다.** 고르는 도중에 다른 데로 새는 길을 만들면 그 화면이 끝나지 않는다 —
04·05 는 자기 "홈으로" 버튼으로 빠져나간다.
🚨 **설정에서는 홈이 켜진 채로 둔다.** 설정은 홈 헤더의 아이콘에서 들어가는 곁가지라 자기 칸이 없고,
아무 칸도 안 켜진 네비는 고장난 것처럼 보인다.
🚨 **다만 그건 시각적 결정이라 `aria-current` 는 뺀다.** 켜 보이는 것과 "지금 그 화면에 있다" 는
다른 신호다. 제목이 "설정" 인 화면에서 스크린리더가 "홈, 현재 페이지" 라고 읽으면 그건 사실이 아니다 (§10).
🚨 **라벨을 지우지 않는다.** 아이콘만 있는 탭은 무엇인지 외워야 하고, 색과 모양이 단독 신호가 되면 안 된다 (§3 · §10).
🚨 **아이콘은 lucide 다.** 프로토타입의 `⌂ ▦ ☰` 처럼 기호를 글자로 찍지 않는다 (§4).

붙는 것이 둘(03 홈의 채팅바 + 네비)이면 **채팅바가 위, 네비가 아래**로 한 덩어리가 되고 safe area 는 제일 아래 것만 받는다 —
각자 받으면 그만큼 두 번 밀린다.

🚨 **채팅바 구역의 위 여백보다 아래 여백이 커야 한다 (8 / 20).** 구역 **사이**가 구역 **안**
(제안 줄↔알약 8px)보다 넓어야 두 덩어리로 갈린다. 예전엔 12/12 라 사이와 안이 같았고,
근접성이 무엇을 묶을지 결정해 주지 못했다. 03 홈 고정 영역은 이 조합으로 192px 이다. 이 조립은 [`Screen`](../../apps/web/src/components/ui/screen.tsx) 의 `bottomBar` · `nav` 가 소유한다 (§5).

### 07 기록 줄 · 기억 카드

**부르는 말** — 화면에서 관찰(`observation`)은 **기록**, 프로필(`profile_affinity`)은 **기억**이다.
🚨 **코드의 이름은 계약서를 따르고(`observation`·`affinity`), 화면의 말만 바꾼다.** 둘을 같이 바꾸면 계약서와 어긋난다.

| | 기록 줄 (`ObservationList`) | 기억 카드 (`AffinityList`) |
| --- | --- | --- |
| 모양 | 가는 선으로만 나뉜 **한 덩어리 줄 목록** | 따로 서는 **카드** |
| 왼쪽 | `icon-tile` **도메인 색** (`{domain}-soft` + `{domain}-ink`, 아이콘 20) | 〃 (같은 타일 — 두 탭이 한 화면이다) · 🚨 `is_stale` 만 neutral |
| 본문 | 부모가 적은 말 `body`/`ink` | 기억 이름 `title`(20) |
| 메타 | 도메인 · 날짜 `caption`/`ink-subtle` | 상태 칩 + 도메인 · 기록 건수 |
| 아래 | **묶인 기억 칩** (`surface-muted` full) | 성향 `body-sm` + 서버의 `state_reason` |

🚨 **줄과 카드를 한 컴포넌트로 만들지 않는다** — 섞으면 "한 번 본 것" 과 "확정된 성향" 이 같은 무게로 읽혀서 최상위 §2 가 화면에서 사라진다.
🚨 **묶인 기억을 회색 글자 한 줄로 두지 않는다.** "이 기록이 어느 기억에 묶였나" 는 이 제품의 논지 자체(기록이 쌓여 기억이 된다)라, 날짜와 같은 무게로 두면 목록에서 제일 약한 것이 제일 중요한 사실이 된다. **칩**으로 모양을 준다.
🚨 **승격 상태는 카드 실루엣 + 글자 둘 다** 진다 (`confirmed` 실선 · `candidate` 점선 · `is_stale` `surface-muted`). 색으로 가르지 않는다.

### 교정 (07 기록·기억 상세)

**묻는 것이 대상마다 다르다.** 기록은 "그 일이 실제로 어땠나" 한 건에 대한 말이고, 기억은 "그래서 아이가 그렇다고 볼 수 있나" 에 대한 말이다.

| 대상 | 버튼 |
| --- | --- |
| 기록 (`observation`) | 이번만 그랬어요(`once_only`) · 잘못된 기록(`wrong`) |
| 기억 (`profile_affinity`) | 기록이 더 필요해요(`need_more_observation` ⚠️) · 지금은 달라요(`outdated`) · 잘못된 기록(`wrong`) |

🚨 **같은 버튼 묶음을 양쪽에 쓰지 않는다.** 기억에 "이번만 그랬어요" 가 서고 기록에 "더 지켜봐요" 가 서면 둘 다 뜻이 안 맞는다.
🚨 **`confirm` 은 묻지 않는다.** 지난 이력에는 실려 오므로 라벨 표에는 남기되 버튼으로 세우지 않는다.
⚠️ `need_more_observation` 은 **계약서 v1 에 없는 값**이다 — 👉 `apps/api` Owner 협의 대상 (최상위 §8).

**고르면 확인 단계가 뜬다.** 무엇이 바뀌는지와 그 뒤에 어떻게 되는지를 보여 주고 `바꾸기` / `그만두기` 를 묻는다.

🚨 **이건 승인 게이트가 아니다.** 승인 게이트는 딱 2곳이고 늘리지 않는다 (최상위 §2) —
그래서 여기에는 `btn-approve` 도 `caution` 도 쓰지 않는다 (`btn-primary` + `btn-tertiary` 다).
게이트가 **되돌릴 수 없는 것을 막는** 장치라면, 이 단계는 **무엇이 일어나는지 먼저 보여 주는** 자리다.

🚨 **되돌릴 수 있다고 쓰지 않는다.** 교정 자체는 append-only 라 데이터가 지워지지는 않지만
**화면에는 되돌리는 기능이 없다**(제품 결정). 한동안 "고쳐서 뺀 기록" 필터로 다시 찾을 수 있게 해 뒀다가
그 기능을 내리기로 하면서 문구도 같이 내렸다 — 찾지 못할 길을 약속하면 그게 더 나쁘다.
목록에서 빠진다는 사실과 앞으로 어떻게 되는지만 말한다.
🚨 **확인 문구에 예측을 쓰지 않는다.** 일어날 일만 적는다 — 무엇이 다시 계산됐는지는 응답의 `cascade` 만 안다.
🚨 **성공하면 확인 패널을 닫고 버튼으로 되돌린다.** 열어 두면 방금 바꾼 것을 또 바꾸라고 묻는 화면이 된다. 실패하면 그 자리에 남는다 — 다시 누르는 것이 재시도다.
🚨 **라벨에 조사를 박지 않는다.** "잘못된 기록**로** 바꿀까요?" 가 실제로 나왔다 — 라벨은 데이터고 조사는 문법이라, 받침으로 고르는 것은 `es-hangul` 의 `josa` 가 한다 (`ㄹ` 받침 예외까지 들어 있다).

### 탭 (07 화면 2계층)

| 상태 | 사양 |
| --- | --- |
| 활성 | `ink` · label 600 · 아래 `brand` 2px |
| 비활성 | `ink-muted` · label 400 · 밑줄 없음 |

높이 `touch`. 탭 전환은 URL 에 남긴다 — 관찰/프로필은 다른 엔드포인트라 뒤로가기가 동작해야 한다.

🚨 **활성 신호를 굵기에 걸지 않는다.** 위 표의 "label 600" 은 선언일 뿐 화면에서는 `label`(500)과 똑같이 나온다 (§4 — 본문 서체가 단일 웨이트라 브라우저가 600 이상만 합성한다). 실제로 구분을 만드는 것은 **글자색(`ink` ↔ `ink-muted`)과 아래 `brand` 2px** 둘이고, 둘 다 있어야 한다. 구현은 [`components/ui/tabs.tsx`](../../apps/web/src/components/ui/tabs.tsx) 이고 **버튼이 아니라 링크**다 — 주소가 바뀌므로 ARIA `tablist` 가 아니라 탐색이고, 현재 위치는 `aria-current="page"` 가 진다.

### 캘린더 그리드 (09)

`react-day-picker` 위에 얹고 **기본 CSS 를 불러오지 않는다** — `classNames` 로 토큰만 입힌다 (§7 머리말의 예외 둘 중 하나). 라이브러리가 맡는 것은 그리드 ARIA · 방향키 · 월 경계 · 로케일 넷뿐이다.

날짜 칸은 숫자 한 단과 **표식 줄** 한 단이다 (`rounded-field` · `min-h-touch` · 표식 줄은 비어도 자리를 지킨다 — 있고 없고에 따라 숫자가 흔들리면 달을 훑을 때 줄이 안 맞는다).

| 표식 | 모양 | 뜻 |
| --- | --- | --- |
| 일정 | 가로 막대 10×3 | 확정된 일정이 있다 (`has_event` — 🚨 `confirmed` 만) |
| 기록 | 찬 점 6 | 그날 남긴 기록이 있다 |
| 일기 | **빈 네모 7** (테두리 1.5 · radius 1.5) | 그날 일기가 있다 |
| 기억 변화 | 빈 고리 8 (테두리 1.5) | 그날 기억이 승격·강등됐다 (⚠️ 응답 필드 협의 중 — §14) |

🚨 **네 모양이 한 가족이어야 한다.** 차트 범례처럼 같은 언어로 읽혀야지, 제각각이면 칸에 부스러기가 흩어진 것처럼 보인다.
그래서 **기울어진 것을 두지 않는다** — 화면의 다른 모든 선이 수직·수평인데 표식 하나만 대각선이면 그것만 혼자 튄다.

> 여기까지 두 번 고쳤다. 처음엔 일기가 **세로 막대**(3×6)였는데 한 칸에 실제로 같이 서는 짝(기록 vs 일기)이 둘 다
> "작고 검은 덩어리" 로 읽혔고, 다음엔 **비스듬한 획**으로 바꿔 구분은 됐지만 혼자 기울어져 튀었다.
> 지금이 세 번째다 — 구분과 정돈을 같이 만족하는 자리를 찾는 데 두 번의 실측이 들었다.

그 다음이 구분이다. 작은 크기에서 버티는 축은 **비율 > 채움 > 각짐** 순이고, 어느 두 짝도 **두 축 이상**에서 갈린다.

| | 비율 | 채움 | 각짐 | 크기 |
| --- | --- | --- | --- | --- |
| 일정 | 가로로 길다 | 참 | 둥근 끝 | 10×3 |
| 기록 | 정사각 | 참 | 둥글다 | 6 |
| 기억 변화 | 정사각 | 빔 | 둥글다 | 8 |
| 일기 | 정사각 | 빔 | **각졌다** | 7 |

🚨 **제일 약한 짝은 일기(빈 네모) ↔ 기억 변화(빈 고리)다.** 둘 다 비어 있어 각짐 하나로만 갈리면 위태로워서,
크기를 한 단계 벌려 **각짐 + 크기** 두 축으로 잡았다. 둘 중 하나의 크기를 건드릴 때 이 문장을 같이 볼 것.
🚨 **표식 크기는 `rem` 으로 준다.** `px` 로 박으면 글자를 키워도 그 표식만 제자리에 남아 **크기 서열이 뒤집힌다**
(200% 에서 기록 12 < 일기 7 < 기억 16 이 됐다). 표식 줄 높이는 제일 큰 표식(고리 8)에 맞춘 **8px** 이다.

🚨 **표식을 색으로 가르지 않는다.** 이 시스템의 색은 뜻이 1:1 이고(§3) 네 가지는 그 목록에 없다 — 새 색을 넷 만들면 도메인 4색과 섞여 색의 뜻이 통째로 흐려진다. 표식은 전부 `currentColor` 라 고른 날(`brand` 채움 · 흰 글자) · 오늘 · 비활성의 글자색을 그대로 따라간다.

🚨 **모양도 단독 신호가 될 수 없다** (§3 · §10). 모양을 뜻으로 잇는 것은 **그리드 아래 범례**이고, 칸마다 `aria-label` 이 같은 사실을 말로 다시 낸다. 범례를 지우면 표식이 단독 신호가 된다.

🚨 **오늘을 색 하나로 표시하지 않는다.** `brand` 글자색에 `brand` 1px 테두리를 함께 준다 — `brand` 와 `ink` 는 그레이스케일에서 가깝고 굵기로도 못 만든다 (§3 · §4). `aria-label` 에도 "오늘" 을 싣는다.

🚨 **표식은 건수를 세지 않는다.** 점 세 개와 다섯 개를 눈으로 구별하는 사람은 없고, 작은 점을 늘리면 칸만 지저분해진다. 종류만 모양이 말하고 건수는 `aria-label` 과 아래 하루 패널이 진다.

🚨 **지난 달 날짜를 그리지 않는다** (`showOutsideDays={false}`). 그리면 누를 수 있는데, 누르면 아직 받아오지 않은 달의 하루가 열려 빈 화면으로 보인다.

🚨 **`DayButton` 을 덮어쓸 때 포커스 이동을 같이 가져온다.** 라이브러리의 방향키·월 경계 처리는 `focused` 모디파이어만 옮기고 **DOM 포커스는 기본 `DayButton` 안의 effect 가** 옮긴다. 그 effect 없이 덮어쓰면 그리드가 로빙 탭인덱스라 **키보드로 다른 날에 도달할 방법이 통째로 사라진다** — 라이브러리를 얹은 이유 넷 중 둘이 죽는다.
🚨 **`components` 는 모듈 상수여야 한다.** 렌더 안의 객체 리터럴로 넘기면 매 렌더 새 컴포넌트 타입이라 날짜 칸이 전부 리마운트되고, 날을 고를 때마다 포커스가 `<body>` 로 날아간다.
🚨 **`aria-label` 에 "오늘" 을 직접 더하지 않는다.** ko 로케일의 `labelDayButton` 이 "오늘" 과 "선택됨" 을 이미 앞에 붙인다 — 더하면 칸마다 두 번 읽힌다.

### 날짜 고르기 달력 (`date-field`)

09 월 그리드와 **같은 라이브러리 위에 있지만 머리줄이 다르다.** 09 는 지나간 달을 훑는 자리라 라이브러리 머리줄(화살표 + 달 이름)로 충분한데, 여기는 **생일**을 받는다 — 만 4세 아이면 48개월을 거슬러야 하고 화살표만으로는 48번이다.

🚨 **그래서 머리줄만 우리가 그린다** (`hideNavigation` · `month_caption: "sr-only"`). 라이브러리가 맡는 넷(그리드 ARIA · 방향키 · 월 경계 · 로케일)은 그대로 두고, `month` 만 통제 상태로 올려 `onMonthChange` 로 되받는다.

🚨 **라이브러리의 `captionLayout="dropdown"` 을 쓰지 않는다.** 그건 네이티브 `<select>` 두 개이고, 이 시스템은 §7 "고르기 상자" 에서 **네이티브 `<select>` 를 쓰지 않기로** 이미 정했다 (닫혀 있을 때 말고는 생김새를 우리가 못 정하고 OS 마다 다른 휠이 뜬다). 달력 안이라고 예외를 두지 않는다 — 한동안 여기만 드롭다운이었고, 그게 규칙이 한 곳에서 새고 있던 자리다.

| 면 | 무엇 |
| --- | --- |
| 날짜 | 기본. 머리줄은 `‹ 2021년 4월 ⌄ ›` 한 줄 |
| 연도 | 연월을 누르면 펼친다. **4열 · 최근 연도가 위** |
| 달 | 연도를 고르면 이어서. **3열 · 1~12월**, 범위 밖은 잠금 |

**최근 연도가 위인 이유** — 이 입력이 받는 것은 아이 생일과 잰 날이라 찾는 값이 거의 항상 최근 몇 해 안에 있다. 오래된 쪽부터 쌓으면 매번 끝까지 스크롤해야 한다.

🚨 **화살표는 날짜 면에서만 선다.** 연도·달 그리드가 펼쳐진 동안 뒤에서 달이 넘어가면 무엇을 고르는 중인지 흐려진다. 비활성이 아니라 **감춘다** — 다만 `invisible`(= `visibility: hidden`)이라 포커스와 접근성 트리에서 함께 빠진다. `opacity-0` 로 감추면 보이지 않는데 탭으로 닿는 버튼이 된다.

🚨 **포커스를 옮긴다.** 그리드가 열리면 고른 칸으로 들어가고, 달을 고르면 연월 버튼으로 돌아온다. 안 옮기면 방금 누른 버튼이 사라지는 순간 포커스가 `<body>` 로 떨어진다 — §7 "고르기 상자" 와 09 달력에서 이미 낸 사고다. 고른 칸은 `brand` 채움 + 흰 글자 + `aria-pressed` 셋으로 말한다 (색은 단독 신호가 될 수 없다 · §3).

🚨 **쉐브론을 회전시키지 않는다.** 펼침 방향은 아이콘을 갈아 끼워 말한다 (§8 — 상호작용 전환은 색만 바꾸고 크기·위치는 건드리지 않는다). §7 "고르기 상자" 와 같은 처리다.

🚨 **세 면의 높이를 날짜 면에 맞춘다.** 그냥 두면 달 그리드가 제일 짧아서 시트 윗변이 448 ↔ 548px 로 오르내린다 — 연도를 고를 때마다 시트가 뛴다. 바닥값은 `rem` 이다: `px` 로 박으면 글자를 키웠을 때 그리드만 커지고 바닥은 제자리에 남아 소용이 없다 (09 표식 크기와 같은 이유).

🚨 **연도만 고르면 달이 범위를 넘을 수 있다** (2021년 12월에서 올해로 옮기면 올해 12월은 아직 안 왔다). 코드가 범위 안으로 붙잡는다 — 고를 수 없는 달을 머리줄에 세우지 않는다.

🚨 **시트를 닫으면 달력을 버린다.** 살려 두면 다음에 열 때 지난번에 넘겨 둔 달과 펼쳐 둔 그리드가 그대로 남는다 — 다시 열면 **고른 값의 달**에서 시작해야 한다.

- 🚨 **키와 몸무게를 한 장에 겹치지 않는다.** 단위도 자릿수도 달라서 겹치려면 세로축이 둘이 되는데,

- 🚨 **세로축을 값에 딱 맞춰 자르지 않는다.** 축을 조이면 1cm 차이가 화면 절반을 가로지르고,

- 🚨 **점이 두 개 미만이면 선을 안 그린다** — 왜 아직 없는지를 글자로 말한다. 한 점짜리 그래프는

- 🚨 **선에 브랜드색도 도메인색도 쓰지 않는다.** 측정은 Agent 도 영역도 아니다 (`icon-tile` 의 뉴트럴과 같은 판단).

- 🚨 **그림은 `aria-hidden` 이다.** 같은 값이 바로 아래 목록에 글자로 서 있어서 점 좌표를 읽어 주는 것은

- 🚨 **등장 애니메이션이 없다** (§8). 하루에 여러 번 지친 상태로 여는 화면이다

전환은 전부 `fast`(120ms) + `--ease-standard` 다. 색만 바꾸고 **크기·위치는 건드리지 않는다.**

🚨 **press 칸이 비면 웹뷰에서 그 요소는 눌러도 아무 반응이 없다.** 이 화면은 대부분 웹뷰인데 호버가 없고,
`hover:` 는 `globals.css` 의 `@custom-variant` 로 `@media (hover: hover)` 안에서만 걸린다. 칩과 체크박스가
실제로 그 상태였다 — 07 피드백 탭의 유일한 조작이 칩이고 09 준비물 체크의 유일한 조작이 체크박스라,
그 두 화면이 붙고 나서야 드러났다. **표에 `—` 를 남기지 않는다.**

🚨 **`cursor` 는 `globals.css` 가 한 번에 건다** — 누를 수 있는 것은 `pointer`, 비활성은 `not-allowed`. Tailwind 4 preflight 는 버튼에 `cursor` 를 주지 않아서(v3 에서 달라진 점) 전부 기본 화살표였다. 웹뷰에는 커서가 없지만 브라우저로 들어오면 누를 수 있는지가 안 보인다.

🚨 **`hover` 는 `@media (hover: hover)` 안에서만 건다.** Tailwind 기본 `hover:` 는 미디어쿼리 없이 `:hover` 를 내는데(생성 CSS 로 확인), 터치 기기에서는 **탭한 뒤 손을 떼도 호버가 눌러붙어** 방금 누른 버튼이 계속 눌린 것처럼 보인다. 이 화면은 대부분 웹뷰·모바일이라 그게 기본 경험이 된다. `globals.css` 에서 `@custom-variant hover` 로 덮어 뒀으니 화면 코드는 `hover:` 를 그냥 쓰면 된다.

**웹뷰에는 호버가 없다.** 호버는 모바일·데스크톱 브라우저로 들어온 경우를 위한 것이고, 누른 느낌은 터치에서도 걸리는 `active:` 가 맡는다. 그래서 **`active` 를 빠뜨리면 웹뷰에서는 아무 반응이 없다.**

#### 브라우저가 대신 칠하는 표면

우리가 정하지 않으면 **기본값이 그대로 나간다** — 대개 채도 높은 파랑과 반투명 순검정이다. 웜 오프화이트 위에서 그 파랑만 혼자 다른 앱에서 온 것처럼 보인다. 넷 다 `globals.css` 의 `@layer base` 에 있다.

| 무엇 | 값 | 왜 |
| --- | --- | --- |
| `::selection` | `brand-soft` 배경 + `brand-ink` 글자 (8.6:1) | 문장을 끌어 복사하는 화면(기억·근거)이 있다 |
| `-webkit-tap-highlight-color` | `rgb(34 31 27 / 0.06)` | 🚨 **웹뷰에서 누를 때마다 보인다.** 투명으로 지우지 않는다 — `active` 가 없는 요소는 아무 반응이 없어진다 |
| `caret-color` | `brand` | 입력 커서. 기본값은 순검정이라 `ink` 보다 진하다 |
| `scrollbar-color` | `line-strong` / `canvas` | 데스크톱 브라우저에서만 보인다 (웹뷰·모바일은 오버레이 스크롤바) |

### 기다림 표시

| 이름 | 사양 |
| --- | --- |
| `spinner` | 버튼 글자 옆에 들어가는 크기 · **트랙 = 현재 글자색 25% · 머리 = 100%** · 1초에 1바퀴 · 버튼 안이나 대기 화면에서 문구 왼쪽에 |

**위쪽만 투명하게 뚫지 않는다.** 그렇게 하면 어디서 끊겼는지가 눈에 남아 3/4 짜리 조각이 도는 것으로 보인다. 원이 계속 보이고 그 위를 밝은 머리가 도는 쪽이 조용하고, 밤에 보는 화면에서는 그 차이가 크다.

🚨 **`prefers-reduced-motion` 에서는 스피너를 숨긴다.** 애니메이션만 멈추면 "고장난 화면" 으로 읽힌다 — 옆의 문구("저장하는 중…")가 상태를 대신 말한다.

### 하지 않는 것

- **승인 게이트에는 등장 애니메이션을 넣지 않는다.** 확인해야 할 것을 부드럽게 흘려보내면 안 된다.
- **등장·스크롤 애니메이션을 만들지 않는다.** 하루에 여러 번, 자주 밤에, 지친 상태로 여는 화면이다(§1). 처음엔 살아 있어 보이지만 100번째에는 "매번 기다려야 하는 것" 이 된다.
- 화면 전체를 움직이는 전환(슬라이드 페이지)을 쓰지 않는다. 웹뷰에서 프레임이 떨어지고, 밤에 보면 멀미가 난다.
- 🚨 **`prefers-reduced-motion: reduce` 에서는 `transform` 을 전부 끄고 `opacity` 만 남긴다.** 스켈레톤 깜빡임도 멈춘다.
- 깜빡이는(1초에 3회 이상) 요소를 만들지 않는다.

## 9. 반응형

이 화면은 대부분 [`apps/mobile`](../../apps/mobile) 웹뷰 안에서 보인다. **모바일 우선이 아니라 모바일 전용에 가깝다.**

| 구간 | 폭 | 동작 |
| --- | --- | --- |
| 좁은 폰 | < 380px | 좌우 여백 12 · `display` 를 `title` 로 낮춤 (`Screen` · `PageTitle` 이 처리) |
| 기본 | 380 ~ 560px | 좌우 여백 16 · 1열 · 기준 설계 |
| 그 이상 | > 560px | **컨테이너 560 고정 + 가운데 정렬.** 양옆은 `canvas` |

**데스크톱 레이아웃을 만들지 않는다.** 폭이 남는다고 2열로 벌리면 화면이 두 벌이 되고, 그때부터 §2 를 두 곳에서 지켜야 한다 (CLAUDE.md §6 의 `web` / `mobile` 분리와 같은 이유다).

### 터치 타깃

| 요소 | 최소 크기 |
| --- | --- |
| 승인 게이트 버튼 | **48 × 48** 이상 (전체 폭 · `approve` 높이) |
| 일반 버튼 · 탭 · 칩 | 44 × 44 |
| 아이콘 버튼 | 아이콘 24 + 여백 10 = 44 |
| 인접 타깃 사이 간격 | 8 이상 |

이 표는 **요구사항**이다. 코드는 높이 토큰(`touch` · `button` · `approve`)으로 이걸 지킨다 — 토큰 값을 바꿀 때 이 표의 최소값 아래로 내려가면 안 된다.

보이는 칩(`chip`)은 이보다 작지만 **누를 수 있는 칩은 위아래 투명 여백으로 `touch` 를 채운다.**

## 10. 접근성

- **포커스는 항상 보인다.** `:focus-visible` 에 `brand` 2px outline + offset 2 (5.9:1). `outline: none` 을 쓰지 않는다.
- **색만으로 정보를 전달하지 않는다** (WCAG 1.4.1). 도메인 칩은 아이콘+라벨, 개인화/일반은 라벨과 건수, 실패는 문장이 함께 나간다. 검증은 **도메인 칩에서 라벨을 지워 보는 것** — 그래도 구분되면 통과가 아니라 위반이다.
- **크기는 `rem` 으로 쓴다.** 문서에는 px 로 적은 곳이 있지만 토큰 값은 rem 이다. 사용자가 글자 크기를 키웠을 때 따라 커져야 한다.
- 🚨 **높이는 최소값이다. `h-*` 로 고정하지 않고 `min-h-*` 로 쓴다.** 높이 값이 맞아도 문구가 두 줄이 되거나 글자를 키우면 고정 높이는 글자를 밖으로 흘린다. 개정 전 코드로 재 보니, 긴 문구에서 글자만 200% 로 키웠을 때 primary·승인 버튼 글자가 위아래로 27~29px 넘쳐 **아래 설명 문구를 덮었다.** 승인 버튼에서 그러면 무엇을 승인하는지가 가려진다.
- **컴포넌트를 추가·수정하면 `/design-system` 의 "긴 문구" 줄을 두 상태에서 본다.**

  | 상태 | 어떻게 | 왜 따로 보나 |
  | --- | --- | --- |
  | 긴 문구 | 버튼·칩 문구가 두세 줄이 되는 예시 (그 줄에 있다) | 기본 글자 크기에서도 줄이 늘어난다 |
  | 글자만 확대 200% | 개발자도구에서 `:root { --text-button: 1.875rem; --text-label: 1.625rem; --text-body: 2rem }` · 실기기는 안드로이드 설정의 글꼴 크기 | **글자만 커지고 높이 토큰은 그대로다.** 고정 높이가 가장 잘 깨지는 상태다. 안드로이드 웹뷰는 기본값이 시스템 글꼴 크기를 따라가는 것으로 알려져 있고, 셸이 이를 끄지 않았다 (`react-native-webview` 의 `textZoom` 을 두지 않음). ⚠️ 실기기로는 아직 확인 전이다 |
  | 전체 확대 200% | 브라우저 기본 글자 크기 · 모바일 사파리의 페이지 확대 | rem 이 전부 같이 커진다. 줄바꿈이 늘어 시트·화면 하단이 밀린다 |

  확인할 것은 셋이다 — **글자가 컴포넌트 밖으로 나가거나 잘리지 않는가**, **승인 버튼의 문구가 전부 보이는가**, **바텀시트 하단 버튼이 화면 밖으로 밀려나지 않는가**(시트는 안에서 스크롤해야 한다).
- **`-webkit-text-size-adjust: 100%`** 는 회전 시 글자가 튀는 것만 막는 값이다. 확대 자체를 막는 `user-scalable=no` 는 쓰지 않는다.
- **한국어 스크린리더 라벨**을 붙인다. 아이콘 버튼의 `aria-label`, 진행 오버레이의 `aria-live="polite"`, 승인 시트의 `role="dialog"` + `aria-modal`.
- **대비비는 눈으로 고르지 않고 계산한다.** WCAG 2.2 상대 휘도 공식(`sRGB → linearize → 0.2126R + 0.7152G + 0.0722B`)으로 §2 의 모든 쌍을 돌렸고 **본문 쌍 전부 4.5:1 이상, 비텍스트 쌍 전부 3:1 이상**이다. 토큰을 바꿀 때는 값만 바꾸지 말고 **그 색이 얹히는 배경과의 쌍을 다시 계산한다.** soft 배경 위 텍스트는 `canvas` 가 아니라 그 soft 색과 비교해야 한다 — 여기서 많이 틀린다.

같은 패턴이라도 **그 패널이 앉는 화면**을 보고 정한다.

## 12. 다크모드 방침

**v1 은 라이트만 낸다.** 새벽 수유·재운 뒤 확인이 실제 사용 시나리오라 피로도에 가장 크게 작용하는 변수지만, 10주 안에 두 벌을 검증할 여유가 없다. 절반만 맞는 다크모드는 라이트만 있는 것보다 나쁘다.

대신 **나중에 값만 갈아끼울 수 있게 이름을 지어 뒀다.** 토큰 이름에 색이 들어가지 않는다 — `canvas` · `ink` · `line` 은 다크에서도 뜻이 유지되지만 `white` · `gray-50` 은 거짓말이 된다. 이 규칙만 지키면 다크는 `@media (prefers-color-scheme: dark)` 블록에서 값 재정의로 끝난다.

지금 `globals.css` 의 `color-scheme: light` 는 **의도된 고정**이다. 지우지 말 것 — 지우면 브라우저가 폼 컨트롤만 다크로 바꿔서 화면이 반쪽만 어두워진다.

## 13. `globals.css` 적용

**공통 값의 원본은 이 파일이다** (머리말). 이 문서의 절마다 어떤 토큰으로 가는지만 적는다. Tailwind 4 CSS-first 라 `tailwind.config.*` 는 없고, `@theme` 에 넣으면 유틸이 자동 생성된다.

| 문서 | `@theme` | 생성되는 유틸 |
| --- | --- | --- |
| §2 색 | `--color-*` | `bg-canvas` · `text-ink-muted` · `border-line` |
| §4 타이포 | `--text-*` (+ `--text-*--line-height` · `--font-weight`) | `text-body` · `text-caption` |
| §5 컨테이너 | `--container-content` | `max-w-content` |
| §6 radius · 그림자 | `--radius-*` · `--shadow-sheet` | `rounded-card` · `shadow-sheet` |
| §7 · §9 높이 | `--height-*` | 🚨 **`min-h-button` 으로만 쓴다.** `h-button` 도 생성되지만 쓰지 않는다 (§10) |
| §8 이징 | `--ease-standard` | `ease-standard` |

⚠️ 높이 토큰이 `--spacing-*` 이 아니라 `--height-*` 인 이유: `--spacing-*` 에 넣으면 `p-button` · `gap-chip` 같은 여백 유틸까지 생긴다. 높이 값이 여백으로 새어 나가지 않게 높이 계열(`h-*` · `min-h-*` · `max-h-*`)에만 걸리는 이름공간을 골랐다. 그래서 `size-touch` 는 없다 — 정사각형은 `h-touch aspect-square` 로 쓴다.

§5 간격은 Tailwind 기본 4px 스케일을 그대로 쓴다 (`p-4` = 16px). 별도 토큰을 만들지 않는다.

🚨 **`@theme` 이 아니라 `@theme static` 이다.** Tailwind 4 는 기본적으로 **실제로 쓰인 토큰의 변수만** CSS 로 내보낸다 — 아직 컴포넌트가 없는 토큰 9개(`caution` 계열 · `scrim` · 도메인 주색)가 통째로 빠져 있었고, `/design-system` 이 그 색들을 "읽기 실패" 로 잡아냈다. 이 문서가 색이 35개라고 말하고 `/design-system` 이 그 전부를 검사하므로, 쓰이든 안 쓰이든 다 있어야 한다.

| **에러 화면 전문** | 네트워크 끊김 · 세션 만료 등 화면 단위 에러는 계약서 에러 코드가 확정된 뒤 |
| **월 조회의 프로필 변화 건수** | 09 월 그리드가 일정 · 관찰 · 일기 · 프로필 변화를 **모양 4종**으로 가르는데, 계약서의 월 조회 응답에는 `has_diary` · `has_event` · `has_image` · `observation_count` 뿐이라 "이날 프로필이 달라졌다" 를 실을 자리가 없다. 프론트가 셀 수 없는 값이다 — 승격은 Curator 의 반복 집계 결과라 관찰 건수로 역산되지 않는다. `CalendarDay.profile_changed_count` 를 optional 로 두고 목으로 세웠다(안 오면 고리 표식과 범례의 그 줄이 안 나온다). 👉 `apps/api` Owner 협의 대상 |
| **`GET /children/{cid}/suggestions`** | 07 제안 피드백 탭이 평가할 제안을 **목록으로 얻을 길이 없다.** 계약서 §03 은 07 에 `PATCH /feedback` 을 배정했는데 조회가 빠져 있다. `SuggestionListResponse` 를 optional 로 두고 목으로 세웠다(안 오면 빈 상태를 그린다). 👉 `apps/api` Owner 협의 대상 |
| **일반 추천의 응답 필드** | 화면은 만들었고(`card-general`) 목으로 돌아간다. 남은 것은 계약서다 — v1 의 `scarcity` 응답은 `suggestions: []` 로 끝나서 또래 기준 추천을 실을 자리가 없다. 프론트는 `SuggestionsResponse.general: GeneralSuggestion[]` 과 양쪽의 `kind` 필드를 **제안 형태로** 두고 optional 로 받는다(서버가 안 보내면 질문 1개만 그린다). 👉 `apps/api` Owner 협의 대상 (최상위 CLAUDE.md §8) |
| **`Evidence.is_stale`** | `chip-evidence-stale` 을 그리려면 6개월 판정이 필요한데 프론트는 날짜를 계산하지 않는다(CLAUDE.md §3). `Affinity` 에는 `is_stale` 이 있고 `Evidence` 에는 없다 — 계약서 수정 대상이고, 그때까지 점선 칩은 목에서만 나온다 |
