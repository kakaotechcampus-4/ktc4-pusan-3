# 디자인 시스템 v1

**살아 있는 버전이 있다 — `pnpm dev` 후 [`/design-system`](../../apps/web/src/app/design-system/page.tsx).** 이 문서의 표를 실제 토큰·컴포넌트로 렌더하고, **대비비를 그 자리에서 계산한다.** 토큰을 바꾸면 통과/미달이 바뀌므로 문서와 코드가 어긋나면 눈에 보인다.

## 1. 한눈에

웜 오프화이트 바탕 위에 **세이지 그린 하나**를 브랜드로 쓴다. 도메인 4색과 상태 2색이 있고, 그 밖의 모든 것은 뉴트럴이다. 그림자는 바텀시트 **한 단계뿐**이고 카드 경계는 테두리가 만든다. 단일 컬럼 고정 — 데스크톱 레이아웃이 따로 없다.

| | |
| --- | --- |
| 색 토큰 | **35개** (뉴트럴 8 · 브랜드 4 · 도메인 12 · 상태 7 · 외부 브랜드 3 · 오버레이 1) |
| 타이포 | **8단계** · 본문 16px / 1.6 · Pretendard |
| 간격 | 4px 배수 7단계 · 컨테이너 최대 폭 560px |
| radius | 4개 (10 · 14 · 20 · 9999) |
| 그림자 | **1개** (바텀시트) + 스크림 |
| 컴포넌트 | 버튼 6 · 입력 3 · 칩 4 · 카드 5 · 배너 2 · 시트 · 탭 · 진행 · 빈 상태 · 스켈레톤 |
| 브레이크포인트 | 3개 · 전 구간 1열 |

**성격** — 하루에 여러 번, 자주 밤에, 지친 상태로 여는 화면이다. 한 번 보고 감탄하는 화면이 아니라 100번째에도 안 피곤한 화면을 목표로 한다. 그래서 강조는 채도가 아니라 **명도**로 만들고, 색은 전부 "이 색 = 이 뜻" 이 1:1 이며, 예쁘라고 칠하는 색은 없다.

## 2. 색

전 항목 [WCAG 2.2 AA](https://www.w3.org/WAI/WCAG22/quickref/#contrast-minimum) 기준으로 계산했다 (본문 4.5:1 · 비텍스트 3:1). 괄호 안은 실측 대비비, 재현 방법은 §10.

### 2-1. 뉴트럴 — 화면의 90%

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-canvas` | `#FBF9F5` | 페이지 바탕. **웜 오프화이트** — 순백 대비 야간 글레어를 줄인다 |
| `--color-surface` | `#FFFEFB` | 카드·시트·입력. 바탕 위에서 1.04:1 로만 뜬다 |
| `--color-surface-muted` | `#F3F1EC` | 비활성 · 접힌 영역 · 실패 카드 · 스켈레톤 |
| `--color-ink` | `#221F1B` | 본문 (15.6:1). 순검정 아님 |
| `--color-ink-muted` | `#605A52` | 보조 텍스트 · 설명 (6.5:1) |
| `--color-ink-subtle` | `#6F6A61` | 메타 · 타임스탬프 · 건수 (5.1:1) |
| `--color-line` | `#E8E4DC` | 기본 구분선 · 카드 테두리 |
| `--color-line-strong` | `#969086` | 입력 테두리 · 점선 테두리 (3.0:1 — 비텍스트 AA) |

🚨 **`surface` 도 순백이 아니다.** 처음엔 `#FFFFFF` 였는데 색조가 아예 없어서 웜 캔버스 위에서 **혼자 차가웠다.** 카드가 읽는 면적의 대부분이라 야간 글레어(§2-1 이 `canvas` 를 웜으로 잡은 이유)는 바탕보다 카드에서 더 문제가 된다. `canvas` 와 같은 색조(OKLCh H 85)로 옮기고 밝기만 올렸다 — 리프트는 1.052 → 1.043 으로 사실상 그대로고, **어차피 카드 경계는 그림자가 아니라 `line` 1px 이 만든다**(§6).

> `ink-subtle` 도 4.5:1 을 넘긴다. **"흐린 회색 글씨" 를 만들지 않는다** — 기록 건수·날짜는 부모가 실제로 읽는 정보다.

### 2-2. 브랜드 — 세이지 그린

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-brand` | `#3A6B52` | 주 버튼 · 활성 탭 · 링크 · 포커스 링 (5.9:1 · 흰 글자 6.2:1) |
| `--color-brand-hover` | `#2F5943` | press / hover (흰 글자 8.0:1) |
| `--color-brand-soft` | `#E7EFE9` | **개인화 추천 카드 배경** |
| `--color-brand-ink` | `#26493A` | soft 위 텍스트 (8.6:1) |

성공 상태에는 별도 색을 두지 않는다. `brand` 를 쓴다 — 초록을 두 뜻으로 쓰면 브랜드가 "성공" 으로 읽힌다.

### 2-3. 도메인 4종

[`suggestion_agent`](../../CLAUDE.md) enum 과 1:1 이다. **여기 있는 색은 다른 용도로 쓰지 않는다.**

| 도메인 | 주색 | soft 배경 | soft 위 텍스트 |
| --- | --- | --- | --- |
| 식사 `food` | `#9A4F22` 테라코타 (5.7:1) | `#F6EBE1` | `#7E3F1B` (6.8:1) |
| 놀이 `activity` | `#0F7084` 틸 (5.4:1) | `#E5EFF1` | `#055766` (7.0:1) |
| 교육 `education` | `#4E5AA0` 인디고 (6.1:1) | `#E9EAF5` | `#3B4680` (7.4:1) |
| 건강 `health` | `#8A4E74` 플럼 (5.8:1) | `#F3E9EF` | `#6E3B5B` (7.3:1) |

`activity` 로 통일한다 — 기획서·테크스펙의 `play` / `interest` 는 쓰지 않는다 (CLAUDE.md §5).

**네 색은 동급이어야 한다 — 그런데 틸만 흐렸다.** 도메인 사이에는 우열이 없다 (한 화면에 최대 2개가 나란히 뜬다). 그래서 명도는 넷 다 OKLCh L 49~51 로 이미 맞춰져 있었는데, 지각 채도는 `food` 0.115 · `education` 0.112 · `health` 0.095 인 사이에서 **`activity` 만 0.072** 였다. 같은 크기·같은 자리에 놓아도 놀이 칩만 한 단계 물러나 보이고, 하필 놀이가 넷 중 제일 생생해야 하는 자리다.

| | 옛 | 새 |
| --- | --- | --- |
| chroma | 0.072 (`food` 의 0.63배) | **0.086 (0.75배)** |
| `activity` on `canvas` | 5.3:1 | 5.4:1 |
| `brand`(세이지) 와의 거리 | 0.069 | **0.077** |
| `education`(인디고) 와의 거리 | 0.098 | 0.099 |

**0.086 이 끝이다.** 216° 는 sRGB 가 채도를 가장 못 내는 구간이라 그 명도에서 천장이 0.089 고, 그 위는 색이 뭉개진다. 넷을 완전히 같은 채도로 맞추려면 나머지 셋을 0.086 까지 **내려야** 하는데, 그러면 `danger` 가 도메인 최고치의 1.43배가 되어 §2-6 에서 맞춰 둔 1.22배가 깨진다. 그래서 **올릴 수 있는 쪽을 올려** 폭을 1.60배에서 1.29배로 줄였다. 남은 차이는 sRGB 의 한계지 취향이 아니다.

세이지와 틸은 원래 제일 헷갈리는 한 쌍인데, 채도를 올리면 오히려 **멀어진다** — 브랜드는 차분한 초록이고 놀이는 선명한 청록이라는 차이가 생기기 때문이다.

### 2-6. 외부 브랜드 — 카카오

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-kakao` | `#FEE500` | 카카오 로그인 버튼 배경 |
| `--color-kakao-hover` | `#F0D800` | 그 버튼의 hover / press (`kakao-ink` 10.5:1) |
| `--color-kakao-ink` | `rgb(0 0 0 / 0.85)` | 그 위 라벨 (16.4:1) |

🚨 **우리 팔레트가 아니다.** 카카오 로그인 버튼은 카카오가 정한 색·모양을 써야 해서 예외로 뒀고, **로그인 버튼 밖에서는 쓰지 않는다.** 노랑이 승인 게이트의 `caution` 과 가까워 보이지만 뜻이 겹치지 않는 이유는 이 색이 **로그인 화면에만 있고 `caution` 이 그 화면에 없기** 때문이다 — 두 색이 한 화면에 같이 나오면 규칙이 깨진다.

말풍선 심볼도 lucide 가 아니라 카카오 마크를 인라인 SVG 로 쓴다 (§7 아이콘 규칙의 예외).

**`danger` 의 채도를 팔레트 안으로 맞춰 뒀다.** 처음 값은 Material 기본 빨강(`#B3261E`)이었는데, 지각 채도(OKLCh chroma)로 재 보니 **0.178 로 도메인 최고치(food 0.115)의 1.55배**였다. §1 이 "강조는 채도가 아니라 **명도**로 만든다" 라고 정했는데 혼자 다른 팔레트에서 온 색이었다.

| | 옛 | 새 |
| --- | --- | --- |
| chroma | 0.178 (최고치의 1.55배) | **0.140 (1.22배)** |
| `danger` on `canvas` | 6.2:1 | 6.4:1 |
| 흰 글자 on `danger` | 6.5:1 | 6.8:1 |
| `food`·`health` 중 가까운 쪽과의 거리 | 0.081 | 0.075 |

**1.22배는 의도한 값이다** — `danger` 는 화면에서 가장 급한 색이어야 하므로 도메인보다 위에 두되, 가족 밖으로 나가지는 않는다. 색조도 18° 로 잡아 `food`(49°) 와 벌렸다 — **알레르기 경고는 식사 화면에 뜨는 색**이라 그 둘이 섞이면 안 된다.

**비활성 상태에는 토큰을 만들지 않는다.** 어떤 컴포넌트든 `surface-muted` 배경 + `ink-subtle` 텍스트 (4.8:1) + `line` 테두리로 만든다. 브랜드색을 흐리게 만든 비활성 버튼은 "누를 수 있어 보이는데 안 눌리는" 상태가 되어 지친 사용자에게 제일 나쁘다.

## 3. 🚨 색 사용 규칙

[CLAUDE.md §2](../../CLAUDE.md) 와 [`apps/web/CLAUDE.md` §4](../../apps/web/CLAUDE.md) 가 색으로 떨어지는 지점이다. 어기면 스타일 문제가 아니라 **규칙 위반**이다.

- 🚨 **실패는 빨강이 아니다.** Agent 2개 중 1개만 성공해도 화면은 나가야 한다(NF-06). 그걸 빨강으로 칠하면 부모가 매일 빨간 화면을 본다. **실패 카드는 `surface-muted` + `ink-muted`**, 빨강은 알레르기에만 남긴다. `llm_unavailable`(503) 도 같다 — 실패했다고 말하되 경보로 말하지 않는다.
- 🚨 **일반 추천과 개인화 추천을 색으로 구분하지 않는다.** 개인화 = `brand-soft` 배경 + 근거 칩 N개, 일반 = `canvas` 그대로 + 점선 `line-strong` 테두리 + **"또래 기준 일반 추천" 라벨 + 쌓인 기록 건수**. 적록색약에서도 §2 가 지켜져야 하므로 **라벨이 본체이고 배경색은 거들 뿐이다.**
- 🚨 **`caution` 은 승인 게이트 2곳에만.** ㉠ 캘린더 쓰기 ㉡ 건강·알레르기 기록 확정. 06 화면 상단 `prechecks` 배너가 여기다. 승인을 늘리지도 줄이지도 않는 규칙이라 **색도 늘리지 않는다.**
- 🚨 **도메인 색을 단독 신호로 쓰지 않는다.** 항상 아이콘 + 텍스트 라벨과 함께 나간다. 4색 중 `food`(테라코타) 와 `health`(플럼) 는 적록색약에서 가까워진다.
- **한 화면에 도메인 색은 최대 2개.** Agent 가 최대 2개(NF-01)라 자연히 지켜진다. 홈에 4색을 다 깔지 않는다.
  - **예외는 로그인 전 소개 화면(00) 하나뿐이다.** 이 규칙의 근거가 "Agent 가 최대 2개" 인데, 소개 화면에는 추천이 없어서 도메인 색이 "이 추천이 어느 Agent 에서 왔는가" 라는 **신호로 쓰이지 않는다.** 거기서는 4개를 나열하는 것 자체가 설명이다. 로그인 뒤 화면에서는 예외를 만들지 않는다.
- **`is_stale` 근거 칩은 `ink-subtle` + 점선** 으로 눌러서 그린다. 6개월 넘은 기록은 단독 근거로 못 쓴다(NF-08) — 색으로도 대등해 보이면 안 된다.
- **컴포넌트에서 `#hex` 를 직접 쓰지 않는다.** Tailwind 토큰 클래스만 (`text-ink-muted` · `bg-brand-soft`).

## 4. 타이포

`Pretendard Variable` → `Pretendard` → 시스템 폰트 순으로 떨어진다. 웹폰트가 안 떠도 한글 자간이 무너지지 않는 순서다. 별도 디스플레이 서체는 두지 않는다.

**자체 호스팅 · 동적 서브셋으로 확정했다** (§14 에서 열려 있던 결정).

| | |
| --- | --- |
| 어디에 | `apps/web/public/fonts/pretendard/` (92개 · 3.1MB) · `@font-face` 는 [`src/app/pretendard.css`](../../apps/web/src/app/pretendard.css) |
| 왜 동적 서브셋 | 전체 variable 은 **2.06MB** 다. 동적 서브셋은 `unicode-range` 로 화면에 실제 쓰인 글자 범위만 받는다 — 00 로그인 화면 실측 **9개 · 111KB** |
| 왜 CDN 이 아닌가 | 저장소가 public 이고 외부 리소스는 보안 검토 대상이다 (CLAUDE.md §9). 자체 호스팅이면 앱이 우리 오리진 밖으로 나가지 않는다 |
| 라이선스 | SIL Open Font License 1.1 — `public/fonts/pretendard/LICENSE.txt` 를 같이 둔다 |

| `label` | 13 / 1.4 | 500 | 0 | 칩 · 탭 · 폼 라벨 |
| `caption` | 12 / 1.4 | 400 | 0 | 메타 · 타임스탬프. **이보다 작게 쓰지 않는다** |

🚨 **`display` 는 좁은 폰(< 380px)에서 `title` 로 낮춘다** (§9). 화면마다 손으로 쓰면 어긋나므로 [`components/ui/page-title.tsx`](../../apps/web/src/components/ui/page-title.tsx) 한 곳에 뒀다 — **화면 제목은 `<h1>` 을 직접 쓰지 말고 `PageTitle` 을 쓴다.**

한글은 라틴보다 행간이 더 필요해서 본문 1.6 을 잡았다. 크기가 커질수록 자간을 음수로 조여야 한글이 헐거워 보이지 않는다.

🚨 **화면에 보이는 글자에 이모지·기호를 쓰지 않는다.** `①②③` · `↓` · `★` · `▶` 같은 것으로 뜻을 나타내지 않는다.

- **스크린리더가 제각각으로 읽는다.** 순서를 나타내려던 `①` 이 "동그라미 일" 로 읽히거나 통째로 건너뛰어지고, `↓` 는 읽히지 않아 의미가 사라진다.
- **기기·폰트에 글리프가 없으면 두부(□)로 보인다.** Pretendard 서브셋에 없는 문자면 폴백 폰트로 떨어져 크기·정렬도 어긋난다.
- **아이콘은 lucide 한 곳에서 관리하는데**(§7) 텍스트 기호는 그 관리 밖으로 샌다. 색 단독 금지(§3)를 아이콘에 걸어 둔 것과 같은 이유로, 뜻을 나르는 것은 한 곳에 모아야 한다.

대신 이렇게 한다 — **뜻은 글자로 쓰고**, 순서가 필요하면 `<ol>`, 목록 마커가 필요하면 CSS `list-*`/`marker:` 로 그린다(브라우저가 접근성 트리에 맞게 처리한다). 그림이 필요하면 lucide 아이콘 + 텍스트 라벨을 쓴다.

**문장부호는 이렇게 나뉜다.**

| | 규칙 |
| --- | --- |
| 줄표 `—` | 🚨 **화면 텍스트에 쓰지 않는다.** 괄호 · 쉼표 · 줄바꿈으로 바꾼다. 한국어에서 정상 부호이긴 하지만 **뜻이 애매해지는 자리에 아무 데나 들어가기 쉬워서**, 쓰지 않는 쪽이 문장을 또렷하게 만든다 |
| 붙인 가운뎃점 `수집·이용` | 그대로 쓴다. **병렬 합성어**를 만드는 한국어 정서법이지 구분자가 아니다 (`건강·알레르기`, `예약·발송·결제`) |
| 띄운 가운뎃점 ` · ` | **한 줄에 하나까지.** 메타 스트립 전용이다 (`아이 등록 · 1 / 2`). 문장 안에서 나열할 때는 쉼표를 쓰고, 항목이 셋 이상이면 목록으로 쪼갠다 |

⚠️ 코드 주석·마크다운 문서·[`/design-system`](../../apps/web/src/app/design-system/page.tsx) 은 대상이 아니다 — 앞의 둘은 화면에 안 나가고, `/design-system` 은 팀이 보는 내부 문서라 설명문의 리듬을 유지한다.

**줄바꿈은 `word-break: keep-all`** 로 어절 단위를 유지한다 — 좁은 웹뷰에서 단어가 잘리면 읽는 속도가 눈에 띄게 떨어진다. 한 줄은 **35자 안팎**에서 끊는다(컨테이너 폭이 그 역할을 한다).

⚠️ **입력 필드의 글자는 16px 미만으로 내리지 않는다.** iOS 웹뷰는 16px 미만 입력에 포커스가 가면 화면을 자동으로 확대하고, 확대된 채로 남는다.

🚨 **프로토타입은 11~13px 이 전체의 70% 였다** (11px 108곳 · 12px 68곳 · 13px 56곳). 데스크톱 브라우저에서 모바일을 흉내 내다 나온 크기고, 실제 기기에서 지친 눈으로 읽을 크기가 아니다. **그대로 옮기지 말 것.**

## 5. 레이아웃

### 간격

4px 배수만 쓴다.

| 토큰 | 값 | 기본 용도 |
| --- | --- | --- |
| `2xs` | 4px | 아이콘과 라벨 사이 |
| `xs` | 8px | 칩 사이 · 인라인 요소 |
| `sm` | 12px | **카드와 카드 사이** |
| `md` | 16px | **카드 안쪽 여백 · 화면 좌우 여백** |
| `lg` | 20px | 시트 안쪽 여백 |
| `xl` | 24px | **섹션과 섹션 사이** |
| `2xl` | 32px | 화면 상단 여백 · 빈 상태 위아래 |

### 컨테이너 · 그리드

- **콘텐츠 최대 폭 560px**, 그 이상에서는 가운데 정렬하고 양옆은 `canvas` 로 둔다.
- 화면 좌우 여백 16px. 폭 360px 미만 기기에서만 12px.
- **그리드는 1열 고정이다.** 제안 카드도, 관찰 목록도, 도메인 칩 줄도 세로로 쌓는다. 2열이 필요해 보이면 정보가 많은 것이지 열이 부족한 게 아니다.
- **상하 여백 32px(`2xl`) 과 노치·홈 인디케이터는 [`components/ui/screen.tsx`](../../apps/web/src/components/ui/screen.tsx) 가 `calc` 로 함께 소유한다.** 웹뷰 안에서는 네이티브 셸이 safe area 를 이미 처리해서 0 이 되고, 모바일 브라우저 직접 접속에서만 값이 생긴다.
- 🚨 **safe-area 유틸은 여백을 함께 받는다 — `pt-safe-8` = safe area + 32px.** 예전에는 safe area 만 넣는 `pt-safe`/`pb-safe` 였는데, 같은 padding 속성이라 `py-8` 을 나란히 쓰면 **뒤에 오는 쪽이 이겨 한쪽이 조용히 죽었다.** 이 사고를 두 번 냈다 — 화면 5개의 상하 여백이 0 이었고(하단 문구가 모서리에 붙음), 바텀시트 닫기 버튼이 화면 맨 아래에 붙었다. 그래서 유틸이 `calc` 로 합쳐서 내보내고, **여백만 주는 `py-*` 를 그 위에 겹치지 않는다.**

### 여백 철학

**위는 넉넉하게, 목록은 촘촘하게.** 화면 상단(인사말·상태)은 32px 을 쓰고 카드 목록은 12px 로 붙인다. 스크롤 한 번에 더 많은 카드가 들어오는 편이, 카드마다 숨 쉴 공간을 주는 것보다 이 서비스에 맞다 — 부모는 감상하러 온 게 아니라 확인하러 왔다.

## 7. 컴포넌트

값이 비어 있으면 §5 기본값(카드 안쪽 16px 등)을 따른다. 타이포 열은 §4 역할 이름이다.

**구현은 직접 한다.** 별도 UI 라이브러리를 쓰지 않는다 — 토큰과 1:1 로 붙고 고치기 쉬운 쪽을 골랐다.
대신 접근성이 전부 우리 책임이 되므로, **직접 짜면 반드시 빠뜨리는 것은 이미 검증된 것 위에 얹는다.**

| 무엇 | 무엇 위에 | 왜 |
| --- | --- | --- |
| 바텀시트 | 네이티브 `<dialog>` | 포커스 트랩 · ESC · 바깥 `inert` · 스크림을 브라우저가 준다 |
| 달력 | [`react-day-picker`](https://daypicker.dev) | 그리드 ARIA · 방향키 이동 · 월 경계 처리 · 로케일. 이 넷을 손으로 짜면 어딘가 빠진다 |

🚨 **이 둘이 "UI 라이브러리를 쓰지 않는다" 의 예외 전부다.** `react-day-picker` 는 달력 하나만 하는 라이브러리라 자기 디자인을 들고 오지 않는다 — 기본 CSS 를 **불러오지 않고** `classNames` 로 우리 토큰만 입힌다. 버튼·입력·시트 같은 것을 주는 UI 킷은 계속 쓰지 않는다.

**아이콘은 [lucide](https://lucide.dev) 를 쓴다.** 크기 3단계(16 · 20 · 24)와 `strokeWidth: 1.75` 로 고정한다 — lucide 기본값 2 는 16px 에서 두껍게 보인다.
도메인 4종 매핑은 `apps/web/src/components/ui/icon.tsx` 한 곳에 있고, 그 컴포넌트는 **`aria-hidden`** 이다 — 아이콘이 단독 신호가 되는 것을 구조적으로 막는다 (§3).

🚨 **네 아이콘은 전부 집에 있는 물건이다** — 수저(`Utensils`) · 블록(`Blocks`) · 책(`BookOpen`) · 체온계(`Thermometer`). `health` 에 심전도(`HeartPulse`)를 쓰지 않는다: 그 기호는 **병원과 진단**을 뜻하는데 이 제품은 Health Agent 가 진단하지 않는다고 못박아 뒀다 (CLAUDE.md §2). 아이콘이 제품의 반대말을 하면 안 된다. 넷이 같은 층위의 사물이면 **색을 못 알아봐도 모양으로 구분된다** — §3 이 `food`·`health` 의 적록색약 근접을 걱정한 자리를 아이콘이 받쳐 준다.

| --- | --- | --- | --- | --- | --- | --- | --- |
| `btn-primary` | `brand` | `#FFF` | — | 48 | 20 | field | button |
| `btn-primary:active` | `brand-hover` | `#FFF` | — | 48 | 20 | field | button |

- `btn-danger` 는 **파괴적 확정에만** (10 설정의 동의 철회·기록 삭제). 승인 게이트의 "아니에요" 는 `btn-secondary` 다. 거절은 파괴가 아니다.
- `btn-kakao` 는 **00 로그인 화면 전용**이다 (§2-6). 그 화면에 `btn-primary` 가 없어서 "한 화면에 primary 하나" 규칙과 부딪히지 않는다.
- 한 화면에 `btn-primary` 는 **하나**. 두 개면 무엇이 다음 행동인지 부모가 판단해야 한다.

🚨 **`failed` 이벤트가 오면 `raw_text` 를 `textarea` 에 그대로 되돌려 놓는다.** 부모가 다시 타이핑하게 만들지 않는다.

**표식은 20px 이다.** 처음 24px 로 잡았는데 16px 라벨 옆에서 표식이 글자보다 커 보였다. 누르는 영역은 행 전체(44px)라 표식을 줄여도 터치가 나빠지지 않는다.

**체크박스에 새 radius 를 만들지 않으려고 `rounded-full` 을 골랐다.** 24px 사각형에 `radius-field`(10px) 는 과하고, 그 사이 값을 만들면 §6 의 radius 4개가 5개가 된다.

🚨 **동의 화면의 체크박스는 승인 게이트가 아니다.** `btn-approve` 와 `caution` 색을 쓰지 않는다 — 그 둘은 되돌릴 수 없는 2곳 전용이고(§3), 법적 동의는 그 2곳이 아니다. 제출은 `btn-primary` 다.

- 하단 버튼 영역은 **`pb-safe-4`** (safe area + 16). 🚨 `pb-safe` 와 `py-*` 를 나란히 쓰면 아래 패딩이 죽어 버튼이 화면 맨 아래에 붙는다 — 실제로 그렇게 났다
- **승인 시트는 스크림 탭으로 닫히지 않는다.** 명시적으로 닫아야 한다 — 실수로 닫혀서 draft 가 만료되는 경로를 만들지 않는다 (승인 없는 draft 는 24시간 뒤 만료된다).
- 구현은 [`components/ui/bottom-sheet.tsx`](../../apps/web/src/components/ui/bottom-sheet.tsx) 다. `dismissible: false` 가 위 규칙(스크림·ESC 로 안 닫힘)이고 **승인 시트 전용**이다 — 되돌릴 수 있는 것(약관 상세 등)에는 쓰지 않는다.
- `showModal()` 이 바깥 조작은 막아 주지만 **배경 스크롤까지 막지는 않는다.** 컴포넌트가 `body` 를 `overflow: hidden` 으로 잠근다.

전환은 전부 `fast`(120ms) + `--ease-standard` 다. 색만 바꾸고 **크기·위치는 건드리지 않는다.**

🚨 **`cursor` 는 `globals.css` 가 한 번에 건다** — 누를 수 있는 것은 `pointer`, 비활성은 `not-allowed`. Tailwind 4 preflight 는 버튼에 `cursor` 를 주지 않아서(v3 에서 달라진 점) 전부 기본 화살표였다. 웹뷰에는 커서가 없지만 브라우저로 들어오면 누를 수 있는지가 안 보인다.

🚨 **`hover` 는 `@media (hover: hover)` 안에서만 건다.** Tailwind 기본 `hover:` 는 미디어쿼리 없이 `:hover` 를 내는데(생성 CSS 로 확인), 터치 기기에서는 **탭한 뒤 손을 떼도 호버가 눌러붙어** 방금 누른 버튼이 계속 눌린 것처럼 보인다. 이 화면은 대부분 웹뷰·모바일이라 그게 기본 경험이 된다. `globals.css` 에서 `@custom-variant hover` 로 덮어 뒀으니 화면 코드는 `hover:` 를 그냥 쓰면 된다.

**웹뷰에는 호버가 없다.** 호버는 모바일·데스크톱 브라우저로 들어온 경우를 위한 것이고, 누른 느낌은 터치에서도 걸리는 `active:` 가 맡는다. 그래서 **`active` 를 빠뜨리면 웹뷰에서는 아무 반응이 없다.**

#### 브라우저가 대신 칠하는 표면

우리가 정하지 않으면 **기본값이 그대로 나간다** — 대개 채도 높은 파랑과 반투명 순검정이다. 웜 오프화이트 위에서 그 파랑만 혼자 다른 앱에서 온 것처럼 보인다. 넷 다 `globals.css` 의 `@layer base` 에 있다.

| 무엇 | 값 | 왜 |
| --- | --- | --- |
| `::selection` | `brand-soft` 배경 + `brand-ink` 글자 (8.6:1) | 문장을 끌어 복사하는 화면(기억·근거)이 있다 |
| `-webkit-tap-highlight-color` | `rgb(34 31 27 / 0.06)` | 🚨 **웹뷰에서 누를 때마다 보인다.** 투명으로 지우지 않는다 — `active` 가 없는 요소는 아무 반응이 없어진다 |
| `caret-color` | `brand` | 입력 커서. 기본값은 순검정이라 `ink` 보다 진하다 |
| `scrollbar-color` | `line-strong` / `canvas` | 데스크톱 브라우저에서만 보인다 (웹뷰·모바일은 오버레이 스크롤바) |

### 기다림 표시

| 이름 | 사양 |
| --- | --- |
| `spinner` | 16 × 16 · 2px 테두리 · **트랙 = 현재 글자색 25% · 머리 = 100%** · 1초에 1바퀴 · 버튼 안이나 대기 화면에서 문구 왼쪽에 |

**위쪽만 투명하게 뚫지 않는다.** 그렇게 하면 어디서 끊겼는지가 눈에 남아 3/4 짜리 조각이 도는 것으로 보인다. 원이 계속 보이고 그 위를 밝은 머리가 도는 쪽이 조용하고, 밤에 보는 화면에서는 그 차이가 크다.

🚨 **`prefers-reduced-motion` 에서는 스피너를 숨긴다.** 애니메이션만 멈추면 "고장난 화면" 으로 읽힌다 — 옆의 문구("저장하는 중…")가 상태를 대신 말한다.

### 하지 않는 것

- **승인 게이트에는 등장 애니메이션을 넣지 않는다.** 확인해야 할 것을 부드럽게 흘려보내면 안 된다.
- **등장·스크롤 애니메이션을 만들지 않는다.** 하루에 여러 번, 자주 밤에, 지친 상태로 여는 화면이다(§1). 처음엔 살아 있어 보이지만 100번째에는 "매번 기다려야 하는 것" 이 된다.
- 화면 전체를 움직이는 전환(슬라이드 페이지)을 쓰지 않는다. 웹뷰에서 프레임이 떨어지고, 밤에 보면 멀미가 난다.
- 🚨 **`prefers-reduced-motion: reduce` 에서는 `transform` 을 전부 끄고 `opacity` 만 남긴다.** 스켈레톤 깜빡임도 멈춘다.
- 깜빡이는(1초에 3회 이상) 요소를 만들지 않는다.

## 10. 접근성

- **포커스는 항상 보인다.** `:focus-visible` 에 `brand` 2px outline + offset 2 (5.9:1). `outline: none` 을 쓰지 않는다.
- **색만으로 정보를 전달하지 않는다** (WCAG 1.4.1). 도메인 칩은 아이콘+라벨, 개인화/일반은 라벨과 건수, 실패는 문장이 함께 나간다. 검증은 **도메인 칩에서 라벨을 지워 보는 것** — 그래도 구분되면 통과가 아니라 위반이다.
- **크기는 `rem` 으로 쓴다.** 표에는 px 로 적었지만 CSS 는 rem 이다. 사용자가 시스템 글자 크기를 키웠을 때 따라 커져야 한다.
- **`-webkit-text-size-adjust: 100%`** 는 회전 시 글자가 튀는 것만 막는 값이다. 확대 자체를 막는 `user-scalable=no` 는 쓰지 않는다.
- **한국어 스크린리더 라벨**을 붙인다. 아이콘 버튼의 `aria-label`, 진행 오버레이의 `aria-live="polite"`, 승인 시트의 `role="dialog"` + `aria-modal`.
- **대비비는 눈으로 고르지 않고 계산한다.** WCAG 2.2 상대 휘도 공식(`sRGB → linearize → 0.2126R + 0.7152G + 0.0722B`)으로 §2 의 모든 쌍을 돌렸고 **본문 쌍 전부 4.5:1 이상, 비텍스트 쌍 전부 3:1 이상**이다. 토큰을 바꿀 때는 값만 바꾸지 말고 **그 색이 얹히는 배경과의 쌍을 다시 계산한다.** soft 배경 위 텍스트는 `canvas` 가 아니라 그 soft 색과 비교해야 한다 — 여기서 많이 틀린다.

## 12. 다크모드 방침

**v1 은 라이트만 낸다.** 새벽 수유·재운 뒤 확인이 실제 사용 시나리오라 피로도에 가장 크게 작용하는 변수지만, 10주 안에 두 벌을 검증할 여유가 없다. 절반만 맞는 다크모드는 라이트만 있는 것보다 나쁘다.

대신 **나중에 값만 갈아끼울 수 있게 이름을 지어 뒀다.** 토큰 이름에 색이 들어가지 않는다 — `canvas` · `ink` · `line` 은 다크에서도 뜻이 유지되지만 `white` · `gray-50` 은 거짓말이 된다. 이 규칙만 지키면 다크는 `@media (prefers-color-scheme: dark)` 블록에서 값 재정의로 끝난다.

지금 `globals.css` 의 `color-scheme: light` 는 **의도된 고정**이다. 지우지 말 것 — 지우면 브라우저가 폼 컨트롤만 다크로 바꿔서 화면이 반쪽만 어두워진다.

## 13. `globals.css` 적용

이 문서의 표를 그대로 옮겼다. Tailwind 4 CSS-first 라 `tailwind.config.*` 는 없고, `@theme` 에 넣으면 유틸이 자동 생성된다.

| 문서 | `@theme` | 생성되는 유틸 |
| --- | --- | --- |
| §2 색 | `--color-*` | `bg-canvas` · `text-ink-muted` · `border-line` |
| §4 타이포 | `--text-*` (+ `--text-*--line-height` · `--font-weight`) | `text-body` · `text-caption` |
| §5 컨테이너 | `--container-content` | `max-w-content` |
| §6 radius · 그림자 | `--radius-*` · `--shadow-sheet` | `rounded-card` · `shadow-sheet` |
| §8 이징 | `--ease-standard` | `ease-standard` |

§5 간격은 Tailwind 기본 4px 스케일을 그대로 쓴다 (`p-4` = 16px). 별도 토큰을 만들지 않는다.

🚨 **`@theme` 이 아니라 `@theme static` 이다.** Tailwind 4 는 기본적으로 **실제로 쓰인 토큰의 변수만** CSS 로 내보낸다 — 아직 컴포넌트가 없는 토큰 9개(`caution` 계열 · `scrim` · 도메인 주색)가 통째로 빠져 있었고, `/design-system` 이 그 색들을 "읽기 실패" 로 잡아냈다. 이 파일은 위 표를 옮긴 것이고 표가 35개라고 말하므로, 쓰이든 안 쓰이든 다 있어야 한다.
