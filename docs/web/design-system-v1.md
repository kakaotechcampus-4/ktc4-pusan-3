## 1. 설계 기준 — 왜 이 색인가

전제부터 적는다. **하루에 여러 번, 자주 밤에, 지친 상태로 여는 화면**이다. 한 번 보고 감탄하는 화면이 아니라 100번째에도 안 피곤한 화면이 목표다. 여기서 네 가지가 나온다.

1. **채도가 아니라 명도로 위계를 만든다.** 강조하고 싶을 때 색을 더 쨍하게 하지 말고 더 어둡게 한다. 채도는 피로를 만들고 명도는 안 만든다.
2. **색은 의미에만 쓴다.** 이 문서에 있는 색은 전부 "이 색 = 이 뜻" 이 1:1 이다. 예쁘라고 칠하는 색은 없다.
3. **경보를 아껴 쓴다.** 빨강을 매일 보면 빨강이 안 보인다. `danger` 는 알레르기·건강 중단에만 남긴다 (§3).
4. **순백·순검정을 쓰지 않는다.** 바탕은 웜 오프화이트, 본문은 짙은 웜 그레이다. 대비는 충분히 두되 극단은 피한다.

### 안 고른 것과 이유

**파스텔 베이비블루·핑크** — 육아 앱 팔레트의 기본값이지만 뺐다. ㉠ 신생아 기록 앱의 언어다. 우리는 4~7세까지 몇 년 쓰는 서비스고 화면에 나가는 말은 "근거 N건 · 승인해 주세요" 다. ㉡ 파스텔은 명도가 다 비슷해서 위계가 안 선다 — 개인화/일반·승인 대기·부분 실패를 한 화면에 섞어야 하는데(NF-06) 색만으로는 못 나눈다. ㉢ 블루/핑크는 성별 코드가 붙는다. 프로필 질문을 안 늘리기로 한 서비스(§2 개인정보)가 색으로 성별을 묻는 꼴이 된다.

**오렌지 브랜드** — 따뜻하고 성별 코드가 없어서 후보였지만 뺐다. 결정적인 건 **경고색 대역 충돌**이다. 오렌지는 빨강과 노랑 사이에 있고, 그 대역은 이미 `caution`(승인 게이트) 과 `danger`(알레르기) 가 예약했다.

```text
#C2410C 오렌지  vs  #97620E caution   →  1.00 : 1     구분 불가
#C2410C 오렌지  vs  #B3261E danger    →  1.26 : 1     구분 불가
```

브랜드가 오렌지면 "확인해 주세요" 배너가 브랜드 장식처럼 보이고 승인 게이트가 시각적으로 죽는다. **되돌릴 수 없는 행동을 색으로 못 가려내는 건 취향 문제가 아니라 §2 위반이다.** 덤으로 밝은 오렌지는 AA 를 못 넘긴다 (`#F97316` 2.68:1 · `#FF9800` 2.06:1). 4.5:1 을 넘기는 순간 벽돌색이 되어 더는 오렌지가 아니다.

오렌지가 주던 **따뜻함은 채도 없이 뉴트럴로 가져왔다** — 바탕을 중성 회색이 아니라 웜 오프화이트로 잡았다 (§2-1). 면적이 90% 라 효과는 브랜드색보다 크다. 오렌지 계열은 **식사 도메인**(`#9A4F22`) 과 삽화에만 남는다.

## 2. 색 토큰

전 항목 [WCAG 2.2 AA](https://www.w3.org/WAI/WCAG22/quickref/#contrast-minimum) 기준으로 계산했다 (본문 4.5:1 · 비텍스트 3:1). 괄호 안은 실측 대비비, 재현 방법은 §10.

### 2-1. 뉴트럴 — 화면의 90%

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-canvas` | `#FBF9F5` | 페이지 바탕. **웜 오프화이트** — 순백 대비 야간 글레어를 줄이는 가장 큰 한 수 |
| `--color-surface` | `#FFFFFF` | 카드·시트. 바탕 위에서 1.05:1 로만 뜬다 (테두리가 경계를 만들지 그림자가 만들지 않는다) |
| `--color-surface-muted` | `#F3F1EC` | 비활성·접힌 영역·실패 카드 |
| `--color-ink` | `#221F1B` | 본문 (15.6:1). 순검정 아님 |
| `--color-ink-muted` | `#605A52` | 보조 텍스트·설명 (6.5:1) |
| `--color-ink-subtle` | `#6F6A61` | 메타·타임스탬프·건수 (5.1:1) |
| `--color-line` | `#E8E4DC` | 기본 구분선·카드 테두리 |
| `--color-line-strong` | `#969086` | 입력 테두리·포커스 링 (3.0:1 — 비텍스트 AA) |

> `ink-subtle` 도 4.5:1 을 넘긴다. **"흐린 회색 글씨" 를 만들지 않는다** — 기록 건수·날짜는 부모가 실제로 읽는 정보다.

### 2-2. 브랜드 — 세이지 그린

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-brand` | `#3A6B52` | 주 버튼·활성 탭·링크 (5.9:1 · 흰 글자 6.2:1) |
| `--color-brand-hover` | `#2F5943` | press/hover (흰 글자 8.0:1) |
| `--color-brand-soft` | `#E7EFE9` | **개인화 추천 카드 배경** |
| `--color-brand-ink` | `#26493A` | soft 위 텍스트 (8.6:1) |

프로토타입이 이미 그린 계열(`#2E6E60`)이었고 임시 토큰도 그린(`#2f6f4e`)이었다. 방향은 유지하고 채도만 낮췄다.

### 2-3. 도메인 4종

[`suggestion_agent`](../../CLAUDE.md) enum 과 1:1 이다. **여기 있는 색은 다른 용도로 쓰지 않는다.**

| 도메인 | 주색 | soft 배경 | soft 위 텍스트 |
| --- | --- | --- | --- |
| 식사 `food` | `#9A4F22` 테라코타 (5.7:1) | `#F6EBE1` | `#7E3F1B` (6.8:1) |
| 놀이 `activity` | `#2C7080` 틸 (5.3:1) | `#E5EFF1` | `#1F5563` (7.1:1) |
| 교육 `education` | `#4E5AA0` 인디고 (6.1:1) | `#E9EAF5` | `#3B4680` (7.4:1) |
| 건강 `health` | `#8A4E74` 플럼 (5.8:1) | `#F3E9EF` | `#6E3B5B` (7.3:1) |

`activity` 로 통일한다 — 기획서·테크스펙의 `play` / `interest` 는 쓰지 않는다 (CLAUDE.md §5).

### 2-4. 상태 — 딱 2개

| 토큰 | 값 | 언제만 쓰는가 |
| --- | --- | --- |
| `--color-caution` / `-soft` / `-ink` | `#97620E` (4.9:1) / `#FAEFDB` / `#7A4F09` (6.3:1) | 🚨 **승인 게이트 2곳 전용.** 도메인에 노랑 계열이 없어서 "노랑 = 내 확인이 필요함" 이 한 번에 학습된다 |
| `--color-danger` / `-soft` / `-ink` | `#B3261E` (6.2:1) / `#FAE8E5` / `#8F1D17` (7.5:1) | 🚨 **알레르기 경고·건강 추천 중단 전용** |

성공 상태에는 별도 색을 두지 않는다. `brand` 를 쓴다 — 초록을 두 뜻으로 쓰면 브랜드가 "성공" 으로 읽힌다.

## 3. 🚨 색 사용 규칙

[CLAUDE.md §2](../../CLAUDE.md) 와 [`apps/web/CLAUDE.md` §4](../../apps/web/CLAUDE.md) 가 색으로 떨어지는 지점이다. 어기면 스타일 문제가 아니라 **규칙 위반**이다.

- 🚨 **실패는 빨강이 아니다.** Agent 2개 중 1개만 성공해도 화면은 나가야 한다(NF-06). 그걸 빨강으로 칠하면 부모가 매일 빨간 화면을 본다. **실패 카드는 `surface-muted` + `ink-muted`**, 빨강은 알레르기에만 남긴다. `llm_unavailable`(503) 도 같다 — 실패했다고 말하되 경보로 말하지 않는다.
- 🚨 **일반 추천과 개인화 추천을 색으로 구분하지 않는다.** 개인화 = `brand-soft` 배경 + 근거 칩 N개, 일반 = `canvas` 그대로 + 점선 `line-strong` 테두리 + **"또래 기준 일반 추천" 라벨 + 쌓인 기록 건수**. 적록색약에서도 §2 가 지켜져야 하므로 **라벨이 본체이고 배경색은 거들 뿐이다.**
- 🚨 **`caution` 은 승인 게이트 2곳에만.** ㉠ 캘린더 쓰기 ㉡ 건강·알레르기 기록 확정. 06 화면 상단 `prechecks` 배너가 여기다. 승인을 늘리지도 줄이지도 않는 규칙이라, **색도 늘리지 않는다.**
- 🚨 **도메인 색을 단독 신호로 쓰지 않는다.** 항상 아이콘 + 텍스트 라벨과 함께 나간다. 4색 중 `food`(테라코타) 와 `health`(플럼) 는 적록색약에서 가까워진다.
- **한 화면에 도메인 색은 최대 2개.** Agent 가 최대 2개(NF-01)라 자연히 지켜진다. 홈에 4색을 다 깔지 않는다.
- **`is_stale` 근거 칩은 `ink-subtle`** 로 눌러서 그린다. 6개월 넘은 기록은 단독 근거로 못 쓴다(NF-08) — 색으로도 대등해 보이면 안 된다.
- **텍스트에 `#hex` 를 직접 쓰지 않는다.** 컴포넌트는 Tailwind 토큰 클래스만 쓴다 (`text-ink-muted` · `bg-brand-soft`).

## 4. 타이포

`Pretendard Variable` → `Pretendard` → 시스템 폰트 순으로 떨어진다. 웹폰트가 안 떠도 한글 자간이 무너지지 않는 순서다.

| 역할 | 크기 / 행간 | 굵기 | 쓰는 곳 |
| --- | --- | --- | --- |
| `display` | 24 / 1.3 | 700 | 화면 제목 (03 홈 인사말) |
| `title` | 20 / 1.35 | 700 | 카드 제목·시트 헤더 |
| `section` | 17 / 1.4 | 600 | 섹션 구분 |
| **`body`** | **16 / 1.6** | 400 | **본문 기본값** |
| `body-sm` | 14 / 1.55 | 400 | 보조 설명 |
| `label` | 13 / 1.4 | 500 | 칩·버튼·탭 |
| `caption` | 12 / 1.4 | 400 | 메타·타임스탬프. **이보다 작게 쓰지 않는다** |

🚨 **프로토타입은 11~13px 이 전체의 70% 였다** (11px 108곳 · 12px 68곳 · 13px 56곳). 데스크톱 브라우저에서 모바일을 흉내 내다 나온 크기고, **실제 기기에서 지친 눈으로 읽을 크기가 아니다.** 본문 기본을 16px 로 올렸다. 화면이 길어지는 건 스크롤로 해결하고 글자를 줄여서 해결하지 않는다.

한글은 라틴보다 행간이 더 필요해서 본문 1.6 을 잡았다. **줄바꿈은 `word-break: keep-all`** 로 어절 단위를 유지한다 — 좁은 웹뷰에서 단어가 잘리면 읽는 속도가 눈에 띄게 떨어진다.

## 5. 간격 · 모양 · 터치

**간격** — 4px 배수만 쓴다: `4 · 8 · 12 · 16 · 20 · 24 · 32`. 카드 안쪽 여백은 16, 카드 사이는 12, 섹션 사이는 24 가 기본값이다.

**radius**

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--radius-field` | 10px | 입력·작은 버튼 |
| `--radius-card` | 14px | 카드 (프로토타입 지배값 유지) |
| `--radius-sheet` | 20px | 바텀시트 상단 |
| `--radius-chip` | 9999px | 근거 칩·도메인 칩·탭 |

**그림자** — 카드에 그림자를 쓰지 않는다. 경계는 `line` 테두리가 만든다. 그림자는 **바텀시트 하나**에만 쓴다 (`0 -2px 16px rgb(34 31 27 / 0.08)`). 미세한 그림자가 깔린 화면은 저조도에서 뿌옇게 보인다.

**터치 타깃** — 최소 44 × 44px. 승인 게이트의 버튼은 **48px 이상**으로 키운다. 되돌릴 수 없는 행동을 잘못 눌러서 실행하는 경로를 만들지 않는다.

| 08 사진 분석 | 승인 전 미저장 상태 | `caution` 계열 (확정 아님을 색으로) |
| 10 설정 | 동의 철회·삭제 | `danger` 는 **파괴적 확정 버튼에만** |

## 7. 프로토타입에서 달라진 것

프로토타입 색은 폐기한다. 통합할 때 헷갈리지 않도록 대응표를 남긴다.

| | 프로토타입 | v1 | 왜 |
| --- | --- | --- | --- |
| 바탕 | `#FCFDFD` 쿨 화이트 | `#FBF9F5` 웜 오프화이트 | 야간 글레어 · 따뜻함을 채도 없이 |
| 본문 | `#516A70` 블루그레이 | `#221F1B` 웜 다크 | 본문을 유채색으로 두면 장시간 읽기에 불리 |
| 브랜드 | `#2E6E60` / `#3B8172` 2개 | `#3A6B52` 1개 | 브랜드 그린이 두 개일 이유가 없었다 |
| 강조 | `#A04E67` 모브 (용도 혼재) | `health` `#8A4E74` 로 한정 | 색 하나 = 뜻 하나 |
| 본문 크기 | 11~13px 지배 | 16px | §4 |
| 카드 경계 | 그림자 | `line` 테두리 | 저조도에서 그림자는 뿌옇다 |

`globals.css` 임시값과의 차이: `--color-surface`(`#ffffff`) 가 페이지 바탕까지 겸하던 걸 **`canvas` 와 `surface` 로 갈랐다.** 이름이 값의 뜻을 담아야 다크모드에서 거짓말이 안 된다 (§8).

## 8. 다크모드 방침

**v1 은 라이트만 낸다.** 새벽 수유·재운 뒤 확인이 실제 사용 시나리오라 피로도에 가장 크게 작용하는 변수지만, 10주 안에 두 벌을 검증할 여유가 없다. 절반만 맞는 다크모드는 라이트만 있는 것보다 나쁘다.

대신 **나중에 값만 갈아끼울 수 있게 이름을 지어 뒀다.** 토큰 이름에 색이 들어가지 않는다 — `canvas` · `ink` · `line` 은 다크에서도 뜻이 유지되지만 `white` · `gray-50` 은 거짓말이 된다. 이 규칙만 지키면 다크는 `@media (prefers-color-scheme: dark)` 블록에서 값 재정의로 끝난다.

지금 `globals.css` 의 `color-scheme: light` 는 **의도된 고정**이다. 지우지 말 것 — 지우면 브라우저가 폼 컨트롤만 다크로 바꿔서 화면이 반쪽만 어두워진다.

## 9. `globals.css` 적용

이 문서의 표를 그대로 옮겼다. **CSS 가 이 문서와 어긋나면 CSS 가 틀린 것이다.**

```css
@theme {
  --color-canvas: #fbf9f5;
  --color-surface: #ffffff;
  --color-surface-muted: #f3f1ec;
  --color-ink: #221f1b;
  /* ... 전문은 apps/web/src/app/globals.css */
}
```

Tailwind 4 CSS-first 라 `tailwind.config.*` 는 없다. `@theme` 에 넣으면 `bg-canvas` · `text-ink-muted` · `border-line` 같은 유틸이 자동 생성된다.

## 10. 검증

대비비는 눈으로 고르지 않고 계산했다. WCAG 2.2 상대 휘도 공식(`sRGB → linearize → 0.2126R + 0.7152G + 0.0722B`)으로 §2 의 모든 쌍을 돌렸고 **본문 쌍 전부 4.5:1 이상, 비텍스트 쌍 전부 3:1 이상**이다.

토큰을 바꿀 때는 값만 바꾸지 말고 **그 색이 얹히는 배경과의 쌍을 다시 계산한다.** soft 배경 위 텍스트는 `canvas` 가 아니라 그 soft 색과 비교해야 한다 — 여기서 많이 틀린다.

색만으로 정보를 전달하지 않는지(WCAG 1.4.1)는 **적록색약 시뮬레이션으로 화면 캡처를 한 번 돌려서** 확인한다. 도메인 칩에서 라벨을 지우고도 구분되면 규칙 위반이다.
