# 목 서버로 화면 확인하기 (v1)

> `apps/web/CLAUDE.md` §7 에서 옮겨 온 조회표다. 목 시나리오의 **의미**와 규칙, 목이 있는 이유는 그쪽에 있다.

**저장소가 둘로 나뉘어 있다.** 이걸 모르면 "탭 닫았는데 왜 그대로지" 로 막힌다.

| | 어디 | 언제 사라지나 |
| --- | --- | --- |
| 로그인 세션 · `bind` · 가입 대기표 | `sessionStorage` | **탭 닫으면** 자동 |
| 목 시나리오 | `localStorage` | **안 사라진다** — 직접 지우거나 `?scenario=default` |

아직 제출하지 않은 **일정 초안**도 `sessionStorage` 다 (`icatch.event-drafts`) — 탭을 닫으면 사라진다.

전부 초기화 (DevTools 콘솔):

```js
sessionStorage.clear();
localStorage.removeItem("icatch.session");
localStorage.removeItem("icatch.mock.scenario");
location.replace("/");
```

| 04 · 홈 왕복 | run 이 도는 중에 "홈으로 돌아가기" → 홈의 **오늘 대화 이어보기** 로 다시 들어오면 결과가 빠짐없이 서 있어야 한다. 🚨 기기 뒤로가기는 홈으로 간다(앱 밖으로 나가지 않는다) |
| 04 · 같은 날 두 번째 한 줄 | 대화 화면에서 한 줄 더 — 첫 답 아래에 이어 붙는다. 날짜 머리줄은 하나다 |
| **04 · 발화에 따라 화면이 갈린다** | 🚨 목이 **낱말만** 본다 (의도 분류를 흉내 내는 게 아니다 — 진짜 판정은 Supervisor 의 일이다). `일정·약속·예약·가기·잡아·등원·소풍·운동회·물놀이` 가 있으면 **일정형**, `했대·했어·놀았·먹었·좋아해·싫어해·그렸·봤대` 가 있으면 **기록형**, 둘 다거나 아무것도 없으면 **혼합형** |
| 04 run 실패 | `/child/c1/home?scenario=failed` 에서 한 줄 남기기 — 말풍선 아래 "읽지 못했어요" + **다시 시도 · 고쳐 쓰기**. 고쳐 쓰기는 원문을 입력창에 되돌린다 |
| 04 부분 결과 | `/child/c1/home?scenario=partial` 에서 한 줄 남기기. 🚨 일정형 한 줄(`주말에 소풍 가기`)이면 저장이 0건이라 **"저장한 기록은 그대로" 가 없어야 한다** (PR #215 리뷰) |
| 04 보내기 실패 (네트워크) | `/child/c1/home?scenario=send_failed` 에서 한 줄 남기기 — "보내지 못했어요" + 다시 시도 · 고쳐 쓰기. 🚨 **그 상태로 다른 한 줄을 보내도 앞 말풍선이 남아야 한다** (원문이 거기밖에 없다 · #231). 다시 시도는 같은 키라 닿는다. 🚨 입력창에 글을 써 두면 고쳐 쓰기가 **잠기고 이유가 선다** |
| 04 저장한 뒤 끊김 | `/child/c1/home?scenario=interrupted` 에서 한 줄 남기기 — 기록 1건 아래에 "나머지는 마무리하지 못했어요" (#271). 🚨 **다시 시도 · 고쳐 쓰기가 없어야 한다** (서버가 이미 저장했다). 일정형 한 줄(`주말에 소풍 가기`)이면 받은 기록 없이 끊긴 갈래다 — 제목이 "적어주신 내용은 반영했어요" 이고 🚨 **"저장하지 않았어요" 가 어디에도 없어야 한다** |
| 04 결과 못 받음 (저장 여부 모름) | `/child/c1/home?scenario=disconnected` 에서 한 줄 남기기 — "저장됐는지 확인하지 못했어요". 다시 시도는 **같은 키**다. 🚨 고쳐 쓰기를 눌러도 **말풍선이 남아야 한다** (서버가 저장했을 수 있다) |
| **04 · 기록형 발화** | 03 에 `오늘 민준이가 그림놀이 했대` — 기록 2건 + 기억. 🚨 **일정 초안은 안 나온다** |
| **04 · 일정형 발화** | 03 에 `이번 주말에 공원 산책 가기 저장해줘` — 초안 **1장**. 🚨 제목이 "이렇게 **이해**했어요" 다(저장한 게 없다) · 기록은 0건 |
| **04 · 혼합형 발화** | 위 낱말이 하나도 안 걸리는 아무 한 줄 (`지어낸 한 줄`) — 기록 + 초안 **2장** |
| 04 · 초안 넘기기 | 대화에는 **카드만** 서고 "확인하고 넣기" 가 시트를 연다. 초안이 2장 이상이면 **한 장씩** 보여주고 아래에 `이전 · 2건 중 1번째 · 다음` 줄이 선다. 🚨 세로로 쌓지 않는다 |
| 04 · 초안 제출 | 카드의 "확인했어요, 캘린더에 넣을게요". 🚨 **건별**이라 카드마다 따로 누른다 — `create` 는 `POST`, `update` 는 `PATCH` 로 갈린다 |
| 04 · 부분 결과에도 초안은 온다 | `?scenario=partial` — 초안 프레임이 `partial` 보다 먼저 흐른다. 🚨 `failed`·`disconnected` 는 그 전에 끊겨서 **안 온다** |
| 04 · 수정 초안의 변화 표시 | `update` 카드의 "이렇게 달라져요" — `before` 와 비교해 "오후 7:47 → 오후 9:47" 을 그린다 |
| 04 안내 — 알레르기는 대신 저장하지 않음 | `/child/c1/home?scenario=guidance` 에서 한 줄 남기기. 저장 0건이라 **제목이 "적어주신 말을 확인했어요"** 로 바뀌고, "직접 입력하러 가기" 가 11 프로필로 간다 |
| 04 섞인 한 줄 — 안내 + 저장 | `?scenario=guidance_mixed` — "계란 잘 먹었어. 그리고 땅콩 알레르기 있어" 같은 경우. 🚨 안내 카드에 **"아래 기록은 그대로 저장했어요"** 가 붙고 기록 목록이 함께 서야 한다 |
| 04 준비 중 Agent + 저장은 그대로 | `?scenario=unavailable` — 🚨 **준비 중 안내와 저장된 기록이 한 화면에 같이** 서야 한다 (NF-06). 안내만 남고 기록이 사라지면 회귀다 |
| 04 되묻기 → 대화 안에서 답하기 | `?scenario=note_question` — 질문이 오면 입력창 위에 **"위 질문에 답하는 중"** 이 선다. 🚨 **입력창은 비어 있어야 한다** — 원문을 되돌리면 이미 저장된 조각이 다시 저장된다 (#158). 앞 이야기는 `reply_to` 로 서버가 찾는다. 답을 보내면 저장된 기록과 **안내 문장 하나**가 같이 서고, 🚨 그 문장에는 **답할 자리가 없어야 한다** (서버가 저장 뒤에 `note(kind=message)` 를 낸다 · #208). 홈으로 가면 입구가 **"답을 기다리는 질문이 있어요"** 로 바뀐다 |
| 04 되묻기 · 답 내려놓기 | 위 상태에서 **답하지 않고 새로 적기** — 질문은 대화에 **열린 채로** 남고 "이 질문에 답하기" 로 다시 고를 수 있어야 한다 (예전 "나중에 할게요" 는 질문을 지웠다) |
| 04 되묻기 · 이어받기 run 이 또 물음 | `?scenario=reply_asks_again` — 답을 보내면 **다른 질문**이 한 번 더 온다. 🚨 그다음 답의 요청 본문 `reply_to` 가 **두 번째 질문을 낸 run** 이어야 한다 (첫 run 이면 400) |
| 04 되묻기 · 재질문 상한 | `?scenario=reply_ask_limit` — 답할 때마다 다른 질문이 오다가 **네 번째 질문에 답하면** "필요한 정보가 다 모이지 않아 이번 내용은 저장하지 않았어요." 로 끝난다 (#246). 🚨 그 문장에 **"이 질문에 답하기" 가 없어야 하고**, 입력창 위의 "위 질문에 답하는 중" 도 사라져야 한다. 앞 질문은 "아래에 답해 주셨어요" 로 닫힌다 |
| 04 일부 저장 + 되묻기 | `?scenario=note_mixed` — 한 run 에 저장과 질문이 같이 온다. 🚨 이어서 적기 → 답을 보내면 요청 본문에 **원문이 없고 `reply_to` 에 이전 `run_id`** 가 실려야 한다 |
| 04 되묻기 답 · 이어받기 실패 | `?scenario=reply_failed` — 답을 보내면 한 번 실패한다. 🚨 **다시 시도**를 누르면 기록이 저장돼야 한다 — 질문이 또 뜨면 다시 시도가 `reply_to` 를 잃은 것이다 (#175). 저장 뒤의 안내 문장은 정상이다 — 이어서 적기가 붙어 있을 때만 회귀다 |
| 04 되묻기 답 · 맥락 만료 | `?scenario=reply_unavailable` — 답을 보내면 400. 🚨 **"다시 시도" 버튼이 없어야 하고** 입력창 위의 "답하는 중" 이 사라지며, 물었던 질문은 말풍선 아래 오류에 남는다. **고쳐 쓰기** 로 답을 되돌려 다시 보내면 새 입력(`reply_to` 없음)으로 받아야 한다 (#175). 🚨 오류 카드에 "다시 적어 주세요" 와 "앞서 저장된 이야기는 다시 적지 않아도 돼요" 가 **같이 서면 안 된다** — 서버 문구는 상황만 말한다 (#208) |
| 04 한 줄 보내기 · 하루 한도 초과 | `/child/c1/home?scenario=daily_limit` 에서 한 줄 남기기 — 대화 화면의 말풍선 아래에 서버 문구. 🚨 **"다시 시도" 버튼이 없어야 하고**(같은 키로 보내면 자정까지 같은 429) 원문은 **입력창에 되돌아와 있어야 한다**. 🚨 03 홈에는 실패 카드가 없다 |
| 05 제안 후보 | `/child/c1/suggestions?agents=food,activity` |
| 05 · 근거 부족 (일반 추천 1건 + 질문 1개) | 위 주소에 `&scenario=scarcity` |
| 05 · 기록 0건 (일반 추천 2건 + 질문 1개) | 위 주소에 `&scenario=empty` |
| 05 · 알레르기 미상 guard · 오래된 근거 | 위 주소에 `&scenario=stale` |
| 06 승인 시트 | 05 에서 "이걸로" (시트라 주소가 없다) |
| **05 · Agent 당 3가지** | 식사 3가지 · 놀이 3가지가 **탭으로** 갈린다(`식사 3가지` / `놀이 3가지`). 한 번에 한 묶음만 서고, 그 안의 줄은 **전부 펼쳐져 있다** — 대안 셋을 견주는 화면이라 접지 않는다 (아코디언이 아니다) |
| **05 · 두 단계다** | ① 고르고 **"이 3가지로 할게요"**(채택 · 캘린더와 무관) → ② "일정으로도 만들까요?" → ③ "일정으로 만들기" 를 눌러야 초안 시트가 뜬다. 🚨 안 만들 거면 그냥 **"홈으로"** 로 나간다(고른 것은 남는다) |
| **05 · 알레르기 확인이 먼저다** | 식사 제안을 고르고 채택을 누르면 **"확인해 주세요" 시트가 먼저** 뜬다(승인 게이트 ㉡). "알레르기가 있어요" → 기록에 저장되고 **그 제안은 채택에서 빠진다**. 🚨 초안 시트에는 이 질문이 더 이상 없다 |
| **05 · 채택 뒤에는 고르기가 잠긴다** | 체크박스를 눌러도 안 바뀐다 — 서버가 받은 것과 화면이 달라지면 안 된다 |
| **05 · 탭을 넘어도 고른 것은 남는다** | 식사에서 2가지 고르고 놀이 탭으로 가서 1가지 더 고르면 하단 요약이 "식사 2가지 · 놀이 1가지" 로 합산한다. 🚨 ←/→ 키로도 탭이 바뀐다 · 🚨 주소는 안 바뀐다(뒤로가기가 탭을 되짚지 않는다) |
| **05 · 여러 개 고르기** | 줄 왼쪽 체크박스로 여러 건을 고른다. 🚨 `health` 줄에는 체크박스가 **없다** |
| **05 · food 는 한 끼로 묶인다** | 식사에서 2가지 이상 고르면 목록 아래에 "고른 N가지는 일정 하나로 묶여요" 가 뜬다. 식사 2 + 놀이 1 을 고르면 초안이 **2장**이다 ("저녁 식사" + 물놀이장) |
| **06 · 일정 초안** | 시트 안에 카드 N장 (2장 이상이면 한 장씩 넘긴다). 🚨 **일시가 비어 있다** — 제안 문장만으로는 언제인지 알 수 없어서, 날짜와 시각을 골라야 넣을 수 있다 |
| **06 · 시각 고르기** | 초안은 `all_day: true` 로 온다 — **"하루 종일" 을 끄면** 시·분 상자가 선다. 🚨 시만 고르면 "몇 분인지도 골라주세요" 가 뜨고 **버튼은 계속 잠겨 있다**(9시를 9:00 으로 접지 않는다) · 🚨 껐다 켜도 고른 시각이 살아 있다 |
| 06 · 잠긴 이유가 여럿 | 날짜(+ 시각)가 안 끝나면 버튼 위에 **막는 줄이 다 선다** — 하나씩 말하면 채운 뒤에야 다음 관문을 알게 된다. ⚠️ 재료 확인은 여기 없다(채택할 때 끝난다) |
| 05 · 재료 확인은 `food` 만 | `activity` 제안(물놀이장)만 고르면 확인 시트가 **안 뜨고 바로 채택된다** — 사전검사는 서버가 붙인다 |
| 07 기록 · 기억 | `/child/c1/memories` (`?tab=profile` · `?tab=feedback` · `?domain=food`) |
| 08 사진으로 적기 | 03 홈의 카메라 버튼 → 시트에서 **어떤 사진인지 고르고** → 최근 사진·촬영·앨범 |
| 08 · 알림장으로 읽기 | 시트에서 "알림장·식단표" 를 고른다 (아무 이미지 파일이나 넣으면 된다) |

🚨 **`consent` 시나리오에서만 아이가 0명이다.** 목의 `/me` 는 다른 시나리오에서 늘 아이 1명을
돌려주고, 00-1 과 초대 화면은 **아이가 없는 계정에서만** 선다 (있으면 홈으로 되돌린다).

(`mocks/handlers/membership.ts`). 새로고침해도 유지되고, 탭을 닫으면 사라진다.

🚨 **초대 실패는 시나리오가 아니라 입력값으로 갈린다.** 만료·재사용·중복 등록은 실서버에서도
그냥 일어나는 일이라, 시나리오로 만들 이유가 없다 (08 의 두 lane 과 같은 판단).

화면만 빨리 보려면 값을 직접 심어도 된다. 🚨 **`bind` 를 빼면 화면은 떠도 제출이 400 이다** — 서버가 형식을 검증하는 게 정상 동작이다.
