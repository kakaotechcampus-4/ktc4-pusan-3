# 웹 푸시 v1 (#609 FE-3)

일정 알림을 브라우저로 받는 길이다. 서버 쪽 결정(알림 값, 발송 배치, 기기를 로그인에 묶기)은
[`docs/notification/reminder-v1.md`](../notification/reminder-v1.md) (#610 에서 생긴다) 에 있고, 여기에는 **웹이 받는 쪽**만 둔다.
안드로이드 앱은 웹뷰에 Push API 가 없어서 이 길을 쓰지 않는다 — 셸이 네이티브 토큰을 넘긴다 (아래 "앱" · FE-4).

## 결정

| | 결정 | 이유 |
| --- | --- | --- |
| 켜고 끄기 | Firebase 값 다섯 개(`NEXT_PUBLIC_FIREBASE_*`)를 **다 넣으면 켜지고 다 비우면 꺼진다.** 일부만 넣으면 부팅(빌드)이 멈춘다. 이 값은 **묻고 넘기기** 스위치이고, 토큰을 **저장할지**는 서버 `PUSH_DEVICE_ACCEPT` 가 정한다 (아래 "켜는 순서") | 값이 없는 팀원 로컬 · CI · 운영이 정상이다. 하나를 빠뜨려 조용히 꺼지는 것은 막는다 |
| 서비스 워커 | 직접 쓴 `public/push-sw.js`. **Firebase 를 불러오지 않는다** | Firebase 워커 SDK 는 알림 클릭을 가로채고(`stopImmediatePropagation`) 메시지에 `fcm_options.link` 가 없으면 아무 데도 열지 않는다(`@firebase/messaging` 0.13.3 `onNotificationClick`). 서버는 웹 주소가 아니라 `data` 만 싣는다(#610) — 라우트는 웹이 안다 |
| 워커 범위 | `/push/` (페이지를 다스리지 않는다) | `/` 로 두면 개발 환경의 목 워커와 같은 자리를 다퉈 한쪽이 밀려난다. 푸시와 알림 클릭은 범위와 상관없이 온다 |
| Firebase 를 쓰는 곳 | 페이지에서 **토큰을 받을 때만**(`getToken`). 등록할 때 동적으로 불러온다 | FCM 등록 API 를 직접 부르면 설치 인증까지 손으로 해야 한다. 알림을 안 쓰는 화면의 번들에는 들어가지 않는다 |
| 권한 묻기 | **처음 알림을 고를 때**(`ReminderField`) | 앱을 열자마자 물으면 무엇에 쓰는지 모른 채 거절한다. 브라우저는 한 번 거절하면 다시 묻지 못한다 |
| 기기 등록 | 로그인이 살아날 때마다(앱 실행 · 로그인 직후) **이미 허용한 브라우저만** `PUT /me/push-device`. 같은 로그인에 같은 토큰은 한 번 | 기기는 로그인에 묶여 만료되면 지워진다(#605). 토큰이 바뀌면 그때 새 토큰이 나간다. 로그아웃 때 따로 지우지 않는다 — 서버가 지운다 |
| 탭을 보고 있을 때 | 그래도 **시스템 알림을 띄운다** | 화면 안에서 알리려면 토스트인데, 토스트는 "조용히 되돌아간 실패" 에만 쓴다 (apps/web/CLAUDE.md §3) |
| 알림을 누르면 | 그 아이의 그날 09 캘린더(`/child/{child_id}/calendar?date={date}`). 열린 탭이 있으면 그 탭을 앞으로 가져와 옮기고(`WebPushBridge`), 없을 때만 새 탭 | 워커가 다스리지 않는 탭이라 `navigate()` 를 못 부른다 — 메시지로 갈 곳을 보낸다. `data` 는 모양을 본 값만 주소에 쓴다 |
| 실패 | 아무 말 하지 않는다. 일정 제출 · 알림 고르기는 그대로 된다 | 알림은 덤이다. 토큰이 섞일 수 있어 로그에도 남기지 않는다 |
| 토큰이 남는 곳 | **우리 코드는** 토큰을 메모리에만 들고(같은 토큰을 다시 보내지 않으려고) 로그 · 웹 저장소 · 에러 리포트에 쓰지 않는다. **Firebase SDK 는** 브라우저 단위로 IndexedDB(`firebase-messaging-database` · 설치 id)에 둔다. 로그아웃 때 `deleteToken` 을 부르지 않는다 | 서버가 기기 행을 로그인과 함께 지워서 그 토큰으로는 더 오지 않는다. 지우면 같은 브라우저의 다음 로그인이 새 토큰을 받느라 늦어질 뿐 얻는 것이 없다 |
| 로그아웃 중 등록 | 토큰을 받는 사이 로그아웃했으면 보내지 않는다 | 토큰 없이 나간 요청이 401 을 맞으면 세션 만료 처리(로그인 화면으로)가 한 번 더 돈다 |

## 켜는 순서 (운영)

스위치가 둘이다 — 서버의 **저장**(`apps/api/.env` 의 `PUSH_DEVICE_ACCEPT` · #610)과 웹의 **묻고 넘기기**(`deploy/docker/.env` 의 Firebase 값 다섯 개).
기기 토큰은 별도 동의 없이 처리방침에 적고 받기로 했다 (10-28 PM · #605 · 개인정보 보호법 제15조 ①항 4호).

1. 기기 토큰이 실린 **처리방침 새 판**을 게시한다
2. 서버 `PUSH_DEVICE_ACCEPT=true` — 이때부터 기기를 저장한다
3. 웹 Firebase 값을 넣고 **이미지를 다시 굽는다** — 이때부터 보호자에게 권한을 묻고 토큰을 넘긴다

🚨 **3을 2보다 먼저 하지 않는다.** 서버가 받지 않는 동안에도 권한 창은 뜨고 등록 요청은 204 로 끝나서, 허용한 보호자에게
알림이 오지 않는다. 화면은 앱을 켤 때마다 다시 등록하므로 순서가 엇갈려도 다음 실행부터는 들어가지만, 그 사이 알림은 빠진다.

## 🚨 규칙

- **서비스 워커에 Firebase 를 넣지 않는다.** 위 표의 "서비스 워커" 줄이 이유다
- **워커 범위를 `/` 로 바꾸지 않는다** (`/push/`). 목 워커와 자리를 다툰다
- **권한은 처음 알림을 고를 때만 묻는다** (`shouldAskWebPush` · `ReminderField`). "없음" 을 고를 때 · 앱을 켤 때는 묻지 않는다.
  브라우저는 한 번 거절하면 다시 묻지 못해서 되돌릴 수 없다 (`src/lib/push/web-push.test.ts`)
- **우리 코드는 FCM 토큰을 로그 · 웹 저장소 · 에러 리포트에 쓰지 않는다.** SDK 가 IndexedDB 에 두는 것은 위 표
- **Firebase 는 토큰 받기 한 곳에만 쓴다** (`lib/push/web-push.ts`). 다른 Firebase 기능(분석 · 원격 설정)을 붙이지 않는다

## 앱 (안드로이드 셸 · FE-4)

| | 결정 | 이유 |
| --- | --- | --- |
| 토큰 | **셸이 기기의 FCM 토큰을 받아 웹에 넘기고, 등록은 웹이 한다** (`platform: "android"`) | 셸은 API 를 부르지 않는다 (`apps/mobile/CLAUDE.md` §1). 등록 규칙(같은 토큰은 한 번, 로그아웃 중엔 안 보냄)이 브라우저와 한 곳에 있다 |
| 창구 | 웹 → 셸 `window.icatch.push` 의 `ready` · `sync` · `ask`, 셸 → 웹 `icatch:push` 의 `token` · `open` (`lib/native/push.ts` ↔ `apps/mobile/src/native/push.ts`) | 말로 적기(#595)가 연 창구에 `kind: "push"` 를 더했다 |
| 스위치 | **앱도 웹의 Firebase 값(`FIREBASE_WEB`)을 따른다.** 비어 있으면 앱에서도 묻지도 넘기지도 않는다 | 묻는 스위치가 웹 배포 한 곳이라 스토어 업데이트 없이 켜고 끈다. 저장은 서버 `PUSH_DEVICE_ACCEPT` 가 앱 · 웹 모두 막는다. 앱의 `google-services.json` 은 "받을 수 있는 빌드인가" 일 뿐 켜는 스위치가 아니다 |
| 권한 묻기 | 웹과 같이 알림을 고를 때. 셸은 **허용 전이고 OS 가 다시 물을 수 있을 때** 창을 띄운다(`shouldAskPermission` · `canAskAgain`) — 많아야 두 번 | Android 13+ 는 한 번도 묻지 않았어도 `"denied"` 로 와서 `"undetermined"` 로는 가를 수 없다(실기기 확인). 두 번 거절하면 OS 가 막는다. 한 번 거절한 보호자도 다시 켤 길이 있다 — 브라우저(한 번 거절하면 끝)와 다른 점이다 |
| 알림 띄우기 | OS(FCM)가 띄운다. 앱을 보고 있을 때도 띄운다(`setNotificationHandler`). 채널은 `schedule`("일정 알림") | 웹과 같은 이유(토스트 규칙). FCM 이 앱 밖에서 띄우는 알림은 `defaultChannel` 로, 앱을 보고 있을 때 온 알림은 서버가 싣는 `android.notification.channel_id: "schedule"`(#610)로 같은 채널을 쓴다. 🚨 채널 id 를 바꾸면 서버 `ANDROID_CHANNEL` 도 같이 바꾼다 — 없으면 영문 기본 채널로 간다(실기기 확인) |
| 창구 켜기 | 셸은 `google-services.json` 이 들어간 빌드에서만 창구를 켠다(`available`) | 설정 없이 켜 두면 권한 창을 띄운 뒤에야 토큰 받기가 실패한다 |
| 누르면 | 셸이 data 로 주소를 만들어(`pushOpenPath`) 웹에 `open` 으로 넘긴다. 앱이 알림으로 열렸으면 웹이 `ready` 를 보낼 때까지 들고 있다. 웹은 받은 주소를 `lib/push/open-path.ts` 모양으로 다시 본다 | 그 순간에는 웹이 아직 안 떠 있다. data 는 모양을 본 값만 쓴다 — 워커 · 셸 · 웹이 같은 모양을 따로 들고 있어 셋을 같이 고친다 |
| `google-services.json` | 저장소에 두지 않는다. EAS 는 파일 환경변수 `GOOGLE_SERVICES_JSON`, 로컬은 `apps/mobile/google-services.json`(`.gitignore`). 없으면 알림만 꺼진 빌드 (`app.config.ts`) | 저장소가 public 이다 |

## 값

[`apps/web/.env.example`](../../apps/web/.env.example) 에 어디서 가져오는지 적혀 있다. 공개 식별자라 번들에 들어가도 된다
(최상위 CLAUDE.md §9 의 예외). 저장소가 public 이라 **값은 저장소에 쓰지 않는다** — 로컬은 `.env.local`, 배포는
`deploy/docker/.env`. 빌드 인자라 바꾸면 이미지를 다시 굽는다 ([`toolchain-deploy-v1.md`](toolchain-deploy-v1.md) §4).

🚨 **웹 푸시 인증서(VAPID 키 쌍)는 새로 만들지 않는다.** 바꾸면 그 전에 받은 웹 토큰이 모두 맞지 않는다.

## 확인하지 못한 것

- iOS Safari 는 홈 화면에 추가한 웹앱에서만 웹 푸시를 받는다. iOS 는 하지 않기로 해서(#594) 확인하지 않는다.
- 브라우저에서 권한을 거절한 보호자에게 알림 칸 아래 안내를 둘지 (#609 "정할 것").
