- 단계 정의는 화면마다 `apps/web/src/lib/tour/screens/<화면>.ts` 한 파일이다. 덮개와 ? 버튼은 `components/screen-tour.tsx`
- 화면은 비출 요소에 `data-tour="<이름>"` 을 단다. `Card` · `Section` · `SectionAction` · `EmptyState` · `SettingsInfoRow` 는 그 속성을 받는다
- 설정 › 고객센터의 **화면 설명 다시 보기**가 모든 화면의 "봤음" 을 지운다. 지금 화면에 바로 띄우지 않고 다음에 들어갈 때 뜬다

## 2. 정한 것

- **"봤음" 은 서버의 별도 테이블에 계정 · 화면 단위로 둔다** (백엔드와 합의). 엔드포인트가 아직 없어서 지금은 기기(`localStorage`)에 둔다. 서버가 생기면 `lib/tour/seen.ts` 의 `readSeen` · `writeSeen` · `clearSeen` 셋만 바꾼다. 화면은 훅만 안다
- **그만 봐도 본 것이다.** "다 봤어요" · "그만 볼래요" · Esc 모두 같다. 화면을 떠나서 닫힌 것은 본 것이 아니다
- 🚨 **"건너뛰기" 라고 쓰지 않는다.** 이 단계 하나만 넘기는 것으로 읽혀서 헷갈렸다 (사용자 피드백). 남은 설명 전체를 끝낸다는 말로 쓴다. 마지막 단계에는 없다
- **가입 직후 홈은 빈 상태 단계만** (`home-empty`). 첫 기록이 생긴 뒤 홈에 다시 오면 `home` 이 뜬다. `home` 의 입력창 단계는 `home-empty` 를 봤으면 빠진다 (`skipIfSeen`)
- **화면이 바뀌어도 다시 띄우지 않는다.** 투어 버전 숫자를 두지 않는다. 🚨 그래서 **투어 이름(`TourKey`)을 바꾸지 않는다** — 바꾸면 이미 본 사람에게 다시 뜬다
- **초대받은 보호자도 같은 투어다.** 따로 갈래를 두지 않는다
- **라이브러리 없이 직접 만든다** — `inert` · Esc · 디자인 토큰 · 즉시 스크롤 · 페이드 교체를 라이브러리 위에 덮어쓰는 쪽이 더 컸다

## 3. 움직임 규칙

- 한 번에 한 곳만 비춘다. 나머지는 시트와 같은 `--color-scrim` 으로 덮는다. 구멍은 요소의 모서리를 따라간다 (동그란 버튼은 동그랗게)
- 화면당 6단계 이하. **자동으로 뜬 투어에만** 마지막 "다시 보고 싶을 때" 단계(? 버튼)가 붙는다
- 🚨 **비출 요소가 없으면 그 단계를 빼고 분모도 줄인다.** 예시 데이터로 채우지 않는다 — 기록이 없는데 기록 카드를 띄우면 우리 아이를 아는 척하는 화면이 된다 (최상위 CLAUDE.md §2 기억)
- 🚨 **설명할 단계가 하나도 없으면 열지 않는다** — ? 안내 한 단계만 띄우지 않는다. 본 것으로도 치지 않는다. 실서버 05 에서 식사가 막히고(영아 · guard) 아무 제안도 없을 때 "다시 보고 싶을 때" 만 떴었다
- 🚨 **받은 즉시 열지 않는다.** 받은 내용은 `Swap` 이 스켈레톤을 내린 뒤에 그려져서 `ready` 순간에는 비출 것이 DOM 에 없다. 그려질 때까지 최대 1.5초 기다린다
- 🚨 **화면 전환(View Transition) 중에는 띄우지 않는다.** 03 홈 → 04 대화처럼 화면이 밀려 들어오는 동안 열면, 아직 움직이는 화면 위에 구멍이 잠깐 서서 엉뚱한 곳을 짚는 것처럼 보인다 (사용자 피드백). `:active-view-transition` 이 풀린 뒤에 연다
- 시트가 열려 있으면 띄우지 않는다
- 🚨 **바깥을 눌러도 닫히지 않고, 비춘 요소도 눌리지 않는다.** "확인하고 넣기" 를 설명하다 승인 시트가 열리면 안 된다. 닫는 길은 그만 볼래요 · 다 봤어요 · Esc
- 🚨 **단계 사이에 덮개는 그대로다.** 말풍선만 `--motion-swap`(90ms) 동안 사라졌다가 새 자리에서 선다. 구멍은 그 사이에 다음 요소로 바로 옮긴다. 덮개까지 같이 투명하게 하면(예전) 화면 전체가 단계마다 밝아졌다 어두워져 깜빡인다 (사용자 피드백). 구멍이 다음 요소 크기로 늘어나며 옮겨가지 않는다 (디자인 시스템 §8 "높이 · 크기를 움직이지 않는다"). reduced-motion 이면 `globals.css` 가 즉시로 만든다
- 화면 밖 요소는 즉시(`behavior: "instant"`) 스크롤해서 비춘다
- 같은 `data-tour` 가 여럿이면 첫 번째를 비춘다. 04 대화는 단계에 `within: "turn"` 을 달아 **가장 최근 턴 하나** 안에서만 찾는다 — 단계마다 따로 "마지막" 을 고르면 말풍선은 마지막 턴, 저장 결과는 그 앞 턴을 비추며 스크롤이 튄다. 그 턴에 없는 단계는 빠진다
- 구멍은 창 크기와 요소 크기가 바뀔 때마다 다시 잰다 (늦게 오는 글꼴 · 들어오는 움직임)
- 모양(덮개 · 구멍 · 말풍선)의 사양은 [디자인 시스템 §7 "화면 투어"](design-system-v1.md) 다

## 4. 문구 규칙

- 화면에 적힌 이름 그대로 부른다 — 기록/기억, 제안 후보, 확인하고 넣기. Agent · Memory · run 같은 안쪽 말을 쓰지 않는다
- AI 가 하는 일을 부풀리지 않는다. 무엇을 근거로 하는지, 무엇은 확인을 받은 뒤에만 되는지를 말한다
- 🚨 키 · 몸무게에 평가 말을 쓰지 않는다 — "잘 크고 있어요", "또래보다", "정상" (최상위 CLAUDE.md §2 개인정보)
- 🚨 알레르기 단계는 화면에 이미 있는 문장("AI 는 이 목록을 만들지도 고치지도 못해요")을 그대로 쓴다
- 승인 게이트는 여는 버튼까지만 가리키고 시트 안은 비추지 않는다. `caution` · `danger` · 도메인 색을 쓰지 않는다
- ⚠️ 상한 6단계에 "다시 보고 싶을 때" 단계는 세지 않는다 — 자동으로 뜬 투어에만 붙는 꼬리라서다

## 5. 접근성 · 셸

- 네이티브 `<dialog>` 의 `showModal` 위에 얹는다 — 뒤는 `inert`, 포커스는 말풍선 안에 갇힌다. 단계가 바뀌면 포커스가 제목으로 간다
- 화면 읽개에는 "6단계 중 2단계" 로 읽힌다
- ⚠️ **Android 뒤로가기는 아직 투어를 닫지 못한다.** 셸이 웹에 뒤로가기를 넘기는 창구가 없다 (`apps/mobile/App.tsx` 가 `onMessage` 를 받지 않는다). 하위 화면에서는 화면째 돌아가고(투어는 안 본 채로 남는다), 탭 화면에서는 종료 확인 토스트가 뜬다. 셸 창구가 생기면 그때 붙인다

## 6. 테스트

- `e2e/screen-tour.spec.ts` 가 자동 시작 · 그만 보기 · Esc · 누르기 막힘 · 빈 홈 · 다시 보기를 건다. 🚨 "봤음" 은 화면에 안 뜨는 것만 보지 말고 **저장소에 남았는지**(`seenTours`)를 먼저 본다 — 안 뜨는 것은 저장이 깨져도 잠깐은 성립한다
- `lib/tour/steps.test.ts` 가 어느 단계를 보여 줄지(빠지는 단계 · ? 안내는 자동에만 · 설명할 것이 없으면 안 연다 · `skipIfSeen`)를 건다
- 🚨 **다른 e2e 는 투어를 다 본 채로 시작한다** (`e2e/fixtures.ts` 의 `toursSeen`). 없으면 처음 들어온 화면마다 덮개가 떠서 모든 누르기가 막힌다. 새 투어 이름을 더하면 `TOUR_KEYS` 에도 더해야 이 바탕이 그 투어를 심는다

## 7. 화면이 바뀌면

화면에 구역을 더하거나 빼면 **같은 PR 에서** 투어를 맞춘다. Claude Code 에서는 `/screen-tour` 스킬(`.claude/skills/screen-tour/`)이 이 절차와 실서버 확인 스크립트를 들고 있다.

1. 새 구역이 보호자가 처음 보고 헷갈릴 자리면 그 요소에 `data-tour` 를 달고 `lib/tour/screens/<화면>.ts` 에 단계를 더한다. 6단계를 넘으면 덜 중요한 단계를 뺀다
2. 지운 구역의 단계는 지운다. 남겨도 화면에서는 빠지지만, 정의와 화면이 어긋난 채로 남는다
3. 이름이 바뀐 구역은 단계 문구도 화면 글자에 맞춘다 (§4)
4. 새 화면에 투어를 붙이면 `TourKey` · `TOUR_KEYS` 와 §1 표에 더한다. 기존 투어 이름은 바꾸지 않는다 (§2). ⚠️ 스모크(`.claude/skills/web-smoke/smoke.mjs`)도 투어 이름을 손으로 들고 있어 같이 고친다
5. 실제 화면에서 그 투어를 한 번 끝까지 넘겨 본다 — 비출 요소가 그려지는 조건(`ready`)이 맞는지는 목보다 실서버에서 드러난다
