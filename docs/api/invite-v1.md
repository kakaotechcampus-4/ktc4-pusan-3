## 2. 왜 링크가 아닌가

**⚠️ 먼저 정정** — "링크는 카카오 OAuth 왕복을 못 넘긴다" 는 **사실이 아니다.** 프론트는 이미 `bind`·`provider`·`consent_code` 를 `sessionStorage` 로 왕복시키고 있어서(`auth-kakao-v1.md` §5-6) 토큰 한 줄 더 넣는 것은 된다. 그 이유로 코드를 고른 게 아니다.

**① 진입 브라우저를 통제할 수 없다.** 카톡으로 보낸 링크는 **인앱 브라우저**에서 열린다. 거기서 카카오 로그인이 카카오톡 앱으로 넘어갔다 돌아오면 같은 탭 세션이라는 보장이 없고, `sessionStorage` 가 날아가면 **초대 토큰만이 아니라 `bind` 까지 잃는다** — 그러면 초대가 아니라 **로그인 자체가 깨진다** (`bind` 가 없으면 1회용 코드를 세션으로 바꿀 수 없다).

**② 앱 딥링크 설정이 필요해진다.** `https://` 링크를 눌러 `apps/mobile` 웹뷰 셸로 들여보내려면 universal link / app link(`apple-app-site-association` · `assetlinks.json` · 도메인 검증)를 세워야 한다. 10주 안에 넣을 물건이 아니다.

**③ 입력 화면 하나를 두 곳에서 쓴다.** 초대를 받는 사람이 신규 가입자라는 보장이 없다 — 이미 쓰고 있는데 아이가 없는 보호자도 있다. 링크였다면 로그인/비로그인 두 갈래를 다 처리해야 한다. 코드는 **로그인을 끝낸 뒤 입력**하므로 왕복에 실어 보낼 상태가 하나도 없다.

> 🔶 **링크는 나중에 코드의 상위 호환으로 붙일 수 있다** — `/i/{code}` 가 코드 입력칸을 프리필하는 편의 기능이 되고, 아래 엔드포인트는 그대로다. 지금 코드로 고정하는 것이 그 길을 막지 않는다.

## 3. 엔드포인트

경로·시간 표기는 [계약서 §01](./api-interface-v1.html)을 따른다. **세 개 모두 `Bearer` 를 요구한다** — 무인증 예외 5개(`auth-kakao-v1.md` §3)를 늘리지 않는다.

### 3-1. `POST /children/{cid}/invites` — 발행 (owner 전용)

**요청 `{}`**

🚨 **`relation` 을 받지 않는다.** 아이와 어떤 사이인지는 **받는 쪽이 자기 입으로 말할 값**이다 — 보내는 사람이 미리 찍으면 잘못 찍었을 때 받는 쪽이 자기 프로필을 고치러 가야 하고, 그 값은 기록마다 "누가 적었나" 로 남는다 (#89 → #96).

```json
// 응답 201
{ "invite_code": "MKGRAND1", "expires_at": "2026-09-23T00:00:00+09:00" }
```

부를 때마다 **새 코드**다. 여러 명을 초대하려면 그만큼 발행한다.

### 3-2. 🔶 `GET /invites/{code}` — 수락 전 확인 (협의 대상)

받는 사람이 **어느 아이에 붙는지 보지 못한 채로 연결되는 것**을 막는다. 코드는 카톡으로 오가는 여덟 글자라 잘못 받아 적거나 남에게 갈 코드를 받을 수 있는데, 붙고 나면 되돌리는 길이 "설정에서 연결 끊기" 뿐이고 **그 사이에 아이의 기록과 건강 정보를 다 본다.** 되돌릴 수 없는 것은 아니지만 **보고 나서 되돌릴 수는 없다.**

```json
// 응답 200
{
  "child": { "nickname": "…", "age_display": "만 4세" },
  "invited_by": { "nickname": "…" },
  "expires_at": "2026-09-23T00:00:00+09:00"
}
```

- 🚨 **코드를 소비하지 않는다.** 확인만 하고 그만둔 사람의 코드가 닫히면 1회용이라 다시 받아야 한다. 소비는 §3-3 하나만 한다.
- 🚨 **건강·알레르기를 내리지 않는다.** 아직 `parent_child` 행이 없는 사람이고, 코드만 알면 누구나 부를 수 있는 창구다 — 별명·나이와 초대한 보호자 별명까지다 (NF-04 최소 수집).
- 🚨 **§4 의 시도 제한에 함께 걸린다.** 코드를 소비하지 않고 계정 상태도 보지 않아서 **수락보다 더 좋은 추측 도구**다. 여기만 열려 있으면 제한이 있으나 마나다.

### 3-3. `POST /invites/{code}/accept` — 수락

```json
// 요청 — relation 은 선택. 안 고르면 필드를 빼고 보낸다
{ "relation": "sitter" }
```

```json
// 응답 200
{ "child_id": "c1", "nickname": "…", "age_display": "만 4세", "role": "member" }
```

`parent_child` 행 생성 + `invite.used_at` · `used_by` 기록. 🚨 **승인 대기 상태가 없다** — 수락하면 바로 연결된다 (계약서 §04 `GET /me`).

🔶 응답 모양은 협의 대상이다. 화면이 수락 뒤 그 아이 홈으로 가야 해서 `child_id` 가 필요하다 — 없으면 `GET /me` 를 한 번 더 부른다.

## 4. 코드 형식과 시도 제한

**Crockford Base32** — `0123456789ABCDEFGHJKMNPQRSTVWXYZ`. 사람이 옮겨 적다 헷갈리는 `I` · `L` · `O` · `U` 가 빠져 있다.

- 화면은 `ABCD-1234` 로 끊어 보여주고, **보낼 때는 정규화한 값**이다. 하이픈이 섞여 나가면 서버에서 없는 코드가 된다.
- 정규화는 대문자화 + 하이픈·공백 제거 + 혼동 문자 **치환**(`O`→`0`, `I`·`L`→`1`). 버리지 않고 옮긴다 — 0 을 O 로 받아 적은 사람에게 틀렸다고 말하지 않는다.
- 서버는 정규화한 값을 **해시로** 저장한다 (`session` · `auth_handoff` 와 같은 원칙 · `auth-kakao-v1.md` §7-4).
- 클라이언트 쪽 절반은 [`apps/web/src/lib/invite-code.ts`](../../apps/web/src/lib/invite-code.ts) 다.

### 🚨 시도 제한 — 이 선택의 전제다

8자는 **40비트**라 제한이 없으면 긁을 수 있다. 링크(128비트 토큰)에는 없던 요구사항이고, **이게 없으면 코드로 바꾼 것이 그대로 취약점이 된다.**

- 호출자 기준 실패 **N회/시간**을 넘기면 `429`.
- 🚨 **§3-2 와 §3-3 이 같은 통을 쓴다.** 확인 쪽이 더 좋은 추측 도구라, 따로 세면 막은 것이 아니다.
- 🔶 N 과 기준 키(`parent_id` 인지 IP 인지)는 백엔드가 정한다. 프론트 목은 **5회**로 두고 회귀 테스트를 걸어 뒀다.

## 5. 🔶 에러

이름은 프론트 제안이다. 다르게 정하면 화면 문구를 그 이름으로 맞춘다.

| 코드 | 상태 | 언제 | 화면이 하는 말 |
| --- | --- | --- | --- |
| `invite_not_found` | 404 | 없는 코드 | 받은 코드를 다시 확인해 주세요 |
| `invite_used` | 409 | 이미 쓴 코드 | 초대한 분에게 새 코드를 받아 주세요 |
| `child_already_exists` | 409 | 이미 아이가 있는 보호자가 수락 | 한 보호자는 아이 한 명만 등록할 수 있어요 |
| `invite_expired` | 410 | 기한 만료 | 초대한 분에게 새 코드를 받아 주세요 |
| `too_many_attempts` | 429 | §4 시도 제한 | 잠시 후에 다시 시도해 주세요 |

🚨 **중복 등록은 §3-2(확인) 에서 먼저 막는다.** 수락에서야 막으면 **연결되지 않을 아이의 별명·나이를 보여준 뒤에** 거절하는 꼴이 된다.

## 6. 계약서 §05 와 달라진 것

| | `api-interface-v1.html` §05 (동결) | 이 문서 |
| --- | --- | --- |
| 발행 응답 | `invite_url: "https://.../i/AbC123"` | `invite_code: "MKGRAND1"` |
| 수락 경로 | `POST /invites/{token}/accept` | `POST /invites/{code}/accept` |
| `relation` | 발행 요청에 싣고 수락자에게 프리필 | **발행 요청은 `{}`**, 수락 요청이 싣는다 |
| 확인 | 없음 | 🔶 `GET /invites/{code}` 신설 |
| 시도 제한 | 없음 | 🚨 필수 (§4) |
