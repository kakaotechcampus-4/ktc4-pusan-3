# 삭제 제안 — 대화로 지울 때 사람이 버튼으로 확정한다 (#535)

모양(필드 · 오류 코드)의 정본은 Swagger 다. 여기는 Swagger 가 담지 못하는 흐름과 이유만 적는다.

## 왜

대화로 "저번주 기록 지워줘" 하면 예전에는 AI 가 "N건 지울까요?" 라고 묻고, 보호자가 채팅으로 "응" 하면
삭제 tool 을 한 건씩 불러 지웠다. 세 가지가 걸렸다.

- 보호자는 무엇이 지워지는지 보지 못하고 건수와 AI 문장만 보고 답했다.
- "응/아니" 를 모델이 해석했다. 모델 입력을 조금 바꿨을 때 "아니, 그냥 둬" 에도 지워졌다 (D16).
- 30건이면 삭제 tool 을 30번 불렀다.

지운 기록은 되살릴 수 없다 — 루트 §2 "되돌릴 수 없는 것은 사람이 승인한다" 의 자리인데, 채팅 확인은 모델의
해석이라 게이트가 아니었다. 비어 있던 게이트를 채운다 (11-03 팀 회의). §2 문구도 승인 게이트 3곳(㉢ 삭제 확정)으로 고쳤다.

## 흐름

```
보호자  "저번주 식사 기록 중에 간식은 빼고 지워줘"
AI      조회 → 제안 tool 로 후보와 기본 체크를 남긴다 (지우지 않는다)
        └ Memory commit 때 delete_proposal 1행이 함께 저장된다
SSE     delete_proposal { proposal_id, status: pending, expires_at, result: null, tabs: [{kind, truncated, records, events, picked_ids}] }
보호자  체크를 고치고 [N건 삭제하기] → 한 번 더 확인
화면    POST /children/{cid}/delete-proposals/{pid}/confirm  { ids }  + Idempotency-Key
서버    후보 안의 체크한 것만 한 트랜잭션에서 지운다 → 관찰을 지웠으면 Curator
```

- **AI 는 지우지 않는다.** 삭제는 버튼 API 한 곳뿐이다. 제안을 남긴 run 은 되묻기가 아니다 — 다음 채팅은
  제안을 모르는 새 run 이고, 채팅으로 "응" 해도 지워지지 않는다.
- **후보 밖은 하나도 지우지 않는다.** 체크한 id 가 하나라도 후보 밖이면 422 이고 아무것도 지우지 않는다.
  지우기는 AI 가 쓰던 것과 같은 store 함수다 — 관찰은 soft delete 와 Profile 재계산, 일정은 준비물까지.
  store 가 아이로 다시 거른다.
- **후보는 모델이 본 것까지다.** 탭마다 최근 40건 — 사람이 한 화면에서 보고 판단할 수 있는 양이다. 잘린
  탭은 `truncated` 로 알리고, 보이지 않던 기록은 후보가 아니라 지워지지 않는다.

## 누가 누르나

**제안한 보호자만.** 대화는 보호자마다 따로라 다른 보호자에게는 그 카드가 없다 — 남의 제안은 없는 것과 같은
404 다. 기록 · 일정을 지우는 권한 자체는 owner · member 가 같다(둘 다 자기 대화에서 요청하면 자기 카드가
생긴다). 아이 연결이 끊기면 자기 제안이라도 403 이고, 연결 끊기는 대화 기록과 함께 제안도 지운다.

## 상태와 만료

| 상태 | 뜻 | 버튼 |
| --- | --- | --- |
| `pending` | 결정 전 | 확정 · 취소 가능 |
| `deleted` | 지움. `result` 에 종류별 실제 지운 건수 | 409 `proposal_closed` |
| `cancelled` | 취소 | 확정은 409, 다시 취소하면 같은 응답 |
| `expired` | 24시간이 지난 `pending` — 저장하지 않고 읽을 때 판정 | 409 `proposal_expired` |

- 만료를 배치로 바꾸지 않는다 — 배치가 늦거나 멈춰도 만료된 제안으로는 지울 수 없다.
- 행을 잡고(FOR UPDATE) 판단한다. 같은 키로 겹쳐 와도 뒤의 것은 처음 응답을 받는다.
- 그사이 다른 경로로 지워진 후보는 `result` 에 세지 않는다.

## 지난 대화

대화 기록에는 제안 id 하나만 남긴다(조회 카드는 탭마다 (종류, id) 만). 지워 달라고 한 내용의 사본을 대화 표에
따로 두면 삭제가 무의미해지기 때문이다. 지난 대화를 열면 지금 상태로 그린다 — 결정 전이면 후보와 버튼을
그대로, 끝났으면 상태와 건수로 한 줄 요약("식사 30건 · 놀이 12건을 삭제했어요" · 취소 · 만료)만.

## 범위 밖

- 준비물(일정 안 항목) 삭제 — 지금처럼 채팅 확인. 제안 카드로 옮기는 것은 후속 이슈.
- 수정 — 지금처럼 채팅. 후보를 조회 카드로 보여주기만 한다.
