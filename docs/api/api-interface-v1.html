01공통 규약

엔드포인트마다 반복하지 않는다. 여기 있는 건 전부에 적용된다.

기본

Base/api/v1 · Content-Type: application/json; charset=utf-8
인증Authorization: Bearer <token> — 예외 없음. 인증 없는 엔드포인트를 만들지 않는다 (NF-09)
시간RFC 3339 · 2026-09-05T18:30:00+09:00. 날짜는 YYYY-MM-DD. 나이는 저장하지 않고 서버가 birth_date 로 계산해 age_display 로 내린다
아이 스코프/children/{cid}/* 는 호출자의 parent_child 연결을 매 요청 확인. 없으면 403 child_access_denied
삭제상태 전이가 기본 (inactive · archived · cancelled). 하드 삭제는 health_safety 한 곳뿐 — 아이와 무관해진 안전 정보는 행을 지운다
페이지네이션?cursor=&limit=. 커서는 (observed_to, kind, id) 를 base64 로 인코딩 — 테이블별 uuid 만으로는 4개 테이블 병합 정렬 위치를 복원할 수 없다

Ref — 도메인 간 참조

4개 observation 테이블이 물리적으로 나뉘어 있어 id 만으로는 어느 테이블인지 알 수 없다. 모든 참조는 항상 이 모양이다.

{
  "kind": "observation_activity",
  "id": "o_9f3a"
}

// kind 허용값
// observation_food | observation_health | observation_education | observation_activity
// profile_affinity | health_safety | event | suggestion

에러

{
  "error": {
    "code": "consent_required",
    "message": "아이 건강정보 동의가 필요해요",
    "detail": {
      "scope": "child_health",
      "deeplink": "settings/consent"

Idempotency-Key

중복 실행이 기억을 두 번 쌓거나 캘린더에 두 번 쓰는 엔드포인트에만 필수다. 헤더가 없으면 400.

  • POST /children/{cid}/inputs — 같은 한 줄이 관찰 N건씩 두 번 저장되는 것을 막는다
  • POST /events/{eid}/confirm — 승인 게이트 ㉠
  • POST /children/{cid}/health-safety — 승인 게이트 ㉡
  • POST /children/{cid}/photos · POST /children/{cid}/onboarding

02공통 타입

아래 5개가 화면 대부분을 채운다. 엔드포인트 상세에서는 이름으로만 참조한다.

Observation

공통 컬럼 + 도메인 필드. 도메인 필드는 domain_fields 안에 넣는다 — 4개 테이블을 한 배열로 병합해 내릴 때 키 충돌을 막는다.

{
  "kind": "observation_activity",          // Ref 의 kind 와 같은 값
  "id": "o_9f3a",
  "child_id": "c1",
  "raw_text": "레고로 자동차 만들고 30분 넘게 앉아 있었어",
  "subject": "레고 자동차",                // LLM 추출. health 에는 없음
  "polarity": 1,                           // -1 / 0 / 1
  "strong_signals": [
    "self_initiated",
    "resistance_to_redirect"
  ],
  "confidence_source": "parent_direct",    // institution_notice | parent_direct
                                             // | parent_hedged | parent_hearsay
                                             // "맞아요" 교정으로 상향된다
  "status": "active",                      // active | inactive
  "observed_from": "2026-09-05",           // observed_range 하한
  "observed_to": "2026-09-05",             // 상한. 무한대 금지
  "observed_label": "오늘",                 // 표시 문구. 서버가 만든다
  "affinity": {
    "id": "a_12",
    "merge_key": "만들기 놀이",
    "state": "candidate"
  },
  "source_writer": {
    "parent_id": "p1",
    "nickname": "지은"
  },
  "source_notice_id": null,
  "domain_fields": {
    "activity": "레고 조립",
    "location": "집",
    "companions": "혼자",
    "duration_min": 35,
    "engagement_level": "high"
  },
  "created_at": "2026-09-05T18:30:00+09:00"
}
🚨 health 는 모양이 다르다

observation_health 응답에는 subject · polarity · strong_signals · affinity 키 자체가 없다 (승격 파이프라인 밖이라 프로필 행이 존재하지 않는다). 프론트는 null 검사가 아니라 kind === "observation_health" 로 분기한다.

  "confidence_source": "parent_direct",
  "status": "active",
  "observed_from": "2026-09-05",
  "observed_to": "2026-09-05",
  "domain_fields": {
    "symptom": ["발열", "콧물"],       // 배열이다
    "severity": "mild",
    "body_part": "얼굴",
    "suspected_trigger": "우유 먹은 뒤",
    "action_taken": "관찰",
    "observed_time": "2026-09-05T07:10:00+09:00"

}

Affinity

observation_count · state_reason · source_refs 는 컬럼이 아니라 서버 파생값이다 (affinity_id 역참조 집계).

{
  "kind": "profile_affinity",
  "id": "a_12",
  "merge_key": "만들기 놀이",               // 사람이 읽는 라벨. 수정 가능
  "domain": "activity",                    // food | activity | education
  "state": "candidate",                   // candidate | confirmed | archived
  "polarity": 1,                           // confirmed 면 NOT NULL
  "strength": 0.42,
  "last_observed_on": "2026-09-04",
  "observation_count": 3,                  // 파생
  "state_reason": "서로 다른 3일에 관찰됐어요",   // 승격 임계값 기준으로 서버가 만든 문구
  "is_stale": false,                      // 6개월 이상 전이면 true (NF-08)
  "source_refs": [
    { "kind": "observation_activity", "id": "o_9f3a" }
  ]
}

04인증 · 동의

로그인과 첫 진입 사이에 동의 단계가 있다. 필수 동의가 비어 있으면 그 아래 어떤 저장도 일어나지 않는다.

POST/auth/{provider}

provider ∈ kakao · apple · google · naver. 서버는 (provider, provider_user_id) 로 auth_identity 를 찾고, 없으면 parent 를 만든다. 이메일·프로필 이미지는 받아도 저장하지 않는다 (NF-04).

요청

{
  "access_token": "..."
}

응답 200

{
  "token": "...",
  "is_new": true,
  "parent": {
    "id": "p1",
    "nickname": null
  },
  "consent_required": [
    "service_terms",
    "privacy_account"
  ]
}

consent_required 가 비어 있지 않으면 프론트는 다른 화면으로 못 넘어간다. 계정 스코프 2건은 보호자마다 각자 1회.

GET/me

아이 목록. role 은 child.owner_parent_id 와 호출자를 비교해 서버가 계산한다.

{
  "id": "p1",
  "nickname": "지은",
  "children": [
    {
      "child_id": "c1",
      "nickname": "민준",
      "age_display": "만 4세",
      "relation": "mother",
      "role": "owner",                    // owner | member
      "consent_required": []
    }
  ]
}

승인 대기 상태는 없다. 초대 링크를 수락하면 parent_child 행이 바로 생기고 즉시 연결된다. 목록에 있는 아이는 전부 조회 가능하고, 권한 차이는 role 뿐이다.

POST/consents저장 전 게이트

append-only. 철회도 withdrawn 행을 추가한다. 현재 상태 = 해당 스코프의 최신 행이 granted 인가.

요청

{
  "scope": "child_health",
  "action": "granted",
  "child_id": "c1",              // 계정 스코프면 생략
  "policy_version": "2026-09-01",
  "guardian_attested": true
}

응답 201

{
  "consent": {
    "id": "cs_4",
    "scope": "child_health",
    "action": "granted",
    "acted_at": "2026-09-05T09:00:00+09:00"
  },
  "effective": {
    "service_terms": true,
    "privacy_account": true,
    "child_basic": true,
    "child_health": true,
    "quality_improve": false
  }
}
🚨 동의는 저장보다 먼저다

child_basic 없이 POST /children → 403. child_health 없이 POST /inputs · /health-safety · Food·Health Agent → 403 consent_required. 동의 시점은 아직 팀 미결(9월 2주)이지만, API 는 "저장 전 차단"으로 먼저 고정한다 — 나중에 풀기는 쉽고, 나중에 조이기는 못 한다.

GET/consents?child_id=c1
