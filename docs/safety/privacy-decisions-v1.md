## 1. 순서 — 왜 이 차례인가

```
[오늘]  3-C  Elice 서면 질의 발송 ────── 리드타임이 가장 길다
[1순위] 결정 4  법정대리인 확인 ───────── 10월 3주 배포 게이트. 9월 말 확정 필수
[2순위] 결정 3-A 전달 범위
          ├─→ 3-B 동의 구조 ──→ 결정 6 (한 쌍)
          ├─→ 2-B 제3자 고지
          └─→ Food 프롬프트 구현 착수 가능
[3순위] 결정 5  탈퇴 유예 ────────────── 리포지토리가 3개일 때 닫으면 싸다
[4순위] 결정 1 · 2-A ─────────────────── 위가 정해지면 기계적으로 따라온다
```

**지금 정하면 공짜, 나중에 정하면 비싼 것이 셋 있다.** 3-A(Food 프롬프트가 아직 미구현), 5(조회 필터를 걸 리포지토리가 아직 3개), 6(사진 API 가 아직 미구현). 이 비대칭이 안 보이면 "나중에 정하자" 를 계속 고르게 된다.

## 결정 2. 삭제 범위 + 제3자 정보

두 개가 한 칸에 들어 있었다. 쪼갠다. 앞은 "어떻게 지우나", 뒤는 **"애초에 받아도 되나"** 라 성격이 다르다.

### 2-0. 이미 정해져 있는 것

삭제 경로는 하나뿐이고, 동의 행의 외래키가 우회를 막는다. 아이·보호자 행을 지우면 관찰·건강·연결·세션이 따라 지워진다. 임베딩은 같은 행의 컬럼이라 따로 지울 것이 없다. 기록을 남긴 보호자만 탈퇴하면 기록은 남고 작성자 연결만 끊긴다. 자세한 근거는 [inventory §6](personal-data-inventory-v1.md).

| | 선택지 | 잠그거나 바꾸는 것 | 비용 |
|---|---|---|---|
| **A** | 행 삭제가 전부 (지금 구조) | 없음 | 0 |
| **B** | A + 비식별 보관 (평가·통계용) | 루트 §9 "테스트 자료에 실제 발화·아이 정보 금지" 와 충돌. **저장소가 공개라 둘 곳이 없다** → 비공개 저장소 신설 | 큼. 10주에 비권장 |

### 3-B. 사용자가 거부할 수 있는가

**PM 이 가장 오래 붙잡을 칸이다.** 필수로 걸면 거부자는 서비스를 못 쓰고, 선택으로 하면 두 갈래 코드가 필요하다.

| | 구조 | 거부한 사용자는 | 분기 코드 |
|---|---|---|---|
| **㉠** | 필수 동의 | **가입 자체가 안 된다** | **0줄** |
| **㉡** | 선택 동의 (가입은 되고 AI 기능만 꺼짐) | 아래 참고 | 많음 |
| **㉢** | 기능별 분리 (급식표 사진만 선택) | 엑셀·한글로 대신 올린다 | 적음 |

**㉠ 이 가장 싸다.** 동의 항목을 하나 추가하면 기존 게이트가 그대로 막는다. 반나절. 단 항목을 추가할 때 **두 곳을 같이 고쳐야 한다** — 안 그러면 DB 제약이 막는다 ([consent/models.py:26](../../apps/api/app/domains/consent/models.py) 주석에 경고 있음). 법적 쟁점은 "필요 최소한을 넘는 동의 강제" 인데, **이 서비스는 AI 처리가 본질적 기능**이라 "서비스 제공에 필수" 가 성립할 여지가 있다. **그 근거 문장을 PM 이 직접 써 둬야 한다.**

**㉡ 의 함정.** 거부한 사용자가 기록을 남기려 하면 어떻게 되나.

| 하위 선택 | 실제 결과 |
|---|---|
| **(i) 막기만 한다** | **거부자가 쓸 수 있는 기능이 0개다.** 기록·관찰·추천·분류가 전부 모델이다. ㉠ 과 결과가 같은데 이탈 지점만 가입 뒤로 밀린다. 사용자 입장에선 더 나쁘다 |
| **(ii) 수동 입력 화면을 준다** | 화면·API·저장 경로를 새로 만든다. **10주에 UI 두 벌은 비현실적** |

게이트를 붙일 자리 자체는 싸다. 관련 라우터가 전부 미구현이라, 인증이 기본값인 지금 패턴을 그대로 복제하면 된다. **진짜 비용은 게이트가 아니라 "거부자가 볼 화면"이다.** (i) 는 선택 동의를 표방한 필수 동의라 **방침 문구와 실제 동작이 어긋난다.**

**㉢ 만 대체 경로가 실재한다.** 엑셀 리더가 이미 있고 모델을 쓰지 않는다. 사진 동의를 거부해도 엑셀·한글로 **같은 결과**를 만든다. 게다가 "키가 없으면 사진 입력만 꺼지고 서버는 뜬다" 는 실패 모양이 이미 구현돼 있어 그대로 재사용한다.

**권고: ㉠ + ㉢.** 문장 처리는 필수, 급식표 사진은 선택. 원칙은 **"대체 경로가 있는 것만 선택으로 만든다"** — 대체 경로 없는 선택 동의는 사용자를 속이는 것이다.

### 3-C. 국외 이전을 어떻게 고지하나

**먼저 알아야 할 것.** 국외 이전이라고 해서 반드시 별도 동의를 받아야 하는 건 아니다. 개인정보보호법 제28조의8 제1항 제3호는 **"계약의 체결 및 이행을 위하여 필요한 처리위탁·보관"** 이면 별도 동의 대신 **아래 다섯을 방침에 공개**하는 것으로 갈음할 수 있게 한다.

1. 이전되는 항목  2. 이전 국가·시기·방법  3. 받는 자의 명칭·연락처  4. 받는 자의 이용목적·보유기간  5. **거부 방법·절차·효과**

아이캐치에서 AI 호출은 서비스 그 자체라 계약 이행으로 볼 여지가 크다. 다만 5번 때문에 **거부 경로가 있어야 하고, 거부하면 무엇이 안 되는지 적어야 한다.** 그래서 3-B 와 묶인다.

| | 선택지 | 전제 | 코드 |
|---|---|---|---|
| **(가)** | Elice 를 수탁자로 보고 위탁만 고지 | **Elice 가 재위탁·국외 이전 사실을 문서로 밝혀야 성립한다. 지금 그 문서가 없다** | 0줄 |
| **(나)** | 실질을 보고 국외 이전으로 고지 | 받는 자와 국가를 적어야 하는데 **"미상" 으로는 법정 기재사항을 못 채운다** | 0줄 |
| **(다)** | **Elice 에 서면 질의 → 답변대로 기재** | 답변 리드타임 | 0줄 |

**셋 다 코드가 0줄 바뀐다. 문구만 바뀐다.** (다)가 유일하게 사실에 기반한 길이고, **PM 이 오늘 당장 할 수 있는 유일한 행동이다.** 답이 오기 전에 나머지를 멈추지 않는다 — (가)든 (나)든 3-A·3-B 는 그대로다.

## 결정 5. 탈퇴 유예기간

### 5-0. 이미 정해져 있는 것

`deleted_at` 칸이 보호자·아이 양쪽에 있다. **보호자 쪽은 이미 쓰이고 있다** — 탈퇴한 계정에 세션을 안 내주고 `404` 로 막는다. 주석이 이유를 적어 뒀다: **"유예기간 N일이 미정이라 그전까지 404 로 막아둔다"** ([deps/auth.py:74-77](../../apps/api/app/api/deps/auth.py) · [routers/auth.py:436-441](../../apps/api/app/api/v1/routers/auth.py)).

즉 **이 결정을 기다리느라 코드가 임시로 막아둔 상태다.** 아이 쪽 `deleted_at` 은 아직 쓰이지 않는다. 지금 실제 삭제는 즉시 완전 삭제다.

### 5-1. 선택지

| | 선택지 | 잠그거나 바꾸는 것 | 지금 / 나중 비용 |
|---|---|---|---|
| **A** | **유예 0일** (즉시 파기) | 실수로 탈퇴하면 복구 불가 → 설정 화면에 경고 필요. 방침에 "즉시 파기, 복구 불가" 명시 | **0 / 0** |
| **B** | 유예 N일 | `deleted_at` 을 채우는 경로 + **모든 조회에 "지워지지 않은 것만" 조건 추가** + 파기 배치 + 로그인 시 복구 분기. "탈퇴하면 세션 전부 삭제" 와 충돌 정리 필요 (유예 중 재로그인을 허용해야 복구 버튼을 누른다) | **중 / 큼** |
| **C** | 데이터는 즉시 비활성, 계정만 복구 | B 의 복잡도에 반쪽 효용 | 비권장 |

**B 의 진짜 비용은 "모든 조회 조건" 이다.** 지금 저장소 코드가 3개뿐이라 싸고, 아이·기록 API 가 붙고 나면 비싸진다. **이 비대칭이 지금 닫아야 하는 유일한 이유다.**

### 5-4. 권한

숫자 자체는 PM 단독. B 를 고르면 **김명성 협의 필수** — 조회 조건이 전 도메인에 걸린다.

**권고: A(0일).** 증빙 경로가 이미 있어 "지웠다는 사실" 은 365일 남는다. 10주에 되돌리기 구조를 전 도메인에 거는 것보다 **설정 화면 경고 한 장이 훨씬 싸다.**

## 9. 운영 주체와 개인정보 보호책임자

처리방침에는 **운영 주체**와 **개인정보 보호책임자의 이름·연락처**를 반드시 적는다 (제30조 제1항 6호). 법적으로 책임지는 것은 **사람 아니면 법인**이라, "아이캐치 팀" 같은 표시명만으로는 채울 수 없다.

**방향 (2026-09-17, PM): 박재형 개인사업자 명의.** PM 이 **이미 사업자등록을 보유**하고 있어 새로 내는 부담이 없다. 이 결정을 위해 만드는 것이 아니므로, 초대제(4-C)와 저울질할 이유도 없어졌다.

처리방침에 들어갈 칸:

```
운영 주체            (상호명)
대표자               박재형
사업자등록번호        ***-**-*****
개인정보 보호책임자    박재형
연락처               (이메일)
```

남은 확인 세 가지. 끝나면 확정으로 바꾼다.

| 확인할 것 | 왜 | 누구에게 |
|---|---|---|
| 기존 사업자의 **업태·종목에 소프트웨어 개발 · 정보통신**이 있는가 | 없으면 홈택스에서 업종을 추가한다 (온라인 · 무료). 처리방침에 운영 주체로 적을 사업자가 서비스와 무관한 업종이면 어색하다. 급하지 않다 | PM 본인 |
| 캠퍼스 프로젝트를 개인사업자 명의로 운영해도 되는가 | 산출물 권리 귀속 규정이 있을 수 있다 | 운영진 |
| 팀원 5인의 코드를 한 사람의 사업자가 운영하는 것에 대한 합의 | 저작권 문제. 캠퍼스 종료 후 계속 운영한다면 더 분명히 해야 한다 | 팀 전체 |

**참고 — 카카오 검수는 아예 필요 없다 (2026-09-18 확인, 이도헌).** 카카오에서 받는 것이 회원번호뿐이라 동의항목 검수 대상이 없다. 회원번호는 로그인하면 항상 제공되고, 닉네임·프로필도 검수 없이 쓸 수 있다. 검수와 비즈 앱 전환이 필요해지는 것은 **이메일 · 전화번호 · 생년월일 · 성별을 카카오에서 받으려 할 때**뿐이다. 지금 구조에서는 해당 없다.

→ 처리방침이 필요한 이유는 카카오가 아니라 **법(제30조)** 이다. 공개 배포하면 카카오와 무관하게 필수다. 아이 별명·생일을 우리 가입 화면에서 받는 것도 카카오가 봐주지 않으므로 우리 처리방침에 정확히 적어야 한다.
