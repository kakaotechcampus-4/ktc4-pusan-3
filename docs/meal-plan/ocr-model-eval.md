# 급식표 OCR — 모델 비교 실험 기록

> 상태: 진행 중 (2026-09 2주차) · 담당: 박재형 · 관련: [ocr-pipeline.md](ocr-pipeline.md) §5 "모델 선택은 인터페이스로 미룬다"

이번 주 목표: **실제 급식표로 모델을 비교해 기본 모델을 정한다.** 결정 기준은 문서 §5 그대로 **정확도**다. 비용은 결정 변수가 아니다(기관당 월 1장).

---

## 1. 측정 방법

| 항목 | 값 |
| --- | --- |
| 입력 | 지자체 어린이급식관리지원센터 공개 배포 급식표 2025-01 ③형(만 1~2세) 1장, 992×1403 px, 기관명 영역 가림 |
| 정답셋 | `apps/api/tests/fixtures/meal_plan_2025_01.json` — 178개 항목, 고해상도 원본과 사람이 대조해 확정 |
| 실행 | `uv run python -m scripts.meal_ocr_eval tests/fixtures/meal_plan_2025_01.jpg --model … --base-url …` |
| 호출 | 1~15일 · 16~31일 **2분할** (게이트웨이 출력 상한 6,000 토큰, 모델 무관) |
| 추론 강도 | medium |

**봐야 할 숫자는 "메뉴 단위 알레르기 번호 일치"** 다. DB 는 메뉴 1개 = 1행이라 이 단위로 맞아야 한다. 끼니 합집합은 한 메뉴에서 번호가 빠져도 옆 메뉴가 가리면 못 잡는다.
원문 일치는 참고용이다. 글자 하나 달라도 번호가 맞으면 서비스엔 문제없고, 그 반대는 문제다.

## 2. 결과 (2026-09-09)

| 모델 | 메뉴 단위 번호 일치 | 끼니 합집합 | 원문(정규화) | 비용/회 | 시간 |
| --- | --- | --- | --- | --- | --- |
| claude-opus-5 | 171/178 (96%) | 62/69 (90%) | 87% | 374원 | 104초 |
| **gemini-3.1-pro-preview** ×3회 | **177 · 178 · 177 (99~100%)** | 69/69 ×3 | 90 · 98 · 97% | 167원 | 70초 |

**오류의 성격이 다르다.**

- Opus 5 의 틀린 7개 중 4개는 **없는 번호를 만들어 낸 것** (`&잼` → 8, `17` → 13, 씨리얼에 1 추가 등). 고등어(7) 누락 1건, 오후간식 행을 옆 칸과 섞은 것 1건. 검수 표시 없이 나온 것이 위험하다.
- Gemini 의 틀린 것은 3회 통틀어 **8일 점심 마지막 줄 `신선과일(샤인머스켓)` 누락** 하나뿐(3회 중 2회). 번호를 지어내거나 빠뜨린 경우 0건.

→ **2026-09-09 부로 기본 모델을 `gemini-3.1-pro-preview` 로 바꿨다.** Opus 5 엔드포인트는 `.env` 주석에 비교용으로 남겨뒀다.

## 3. 게이트웨이(Elice MLAPI)에서 실측한 것

- 엔드포인트가 **모델마다 다르다.** `--base-url` 로 바꿔 끼운다.
- 출력 **6,000 토큰 상한**은 게이트웨이 공통. `max_completion_tokens` 를 더 주어도 무시된다. 한 달치 JSON 은 7,000 이상이라 2분할이 필수.
- 응답을 `{"MealPlanJSON": {...}}` 처럼 스키마 이름으로 한 겹 감싸는 경우가 있다. `parse_plan_content` 가 벗긴다.
- 프롬프트 캐시가 자동 적용된다. Opus 는 첫 호출에 쓰기 할증 1.25배, Gemini 는 할증 없음.
- 5회 시도 중 원인 미확인 일시 오류 1회. 재시도 정책은 아직 없다(SDK 기본 1회).

## 4. 이번 주 남은 실험

- [ ] Gemini 로 **다른 급식표** 2~3장 (다른 센터·다른 양식). 지금 결과는 1장 기준이라 일반화 못 한다
- [ ] 흐린 사진·기울어진 사진 — `unparsed` 로 보내는지, 지어내는지
- [ ] 8일 `신선과일` 누락 — 프롬프트에 "점심 칸 마지막 줄까지" 를 넣고 재확인
- [ ] Gemini `effort high` 가 더 나은지 (출력 상한 안에 들어오는지 포함)
- [ ] 정답셋 재확인 3칸: 10·27일 `잼/쨈`, 14일 `물만두국/물만둣국` — 두 모델이 같은 답을 냈다

## 5. 결정 시 함께 정할 것

- `meal_type` 값 집합 — 실측 결과 `snack_am` / `lunch` / `snack_pm` 세 가지로 충분했다 (§7-2 닫기 후보)
- "A 또는 B" 대체 메뉴를 DB 에 1행으로 둘지 2행으로 둘지 — 데이터 모델 담당과 협의
- 기관명이 박힌 원본 이미지의 보관 — 7-1 결정과 연결
