# 일정 알림 v1 (#594)

일정마다 보호자가 "얼마나 먼저" 알림을 걸고, 서버가 그 시각에 FCM 으로 그 보호자의 기기에 푸시를 보낸다.
웹(브라우저)과 안드로이드 앱이 같은 FCM 으로 받는다. iOS 는 하지 않는다.

API 모양은 Swagger 가 정본이다. 여기에는 Swagger 가 담지 못하는 결정 · 이유 · 운영만 둔다.
복약 알림은 별도 표(`medication_dose`)에서 울릴 것을 정하고, 아래의 **기기 · 스위치 · 발송 모듈을 같이 쓴다.**

## 결정

| | 결정 | 이유 |
| --- | --- | --- |
| 누구의 것 | 알림은 **보호자 개인 것** — 일정 하나에 보호자당 1개(`UNIQUE(event_id, parent_id)`). 만든 사람은 제출할 때, 다른 보호자는 캘린더에서 각자 건다 | 같은 아이를 보는 보호자마다 필요한 시각이 다르다. 남이 건 알림이 내 폰에 울리지 않는다 |
| 고르는 값 | 고정 목록(Apple 캘린더 모양). 시간 있는 일정 `at_start · 5m · 10m · 15m · 30m · 1h · 2h · 1d · 2d · 1w`, 종일 일정 `day_of_9am · 1d_9am · 2d_9am · 1w_9am`(KST 오전 9시). 기본값은 "없음" | 종일 일정에는 "몇 분 전" 이 뜻이 없다. 맞지 않는 값은 422 |
| 저장 | 울릴 시각이 아니라 `lead` 를 저장하고, 보낼 때 일정 시작에서 계산한다(`app/rules/reminder.py`) | 일정 시간을 옮기면 알림이 따라간다. 알림 시각을 따로 고칠 곳이 없다 |
| 일정을 고치면 | 종일 ↔ 시간 있는 일정이 바뀌면 날 수를 지켜 가까운 값으로 옮긴다(`at_start`~`2h` ↔ `day_of_9am`, `1d`/`2d`/`1w` ↔ `*_9am`). 옮긴 값이 이미 지난 시각이면 그 알림만 지운다. 새 울릴 시각이 아직 오지 않은 알림만 `sent_at` 을 비워 다시 울린다 | 예방접종 · 병원 일정은 알림이 안 오는 쪽이 조금 다른 시각에 오는 것보다 나쁘다(#603 PM 결정). 이미 지난 시각으로 옮긴 알림을 비우면 이미 울린 알림이 곧바로 한 번 더 울린다 |
| 받을 기기 | `push_device` 는 **로그인(`session`) 1건**에 묶인다(CASCADE). 로그아웃 · 탈퇴 때 바로, 세션 만료 때는 하루 한 번 정리 배치와 함께 지워진다 | 공용 기기에서 로그아웃한 뒤 앞 보호자의 알림이 울리지 않는다. 화면이 지우기를 빠뜨려도 남지 않는다 |
| 켜고 끄기 | 설정 탭의 스위치 2개(일정 · 복약), 보호자 단위. 행이 없으면 코드의 `DEFAULT_SETTING` | 기본값을 바꿔도 마이그레이션 없이 만진 적 없는 보호자 모두에게 적용된다 |
| 승인 게이트 | 아니다 | 알림은 일정 쓰기가 아니라 개인 설정이다 (루트 CLAUDE.md §2 — 게이트를 늘리지 않는다) |

## 발송 — `app/workers/reminder_dispatch.py`

서버 cron 이 **1분마다** 부른다. 한 번 돌 때:

1. 울릴 시각이 **지난 10분 안**인 알림을 맡아 `sent_at` 을 찍고 커밋한다 (`claim_due_reminders`).
   - **보내기 전에 찍는다.** 보내다 죽으면 그 알림은 다시 보내지 않는다 — 두 번 울리느니 한 번 빠진다.
   - `FOR UPDATE SKIP LOCKED` — 배치가 겹쳐 돌아도 하나만 맡는다. 일정 수정이 쥔 알림은 다음 차례로 미룬다.
   - 10분보다 오래 지난 알림은 맡지 않는다 — 배치가 멈췄다 살아났을 때 몰아서 울리지 않고, 고친 일정의 새 시각이 이미 지났을 때 뒤늦게 울리지 않는다.
2. 그 알림을 건 **보호자 본인**의 기기 중, 일정 알림 스위치가 켜져 있고 로그인이 살아 있는 기기에 보낸다.
   - 기기마다 **보내기 직전에 한 번 더 본다**(기기 · 토큰 · 로그인 · 스위치). 배치가 보내는 사이 로그아웃하고 다른 계정으로 로그인한 공용 기기에 앞 보호자의 알림이 가지 않게. 이 확인과 발송 사이의 짧은 틈은 남는다 — 보내는 동안 행을 잡으면 로그아웃이 FCM 응답을 기다린다.
3. FCM 이 `UNREGISTERED`(앱 삭제 · 구독 해지)라고 한 기기를 지운다. 그 밖의 실패는 다시 보내지 않는다.

**TTL** — 푸시에 10분(`STALE_AFTER` 와 같은 값)을 단다. 기기가 꺼져 있으면 FCM 이 들고 있다가 켜질 때 보내는데, 문구가 "5분 뒤에" 처럼 받는 순간 기준이라 늦게 도착하면 틀린 말이 된다. 10분 안에 못 받으면 버린다 (#610 리뷰).

**안드로이드 채널** — `android.notification.channel_id` 에 `schedule`(앱 셸이 만든 "일정 알림" 채널)을 싣는다. 앱 밖에서는 FCM 이 앱의 기본 채널로 띄우지만, **앱을 보고 있을 때 온 알림**은 앱(`expo-notifications`)이 메시지의 채널 id 로 띄우고 없으면 영문 기본 채널("Miscellaneous")에 띄운다. 그러면 설정에 채널이 하나 더 생기고, 보호자가 "일정 알림" 채널을 꺼도 앱을 보는 동안에는 계속 뜬다. 값을 바꾸면 앱과 같이 바꾼다 (#610 리뷰).

**문구** — 제목 "일정 알림", 본문 "1시간 뒤에 일정이 있어요" 처럼 **일정 제목을 넣지 않는다.** 푸시는 Google(FCM)을 거쳐 잠금 화면에 뜬다.
넣을지는 PM 확인 대기 중이다 (#605). 정해지면 `reminder_message` 만 고친다.

**data** — 화면이 알림을 눌렀을 때 쓴다. `type=schedule_reminder` · `child_id` · `event_id` · `date`(그 일정의 KST 날짜). id 만 싣는다.

**로그** — 건수만 남긴다(맡음 · 보냄 · 받을 기기 없음 · 지운 기기 · 실패). 기기 토큰 · 문구 · 아이 · 일정 정보는 남기지 않는다.

## FCM 준비 (운영)

1. Firebase 콘솔에서 프로젝트를 만들고 웹 앱 · 안드로이드 앱을 등록한다.
2. **서버** — 프로젝트 설정 › 서비스 계정 › 새 비공개 키 생성(JSON). 이 파일을 서버의 저장소 밖 경로에 두고
   - `deploy/docker/.env` 의 `FCM_KEY_PATH=<서버의 파일 경로>` → api 컨테이너의 `/run/secrets/fcm-service-account.json` 에 읽기 전용으로 붙는다
   - `apps/api/.env` 의 `FCM_SERVICE_ACCOUNT_FILE=/run/secrets/fcm-service-account.json`
   - 로컬에서는 `FCM_SERVICE_ACCOUNT_FILE` 에 노트북의 파일 경로를 바로 넣는다.
3. **웹** — 웹 앱 설정값과 웹 푸시 인증서(VAPID) 공개 키는 FE 가 쓴다. 공개 값이라 번들에 들어가도 된다.
4. **안드로이드** — `google-services.json` 은 커밋하지 않는다 (EAS secret file).
5. **받기 켜기** — 기기 토큰이 실린 처리방침 새 판을 게시한 뒤 `apps/api/.env` 에 `PUSH_DEVICE_ACCEPT=true`. 그 전에는 기기가 저장되지 않아 키를 붙여도 아무에게도 가지 않는다.

🚨 **서비스 계정 키는 비밀이다.** 저장소 · 이미지 · 로그 어디에도 넣지 않는다. 실수로 커밋했다면 지워도 히스토리에 남으므로 **키를 폐기**하고 새로 만든다 (루트 CLAUDE.md §9).

`FCM_SERVICE_ACCOUNT_FILE` 이 비어 있으면 배치는 알림을 맡지도 않고 경고 한 줄만 남긴다. 그 사이 시각이 지난 알림은 10분 뒤 울리지 않게 된다.

cron 한 줄 · 확인 방법은 [`apps/api/README.md`](../../apps/api/README.md) "일정 알림 발송".

## 개인정보

| 저장하는 것 | 어디 | 지우는 때 |
| --- | --- | --- |
| 알림 값(`lead`) · 울렸는지(`sent_at`) | `reminder` | 일정 삭제 · 연결 끊기 · 탈퇴 |
| FCM 등록 토큰 원문 · 기기 종류 · 마지막 등록 시각 | `push_device` | 로그아웃 · 탈퇴(바로), 세션 만료(하루 한 번 정리 배치) |
| 알림 스위치 2개 | `notification_setting` | 탈퇴 |

- 토큰은 FCM 에 그대로 넘겨야 해서 해시가 아니라 원문이다. 로그에 남기지 않고, API 는 본문으로만 받는다(접근 로그에 남지 않게).
- **밖으로 보내는 것** — FCM(Google)에 기기 토큰과 알림 문구 · data(id)를 보낸다.
- **동의** — 별도 동의 없이 처리방침에 적고 받는다 (10-28 PM, #605 — 개인정보 보호법 제15조 ①항 4호). 보관 · 삭제는 [`retention-v1.md`](../safety/retention-v1.md) 의 푸시 기기 행.
- 🚨 **처리방침 새 판 게시 전에는 받지 않는다** — `apps/api/.env` 의 `PUSH_DEVICE_ACCEPT` 가 꺼져 있으면(기본) 기기 등록이 204 만 주고 저장하지 않는다. 웹 빌드 인자를 거치지 않는 앱 토큰까지 서버 한 곳에서 막는다.
