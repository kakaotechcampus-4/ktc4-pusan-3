## 한 번 발급하면 여러 API에 쓰는 것

**공공데이터포털(data.go.kr)은 계정당 인증키가 하나입니다.** 키는 하나로 공유하고, API마다 **활용신청**을 따로 넣어 승인받는 구조입니다. 아래 표에서 발급처가 data.go.kr인 것들은 전부 같은 키를 씁니다.

---

## 1. 공통 — 없으면 아무것도 안 돎

| 키 | 발급처 | 쓰는 곳 | 메모 |
| --- | --- | --- | --- |
| **LLM API 키** | Anthropic Console | 전 Agent 모델 호출 | 개발/운영 키 분리 |
| **임베딩 API 키** | 사용하는 임베딩 제공사 | `*_doc` 의미 검색 | 스키마가 `vector(1536)`이라 그 차원을 내는 모델이어야 함. 제공사 확정 필요 |

---

## 2. Food

| 키 | 발급처 | 쓰는 곳 | 메모 |
| --- | --- | --- | --- |
| **공공데이터포털 인증키** + 활용신청: 식품의약품안전처_식품영양성분DB정보 | data.go.kr | `menu_catalog` 영양 | 활용신청 1건 |
| **식품안전나라 인증키** | foodsafetykorea.go.kr | 조리식품 레시피 DB(`COOKRCP01`) — 재료 목록 | **data.go.kr 키와 별개.** 회원가입 후 Open API 인증키 신청 |
| **NEIS 교육정보 개방포털 키** | open.neis.go.kr | 학교·해당 유치원 급식 | 어린이집은 대상 아님. 급식을 OCR로만 받을 거면 **후순위** |

키가 필요 없는 것: 한국인 영양소 섭취기준(문서 → 시드), 알레르기 19종(상수), K-FIND(검수용 웹 조회).

## 3. Growth

| 키 | 발급처 | 쓰는 곳 | 메모 |
| --- | --- | --- | --- |
| **도서관 정보나루 인증키** | data4library.kr | `search_books` · `book_catalog` | 승인까지 하루 정도. **서버 IP를 등록해야** 하루 한도가 500회 → 30,000회로 늘어남 |

키가 필요 없는 것: 표준보육과정·누리과정(문서 → `growth_doc` 행).

## 4. Health

| 키 | 발급처 | 쓰는 곳 | 메모 |
| --- | --- | --- | --- |
| 공공데이터포털 인증키 + 활용신청: **건강보험심사평가원_병원정보서비스** | data.go.kr | 평일 소아과 찾기 | 활용신청 1건 |
| 공공데이터포털 인증키 + 활용신청: **국립중앙의료원 응급의료정보 조회 서비스** | data.go.kr | 야간·응급 · 실시간 | 활용신청 1건 |
| (확인 필요) 국립중앙의료원 병·의원 찾기 서비스 | data.go.kr | 달빛어린이병원 목록 | 목록을 이 API로 받을지, 공개 파일로 받을지 먼저 확인(E-5). 파일이면 키 불필요 |

키가 필요 없는 것: 성장도표 LMS(파일 다운로드), 영유아 검진 주기·예방접종 지침(문서 → 상수), 예방접종도우미(링크만).

**의도적으로 발급하지 않는 것**: 의약품 정보 API. 약명·용량을 보정할 경로가 생기기 때문입니다. 처방전 약품명의 "일치 여부 표시"(H-10)를 허용하기로 결정되면 그때 신청합니다.

**처방전 OCR 키는 발급하지 않습니다.** OCR 파이프라인 담당자 몫이고, Health는 결과 테이블만 읽습니다.

## 5. Activity — 담당자와 누가 발급할지 확인

같은 저장소라 키를 공유할 수 있어서 적어 둡니다.

| 키 | 발급처 | 메모 |
| --- | --- | --- |
| data.go.kr 활용신청: 기상청 단기예보 | data.go.kr | 같은 인증키 |
| data.go.kr 활용신청: **에어코리아 대기오염정보** | data.go.kr | **운영계정은 심의승인** — 가장 오래 걸림 |
| **Kakao REST API 키** | developers.kakao.com | **로그인용 앱과 다른 앱으로** 새로 만들 것. 쿼터가 섞이면 장소 검색이 로그인을 막음 |

## 6. 발급 순서

| 순서 | 할 일 | 이유 |
| --- | --- | --- |
| 1 | 에어코리아 운영 활용신청 (Activity와 협의) | 심의라 리드타임이 가장 김 |
| 2 | data.go.kr 인증키 + 활용신청 3건 (식품영양성분 · 심평원 · 응급의료) | 한 번에 신청 |
| 3 | 도서관 정보나루 키 신청 → 승인 후 **서버 IP 등록** | IP 등록을 잊으면 하루 500회에서 막힘 |
| 4 | 식품안전나라 인증키 | data.go.kr과 별개라 빠뜨리기 쉬움 |
| 5 | LLM · 임베딩 키 (개발/운영 분리) | – |
| 6 | NEIS · 국립중앙도서관 | 후순위 |

활용신청 화면에서 **개발계정/운영계정 구분과 승인 방식(자동/심의)을 꼭 확인하세요.** 서비스마다 다르고, 개발계정 한도로 도그푸딩을 돌리면 중간에 막힐 수 있습니다.

## 7. 보관 규칙

```
# .env.example (값은 비워서 커밋)
ANTHROPIC_API_KEY=
EMBEDDING_API_KEY=
DATA_GO_KR_SERVICE_KEY=        # 식품영양성분·심평원·응급의료·기상청·에어코리아 공용
FOODSAFETYKOREA_API_KEY=
NEIS_API_KEY=
DATA4LIBRARY_API_KEY=
NL_GO_KR_API_KEY=
KAKAO_REST_API_KEY_PLACES=     # 로그인 키와 분리
```

- 실제 키는 커밋하지 않습니다. `core/config.py`로만 읽습니다.
- data.go.kr 키는 **인코딩/디코딩 두 형태**로 나옵니다. HTTP 클라이언트가 자동 인코딩하면 디코딩 키를 써야 이중 인코딩 오류가 안 납니다. 가장 흔한 첫 호출 실패 원인입니다.
- 쿼터 소진 알람을 키마다 둡니다. 특히 정보나루와 에어코리아입니다.
