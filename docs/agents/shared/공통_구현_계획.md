## 1. 공통으로 두지 않은 것

**`execute_tool` 을 공통화하지 않았다.** 허용 목록·핸들러 표·컨텍스트 타입이 Agent 마다
달라서 제네릭으로 만들면 타입만 깊어지고 얻는 게 없다. 각 Agent 의 `registry.py` 가 자기
것을 갖는다 — [food/registry.py](../../../apps/api/app/agents/food/registry.py) 가 선례이고
모양은 이렇다.

```python
def tools_for(task_type, gate) -> tuple[str, ...]      # 빈 튜플이면 모델을 안 부른다
def specs_for(names) -> list[dict]                      # 모델에게 보낼 스펙
async def execute_tool(name, arguments, context, *, allowed) -> ToolResult
```

돌려주는 `ToolResult` 와 실패 코드만 공통이다. **같은 실패가 Agent 마다 다른 이름으로
로그에 남으면 집계가 안 된다.**

**`Operation` 도 Agent 마다 다르다.** Memory 는 `parse/create/query/update/delete`,
Food 는 `query/propose/report`. 공통 `ToolResult.operation` 은 `str | None` 이고, 좁히는
것은 각 Agent 의 `ok()`/`fail()` 래퍼다.

## 2. ErrorCode 를 통일했다

세 벌이던 어휘를 `common/tool_runtime.py` 하나로 모았다. 기존 Memory·Food 를 새 어휘로
옮기는 것은 별도 PR 이다 — 호출부 33곳에서 코드 이름만 바뀌고 동작은 그대로다.

| 옛 이름 | 지금 |
| --- | --- |
| `VALIDATION_ERROR` | `INVALID_ARGS` |
| `UNKNOWN_TOOL` | `TOOL_NOT_ALLOWED` |
| `NO_RECORDS` | 그대로 (공통으로 승격) |

새로 생긴 것: `NOT_FOUND` · `UPSTREAM_ERROR` · `CONSENT_REQUIRED` · `SAFETY_UNAVAILABLE` ·
`EVIDENCE_REQUIRED`.

**Memory 전용 코드는 남겼다.** `TARGET_REQUIRED` · `AMBIGUOUS_TARGET` · `DATE_UNPARSEABLE` ·
`OUT_OF_SCOPE` · `UNKNOWN_EVENT` 는 각각 모델이 할 다음 행동이 달라 공통 `NOT_FOUND` 로
뭉치면 정보가 준다. `app/agents/memory/result.py` 의 `ErrorCode` 가 공통 것을 상속한다.
Agent 가 자기 코드를 더할 때 같은 방식을 쓴다.

## 3. 공통 모듈이 강제하는 것

문서에 적힌 규칙 중 **코드가 막아 주는 것**만 적는다. 나머지는 각 Agent 가 지켜야 한다.

| 규칙 | 어디서 막나 |
| --- | --- |
| 월령을 `//30` 으로 세지 않는다 | `age.months_between()` — 달력 계산만 노출 |
| `date` 자리에 `datetime` 이 안 온다 | `age._require_plain_date()` — `TypeError` |
| 안전 필터는 더 어린 쪽을 본다 | `LifeStage.safety_months` |
| 조산아 이유식은 교정연령으로 연다 | `LifeStage.corrected_stage` 를 따로 낸다 |
| 기피(−1)를 후보에서 지우지 않는다 | `rank_evidence()` 가 제거 목록을 반환하지 않는다 |
| `polarity IS NULL` 은 근거가 아니다 | `rank_evidence()` 가 빼고 `pick_followup()` 이 집는다 |
| 감쇠를 Agent 가 다시 세지 않는다 | `rank_evidence()` 가 유예일 인자를 받지 않는다. `archived` 제외만 |
| 근거 0행이면 일반 추천 | `suggestion.build()` 가 `kind` 를 정한다 |
| 문서 행만으로 개인화가 안 된다 | `Ref.is_child_record` — 품질 지표가 아이 기록만 센다 |
| 기피를 인용했으면 이유에 밝힌다 | `build()` 가 라벨이 문장에 없으면 거절 |
| 추천은 정확히 3개 | `check_count()` — 재호출 뒤 부족만 예외 |
| 되묻기는 한 번에 하나 | `DomainAgentResult.__post_init__` |
| 복약 초안에 실제 알림 시각 필수 | `MedicationDraft.__post_init__` |
| 상수 문구는 키로 관리 | `ReadoutCatalog` — 없는 키는 즉시 `KeyError` |
| 0행이 "없음"인지 "모름"인지 가른다 | `Gate.allergy_filter_ready` (F-4) |

`build()` 의 기피 검사는 **라벨이 문장에 들어 있는가**까지만 본다. 문장 품질은 못 본다 —
라벨조차 안 나오면 확실히 말하지 않은 것이라는 하한만 건다.

## 4. 남은 공통 작업

### 4-1. `app/rules/term_match.py`

Food 의 알레르기 필터, Activity 의 `hazard_term`, Growth 의 활동 행 검사가 같은 매처를
쓴다. 구현이 두 벌이 되면 한쪽만 갱신된다.

알고리즘은 정해져 있다 — **공백 제거 부분 일치 + guards + 가장 엄한 판정 우선.**
guards 는 오탐 취소 목록이다("밀크티"는 밀이 아니다).

선행은 `hazard_term` 스키마다. Activity 담당자가 정한다
([README §5](../README.md#5-growth가-hazard_term에-요구하는-것)에 Growth 요구를 적어 뒀다).
Food 의 `allergen_term` 은 이미 `aliases`·`guards` 를 갖고 있어 그쪽 모양을 따르면 된다.

### 4-2. `config/age_gates.yaml`

문서는 이 파일을 경계값 정본으로 적어 뒀지만 아직 없다. 지금은 `age.py` 의
`_STAGE_BOUNDARIES` 가 유일한 자리다. 로더를 만들 때 **숫자를 두 곳에 두지 않도록**
모듈 상수를 지우고 파일에서 읽는다.

### 4-3. `pipeline` 이 채널을 처리하는 자리

`DomainAgentResult` 는 값만 정한다. 다섯 채널을 실제로 내보내는 것은 pipeline 이다.

| 채널 | pipeline 이 할 일 |
| --- | --- |
| `suggestions` | 주입된 writer 로 INSERT · `suggestion_evidence` 행 생성 · 카드 화면 이벤트 |
| `readouts` | SSE 로 그대로. `authored_by="code"` 는 가공 금지 |
| `event_requests` | Memory 일정 tool 을 코드로 호출 → 초안 payload |
| `needs_observation` | 화면이 한 줄로 묻는 이벤트 |
| `medication_drafts` | payload 로 내보내기만. 제출은 백엔드 |

`suggestion_evidence` INSERT 는 아직 없다 — 테이블 마이그레이션이 선행이다.

## 5. Agent 를 올리는 순서

```
① 공통 뼈대        ✅ 끝
② routing·pipeline  DomainTask · 실행 함수 표 · gather · partial · 채널 처리
   └ 선행: ①
③ Food 실구현      이미 mock 이 있다. 포트·코드 tool·출력 검증을 채운다
   └ 선행: ② · suggestion/suggestion_evidence 마이그레이션 · daycare_meal · 영양 데이터
④ Growth           growth_doc 148행이 임계 경로다. 코드는 며칠, 콘텐츠는 몇 주
   └ 선행: ③ · child_growth_log · 도서 API 키
⑤ Health           안전에 가장 민감하고 외부 API 가 가장 많다. 뼈대가 굳은 뒤에
   └ 선행: ④ · 질병청·건보·E-Gen · medication 마이그레이션
⑥ Activity         담당자 일정에 따라. 공통 뼈대는 이미 쓸 수 있다
```

Activity 를 ③~⑤ 와 병렬로 해도 된다. 공통 모듈이 이미 있어 서로 기다릴 이유가 없다.

### 하드 선행 — 이게 없으면 ③이 못 나간다

| | 없으면 막히는 것 |
| --- | --- |
| `suggestion.kind` + `suggestion_evidence` 테이블 | 전 Agent — 개인화/일반 표시와 품질 지표 |
| `child.allergy_status` (`none`/`has`/`unknown`) | Food 식단 추천 (F-4) |
| `child_growth_log` (`numeric(4,1)` · `check_date NOT NULL`) | Growth 성장폭 · Food 권장 열량 |
| `daycare_meal` 테이블 | Food 급식 연결 |

앞의 둘은 마이그레이션 PR 하나로 묶을 수 있다.
