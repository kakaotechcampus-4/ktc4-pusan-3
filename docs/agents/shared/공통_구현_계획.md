## 1. 공통으로 두지 않은 것

**`execute_tool` 을 공통화하지 않았다.** 허용 목록·핸들러 표·컨텍스트 타입이 Agent 마다
달라서 제네릭으로 만들면 타입만 깊어지고 얻는 게 없다. 각 Agent 의 `registry.py` 가 자기
것을 갖는다 — [food/registry.py](../../../apps/api/app/agents/food/registry.py) 가 선례이고
모양은 이렇다.

```python
def tools_for(task_type, gate) -> tuple[str, ...]      # 빈 튜플이면 모델을 안 부른다
def specs_for(names) -> list[dict]                      # 모델에게 보낼 스펙
async def execute_tool(name, arguments, context, *, allowed) -> ToolResult
```

돌려주는 `ToolResult` 와 실패 코드만 공통이다. **같은 실패가 Agent 마다 다른 이름으로
로그에 남으면 집계가 안 된다.**

**`Operation` 도 Agent 마다 다르다.** Memory 는 `parse/create/query/update/delete`,
Food 는 `query/propose/report`. 공통 `ToolResult.operation` 은 `str | None` 이고, 좁히는
것은 각 Agent 의 `ok()`/`fail()` 래퍼다.

## 2. ErrorCode 를 통일했다

세 벌이던 어휘를 `common/tool_runtime.py` 하나로 모았다. 기존 Memory·Food 를 새 어휘로
옮기는 것은 별도 PR 이다 — 호출부 33곳에서 코드 이름만 바뀌고 동작은 그대로다.

| 옛 이름 | 지금 |
| --- | --- |
| `VALIDATION_ERROR` | `INVALID_ARGS` |
| `UNKNOWN_TOOL` | `TOOL_NOT_ALLOWED` |
| `NO_RECORDS` | 그대로 (공통으로 승격) |

새로 생긴 것: `NOT_FOUND` · `UPSTREAM_ERROR` · `CONSENT_REQUIRED` · `SAFETY_UNAVAILABLE` ·

Agent 가 자기 코드를 더할 때 같은 방식을 쓴다.

## 3. 공통 모듈이 강제하는 것

문서에 적힌 규칙 중 **코드가 막아 주는 것**만 적는다. 나머지는 각 Agent 가 지켜야 한다.

| 규칙 | 어디서 막나 |
| --- | --- |
| 월령을 `//30` 으로 세지 않는다 | `age.months_between()` — 달력 계산만 노출 |
| `date` 자리에 `datetime` 이 안 온다 | `age._require_plain_date()` — `TypeError` |
| 안전 필터는 더 어린 쪽을 본다 | `LifeStage.safety_months` |
| 조산아 이유식은 교정연령으로 연다 | `LifeStage.corrected_stage` 를 따로 낸다 |
| 기피(−1)를 후보에서 지우지 않는다 | `rank_evidence()` 가 제거 목록을 반환하지 않는다 |
| `polarity IS NULL` 은 근거가 아니다 | `rank_evidence()` 가 빼고 `pick_followup()` 이 집는다 |
| 감쇠를 Agent 가 다시 세지 않는다 | `rank_evidence()` 가 유예일 인자를 받지 않는다. `archived` 제외만 |
| 근거 0행이면 일반 추천 | `suggestion.build()` 가 `kind` 를 정한다 |
| 문서 행만으로 개인화가 안 된다 | `Ref.is_child_record` — 품질 지표가 아이 기록만 센다 |
| 기피를 인용했으면 이유에 밝힌다 | `build()` 가 라벨이 문장에 없으면 거절 |
| 추천은 정확히 3개 | `check_count()` — 재호출 뒤 부족만 예외 |
| 되묻기는 한 번에 하나 | `DomainAgentResult.__post_init__` |
| 복약 초안에 실제 알림 시각 필수 | `MedicationDraft.__post_init__` |
| 상수 문구는 키로 관리 | `ReadoutCatalog` — 없는 키는 즉시 `KeyError` |
| 0행이 "없음"인지 "모름"인지 가른다 | `Gate.allergy_filter_ready` (F-4) |

`build()` 의 기피 검사는 **라벨이 문장에 들어 있는가**까지만 본다. 문장 품질은 못 본다 —
라벨조차 안 나오면 확실히 말하지 않은 것이라는 하한만 건다.

## 4. 남은 공통 작업

### 4-1. `app/rules/term_match.py`

Food 의 알레르기 필터, Activity 의 `hazard_term`, Growth 의 활동 행 검사가 같은 매처를
쓴다. 구현이 두 벌이 되면 한쪽만 갱신된다.

알고리즘은 정해져 있다 — **공백 제거 부분 일치 + guards + 가장 엄한 판정 우선.**
guards 는 오탐 취소 목록이다("밀크티"는 밀이 아니다).

선행은 `hazard_term` 스키마다. Activity 담당자가 정한다
([README §5](../README.md#5-growth가-hazard_term에-요구하는-것)에 Growth 요구를 적어 뒀다).
Food 의 `allergen_term` 은 이미 `aliases`·`guards` 를 갖고 있어 그쪽 모양을 따르면 된다.

### 4-2. `config/age_gates.yaml`

문서는 이 파일을 경계값 정본으로 적어 뒀지만 아직 없다. 지금은 `age.py` 의
`_STAGE_BOUNDARIES` 가 유일한 자리다. 로더를 만들 때 **숫자를 두 곳에 두지 않도록**
모듈 상수를 지우고 파일에서 읽는다.

### 4-3. `pipeline` 이 채널을 처리하는 자리

`DomainAgentResult` 는 값만 정한다. 다섯 채널을 실제로 내보내는 것은 pipeline 이다.

| 채널 | pipeline 이 할 일 |
| --- | --- |
| `suggestions` | 주입된 writer 로 INSERT · `suggestion_evidence` 행 생성 · 카드 화면 이벤트 |
| `readouts` | SSE 로 그대로. `authored_by="code"` 는 가공 금지 |
| `event_requests` | Memory 일정 tool 을 코드로 호출 → 초안 payload |
| `needs_observation` | 화면이 한 줄로 묻는 이벤트 |
| `medication_drafts` | payload 로 내보내기만. 제출은 백엔드 |

`suggestion_evidence` INSERT 는 아직 없다 — 테이블 마이그레이션이 선행이다.

## 5. routing · pipeline 이 바뀌는 자리

```python
IMPLEMENTED_AGENTS = frozenset({"food", "activity", "growth", "health"})

_RUNNERS: dict[str, DomainRunner] = {
    "food": run_food, "activity": run_activity,
    "growth": run_growth, "health": run_health,
}

results = await asyncio.gather(
    *(_RUNNERS[t.agent](t, contexts[t.agent]) for t in routing.domain_tasks),
    return_exceptions=True,   # NF-06
)
```

유형별 묶기는 `agent × task_type` 당 하나, 상한(2)은 **agent 단위**로 센다.

1. **동시 실행** — 도메인 Agent 끼리는 순서가 없다. Memory 다음이라는 순서는 유지한다.
2. **부분 실패** — 한 Agent 가 실패해도 나머지는 결과를 낸다. `partial` 이벤트를 여기서 만든다.
3. **호출 예산** — 입력 run 당 최대 5회 · 도메인 Agent 당 1회 이내 (NF-01 재정의).

채널별로 pipeline 이 무엇을 하는지는 §4-3 에 있다.

## 6. `suggestion` 쓰기

- **`status` 는 Agent 가 건드리지 않는다.** 생성은 항상 `draft` · `expires_at=+24h`.
- **요청 1건당 정확히 3개.** 출력 tool 이 개수를 검사한다 — 3개가 아니면 거절. 근거 0행 general 추천도 같다.
- **필터 후 3개 미만이면 재호출 1회** — 안전 필터(알레르기·연령 금지식품·`hazard_term`)를 거른 뒤 후보가 3개 미만이면 해당 Agent 만 모델을 한 번 더 부른다. 기피는 필터가 아니라 근거라 재호출 사유가 아니다. 재호출 프롬프트에 걸러진 항목을 제외 목록으로 넣는다. 1회로 끝나고 그래도 부족하면 남은 만큼만 낸다. `model_calls` 상한은 이 경우에만 Agent 당 2를 허용한다.
- **생성 즉시 화면 전환** — draft 저장과 동시에 pipeline 이 추천 카드 화면 이벤트를 내보낸다. 카드 화면은 그 run 의 응답을 그대로 쓰므로 묶음 키가 필요 없다. 별도 목록 화면은 `expires_at > now()` 인 suggestion 전부를 조회한다.
- **승인되면 Memory Agent 가 관찰로 만든다** — `approved` 전환 직후 백엔드가 Memory Agent 를 부르고, Memory 가 `suggestion` 을 `observation_*` 로 재구조화해 저장한다. 값이 확정값이 아니라 자연어라 코드로는 못 쪼갠다 — 승인 1건당 모델 호출 1회가 붙는다. feedback(`liked`/`disliked`/`not_acted`)은 그 관찰의 `polarity`(+1/−1/0)를 갱신한다.
- **근거 0행 = `kind="general"`** — 정상 경로다. `reason` 을 코드 템플릿으로 바꾸고 응답에 `scarcity`(쌓인 기록 건수 + 되물을 질문 1개)를 함께 싣는다. 추천을 빼고 `scarcity` 만 내리지 않는다.
- 실제 INSERT 는 `store/ports.py` 의 `SuggestionWriter` Protocol 로, 구현체는 `app/api` 가 주입한다.
- 근거는 `suggestion.source_refs`(jsonb) 가 아니라 **`suggestion_evidence` 테이블**이다. `PRIMARY KEY (suggestion_id, source_kind, source_id)` 에 `source_updated_at` · `note` 가 붙는다 (2026-09-23 회의 확정). 컬럼 이름이 `memory_*` 가 아닌 것은 가리키는 대상이 Memory 소유 테이블만이 아니어서다 — 문서 행과 `daycare_meal` 도 들어온다.
- `source_kind` 는 **두 무리**다. 아이 기록(`observation_*` 5종 · `profile_affinity` · `child_growth_log` · `notice` · `intake_daily` · `daycare_meal`)과 문서 행(`food_doc` · `growth_doc` · `activity_doc`). **품질 지표는 아이 기록만 센다** — 문서 행만 달고 나간 개인화 추천은 근거 0행과 같다.

## 7. Agent 를 올리는 순서

```
① 공통 뼈대        ✅ 끝
② routing·pipeline  DomainTask · 실행 함수 표 · gather · partial · 채널 처리
   └ 선행: ①
③ Food 실구현      이미 mock 이 있다. 포트·코드 tool·출력 검증을 채운다
   └ 선행: ② · suggestion/suggestion_evidence 마이그레이션 · daycare_meal · 영양 데이터
④ Growth           growth_doc 148행이 임계 경로다. 코드는 며칠, 콘텐츠는 몇 주
   └ 선행: ③ · child_growth_log · 도서 API 키
⑤ Health           안전에 가장 민감하고 외부 API 가 가장 많다. 뼈대가 굳은 뒤에
   └ 선행: ④ · 질병청·건보·E-Gen · medication 마이그레이션
⑥ Activity         담당자 일정에 따라. 공통 뼈대는 이미 쓸 수 있다
```

Activity 를 ③~⑤ 와 병렬로 해도 된다. 공통 모듈이 이미 있어 서로 기다릴 이유가 없다.

### 하드 선행 — 이게 없으면 ③이 못 나간다

| | 없으면 막히는 것 |
| --- | --- |
| `suggestion.kind` + `suggestion_evidence` 테이블 | 전 Agent — 개인화/일반 표시와 품질 지표 |
| `kind='allergy'` 행들의 `state` | Food 식단 추천 (F-4). 0행이거나 `unknown` 이 섞였으면 막는다 |
| `child_growth_log` (`numeric(4,1)` · `check_date NOT NULL`) | Growth 성장폭 · Food 권장 열량 |
| `daycare_meal` 테이블 | Food 급식 연결 |

앞의 둘은 마이그레이션 PR 하나로 묶을 수 있다.

## 8. Agent별 구현 메모

각 Agent 는 **① mock → ② 읽기 tool → ③ 출력 tool + 코드 규칙** 순서다. Food 가 ①을 끝냈다.

### Food

- **선행**: ORM 어댑터 · `health_safety` 조회 · `daycare_meal` 적재(OCR + 대체식 교체) · 영양 데이터 소스 · 권장 섭취량 외부 소스(연령별 일반값 + 성별 없는 열량 계산식) · 알레르기 "없음 vs 모름" 구분(F-4)
- **코드가 막는 것**: 알레르기 필터 · 정확한 섭취량 생성 금지 · 근거 매핑
- **영양이 선호보다 앞선다**: 기피 affinity 가 있어도 부족한 식품군을 후보 풀에서 빼지 않는다. 기피는 풀을 줄이는 값이 아니라 `reason` 을 쓰는 값이다
- `child_growth_log` 는 권장 열량 계산 입력으로 읽는다(코드 계산). 측정이 없으면 연령별 일반값. **성별은 읽지 않는다**

### Activity (두 번째)

- **왜 두 번째인가**: 외부 API 가 날씨·장소 둘뿐이고 쓰기 계약이 `suggestion` 하나로 끝난다. 공통 뼈대 검증용이다
- **읽기 포트**: `observation_activity` · `profile_affinity(domain=activity)` · Calendar · Weather · Place
- **코드가 막는 것**: 중복 제거 · 나이/안전 필터 · **예약·결제 경로 없음**
- **읽지 않는 것**: `observation_education` · `observation_routine`

### Growth

- **핵심**: `observation_routine` · `observation_education` → `growth_doc` · 도서 API 연결 추천. `notice` 는 보조라 없어도 동작해야 한다
- **읽기 포트**: `observation_education` · `observation_routine` · `observation_activity`(참고) · `profile_affinity(domain ∈ education, activity)` — `routine` 은 승격 대상이 아니라 affinity 가 없다 · `child_growth_log` · `notice` · `growth_doc` · 도서 API. `domain` 을 복수로 받는다 — 포트 시그니처는 `domains: tuple[str, ...]`
- **`routine_coaching` 은 `trigger` 필수** — NULL 이면 역질의
- **`growth_review` 는 모델을 부르지 않는다** — 차분 + 템플릿, `model_calls=0`. 판정 요청("잘 크고 있어?")도 여기로 온다
- **코드가 막는 것**: `strength`·`assistance_level`·`completion_status` 의 점수 환산 금지 · 단발 관찰 승격 금지 · `polarity=-1` 을 "못하는 것"으로 해석 금지 · **백분위 판정 금지**
- 근거가 `observation_activity` 를 가리킬 수 있다 — 화면 문구가 "놀이 기록을 참고했어요"로 나와야 한다

### Health (마지막)

- **왜 마지막인가**: 안전에 가장 민감하고 외부 API 가 가장 많다(질병청·건보·E-Gen). 앞의 셋으로 뼈대가 굳은 뒤에 붙인다
- **경계**: 진단·처방 없음. 같은 증상 3회 반복이면 추천을 멈추고 "병원 확인이 필요해 보여요" + 정리된 기록만. 이 판정은 **규칙**이다
- **Supervisor 와의 분담**: 진단 문의는 `guarded/diagnosis` 로 걸러져 Health 까지 가지 않는다
- **`medication` 이 유일한 쓰기 라벨** — 생성·수정은 초안 payload(DB 저장 없음), 중단은 soft delete. 확인 모달에 실제 알림 시각 필수
- **성장 판정 없음**: 백분위·BMI 판정은 제거됐다. 체중과 관련한 식이·운동 조언은 어느 Agent 도 하지 않는다

## 10. 열린 것

| # | 내용 |
| --- | --- |
| K-1 | `rank_evidence` 가 역질의 후보를 같이 돌려주지 않는다. `pick_followup()` 을 따로 부른다 — 문서의 시그니처(`-> tuple[RankedEvidence, ...]`)를 지키려고 나눴는데, 한 번에 받는 게 나으면 둘을 합친다 |
| K-2 | `Gate.data` 에 Agent 별 축이 더 붙을 수 있다. 지금은 `daycare_meal` · `notice` · `book_api` 셋 |
| K-3 | `SuggestionDraft.content` 가 `str` 이다. 메뉴 후보가 `{menu_key, display_name}` 구조라 jsonb 가 필요해지면 그때 바꾼다 (C-1 에서 지금은 안 하기로 함) |
| K-4 | `app/rules/` 는 **공동 소유**다. 변경 시 김명성·이시하 양쪽 리뷰가 필요하다 |
| K-5 | `app/rules/affinity.py`(감쇠 유예일)는 백엔드 몫이라 여기서 만들지 않았다. Curator 가 붙을 때 생긴다 — Agent 쪽에서 그 값을 참조할 일은 없다 |
| K-6 | **공지 분류 경계** — 텍스트로 붙여넣은 일반 공지의 `notice` 저장 경로, 일정과 일반 안내가 한 장에 섞인 공지를 어떻게 나눌지. 옛 구현 계획에서 유일하게 안 닫힌 항목이다 |
| K-7 | 도메인 Agent 는 `affinity_id=NULL` 인 관찰도 읽을 수 있어야 한다. 승격 전 관찰이 티어 3 근거라서다 |
| K-8 | Growth 는 `suggestion.feedback` 대신 `observation_education.engagement_level` 에서 배운다. `expires_at` 24h 와 학습 주기가 안 맞는다 |
