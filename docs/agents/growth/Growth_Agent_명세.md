# Growth Agent 명세

> **한 줄 요약** — 아이를 **평가하지 않고**, 최근 관심 · 배우는 것 · 생활 루틴 · 몸의 성장을 이어서 **"다음에 뭘 해주면 좋을지"** 를 제안하는 Agent.
>
> 대상 독자: 기획 · 디자인 · 프론트엔드 · 백엔드 · QA
> 최종 갱신: 2026-10-08 · 관련 문서: [`Agent_공통규약.md`](../shared/Agent_공통규약.md)

---

## 1. 이 Agent의 성격 — 먼저 읽어주세요

다른 Agent와 달리 **이 Agent는 "안 하는 것"이 설계의 절반입니다.**

아이의 학습·행동·성장을 다루다 보면 자연스럽게 **평가하는 말**이 나옵니다. "공간지각이 좋네요", "또래보다 늦네요", "이건 잘 못하는 편이에요". 이런 문장은 보호자에게 오래 남고, 근거 없이 나오면 해롭습니다.

> **이 Agent는 아이를 비교하거나 수준을 판정하지 않습니다.** 관찰된 것을 잇고, 다음에 해볼 것을 제안할 뿐입니다.

> **이 Agent의 핵심 기능** — `observation_routine` · `observation_education`에 쌓인 아이의 기록을 **외부 소스와 문서**(`growth_doc` · 도서 API)와 연결해 다음에 해볼 것을 추천하는 것입니다. 기관 공지(`notice`)는 보조 입력이고, 없어도 핵심 기능은 온전히 동작해야 합니다.

몸의 성장도 마찬가지입니다. **"얼마나 컸는지"는 말하지만 "잘 크고 있는지"는 말하지 않습니다.** 신체 성장을 다루는 건 이 Agent뿐이고, **시스템 어디에서도 성장 판정(백분위·BMI)을 하지 않습니다** — Health의 백분위 판정은 제거됐습니다(2026-09-22).

## 2. 이 Agent가 받는 요청

| 라벨 | 이런 말이 들어오면 | 결과물 |
| --- | --- | --- |
| `learning_suggestion` (교육 활동) | "농구 좋아하는데 뭘 배우게 할까" · "숫자 놀이 뭐 없어?" | 교육 활동 후보 |
| `routine_coaching` (생활 루틴) | "밥 먹을 때 혼자 하게 하고 싶어" · "손톱을 자꾸 물어뜯어" | 루틴 지원·교정안 |
| `book_suggestion` (도서) | "공룡 좋아하는데 책 추천해줘" | 실제 도서 목록 |
| `growth_review` (성장 추이) | "6개월 동안 얼마나 컸어?" · "잘 크고 있어?" | 측정 기록 기반 추이 정리 (판정 없음) |

### Activity Agent와 헷갈리는 지점

**기본은 Activity입니다.** "가르치다 · 배우다 · 책 · 글자 · 숫자 · 습관 · 혼자 하게" 같은 **학습·자립 신호**가 있을 때만 Growth로 옵니다.

```
"농구 좋아하는데 뭐 하고 놀까"       → Activity
"농구 좋아하는데 관련된 책 있어?"     → Growth (도서)
"농구 규칙 가르쳐주고 싶은데"        → Growth (교육 활동)
"밥 먹을 때 혼자 하게 하고 싶은데"    → Growth (생활 루틴)
"오늘 블록 쌓는 거 배웠대"           → Memory만. 요청이 아니라 기록
```

마지막 줄이 중요합니다. **"배웠대"에 '배우다'가 들어 있지만 요청이 아닙니다.** 그래서 신호어를 코드로 단순 매칭하지 않고 Supervisor가 문맥으로 판단합니다.

### 신체 성장 질문은 전부 이 Agent로 옵니다

```
"얼마나 컸어?"                → Growth  (10cm 자랐어요)
"잘 크고 있어?"               → Growth  (추이 + 검진 안내)
"10cm 컸는데 많이 큰 거야?"    → Growth  (같음)
```

Health의 성장 판정이 제거되어(2026-09-22) 경계가 없어졌습니다. 대신 판정을 묻는 질문에도 **판정하지 않는 것**이 이 Agent의 몫입니다.

## 3. 하는 일 / 하지 않는 일

### 하는 일

**교육 활동**
- 확정된 관심사를 새로운 학습 경험으로 확장 (농구 → 점수 세기, 던진 거리 비교)
- 과거 활동의 몰입·거절·반복 요청을 다음 추천에 반영
- 공식 교육과정·놀이자료에서 활동 후보 찾기
- (보조) 기관 공지에 나온 활동과 집에서 할 것 연결 — 공지가 있을 때만

**생활 루틴** — `routine_category`에 따라 갈립니다

| 종류 | 예 | 제안 방향 |
| --- | --- | --- |
| 리듬 (0–11개월) | 수면·수유 | **안내 한 줄.** 추천 카드를 만들지 않습니다 |
| 자립 (`self_care` · `household_task`) | 양치, 장난감 정리 | 다음 단계 ("도움 받아서 → 혼자서") |
| 습관 (`habit`) | 손톱 물어뜯기 | 교정안 (관심사와 연계) |
| 예절 (`social_manner`) | 인사하기 | 상황 연습 |

**도서**
- 관심사와 연결되는 실제 책 검색

**성장 추이**
- 측정 기록 **전부**를 시간순으로 정리합니다. "3월에 95cm, 9월에 105cm — 6개월간 10cm 자랐어요"
- 수치는 로그에 있는 값 그대로입니다. 반올림·보정·구간화를 하지 않습니다
- 판정을 묻는 질문("잘 크고 있어?")에도 추이만 말하고 검진을 안내합니다

### 하지 않는 일

| 안 함 | 왜 |
| --- | --- |
| 지능·성적 예측 | 근거 없음 |
| "공간지각이 뛰어나다" 같은 **능력 확정** | 관찰 몇 건으로 능력을 말할 수 없음 |
| 교사의 평가 대체 | 역할이 아님 |
| 한 번 잘한 활동을 **소질**로 해석 | 1회 = 우연 |
| 또래 비교 · 점수 환산 | 평가 Agent가 아님 |
| **키·몸무게로 발달 수준 판단** | 시스템 전체에서 하지 않음. 판정 질문엔 검진 안내 |
| 싫어하는 것을 **"못하는 것"으로 해석** | 기피와 무능은 다름 |
| 관찰 1건으로 **"습관"이라고 규정** | "요즘 손톱 물어뜯어" 한 번 = 습관 아님 |
| **음식·재료가 들어가는 놀이** ("밀가루 점토", "콩으로 숫자 세기") | Activity 몫. Growth 문장에 음식 이름이 나오면 코드가 뺀다 |
| **약 먹이기·안약 같은 처치를 루틴으로 코칭** | 처치 방법은 처방한 병원·약국이 답한다. 코드가 닫는다 |
| 눈 깜빡임·머리 박기 같은 **증상처럼 보이는 행동을 습관으로 교정** | 습관인지 증상인지 가를 수 없다. 교정안 없이 검진 상담을 안내한다 |

## 4. 읽는 것 / 쓰는 것

### 읽기만 합니다

| 무엇 | 쓰는 이유 |
| --- | --- |
| `observation_education` | 배우는 것, 몰입도 |
| `observation_routine` | 생활 습관, 자립 수준, 언제 그 행동이 나오는지 |
| `observation_activity` | **참고용** — 무엇을 하고 노는지가 학습 확장의 출발점 |
| `profile_affinity` (education · activity) | 확정된 관심 — **1순위 근거**. 루틴은 affinity 가 없어 관찰로만 인용합니다 |
| `child_growth_log` | 키·몸무게 **차분만** |
| `health_safety` (`allergy` · `environmental`) | **교육 활동만, 동의가 있을 때** — 보호자가 등록한 알레르기 이름이 든 활동을 빼고, 환경 알레르기가 있으면 확인 문구를 붙이는 데만 씁니다 |
| `notice` (기관 공지) | **보조** — 기관에서 뭘 하는지. 없어도 추천은 동작 |
| `growth_doc` | 교육과정·루틴 자료를 재작성한 문서 행 — 활동 후보 · 루틴 단계 |
| 도서 검색 API | 책 후보 |

> **건강정보는 교육 활동을 거르는 데만 읽습니다** (2026-10-08). 음식·재료가 들어가는 놀이는 Activity 몫이라, Growth 문장에 음식 이름이 나오면 아이와 상관없이 코드가 뺍니다. 그래도 라텍스나 꽃가루·동물털처럼 식품이 아닌 알레르기는 교육과정 활동(자연탐구)에도 닿아서, 교육 활동만 보호자가 등록한 `allergy` · `environmental` 을 읽어 **적은 이름이 든 활동**을 뺍니다. 라텍스로 적었는데 활동이 "풍선" 인 것처럼 이름이 다른 경우까지 넓히는 대응표는 만들지 않고, 환경 알레르기가 있으면 확인 문구 한 줄을 붙입니다(Activity 와 같다, #261). 만성질환·행동 특성은 읽지 않습니다 — 그걸로 추천을 가르면 진단이 됩니다. 루틴 · 도서 · 성장 추이는 `health_safety` 를 읽지 않습니다. 규칙은 [`Growth_Tool_명세.md`](Growth_Tool_명세.md) §2 "안전 필터".

> **읽기 방향은 한쪽입니다.** Growth는 놀이 기록을 읽지만, **Activity는 학습·루틴 기록을 읽지 않습니다.** "관심을 학습으로 확장"이 Growth의 역할이라 놀이 기록이 필요하고, 반대는 필요가 없습니다.

### 쓰는 것

`suggestion` 테이블 하나뿐입니다. `status='draft'`로만 만듭니다.

> **주의** — Growth가 만든 추천의 근거가 **놀이 기록**일 수 있습니다. 이때 화면 문구가 "놀이 기록을 참고했어요"로 나와야 보호자가 이해합니다.

### 문서를 찾는 것도 AI가 아닙니다

교육과정 자료와 루틴 자료는 **별도 KB가 아니라 `growth_doc` 행 하나**입니다. 검색은 `search_growth_doc`가 run 시작에 자동으로 하고, 쿼리는 코드가 조립합니다(라벨·단계·관심사·루틴 카테고리). AI에게 검색 tool을 주면 보호자 발화가 쿼리에 섞이고, 조회를 했는지 안 했는지를 테스트로 고정하기 어렵습니다.

자립 단계도 마찬가지입니다. 관찰의 `assistance_level`로 지금 어디쯤인지 찾고 `next_step_of` 사슬의 **바로 다음 칸**을 코드가 고릅니다. AI는 그 칸을 집 상황에 맞춰 문장으로 옮길 뿐입니다 — 단계를 건너뛰면 아이가 아직 못 하는 걸 시키게 됩니다.

### 성장 추이는 AI를 부르지 않습니다

`growth_review`는 **AI 호출이 0회**입니다. 두 측정치를 빼고 문장 템플릿에 넣는 게 전부입니다. 비용도 지연도 없습니다.

| 조건 | 동작 |
| --- | --- |
| 키·몸무게 각각 2건 이상 | 로그 **전부**를 시간순으로. "3월 12일 95cm, 9월 12일 105cm — 6개월간 10cm 자랐어요" |
| 한 지표만 2건 이상 | 그 지표만 요약 + "몸무게는 두 번 이상 재면 변화도 함께 알려드릴게요" |
| 둘 다 1건 이하 | "성장폭을 보려면 측정 기록이 두 번 이상 필요해요" |
| 키 측정이 24개월 전·후에 걸침 | 위 서술 + 재는 자세가 바뀌는 시기라는 단서 한 줄. 숫자는 그대로 |
| 판정을 묻는 질문 | 위와 같은 추이 서술 + "성장 평가는 영유아 건강검진에서 확인해 보세요" (코드 템플릿). 판정 문구 없음 |

**키와 몸무게는 따로 셉니다.** 한쪽만 잰 날은 그 값만 적고, "직전 대비"는 같은 지표의 바로 앞 측정과 비교합니다(2026-10-08).

**최소 간격을 두지 않습니다.** 2주 만에 다시 쟀으면 그 2주치를 그대로 보여줍니다. 간격이 짧다고 "말하기 어려워요"로 덮으면, 보호자가 넣은 기록을 시스템이 숨기는 셈이 됩니다. 이 라벨이 할 일은 **가진 기록 전부를 정확한 수치로, 보호자가 납득할 수 있게 늘어놓는 것**입니다.

그래서 하지 않는 것도 분명합니다 — 속도·경향·전망을 만들지 않습니다. "요즘 잘 크고 있어요", "작년보다 빨라요" 같은 문장은 수치가 아니라 해석입니다.

**측정일을 반드시 같이 표시합니다.** 측정 출처(보호자 측정인지 검진인지)를 저장하지 않기로 했기 때문에, 언제 잰 기록인지가 유일한 신뢰도 단서입니다.

## 6. 추천의 근거를 고르는 순서

```
1순위  확정된 관심·기피      (Curator가 여러 기록을 모아 확정한 것)
2순위  후보 단계 관심·기피    (아직 확정 전이지만 신호가 강한 것)
3순위  최근 14일 관찰        (교육 · 루틴 · 놀이)
──── 셋 다 없으면 ────
       "또래 기준" 일반 추천
```

**기피도 근거입니다.** "색칠은 싫어해서 만들기 쪽으로 골랐어요"가 되어야지, 싫어하는 것을 목록에서 지우고 아무 말도 안 하면 근거 없는 추천과 구별되지 않습니다. 후보에서 지우는 것은 안전에 걸리는 것뿐입니다 — `hazard_term` · 음식 용어 · (교육 활동) 보호자가 등록한 알레르기.

### 생활 루틴만 예외입니다

`routine_coaching`은 근거가 없을 때 **일반 추천을 내지 않습니다.** 습관이든 자립이든 마찬가지입니다 — 아이가 지금 어디까지 하는지 모르는 채 내놓는 조언은 어느 집에나 해당하는 일반론이고, 그건 이 Agent가 할 일이 아닙니다. 대신 되묻습니다.

> 습관 — "요즘도 손톱 물어뜯나요?" (`ask.habit_current`)
> 그 외 — "양치는 요즘 어느 정도까지 혼자 하나요?" (`ask.routine_current`)

여기서 "근거"는 **물어본 것과 같은 종류(`routine_category`)의 루틴 관찰이 최근 14일 안에 있는지**입니다(2026-10-08). 관심사(공룡을 좋아함)는 제안을 아이에게 맞추는 데 쓰지만, 그것만으로는 아이가 지금 어디까지 하는지 모르니 되묻습니다. 관찰이 있어도 얼마나 혼자 하는지(`assistance_level`)가 비어 있으면 마찬가지입니다. 3주 전에 들은 수준으로 다음 단계를 고르면 이미 넘어선 단계를 시킬 수 있습니다.

교육·도서 라벨은 그대로 일반 추천으로 내려갑니다. 루틴만 다릅니다.

### 습관 교정은 '언제 그러는지'를 알아야 시작합니다

`observation_routine.trigger`(긴장할 때 / 심심할 때 등)가 비어 있으면 교정안을 만들지 않고 되묻습니다.

> "손톱은 주로 어떤 상황에서 물어뜯나요?"

언제 나오는 행동인지 모르면 교정안이 아이와 상관없는 일반론이 됩니다.

## 7. 화면에 나가는 것

| 종류 | 내용 | 저장 | 만료 |
| --- | --- | --- | --- |
| 교육 활동 제안 | 활동 후보 **최대 3개** + 왜 이걸 추천하는지 | `suggestion` | 24시간 |
| 루틴 제안 | 다음 단계 또는 교정안 **최대 3개** | `suggestion` | 24시간 |
| 영아 리듬 안내 | 0–11개월. **추천이 아니라 읽기 전용 한 줄** | 저장 안 함 | – |
| 도서 목록 | 실제 책 **최대 3권** | `suggestion` | 24시간 |
| 개수 안내 | 다 못 채웠을 때만. 1~2개면 "조건에 맞는 추천을 N개 준비했어요", 0개면 추천 없이 "조건에 맞는 추천이 없어요" | 저장 안 함 | – |
| 성장 추이 서술 | "10cm 자랐어요" | 저장 안 함 | – |
| 되묻기 | 한 번에 하나 | 저장 안 함 | – |

추천은 생성과 동시에 `draft`로 저장되고, 대화에는 Food · Activity 와 같은 **결과 블록의 "후보 보기 →"**(#227)가 나갑니다. 링크는 `run_id` 를 싣고 05 제안 화면으로 가고, 05 는 그 run 에서 저장한 추천을 새로 만들지 않고 그대로 보여줍니다(#249 판단 순서). 05 에서 고른 것만 채택(`approved`)되어 Memory로 넘어가고, 거절 버튼이 없어서 고르지 않은 것은 24시간 뒤 `expired` 가 됩니다. 피드백은 채택한 추천에 07 기억 화면의 제안 탭에서 남깁니다 (2026-10-08 FE 리뷰).

> **대화로는 승인하지 않습니다** (2026-10-08). run 은 이전 run 을 기억하지 않아서, 대화창에 "추천해준 책 좋다, 그걸로 할게" 라고 해도 어느 추천인지 알 수 없습니다. 그럴 때는 승인도 새 추천도 하지 않고 제안 화면으로 안내합니다. "다른 책도 알려줘" 는 대화가 아니라 만료 전 `suggestion` 으로 중복을 거르므로 그대로 동작합니다.

> **피드백과 만료** — 24시간 뒤 만료되는 것은 고르지 않은 `draft` 뿐이고 채택한 추천은 남아서, 며칠 뒤에 해 본 활동도 07 제안 탭에서 피드백을 남길 수 있습니다. Growth 는 이 피드백(C-9, 관찰 `polarity`)과 함께 **`observation_education.engagement_level`**(나중에 실제로 해본 기록)에서도 배웁니다.

## 8. 다른 팀이 알아야 할 것

### 프론트엔드
- 성장 추이 서술에 **측정일이 반드시 붙습니다.** 임의로 생략하면 안 됩니다
- 성장 추이의 증감 숫자는 **감소도 부호 그대로** 옵니다(`-0.3cm`). 색 · 강조로 늘고 줄음을 구분하지 않고, 숫자 옆에 평가로 읽히는 말("잘 크고 있어요" · "괜찮아요" · "평균보다")을 붙이지 않습니다 (G-9)
- 추천은 **최대 3개**가 한 번에 저장되고, 대화에는 결과 블록의 **"후보 보기 →"**(#227, `run_id` 포함)가 나갑니다(화면을 바로 전환하지 않습니다). Growth 만의 딥링크 문구는 따로 없습니다. `offer`(04 "이것도 도와드릴까요?")는 그 run 에서 돌지 않은 Agent 를 권하는 줄이라 이것과 다르고, 04 에서 Growth 를 고르면 `run_id` 없이 홈처럼 05 가 새로 만듭니다(#249). 05 에서는 고른 것만 채택하고(거절 버튼 없음 · 고르지 않은 것은 24시간 뒤 `expired`), 피드백은 07 기억 화면의 제안 탭(`?tab=feedback`)에서 받습니다. 다 못 채우면 개수 안내 한 줄이 같이 옵니다(0개면 추천 없이 안내만 — 실패가 아니라서 다시 시도를 띄우지 않습니다). 카드 화면을 나와서 보는 suggestion 목록 화면에는 **만료 전 suggestion 전부**가 나옵니다
- 안전 필터(`hazard_term` · 음식 용어 · 알레르기)나 금지 표현 필터 뒤 3개 미만이면 AI를 한 번 더 부르므로 응답이 조금 늦을 수 있습니다
- 추천의 근거가 `observation_activity`일 수 있습니다 → "놀이 기록을 참고했어요"
- 되묻기는 한 번에 하나
- `growth_review`는 추천 카드가 아니라 **읽기 전용 텍스트**입니다. 05 에 올라가지 않고 고를 것이 없습니다
- 성장 추이에서 한쪽만 잰 날은 **그 값만** 옵니다. 빈 칸을 채우지 않습니다
- 12–17개월 교육 활동에는 경고 문구(물놀이 · 비닐)가, 환경 알레르기를 등록한 아이의 교육 활동에는 확인 문구가 붙어 올 수 있습니다. 두 문구의 자리는 #249 에서 정합니다

### 백엔드
- `profile_affinity` 읽기 포트는 **domain을 복수로 받습니다** — `domains: tuple[str, ...]`. Growth는 education · activity 둘을 봅니다(routine 은 affinity 가 없다, 09-23)
- `health_safety` 읽기 포트(`allergy` · `environmental`)를 Growth 도 받습니다 — 교육 활동 필터용. 읽기 실패는 `SafetyLookupError` 로 올리고 빈 목록으로 돌려주지 않습니다
- Growth는 Activity 패키지를 import하지 않습니다. `observation_activity` 접근은 **포트 주입**입니다
- `growth_review`는 AI 클라이언트를 아예 호출하지 않는 경로입니다

### QA
필수 확인 케이스:
- `trigger`가 NULL인 습관 → 교정안 대신 **되묻기**가 나오는가
- 측정 1건 → "기록이 두 번 이상 필요해요"가 나오고 AI 호출이 **0회**인가
- 측정 간격이 2주여도 **그 값이 그대로 나오는가** (간격으로 막지 않는다)
- `growth_review` 응답에 측정일이 **전부** 있는가
- `routine_coaching` 근거 0행 → 카테고리와 무관하게 **역질의**가 나오는가 (일반 제안 금지)
- 0–11개월 루틴 → 추천 카드가 아니라 **안내 한 줄**인가 (`suggestion` 0건)
- 승인된 추천이 라벨대로 `observation_education` / `observation_routine`에 들어가는가. **`observation_activity`에 0건인가**
- 자립 제안이 `next_step_of` 사슬을 건너뛰지 않는가
- "또래보다", "잘 크고 있", "발달이" 같은 **판정 표현이 출력에 없는가**
- "잘 크고 있어?" → Growth로 오고, 추이 + 검진 안내만 나오는가
- 추천이 **최대 3개**인가 (4개 이상이 없고, 채울 수 있을 때 2개 이하로 나가지 않는가)
- 놀이 기록이 근거일 때 화면 문구가 맞는가
- Curator가 없어서 확정 관심이 0건일 때 정상 동작하는가
- 교육·루틴 후보에 **음식 이름**(알레르기 사전 · 질식 위험 음식)이 없는가 — 아이에게 알레르기가 없어도
- 등록한 알레르기 이름(라텍스 · 꽃가루)이 든 교육 활동이 안 나오고, 환경 알레르기가 있으면 확인 문구가 붙는가. 동의가 없으면 교육이 그대로 나오는가
- 알레르기 조회 실패 → 교육만 닫히고 루틴·도서는 그대로인가
- 같은 카테고리 루틴 관찰이 15일 전 것뿐이면 **역질의**인가. 다른 카테고리 관찰만 있어도 역질의인가
- 한쪽만 잰 기록 · 24개월을 걸친 키 측정에서 서술이 맞는가
- "약 먹기 싫어해" · "눈을 자꾸 깜빡여" → 교정안 없이 닫힘 문구만 나오고 AI 호출이 **0회**인가
- 추천을 저장하면 대화에 결과 블록의 "후보 보기 →"(05 · `run_id`)가 나오고, 그 링크로 연 05 가 추천을 새로 만들지 않고 같은 run 의 것을 보여주는가. 대화로 "그걸로 할게" 라고 하면 **승인 0건** · 제안 화면 안내인가

## 10. 확장 계획

### 다음 단계
- **기관 공지 연동** — 이미지 공지는 OCR 파이프라인이 일반 공지(`notice`) / 일정성 공지(→ Memory → `event`) / 급식표로 나눕니다. 텍스트 공지는 Memory가 구조화합니다. Growth는 `notice`와 `category='institution'` 일정을 읽기만 합니다. 공지 파싱 자체는 이 Agent의 일이 아닙니다
- **루틴 행 보강** — 지금은 교육과정 자료만 `growth_doc`에 있습니다. 습관 교정 전략(`habit_strategy`)은 별도 원문이 필요합니다
- **몰입도 기반 학습** — `engagement_level`(low/mid/high)을 다음 추천에 반영하는 루프

### 중기
- **성장 급등기 맥락 제공** — 성장폭이 클 때 식사량·수면 변화의 **가능한 배경**으로만 언급. 판정은 여전히 안 함
- **형제 간 비교 차단 검증** — 한 계정에 아이가 여럿일 때 비교 문장이 새지 않는지
