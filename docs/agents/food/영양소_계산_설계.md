## 1. 설계 전제 여섯

1. **수치는 내부, 출력은 구간.** 충족률·z값은 계산 근거로만 쓰고 화면·모델 입력에 내보내지 않는다.
2. **판정 기간은 3~7일.** 섭취기준은 습관적 섭취를 전제로 한 값이라 하루로 부족을 말할 수 없다.
3. **결측은 0이 아니다.** 기록이 없는 구간은 분석에서 빼고 기록 건수로 표시한다. 끼니를 정의하지 않으므로 "몇 번째 끼니가 비었나"는 세지 않는다.
4. **기준값은 종류를 구분한다.** 부족은 EAR, 과잉은 UL, 탄단지는 AMDR.
5. **키·몸무게는 권장 열량 계산에만 쓴다** (2026-09-22 변경). 영양소 기준은 연령군 일반값이고, 권장 열량만 최근 측정값으로 조정한다. 측정이 없으면 연령군 일반값. 측정값으로 과체중·저체중을 판정하지 않는다.
6. **성별은 쓰지 않는다.** 성별에 따른 섭취량 차이는 확인할 수 없으므로 성별 구분 없는 값만 쓴다.
7. **부족 판정이 기피보다 앞선다.** `low`로 판정된 식품군은 기피(−1) affinity가 있어도 후보 풀에서 빠지지 않는다. 기피는 그 식품군 **안에서 어떤 형태를 고를지**를 정하는 값이다 — [`Food_Agent_명세.md`](Food_Agent_명세.md) §6.

## 2. `nutrient_reference` — 참조 기준

### 스키마

| 필드 | 타입 | 비고 |
| --- | --- | --- |
| `id` | uuid | PK, `uuidv7()` |
| `age_group` | varchar(8) + CHECK | `0-5m` · `6-11m` · `1-2y` · `3-5y` |
| `sex` | varchar(8) | `male` · `female` · **NULL = 구분 없음.** 지표별로 다름. **조회는 `sex IS NULL` 행만** (성별 미사용) |
| `nutrient` | varchar(32) | `energy` · `protein` · `carbohydrate` · `fat` · `sodium` · `calcium` · `iron` · `vitamin_a` · … |
| `ref_type` | varchar(8) + CHECK | `EAR` · `RNI` · `AI` · `UL` · `AMDR` |
| `value_min` · `value_max` | numeric | `AMDR`은 범위, 나머지는 `value_min`만 |
| `unit` | varchar(16) | `kcal` · `g` · `mg` · `%kcal` |
| `source_version` | varchar(16) | `kdri_2025` |
| `note` | text | 기준의 단서 (예: "모유 섭취 기준") |

```sql
UNIQUE (age_group, sex, nutrient, ref_type, source_version)
CHECK (value_max IS NULL OR value_max >= value_min)
CHECK (ref_type <> 'AMDR' OR unit = '%kcal')
```

### 적재

- 원문 표 → CSV → Alembic 시드. **손으로 옮긴 값은 2인 대조**를 거친다(숫자 오타가 곧 판정 오류).
- `source_version`으로 세대를 관리한다. 기준이 개정되면 새 버전을 넣고 조회 기본값만 바꾼다. **기존 행을 덮어쓰지 않는다.**
- 0–11개월 행도 넣되 **분석에는 쓰지 않는다**(영아기 영양소 분석 미지원). 단계 판정·문구에만 참조.

### 어떤 `ref_type`을 언제 쓰나

| 목적 | 기준 | 이유 |
| --- | --- | --- |
| 부족 여부 | **EAR** | RNI는 집단의 97~98%를 충족시키는 값이라, 개인 기록에 대면 대부분 "부족"이 뜬다 |
| 목표 제시 | RNI · AI | 화면에는 숫자로 내보내지 않고 방향으로만 |
| 과잉 여부 | **UL** | 상한이 정의된 항목에만 |
| 탄단지 균형 | **AMDR** | 양 추정 오차에 가장 덜 민감한 지표 |
| 열량 | 연령군 일반값 → **키·몸무게로 조정** (`compute_energy_target`) | 측정 없으면 연령군 일반값. 계산식은 성별 없는 식으로 선정(N-9) |

**과잉을 말하는 항목은 나트륨 · 당류 · 포화지방으로 제한한다.** 미량영양소 과잉은 식품만으로는 드물고, 언급하면 불안만 만든다.

## 3. 영양 판정 — 저장하지 않고 원본에서 매번 계산

**영양 합계와 영양 구간은 저장하지 않는다.** 판정이 필요할 때마다(식단 추천 직전 · 영양소 분석) 원본에서 계산하고, 결과는 그 task 의 run state 에만 둔다. DB · 로그에 남기지 않는다.

원본은 둘이다. 집에서 먹은 것은 `observation_food`(Memory 소유), 기관에서 먹은 것은 `daycare_meal`(Food 소유 — [`food_agent_own_table.md`](food_agent_own_table.md) §5). 파생 테이블을 따로 두지 않는 이유는 다음과 같다.

- 보호자가 기록을 고치면(수정 · "잘못된 기록" · 삭제) 다음 판정에 바로 반영된다. 파생 행을 같이 고칠 일이 없다.
- 끼니 슬롯도 UNIQUE 제약도 없어서 파생 행을 upsert 할 기준 키가 없다.
- 보관 기간을 정해야 할 아이 데이터가 늘지 않는다.
- 무거운 부분(외부 API 결과)은 메뉴 카탈로그에 쌓여서, 한 번 찾은 메뉴는 다시 외부를 부르지 않는다. 남는 것은 카탈로그 조회와 곱셈이고, 아이 한 명의 2주 치 기록은 많아야 수백 건이다.

### 계산 흐름

```
판정이 필요할 때 (evaluate_nutrient_bands · compare_diet_balance)
  ① 원본 읽기 — 조회 포트 두 번. 판정 창 7일 + 다시 판정 7일 = 14일 치
       observation_food  active · stand_alone 행 (memory_bridge 와 같은 기준)
       daycare_meal      오늘 이전 행 (과거 30일 보존 범위 안)
  ② 메뉴 → 영양 — 정규화 · 표기 사전 → menu_catalog 를 get_many 로 한 번에 조회
       없는 키만 resolve_menu — 외부 조회, 이름이 정확히 같을 때만, 판정 한 번에 상한. 못 찾으면 unresolved
       nutrients 가 빈 행(사람이 넣은 행 등)도 unresolved — 0 으로 넣지 않는다 (§1-3)
       양은 §4 사전, 1인분은 유아 보정 계수(개 단위 식품군은 곱하지 않는다, N-3), amount_known=false 는 그 기록에 절반 가중
       1인분 중량(serving_g)이 빈 메뉴는 영양 합계에서 빼고 식품군 출현에만 쓴다. 빠진 몫이 큰 영양소는 구간을 내지 않는다 (§4 · N-16)
  ③ 날짜별 영양 합계 → 7일 창 일평균. 그날 급식이 있으면 기관 출처 관찰은 뺀다(아래)
  ④ 7일 전부터 하루씩 다시 판정 → 전날 구간 → 오늘 판정에 히스테리시스 (§6)
  ⑤ 결과(구간 · 식품군 · 기록 행 수)는 run state 에만. 저장 · 로그 없음
```

- **다시 판정하는 일수는 7일로 고정한다.** 히스테리시스는 일평균이 EAR 과 1.1배 사이에 머무는 동안만 전날 구간을 이어 가고, 그 범위를 벗어나는 날 구간이 새로 정해진다. 그래서 7일 전부터 하루씩 판정하면 전날 구간이 나온다. 저장해 둔 판정과 결과가 갈리는 것은 일평균이 7일 내내 EAR 과 1.1배 사이에 머문 경우뿐이고, 그때는 기본 기준으로 돌아간다.
- **근거는 원본 행이다.** `suggestion_evidence` 는 `observation_food` · `daycare_meal` 행을 가리킨다.
- **메뉴 카탈로그가 갱신되면 지난 기간의 판정도 새 값으로 바뀐다.** 영양 구간은 최신 카탈로그 기준이 맞다고 본다. 지난 분석 결과를 그대로 다시 보여 줘야 하는 화면이 생기면 다시 본다.
- **당류 · 포화지방은 선택 칸이다** (10-11 정함). 영양DB 에서 당류가 빈 행이 많다(김치볶음밥 · 멸치). 당류가 비었다고 메뉴를 unresolved 로 두면 그 메뉴의 칼슘 · 단백질까지 합계에서 빠져 거짓 `low` 가 난다. 그래서 메뉴는 해석하고 다른 항목 합계에 넣되, 판정 기간에 그 칸을 모르는 메뉴가 섞이면 **그 항목만 구간을 내지 않고 안내만 낸다**(0 으로 채우지 않는다). 안내 문구는 코드 문구로 둔다 — 구현 때 정한다.
- **기관 식사는 `daycare_meal` 만 센다** (N-10, 10-06 정함 — 출처로 짐작). 그날 오늘 이전 `daycare_meal` 행이 있으면, 기관에서 온 것으로 보이는 `observation_food` 행을 하루 합계와 기록 행 수에서 뺀다.
  - 알림장 · 기관 공지에서 온 관찰 — `confidence_source='institution_notice'` 이거나 `source_notice_id` 가 있다.
  - 전해 들은 관찰(`confidence_source='parent_hearsay'`) 가운데 subject 가 그날 급식 `menu_keys` 의 메뉴로 해석되는 것 — "선생님 말로는 카레 먹었대" 같은 말이다. 급식에 없는 메뉴(할머니 댁에서 먹었대 등)는 집 식사로 남는다.
  - 그날 급식 행이 없으면 빼지 않는다. 관찰 행은 그대로 두고 합계에서만 뺀다 — 근거 · 선호 집계는 영향이 없고, 양은 급식 행을 따른다.
  - 기관 신호가 있는 보호자 말("어린이집에서 … 먹었대")은 Supervisor 가 `food/daycare_meal` 로 보내 관찰로 잘 남지 않는다. 겹침은 주로 알림장과, 기관 신호 없이 전해 들은 말에서 생긴다.
  - 출처 두 칸은 저장하는 쪽이 정한다. 보호자 말은 Memory Agent 가 발화를 보고 `confidence_source` 를 고르고(`app/agents/memory/schemas/common.py`), `source_notice_id` 는 채우지 않는다. 그래서 보호자 말에서 온 관찰은 `confidence_source` 로만 갈린다. OCR 분석이 쓰는 관찰은 그 경로가 두 칸을 따로 정한다. Food 는 값을 정하지 않고 `FoodObservation` 으로 읽어 오기만 한다(`app/agents/food/store/ports.py`).
- ① 에서 `observation_food` 의 판정 창에 오늘을 넣는지는 미결이다(N-12). `daycare_meal` 은 오늘 이전으로 정해져 있다.
- ⑤ 의 결과를 담을 칸은 아직 `FoodRunState`(`app/agents/food/context.py`)에 없다. 지금 더하면 쓰는 곳이 없어서, 계산을 구현할 때 더한다.

### 비용을 작게 두는 조건

- **카탈로그에 없는 메뉴는 외부에서 찾아 쌓는다** (10-06). 찾은 메뉴는 메뉴 카탈로그에 쌓여 다음 판정부터 외부를 부르지 않는다. 이름이 정확히 같은 결과만 받고(비슷한 메뉴 추정 금지), 못 찾은 이름과 장애는 카탈로그에 남기지 않는다 — 남기면 보호자 말에서 나온 이름이 전역 테이블에 남는다. 같은 이름을 판정마다 다시 묻지 않게 못 찾은 이름은 프로세스 메모리에 짧게 기억하고, 판정 한 번의 외부 조회 수에는 상한을 둔다 — [`food_agent_own_table.md`](food_agent_own_table.md) §1.
- **메뉴 조회는 한 번에 한다.** `MenuCatalogStore.get_many(menu_keys)` 한 번으로 14일 치 메뉴를 읽는다. `get` 처럼 `resolved` 와 무관하게 있는 행을 돌려받고, 해석 여부는 판정이 `resolved` 로 가른다.
- 그래서 한 번 판정하는 비용은 원본 조회 두 번 · 카탈로그 조회 한 번 · 곱셈, 그리고 처음 보는 이름의 외부 조회(상한 안)다. 1차 배포까지 판정 결과 재사용은 넣지 않는다(N-11).

## 4. 양 추정 규칙

| `amount` 텍스트 | `amount_factor` | `amount_known` |
| --- | --- | --- |
| 엄청 많이 · 많이 · 더 달라고 했대 | 1.5 | true |
| 다 먹음 · 한 그릇 | 1.0 | true |
| 반 그릇 · 절반 | 0.5 | true |
| 조금 · 몇 입 | 0.25 | true |
| 남김 · 남겼대 (양 불명) | 0.5 | **false** |
| 뱉음 · 안 먹음 | 0.0 | true |
| 기록 없음 | 1.0 | **false** |
| 급식 (메뉴만) | 1.0 | **false** |

- `amount_known=false` 행은 **식품군 출현·다양성 계산에는 쓰고, 부족·과잉 판정의 분모에는 절반 가중**으로 들어간다.
- 1인분은 성인 기준이므로 유아 보정 계수를 곱한다(`reference/portion_scale.yaml`, 1–2세 · 3–5세). 이 계수는 **구간 판정에만** 쓰고 절대량으로 노출하지 않는다. 다만 우유 한 팩 · 과일 한 개처럼 개 단위로 먹는 식품군(`dairy` · `fruits`)만 있는 메뉴는 곱하지 않는다(N-3) — 곱하면 우유 200ml 가 56g 이 된다.
- **1인분 중량(`serving_g`)이 빈 메뉴** (10-11 정함, #326 리뷰 — 1차 배포 기준). 영양DB 의 원재료성 · 가공식품 품목대표는 대부분 비어 있다 — 메뉴명 30개 점검에서 찾은 21개 중 5개(우유 · 두유 · 백김치 · 동그랑땡 · 김치볶음밥). 100g 이든 다른 값이든 양을 가정하면 없는 숫자를 만드는 것이라:
  - 그 메뉴는 **영양 합계에서 빼고**, 식품군 출현 · 다양성 계산에만 쓴다.
  - 대신 그 메뉴가 표준 1인분이었다면 더했을 양을 따로 센다(합계에는 넣지 않는다). 합계에 못 넣은 몫이 큰 영양소는 구간을 내지 않는다 — 메뉴 개수가 아니라 영양 기여로 본다(N-16).
  - 1차 배포 뒤 다음 단계로, 식약처 고시 「식품등의 표시기준」의 1회 섭취참고량을 식품 유형별 기본값으로 두는 안을 본다(N-15).
- 이 표의 정본은 `apps/api/reference/amount_terms.yaml` 한 파일이다. 집 식사와 급식이 같이 쓴다.

## 5. 기록이 충분한가 — 행 수

끼니 비율로 세던 커버리지를 버렸다. 끼니 슬롯이 없으니 "기대 끼니 수"라는 분모가 성립하지 않는다.

```
records   = observation_food(최근 7일, active · stand_alone) + daycare_meal(최근 7일, 오늘 이전)  의 행 수
resolved  = 해석된 메뉴 수 / 기록에 나온 메뉴 수        (§3 ② 에서 기록마다 센다)
```

- **`records < 10` (설정값) → `insufficient=True`** → 수치 기반 결론 없음. 선호·반복 기반 추천 + 기록 부족 안내.
- 메뉴 해석률(`resolved`)은 따로 본다. 행은 충분한데 메뉴를 못 읽으면 그것도 결론을 막는다. `unresolved` 메뉴만 있는 기록도 `records` 에 넣는다(N-13, 10-13 정함) — 해석률이 따로 결론을 막아서 행 수에서 또 뺄 필요가 없다.
- `serving_g` 가 없어 합계에 못 넣은 몫이 클 때도 결론을 막는다 — 열량은 판정 전체(`insufficient`), 그 밖의 영양소는 그 영양소만(`unscored`). 영양값이 하나도 없는 메뉴가 전체의 절반을 넘어도 `insufficient` 다(N-16).
- 화면에는 "최근 7일 중 12건 기록됨"처럼 **건수로** 표시한다. 퍼센트는 쓰지 않는다.
- 하루 평균 1.5행이 기준이다. 급식이 있는 아이는 평일만으로 채워지고, 집에서만 먹는 아이도 하루 2건이면 닿는다.

## 6. 구간 판정

```python
def band(intake, ref) -> Literal["low", "ok", "high"]
```

| 항목 | low | ok | high |
| --- | --- | --- | --- |
| 일반 영양소 | 평균 섭취 < EAR | EAR ~ UL | UL 초과 (UL 있는 항목만) |
| 탄수화물·단백질·지방 | AMDR 하한 미만 | AMDR 범위 안 | AMDR 상한 초과 |
| 나트륨·당류·포화지방 | – | 상한 미만 | 상한 근접·초과 |

- 입력은 **분석 기간의 일평균**이다. 하루 값으로 판정하지 않는다. 기록이 없는 날은 평균에서 뺀다 — 0 으로 넣지 않는다(§1-3). 구현은 `app/rules/nutrition.py`.
- "상한 근접" 은 기준값이 정해지지 않아 지금은 **상한을 넘을 때만** `high` 다(10-11). 근접 기준을 정하면 그 숫자를 근거와 함께 여기 적는다.
- 경계에서 흔들리지 않도록 **히스테리시스**를 둔다: 한 번 `low`로 표시한 항목은 EAR의 1.1배를 넘어야 `ok`로 돌아간다. 매일 결론이 뒤집히면 신뢰를 잃는다. 전날 구간은 저장하지 않고 다시 판정해서 얻는다(§3 ④).
- `high`는 나트륨·당류·포화지방과 AMDR 상한에만 쓴다.

### 구간 → 화면 문구 (코드가 식품군으로 번역)

| 항목 · 구간 | 식품군 행동 |
| --- | --- |
| 단백질 `low` | 고기·생선·달걀·콩 반찬 늘리기 |
| 칼슘 `low` | 우유·유제품 |
| 철 `low` | 붉은 고기·달걀노른자·콩 |
| 탄수화물 `high` | 밥·빵·면 줄이고 반찬 한 가지 |
| 나트륨 `high` | 국물·절임 줄이기 |

모델은 이 표에서 나온 `food_group_action`을 문장으로 다듬을 뿐, 항목을 추가하거나 수치를 쓸 수 없다.

문장의 주어는 늘 **먹은 식사 · 기록**이다("기록된 식사 9건을 보면 …"). 아이 몸 상태 · 수치 · 진단 · 처방 · 또래 비교로 읽히는 문장은 `nutrient_wording.wording_problem` 이 거절한다 — 목록 검사라 목록 밖 표현은 못 막으므로 프롬프트와 라이브 eval 이 함께 본다. 판정(`compare_diet_balance`) 없이 `report_nutrient_analysis` 를 부르면 거절한다. 기록은 충분한데 모든 항목이 빈 칸이라 구간이 하나도 없으면 findings 를 비우고 `nutrient.unscored`("아직 살펴보지 못했어요")를 낸다 — "고르게 담겨 있어요" 같은 근거 없는 안심을 하지 않는다(#357 리뷰). 화면 문장의 구간 표현은 "적은 편 · 적당 · 많은 편"(식품을 말하는 표현)으로 맞춘다 — "칼슘이 낮은 편" 은 검사 수치처럼 읽힌다. 1차 출력(N-17)은 이 문장들을 화면에 내지 않는다 — 구간은 판정해 두고 식품군 출현 문장만 코드 틀로 낸다(N-18). 아래 문장 규칙 · `check_summary` 와 `nutrient.band.*` 문장 틀은 구간을 다시 낼 때 쓴다.

**아이의 알레르기 식품은 뺀다**. 표는 아이를 모른다 — 달걀 알레르기 아이도 단백질이 `low` 면 "고기·생선·달걀·콩 반찬 늘리기" 를 받는다. 그래서 표(`reference/nutrient_actions.yaml`)의 먹이는 안내마다 식품별 19종 코드를 달고, 그 식품을 메뉴 행처럼 만들어 `filter_food_safety` 에 그대로 통과시킨 뒤 남은 것만 안내한다(`app/agents/food/nutrient_actions.py`). 알레르기 · 질환 판정을 따로 짜지 않는다 — 묶음 이름("육류") · 질환("유당불내증") · 한 글자 규칙이 모두 필터의 사전을 따른다.

- 달걀 알레르기 + 단백질 `low` → "고기·생선·콩 반찬 늘리기" · 철 `low` → "붉은 고기·콩"
- 표의 식품이 다 빠지면(칼슘 `low` + 우유 알레르기) **식품 안내 없이 구간만** 말한다. 다른 급원 식품을 더하려면 섭취기준 원문 근거가 있어야 한다
- 코드는 넓게 단다 — "고기" 는 돼지 · 닭 · 쇠고기 셋이라 그중 하나만 알레르기여도 "고기" 를 통째로 뺀다(덜 안내하는 쪽)
- 줄이는 안내("밥·빵·면 줄이고 반찬 한 가지" · "국물·절임 줄이기")는 먹이라는 말이 아니라서 거르지 않는다
- **요약 검사는 별칭 + 안전 필터 사전 둘 다 건다**(10-11 정함, #326 리뷰 · N-14) — `check_summary`(`app/agents/food/nutrient_actions.py`). 빠진 식품의 이름 · 별칭이 남았거나(`mentions_removed`), 문장을 메뉴 행처럼 `filter_food_safety` 에 걸어 이 아이에게 막히는 음식(알레르기 · 질환 · 연령 규칙)이 있으면 거절한다. 잘못 막으면 요약 하나를 거절할 뿐이고, 놓치면 알레르기 음식을 권하게 된다(#264 의 "애매하면 막는다" 와 같다). `run()` 에 붙이는 것은 #321 파트 2 다.
  - 별칭은 표에 두 글자 이상으로만 적는다(달걀 → 계란 · 노른자). 사전은 한 글자 별칭이 말끝에 걸리기도 한다(게 알레르기에서 "먹게 해 주세요").
  - 사전에 구멍이 있으면 이 검사도 뚫린다. 그래서 eval 에서 찾은 음식 이름을 단위 테스트에 고정해 두고(`test_nutrient_actions.py` `SUMMARY_FOODS`), 사전을 고칠 때마다 같이 돈다. 10-11 에 이 목록으로 부위 · 요리 이름(안심 · 등심 · 선지 · 곱창 · 장조림 · 앞다릿살 · 돈가스의 달걀 · 프렌치토스트와 수프의 우유 …)을 사전에 더했다(Food_Tool_명세 §3).
  - 다시 돌린 결과(10-11 세 번째) — 확실히 든 음식을 권한 70문장을 모두 막았다(별칭만이면 25개를 놓친다). 남은 식품만 권한 72문장은 하나도 막지 않았다.
- ⚠️ **처음 쟀을 때 — 별칭만으로는 모자랐다** (10-11 라이브 eval `test_nutrient_advice`, N-14). 모델에게 아이의 알레르기 성분이 든 음식을 권하는 문장을 쓰게 하니, 확실히 든 음식을 권한 74문장 중 28개를 별칭 검사가 놓쳤다 — 부위(삼겹살 · 닭다리살) · 다른 이름(돈육 · 계육 · 밀크) · 요리(삼계탕 · 갈비찜 · 에그샌드위치 · 된장국) · 묶음 알레르기(해산물인데 표의 식품은 생선뿐이라 새우 · 오징어). 같은 문장에 안전 필터 사전을 걸면 그중 25개를 잡았고, 남은 식품만 권하는 문장 72개는 두 검사 모두 하나도 막지 않았다. 사전의 한 글자 걱정은 일부만 맞다 — 게 알레르기에서 "적게" 는 통과하고 "먹게 해 주세요" 는 막혔다. 같은 eval 에서 철 `low` 의 "달걀노른자" 별칭에 달걀 · 계란이 없어 "달걀을 챙겨 주세요" 가 지나가는 것을 찾아 별칭을 더했다
- 안전 조회에 실패하면 이 단계까지 오지 않는다 — 영양소 분석 자체가 `blocked.safety` 로 닫힌다(Food_Tool_명세 §1)

## 7. 식단 추천에서의 사용

| 상황 | 쓰는 값 |
| --- | --- |
| 오늘 이미 먹은 끼니가 있음 | 오늘 `observation_food`의 식품군(§3 ② 에서 메뉴 카탈로그로 읽은 것) → **중복 회피**(점심에 고기면 저녁은 채소 위주) |
| 오늘 기록 없음 | 최근 3~7일 구간 판정 → `low` 항목의 식품군에 가중 |
| 행 수 미달 | 영양 가중 없이 선호·반복 기반 |

### 후보 뽑기

```
후보 풀 (≤30)
  → 점수 = 근거 가중 + low 식품군 보너스 − 최근 반복 패널티 (최근 3일 먹은 메뉴와 이름이 같으면 가중치 ↓, 풀에서 빼지 않는다)
  → sample_candidates(seed=run_id): 점수 가중 샘플링으로 10~15개
  → 주재료·식품군 다양성 제약 (같은 주재료 2개 이하)
  → 모델이 3개 선택
  → 사후 안전 필터 후 3개 미만 → 걸러진 메뉴를 빼고 재샘플링 → 모델 재호출 1회
```

- 샘플링은 **안전 필터와 중복 제거 뒤에** 온다. 앞에 두면 위험한 후보가 뽑힐 자리가 생긴다.
- `run_id`를 시드로 저장한다. 같은 `run_id`면 같은 결과가 나와야 한다(재현·QA).
- **부족 판정 자체는 랜덤화하지 않는다.** 흔드는 것은 메뉴뿐이다.

## 8. 테스트

| 케이스 | 기대 |
| --- | --- |
| 아침·점심 결측 + 저녁 요청 | 결측이 0으로 들어가지 않음. 한 끼 몰아주기 없음 |
| 급식만 기록된 날 | `amount_known=false`로 절반 가중, 식품군에는 반영 |
| 7일 8행 | `insufficient=True`, `findings` 비어 있음 |
| `unresolved` 다수 | `menu_coverage` 하락이 `coverage`에 반영 |
| EAR/RNI 혼동 | 같은 섭취량에서 RNI 기준이면 `low`, EAR 기준이면 `ok` — **EAR을 쓰는지 확인** |
| 경계 진동 | EAR 근처 값이 연속 3일 `low`→`ok`→`low`로 바뀌지 않음 (히스테리시스) |
| 미량영양소 UL 초과 | `high`로 보고하지 않음 (대상 항목 제한) |
| 같은 입력 3회 | 후보 3개가 매번 다름. 같은 `run_id`면 동일 |
| 키·몸무게 없음 | 권장 열량이 연령군 일반값으로 계산됨 |
| 성별 입력 | 결과에 영향 없음 (입력 자체가 없음) |
| 출력 검사 | readout에 `%`·`g`·`mg`·`kcal` 문자 0건 |
| 카탈로그 갱신 후 | 지난 기간 판정도 새 값으로 계산됨 (저장한 판정이 없다) |
| 기록을 고친 뒤 | 다음 판정에 바로 반영 — "잘못된 기록"(`inactive`) · 삭제한 관찰은 합계에서 빠짐 |
| 일평균이 7일 내내 EAR ~ 1.1배 사이 | `ok` — 첫날을 직전 구간 없이 판정한다. 저장한 판정과 갈리는 유일한 경우 |
| 판정 중 외부 호출 | 카탈로그에 없는 이름만, 판정 한 번에 상한 이하. 같은 이름은 판정 한 번에 한 번 |
| 레시피 DB 에서만 찾은 메뉴(`nutrients` 빈 행) | 합계에 0 으로 들어가지 않고 unresolved 로 셈 |
| 판정 뒤 메뉴 카탈로그 | 이름이 정확히 같게 찾은 메뉴만 새 행. 못 찾은 이름("맛있는된장찌개" 등)은 남지 않음 |
| 같은 못 찾은 이름으로 다시 판정(짧은 기간 안) | 외부 호출 0회 — 프로세스 메모리에서 거름 |
| 외부 API 장애 중 판정 | 카탈로그에 행이 생기지 않음 · 그 판정에서 unresolved |
| 알림장에서 온 관찰 + 그날 급식 있음 | 그 관찰은 하루 합계 · 기록 행 수에서 빠짐 |
| 전해 들은 관찰 + 그날 급식에 같은 메뉴 | 빠짐 |
| 전해 들은 관찰 + 급식에 없는 메뉴 | 집 식사로 합계에 들어감 |
| 알림장에서 온 관찰 + 그날 급식 없음 | 합계에 들어감 |
| 판정이 끝난 뒤 | DB · 로그에 영양 합계 · 구간이 남지 않음 |
| 당류가 빈 메뉴가 섞임 | 그 메뉴는 다른 항목 합계에 들어가고, 당류만 구간 없이 안내 |
| 달걀 알레르기 + 단백질 `low` | 안내 · 문장에 달걀(계란 · 노른자)이 없음 |
| 우유 알레르기 + 칼슘 `low` | 식품 안내 없이 구간만 |
| 안전 조회 실패 · 포트 미전달 | 영양소 분석이 모델 0회로 `blocked.safety` |

EAR 항목은 다시 판정하는 앞 7일 창마다 같은 기준으로 보고, 하나라도 걸리면 구간을 내지 않는다 — 앞 창의 거짓 low 가 히스테리시스로 남는다. 50% 는 해석률과 같은 값이고 200g 은 우유 한 팩 · 밥 한 공기 · 찌개 한 그릇의 어림이다 — 둘 다 근거 문서가 있는 값이 아니라 잠정 |

| N-17 | 영양소 분석 1차 출력 | **✅ 정함(#357 PM 답글, #411)** — 구간은 판정해 두되 화면에는 식품군 출현만 말한다. 식품군마다 최근 7일(판정 창) 중 나온 날 수(`NutrientVerdict.food_group_days`)와 기록이 있는 날 수(`recorded_days`)를 센다 — "기록된 7일 중 채소가 나온 날은 3일이에요". 무게를 몰라도 센다(`serving_g` 임계를 걸지 않는다). 먹은 것만 센다 — 안 먹음 · 뱉음(양 0)과 싫어한다는 관찰(polarity 음수)은 "나온 날" 이 아니다. 출현을 말해도 되는지(`appearance_ready`)는 기록 행 수 임계(N-1), 메뉴 해석률, 식품군을 아는 메뉴의 비율을 본다 — 앞의 둘은 기록이 2건뿐인데 "7일 중 1일" 이라고 말하지 않으려는 것이고, 마지막은 식품군이 빈 메뉴(찌개 · 국 같은 음식 행)가 절반을 넘으면 "채소 0일" 이 안 나온 게 아니라 모르는 것이라서다(해석률과 같은 50%). 기록은 충분한데 못 읽었으면 `nutrient.unscored`, 기록이 모자라면 `nutrient.insufficient`. 아이의 알레르기 · 질환으로 막히는 식품군은 말하지 않고(`blocked_groups`) 유지 · 당류는 말하지 않는다. 한계: 식품군은 대분류 이름이 대응표에 있는 식품에만 붙어서 찌개 · 국 같은 음식 행과 원재료성 행(우유)은 비어 있다 — 식품군을 아는 메뉴가 절반을 넘기 전까지는 출현 문장 대신 `nutrient.unscored` 가 나가고, 넘더라도 출현은 실제보다 적게 센다(원재료성 행은 별도 이슈) |

| N-19 | 채소 · 과일 부족 가중 | **🟡 잠정 정함(#411)** — 후보 풀의 부족 식품군(`meal_pool._deficit_groups`)에 영양 구간에서 오는 식품군 말고 채소(`vegetables`) · 과일(`fruits`)을 더한다. 최근 7일에 기록된 날의 **절반 미만**으로 나온 식품군이다(7일 기록이면 3일 이하). 출현을 말할 수 있을 때(`appearance_ready`)만 보고, 영양 판정 단계(12개월 이상)가 아니면 보지 않는다. 가중치는 `DEFICIT_BOOST` 를 영양 구간과 같이 쓰고 한 메뉴에 한 번만 곱한다. 기준은 근거 문서가 있는 값이 아니라 "매일 먹는 것이 기본인 식품군이 절반 넘는 날 빠졌다" 는 어림이라 잠정이다. 식품군이 안 붙은 음식 행이 많아 출현이 적게 세어지므로 가중이 걸리기 쉽다 — 후보를 막지 않고 가중치만 올리니 틀려도 후보가 줄지는 않는다 |
