# 영양소 계산 설계 — `nutrient_reference` · `intake_daily`

> Food Agent의 영양소 분석과 식단 추천이 쓰는 계산·스키마 정본.
> 관련: [`Food_Agent_명세.md`](Food_Agent_명세.md) §5-1 · [`Food_Tool_명세.md`](Food_Tool_명세.md) §0 · [`외부연결_계획.md`](../shared/외부연결_계획.md) §2

---

## 1. 설계 전제 여섯

1. **수치는 내부, 출력은 구간.** 충족률·z값은 계산 근거로만 쓰고 화면·모델 입력에 내보내지 않는다.
2. **판정 기간은 3~7일.** 섭취기준은 습관적 섭취를 전제로 한 값이라 하루로 부족을 말할 수 없다.
3. **결측은 0이 아니다.** 기록이 없는 구간은 분석에서 빼고 기록 건수로 표시한다. 끼니를 정의하지 않으므로 "몇 번째 끼니가 비었나"는 세지 않는다.
4. **기준값은 종류를 구분한다.** 부족은 EAR, 과잉은 UL, 탄단지는 AMDR.
5. **키·몸무게는 권장 열량 계산에만 쓴다** (2026-09-22 변경). 영양소 기준은 연령군 일반값이고, 권장 열량만 최근 측정값으로 조정한다. 측정이 없으면 연령군 일반값. 측정값으로 과체중·저체중을 판정하지 않는다.
6. **성별은 쓰지 않는다.** 성별에 따른 섭취량 차이는 확인할 수 없으므로 성별 구분 없는 값만 쓴다.
7. **부족 판정이 기피보다 앞선다.** `low`로 판정된 식품군은 기피(−1) affinity가 있어도 후보 풀에서 빠지지 않는다. 기피는 그 식품군 **안에서 어떤 형태를 고를지**를 정하는 값이다 — [`Food_Agent_명세.md`](Food_Agent_명세.md) §6.

## 2. `nutrient_reference` — 참조 기준

### 스키마

| 필드 | 타입 | 비고 |
| --- | --- | --- |
| `id` | uuid | PK, `uuidv7()` |
| `age_group` | varchar(8) + CHECK | `0-5m` · `6-11m` · `1-2y` · `3-5y` |
| `sex` | varchar(8) | `male` · `female` · **NULL = 구분 없음.** 지표별로 다름. **조회는 `sex IS NULL` 행만** (성별 미사용) |
| `nutrient` | varchar(32) | `energy` · `protein` · `carbohydrate` · `fat` · `sodium` · `calcium` · `iron` · `vitamin_a` · … |
| `ref_type` | varchar(8) + CHECK | `EAR` · `RNI` · `AI` · `UL` · `AMDR` |
| `value_min` · `value_max` | numeric | `AMDR`은 범위, 나머지는 `value_min`만 |
| `unit` | varchar(16) | `kcal` · `g` · `mg` · `%kcal` |
| `source_version` | varchar(16) | `kdri_2025` |
| `note` | text | 기준의 단서 (예: "모유 섭취 기준") |

```sql
UNIQUE (age_group, sex, nutrient, ref_type, source_version)
CHECK (value_max IS NULL OR value_max >= value_min)
CHECK (ref_type <> 'AMDR' OR unit = '%kcal')
```

### 적재

- 원문 표 → CSV → Alembic 시드. **손으로 옮긴 값은 2인 대조**를 거친다(숫자 오타가 곧 판정 오류).
- `source_version`으로 세대를 관리한다. 기준이 개정되면 새 버전을 넣고 조회 기본값만 바꾼다. **기존 행을 덮어쓰지 않는다.**
- 0–11개월 행도 넣되 **분석에는 쓰지 않는다**(영아기 영양소 분석 미지원). 단계 판정·문구에만 참조.

### 어떤 `ref_type`을 언제 쓰나

| 목적 | 기준 | 이유 |
| --- | --- | --- |
| 부족 여부 | **EAR** | RNI는 집단의 97~98%를 충족시키는 값이라, 개인 기록에 대면 대부분 "부족"이 뜬다 |
| 목표 제시 | RNI · AI | 화면에는 숫자로 내보내지 않고 방향으로만 |
| 과잉 여부 | **UL** | 상한이 정의된 항목에만 |
| 탄단지 균형 | **AMDR** | 양 추정 오차에 가장 덜 민감한 지표 |
| 열량 | 연령군 일반값 → **키·몸무게로 조정** (`compute_energy_target`) | 측정 없으면 연령군 일반값. 계산식은 성별 없는 식으로 선정(N-9) |

**과잉을 말하는 항목은 나트륨 · 당류 · 포화지방으로 제한한다.** 미량영양소 과잉은 식품만으로는 드물고, 언급하면 불안만 만든다.

## 3. `intake_daily` — 섭취 파생 테이블

`observation_food`가 원문이고 이 테이블은 **파생**이다. 언제든 재계산해 덮어쓸 수 있어야 한다.

### 스키마

| 필드 | 타입 | 비고 |
| --- | --- | --- |
| `id` | uuid | PK |
| `child_id` | uuid | FK → `child.id`, CASCADE |
| `intake_date` | date | NOT NULL |
| `meal_type` | varchar(8) + CHECK | `meal` / `snack`. **끼니 슬롯이 아니다** — 아침·점심·저녁을 가르지 않는다 |
| `menu_keys` | text[] | 해석된 메뉴 |
| `amount_factor` | numeric(3,2) | 가중치 (§4) |
| `amount_known` | boolean | 급식은 대부분 `false` |
| `nutrients` | jsonb | 항목별 추정치 — **내부 전용** |
| `energy_ratio` | jsonb | `{carb, protein, fat}` %kcal |
| `food_groups` | text[] | 6개 식품군 |
| `resolved_count` · `unresolved_count` | smallint | 메뉴 해석 성공·실패 수 |
| `catalog_version` | varchar(16) | 계산에 쓴 `menu_catalog` 버전 |
| `computed_at` | timestamptz | |

```sql
-- UNIQUE 없음. 같은 날 같은 meal_type 이 여러 행일 수 있다
CREATE INDEX intake_daily_window_idx ON intake_daily (child_id, intake_date DESC);
```

- 보존 **30일**. 그 이상은 배치로 지운다(개인정보 최소 보관).
- `catalog_version`이 현재와 다르면 조회 시 **재계산 대상**으로 표시한다.
- 끼니 행이 아예 없으면 그 끼니는 **결측**이다. 0 행을 만들지 않는다.
- 기관에서 먹는 것은 여기 들어오지 않는다 — `daycare_meal`이 따로 있다(FT-8). 급식표는 미래 날짜를 갖고 기관이 정한 끼니 구분을 따르는데, 파생 테이블에 미래 행을 두면 재계산이 그걸 덮어쓴다.

### 만들어지는 시점

```
Memory가 observation_food 저장
        ↓
compute_intake_daily (코드 · 해당 날짜·끼니만 upsert)
        ↓
분석 직전 재확인 — catalog_version 불일치 행만 다시 계산
```

## 4. 양 추정 규칙

| `amount` 텍스트 | `amount_factor` | `amount_known` |
| --- | --- | --- |
| 다 먹음 · 한 그릇 | 1.0 | true |
| 반 그릇 · 절반 | 0.5 | true |
| 조금 · 몇 입 | 0.25 | true |
| 남김 (양 불명) | 0.5 | **false** |
| 뱉음 · 안 먹음 | 0.0 | true |
| 기록 없음 | 1.0 | **false** |
| 급식 (메뉴만) | 1.0 | **false** |

- `amount_known=false` 행은 **식품군 출현·다양성 계산에는 쓰고, 부족·과잉 판정의 분모에는 절반 가중**으로 들어간다.
- 1인분은 성인 기준이므로 유아 보정 계수를 곱한다(`config/portion_scale.yaml`, 1–2세 · 3–5세). 이 계수는 **구간 판정에만** 쓰고 절대량으로 노출하지 않는다.

## 5. 기록이 충분한가 — 행 수

끼니 비율로 세던 커버리지를 버렸다. `intake_daily`에서 끼니 슬롯을 없앴으니 "기대 끼니 수"라는 분모가 성립하지 않는다.

```
records   = intake_daily(최근 7일) + daycare_meal(최근 7일, 오늘 이전)  의 행 수
resolved  = resolved_count / (resolved_count + unresolved_count)
```

- **`records < 10` (설정값) → `insufficient=True`** → 수치 기반 결론 없음. 선호·반복 기반 추천 + 기록 부족 안내.
- 메뉴 해석률(`resolved`)은 따로 본다. 행은 충분한데 메뉴를 못 읽으면 그것도 결론을 막는다.
- 화면에는 "최근 7일 중 12건 기록됨"처럼 **건수로** 표시한다. 퍼센트는 쓰지 않는다.
- 하루 평균 1.5행이 기준이다. 급식이 있는 아이는 평일만으로 채워지고, 집에서만 먹는 아이도 하루 2건이면 닿는다.

## 6. 구간 판정

```python
def band(intake, ref) -> Literal["low", "ok", "high"]
```

| 항목 | low | ok | high |
| --- | --- | --- | --- |
| 일반 영양소 | 평균 섭취 < EAR | EAR ~ UL | UL 초과 (UL 있는 항목만) |
| 탄수화물·단백질·지방 | AMDR 하한 미만 | AMDR 범위 안 | AMDR 상한 초과 |
| 나트륨·당류·포화지방 | – | 상한 미만 | 상한 근접·초과 |

- 입력은 **분석 기간의 일평균**이다. 하루 값으로 판정하지 않는다.
- 경계에서 흔들리지 않도록 **히스테리시스**를 둔다: 한 번 `low`로 표시한 항목은 EAR의 1.1배를 넘어야 `ok`로 돌아간다. 매일 결론이 뒤집히면 신뢰를 잃는다.
- `high`는 나트륨·당류·포화지방과 AMDR 상한에만 쓴다.

### 구간 → 화면 문구 (코드가 식품군으로 번역)

| 항목 · 구간 | 식품군 행동 |
| --- | --- |
| 단백질 `low` | 고기·생선·달걀·콩 반찬 늘리기 |
| 칼슘 `low` | 우유·유제품 |
| 철 `low` | 붉은 고기·달걀노른자·콩 |
| 탄수화물 `high` | 밥·빵·면 줄이고 반찬 한 가지 |
| 나트륨 `high` | 국물·절임 줄이기 |

모델은 이 표에서 나온 `food_group_action`을 문장으로 다듬을 뿐, 항목을 추가하거나 수치를 쓸 수 없다.

## 7. 식단 추천에서의 사용

| 상황 | 쓰는 값 |
| --- | --- |
| 오늘 이미 먹은 끼니가 있음 | 오늘 `intake_daily`의 식품군 → **중복 회피**(점심에 고기면 저녁은 채소 위주) |
| 오늘 기록 없음 | 최근 3~7일 구간 판정 → `low` 항목의 식품군에 가중 |
| 행 수 미달 | 영양 가중 없이 선호·반복 기반 |

### 후보 뽑기

```
후보 풀 (≤30)
  → 점수 = 근거 가중 + low 식품군 보너스 − 최근 반복 패널티
  → sample_candidates(seed=run_id): 점수 가중 샘플링으로 10~15개
  → 주재료·식품군 다양성 제약 (같은 주재료 2개 이하)
  → 모델이 3개 선택
  → 사후 안전 필터 후 3개 미만 → 걸러진 메뉴를 빼고 재샘플링 → 모델 재호출 1회
```

- 샘플링은 **안전 필터와 중복 제거 뒤에** 온다. 앞에 두면 위험한 후보가 뽑힐 자리가 생긴다.
- `run_id`를 시드로 저장한다. 같은 `run_id`면 같은 결과가 나와야 한다(재현·QA).
- **부족 판정 자체는 랜덤화하지 않는다.** 흔드는 것은 메뉴뿐이다.

## 8. 테스트

| 케이스 | 기대 |
| --- | --- |
| 아침·점심 결측 + 저녁 요청 | 결측이 0으로 들어가지 않음. 한 끼 몰아주기 없음 |
| 급식만 기록된 날 | `amount_known=false`로 절반 가중, 식품군에는 반영 |
| 7일 8행 | `insufficient=True`, `findings` 비어 있음 |
| `unresolved` 다수 | `menu_coverage` 하락이 `coverage`에 반영 |
| EAR/RNI 혼동 | 같은 섭취량에서 RNI 기준이면 `low`, EAR 기준이면 `ok` — **EAR을 쓰는지 확인** |
| 경계 진동 | EAR 근처 값이 연속 3일 `low`→`ok`→`low`로 바뀌지 않음 (히스테리시스) |
| 미량영양소 UL 초과 | `high`로 보고하지 않음 (대상 항목 제한) |
| 같은 입력 3회 | 후보 3개가 매번 다름. 같은 `run_id`면 동일 |
| 키·몸무게 없음 | 권장 열량이 연령군 일반값으로 계산됨 |
| 성별 입력 | 결과에 영향 없음 (입력 자체가 없음) |
| 출력 검사 | readout에 `%`·`g`·`mg`·`kcal` 문자 0건 |
| 카탈로그 갱신 후 | `catalog_version` 불일치 행이 재계산됨 |
