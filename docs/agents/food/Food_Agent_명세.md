# Food Agent 명세

> **한 줄 요약** — 아이가 실제로 무엇을 먹었는지, 기관에서 뭘 주는지, 뭘 좋아하고 못 먹는지를 이어서 **"오늘 뭐 먹이지"** 에 답하는 Agent.
>
> 대상 독자: 기획 · 디자인 · 프론트엔드 · 백엔드 · QA
> 최종 갱신: 2026-09-22 · 관련 문서: [`Agent_공통규약.md`](../shared/Agent_공통규약.md) · `food.md`(내부 구현 이력 — 저장소 밖)

## 1. 이 Agent가 받는 요청

보호자 발화가 들어오면 Supervisor가 먼저 **두 가지 중 하나로** 분류합니다. 이 분류에 따라 Agent가 쓸 수 있는 기능이 달라집니다.

| 라벨 | 이런 말이 들어오면 | 결과물 |
| --- | --- | --- |
| `meal_recommendation` (식단 추천) | "저녁 뭐 먹이지?" · "간식 추천해줘" · "요즘 편식이 심한데 뭘 줄까" | 식사 후보 **3개** |
| `nutrient_analysis` (영양소 분석) | "요즘 단백질 부족하지 않아?" · "이번 주 영양 균형 어때?" | 부족·과잉 영양소 **서술** |
| `daycare_meal` (기관 식사 기록) | "오늘 급식 대신 두유 받았대" · "어린이집에서 계란말이 엄청 많이 먹었대" · "내일모레는 어린이집 빠져" | 급식 기록 갱신·삭제 |

### 이 Agent로 오지 않는 것

| 발화 | 어디로 | 왜 |
| --- | --- | --- |
| "오늘 당근 반 그릇 먹었어" | Memory | 집에서 먹은 것은 `observation_food`. 기관 신호가 있어야 Food로 옵니다 |
| "밥 먹을 때 자꾸 돌아다녀" | Growth | 무엇을 먹었나(Food)와 어떻게 먹나(Growth)는 다름 |
| "우유 먹고 두드러기 났어" | Health | 알레르기 후보 감지는 Health |
| "우리 애 살찐 편이야?" | Growth | 체중 판정은 시스템 어디서도 하지 않음. Growth가 측정 추이만 정리하고 검진 안내 |

## 2. 하는 일 / 하지 않는 일

### 하는 일
- 아이가 실제로 먹은 기록, 좋아하는 음식, 기관 급식을 보고 **식사 후보 제안**
- 최근 반복된 메뉴나 편중된 식단 짚어주기
- 어린이집 급식과 집 식사를 연결해서 확인 — **급식표 + 우리 아이 대체식·제외 메뉴** 기준 (§4)
- 연령·식이 단계에 맞는 식사 보조 (영아기는 이유식, 유아기는 일반식)
- **알레르기·금지식품 걸러내기** — 이건 AI가 아니라 코드가 합니다
- 영양소가 부족하거나 넘치는지 **비중**으로 짚어주기
- 기피하는 식품군이 영양상 부족할 때, **그 식품군을 빼지 않고 먹을 수 있는 형태로** 제안하기 (§6)

### 하지 않는 일
| 안 함 | 이유 |
| --- | --- |
| 질병·영양 결핍 **진단** | 의료 행위 |
| 치료식 **처방** | 의료 행위 |
| "단백질 12g 섭취" 같은 **정확한 수치 생성** | AI가 지어낼 수 있음. 항상 '비중'만 |
| 알레르기를 **추론해서 확정** | 보호자 입력 또는 의료 기록만 신뢰 |
| 섭취 기록 **저장** | Memory Agent가 함. 저장 통로는 하나여야 함 |
| **체중 감량·증량 식단** | 의료 영역. 시스템은 체중 판정 자체를 하지 않음 |

## 3. 읽는 것 / 쓰는 것

### 읽기만 합니다

| 무엇 | 쓰는 이유 |
| --- | --- |
| `observation_food` | 아이가 실제로 먹은 기록 |
| `profile_affinity` (domain=food) | 확정된 선호·기피 — **1순위 근거** |
| `health_safety` | 알레르기·만성질환 |
| `child` (생년월일) | 영아기/유아기 판정 · 권장 섭취량 기준(연령별 일반값) 선택 |
| `child_growth_log` | 키·몸무게 → **권장 열량 계산 입력** (코드 계산) |
| `daycare_meal` | 오늘·내일 급식. OCR이 급식표로 채우고 보호자가 알려준 대체 메뉴로 교체된 값 (§4) |
| 식품 영양성분 데이터 | 영양소 조회 |
| 권장 섭취량 외부 소스 | 연령(발달 단계)별 일반값 |

**성별은 읽지 않습니다.** 성별에 따른 섭취량 차이는 확인할 수 없어서, 권장 섭취량은 외부 소스의 발달 단계별 일반값을 쓰고 **권장 열량만 키·몸무게로 조정**합니다.

- 측정 기록이 없으면 연령별 일반값만 씁니다
- 계산은 코드가 합니다. AI는 결과 숫자를 받아 설명만 합니다
- 키·몸무게로 과체중·저체중을 **판정하지 않습니다.** 권장 열량을 고르는 입력일 뿐입니다

### 쓰는 것

두 가지입니다.

**`suggestion`** — 식사 후보를 `status='draft'`로 저장합니다(실제 INSERT는 주입된 writer). 승인되면 Memory Agent가 관찰로 만듭니다.

**`daycare_meal`** — Food가 직접 고치는 유일한 테이블입니다. 행을 **만드는 것은 OCR 파이프라인뿐**이고, Food는 보호자가 말하는 변경(대체식·먹은 양·결석)을 이미 있는 행에 반영하거나 지울 뿐입니다. 없는 급식을 지어낼 경로가 없습니다.

> 다른 Agent가 읽지 않는 도메인 전용 테이블이라 "공유 테이블의 단일 writer는 Memory" 원칙에 걸리지 않습니다. Health의 복약 테이블과 같은 자리입니다.
>
> 아이의 관찰(`observation_food`)은 여전히 **손대지 않습니다.** 집에서 먹은 것은 Memory가 씁니다.

## 4. 기관 급식 흐름 — Food의 핵심

아이가 기관에서 실제로 뭘 먹는지가 추천의 바탕입니다. 급식표만으로는 부족하고, **우리 아이가 대체식을 받거나 빠진 메뉴**까지 알아야 정확해집니다.

```
① OCR 파이프라인이 급식표 원문으로 `daycare_meal` 행을 채움
② 저장과 함께 안내: "대체식이나 알레르기 때문에 빼놓은 메뉴가 있으면 알려주세요"
③ 보호자가 알려주면 백엔드가 그 행의 `menu_keys`를 대체 메뉴로 교체
```

| 식단 상태 | Food의 동작 |
| --- | --- |
| 보호자 확인 전 | 급식 메뉴를 쓰되 **"대체식 확인 전"** 표시 |
| 확인 완료 · 대체/제외 없음 | 급식표 그대로 사용 |
| 확인 완료 · 대체/제외 있음 | 제외 메뉴는 먹은 것으로 보지 않고 대체 메뉴를 대신 사용 |
| 급식표 없음 | 급식 없이 진행. "급식 정보를 못 찾았어요" |

- 급식은 `daycare_meal`에, 집에서 먹은 것은 `intake_daily`에 들어갑니다. **미래 날짜를 갖는 것은 급식뿐**입니다 — 내일 급식을 봐야 저녁이 안 겹칩니다
- 대체·제외는 그 행의 **`menu_keys`를 교체**합니다. 제외 메뉴를 빼고 대체 메뉴를 넣습니다
- 대체·제외 메뉴는 **보호자가 알려준 값만** 씁니다. AI가 "우유 알레르기니까 우유 메뉴는 빠졌겠지"라고 추정하지 않습니다
- 보호자가 알려준 "우유 알레르기라 두유로 받아요"는 **식단 갱신이지 알레르기 등록이 아닙니다.** `health_safety` 등록은 별도 승인 게이트를 거칩니다

## 5. Tool 목록

### 어떤 Tool이 열리는지는 시스템이 정합니다

AI가 "이 도구를 쓸까 말까"를 정하는 게 아니라, **아이의 나이에 따라 코드가 먼저 도구 목록을 닫습니다.** AI는 열려 있는 것 중에서만 고릅니다.

| | 유아기 | 영아기 |
| --- | --- | --- |
| **식단 추천** | 5개 도구 | 3개 도구 |
| **영양소 분석** | 7개 도구 | **지원 안 함** → "영아기에는 영양소 분석을 지원하지 않아요" 안내 |

### 전체 목록

| Tool | 하는 일 | 식단 추천 | 영양소 분석 | AI에게 |
| --- | --- | --- | --- | --- |
| `search_food_memory` | 먹은 기록·선호 검색 | ✓ | ✓ | 보임 |
| `analyze_meal_records` | 섭취 기록 요약 | ✓ (유아) | ✓ (유아) | 보임 |
| `check_repeated_menus` | 반복 메뉴 확인 | ✓ (유아) | ✓ (유아) | 보임 |
| `lookup_daycare_menu` | `daycare_menu` 조회 (대체·제외 반영) | ✓ (유아) | ✓ (유아) | 보임 |
| `lookup_nutrition` | 식품 영양성분 조회 | – | ✓ (유아) | 보임 |
| `compare_diet_balance` | 식단 균형 비교 | – | ✓ (유아) | 보임 |
| `guide_weaning_stage` | 이유식 단계 안내 | ✓ (영아) | – | 보임 |
| `propose_meal_candidates` | **식사 후보 출력** | ✓ | – | 보임 |
| `report_nutrient_analysis` | **영양 분석 출력** | – | ✓ (유아) | 보임 |
| `filter_food_safety` | **알레르기 필터** | 사전+사후 | 급식 조회 안에서 | **안 보임** |
| `rank_evidence` | **근거 순위 정렬** | ✓ | ✓ | **안 보임** |

### "AI에게 안 보임"이 왜 중요한가

알레르기 필터와 근거 정렬은 **AI가 부를 수 있는 도구가 아닙니다.** AI가 부를 수 있으면 건너뛸 수 있기 때문입니다. 코드가 AI를 호출하기 **전에** 알레르기를 확인하고, AI가 답을 낸 **후에** 다시 한 번 거릅니다.

`health_safety` 조회가 실패하면 **AI를 아예 호출하지 않습니다.** "알레르기를 확인할 수 없어서 추천을 드릴 수 없어요"로 끝냅니다.

## 6. 추천의 근거를 고르는 순서

어떤 기록을 먼저 보는지는 **코드가 정합니다.** AI는 이미 정렬된 목록을 받습니다.

```
1순위  확정된 선호/기피    (Curator가 여러 기록을 모아 확정한 것)
2순위  후보 단계 선호/기피  (아직 확정 전이지만 신호가 강한 것)
3순위  최근 14일 먹은 기록
──── 셋 다 없으면 ────
       "또래 기준" 일반 추천
```

### 규칙

- **기피는 후보에서 빼는 값이 아니라 근거입니다.** "브로콜리를 싫어해서 이렇게 골랐어요"가 되어야지, 브로콜리를 목록에서 지우고 아무 말도 안 하면 보호자는 우리 아이를 보고 나온 추천인지 알 수 없습니다. 후보에서 지우는 것은 **알레르기와 연령 금지식품뿐**입니다.
- **기피를 근거로 썼으면 문장에 밝힙니다.** 무엇을 피했는지, 또는 왜 그럼에도 골랐는지가 `reason`에 있어야 합니다.
- **좋아하는지 싫어하는지 모르는 후보 신호는 근거로 쓰지 않고**, 대신 보호자에게 한 줄 물어봅니다. ("딸기는 좋아하는 편인가요?")
- **6개월 이상 지난 관심 기록은 그것만으로 추천 근거가 될 수 없습니다.** 다른 근거와 함께일 때만 씁니다.

### 영양이 선호보다 앞섭니다 — Food만의 예외

다른 Agent는 선호가 1순위지만 Food는 다릅니다. 기피를 이유로 부족한 식품군을 빼면, 안 먹는 것을 계속 안 먹이는 추천이 됩니다.

> **채소 기피(−1)가 확정이어도, 영양 분석이 채소 부족을 가리키면 채소를 뺀 추천을 내지 않습니다.**

대신 **기피를 피해 가는 형태**로 고르고, 피해 갔다는 사실을 말합니다.

```
답변    "야채를 기피하고 있어요. 야채가 많이 들어가지만
         좋아하는 계란 맛이 강한 음식들을 추천드려요"
카드    오므라이스 · 계란볶음밥 …
근거    채소 기피(확정) + 계란 선호(확정) + 최근 7일 채소 출현일
```

- 우선순위는 **영양 결과 → 기피를 피해 가는 형태 → 선호**입니다. 기피가 후보 풀을 줄이지 않습니다
- 판단 순서는 코드가 정합니다. 부족한 식품군은 `compare_diet_balance`의 구간에서 오고, AI는 그 식품군 안에서 선호에 맞는 형태를 고릅니다
- 영양 분석이 부족을 가리키지 않으면 이 예외는 돌지 않습니다. 그때는 기피를 피해 가기만 하면 됩니다

## 7. 화면에 나가는 것

| 종류 | 내용 | 저장 | 만료 |
| --- | --- | --- | --- |
| 식사 후보 | **3개**. 각각 "왜 이걸 추천하는지" 포함 | `suggestion` | 24시간 |
| 추천 앞의 한 줄 | 기피를 피해 갔거나 부족을 메우는 추천일 때. "야채를 기피하고 있어요. 야채가 많이 들어가지만 좋아하는 계란 맛이 강한 음식들을 추천드려요" | 저장 안 함 | – |

추천 카드 화면은 **그 요청의 결과**를 바로 보여줍니다. 카드 화면을 나와서 보는 suggestion 목록 화면에는 **만료 전 suggestion 전부**가 나옵니다.
| 영양 분석 서술 | 부족/과잉 영양소를 비중으로 | 저장 안 함 | – |
| 미지원 안내 | "영아기에는 영양소 분석을 지원하지 않아요" | 저장 안 함 | – |
| 되묻기 | "딸기는 좋아하는 편인가요?" — **한 번에 하나만** | 저장 안 함 | – |

식사 후보는 생성과 동시에 `draft`로 저장되고 화면이 **추천 카드로 바로 전환**됩니다. 사용자가 승인하면 Memory로 넘어갑니다.

### 개인화 추천 vs 일반 추천

| | 근거 | 화면 표시 |
| --- | --- | --- |
| 개인화 | 아이 기록 1건 이상 필수 (기피 기록도 근거입니다) | "지난주에 당근을 잘 먹어서요" · "야채를 기피해서 계란 맛이 강한 걸로 골랐어요" |
| 일반 | 근거 0건 | **"또래 기준"임을 명시** + "또래 아이들이 많이 먹는 메뉴예요" |

근거가 없는데 개인화된 것처럼 말하는 일이 없도록, 일반 추천의 설명 문구는 **AI가 아니라 코드가 넣습니다.**

## 8. 실패·예외 처리

| 상황 | 동작 |
| --- | --- |
| 알레르기 정보 조회 실패 | **AI 호출 없이 중단.** "알레르기를 확인할 수 없어요" |
| 영아기 + 영양소 분석 | AI 호출 없이 안내 문구 |
| 기관 급식 데이터 없음 | 급식 없이 진행. "급식 정보를 못 찾았어요" 표시 |
| 대체식 확인 전 | 급식 메뉴는 쓰되 "대체식 확인 전" 표시 |
| 안전 필터 후 후보가 3개 미만 | 걸러진 메뉴를 제외 목록에 넣고 **AI를 한 번 더 호출** (이 경우에만, 1회). 기피는 필터가 아니라 근거라 재호출 사유가 아닙니다. 재호출 후에도 3개 미만이면 **미정** (§10) |
| 급식은 있는데 알레르기 표시 매핑 실패 | 메뉴는 주되 **"알레르기 확인 못 함" 반드시 명시** |
| 기록이 아예 없음 | 일반 추천 |
| 20초 초과 | 다른 Agent 결과만이라도 화면에 표시 |

## 9. 다른 팀이 알아야 할 것

### 프론트엔드
- 추천 카드에 **개인화/일반 구분 표시**가 필요합니다
- 근거(어떤 기록을 봤는지)를 펼쳐볼 수 있어야 합니다
- 되묻기는 **한 번에 하나**만 뜹니다
- 알레르기 미확인 메뉴는 시각적으로 구분돼야 합니다
- 추천은 **3개**가 한 번에 오고, 생성 즉시 추천 카드 화면으로 전환합니다
- 급식표 저장 직후 **"대체식·알레르기로 빼놓은 메뉴가 있으면 알려주세요"** 안내와 입력 경로가 필요합니다
- "대체식 확인 전" 급식은 시각적으로 구분돼야 합니다

### 백엔드
- Agent는 DB를 직접 모릅니다. 읽기 포트 구현체를 주입해야 합니다
- `suggestion` INSERT도 Agent가 아니라 주입된 writer가 합니다
- `health_safety` 조회 실패를 빈 목록으로 숨기면 안 됩니다 — 예외로 올려야 합니다

### QA
필수 확인 케이스:
- 알레르기 정보 조회 실패 → AI 호출이 **0회**인가
- 영아기 + 영양소 분석 → AI 호출이 **0회**인가
- 등록된 알레르기·연령 금지식품이 후보에 **절대** 안 나오는가
- 확정 기피가 있을 때 후보가 사라지지 않고 **근거로 인용되며**, `reason`에 무엇을 피했는지가 있는가
- 채소 기피 + 채소 부족 → 채소를 뺀 추천이 아니라 **먹을 수 있는 형태**가 나오고, 기피 사실이 문장에 있는가 (§6)
- 기록 0건 → 일반 추천으로 내려가고 "또래 기준" 표시가 있는가
- 급식에 알레르기 표시가 없을 때 "확인 못 함"이 나오는가
- 보호자가 알려준 제외 메뉴가 "먹은 것"으로 집계되지 않는가
- 추천 개수가 **정확히 3개**인가 (2개 이하·4개 이상이 없는가)
- 성별이 결과에 영향을 주지 않는가
- 키·몸무게가 없을 때 연령별 일반값으로 동작하는가
- 필터 후 3개 미만일 때만 재호출이 일어나고, 재호출은 1회뿐인가
