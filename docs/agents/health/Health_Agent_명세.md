# Health Agent 명세

> **한 줄 요약** — 진단을 대신하지 않고, 보호자가 아이의 건강 기록을 **다시 찾고 · 정리하고 · 챙기는 노동**을 줄이는 Agent. 판단이 필요한 계산은 전부 코드가 공신력 있는 기준표로 하고, AI는 기록을 옮겨 적는 일만 합니다.
>
> 대상 독자: 기획 · 디자인 · 프론트엔드 · 백엔드 · QA
> 최종 갱신: 2026-09-22 (개정 3 — 성장 판정 제거 · 복약 초안 payload · 중단 soft delete · 성별 미사용 · 알레르기 후보 감지 제거 · 문서 테이블 대신 상수 파일 · `event_requests`도 초안 payload) · 관련 문서: [`5agents.md`](../shared/5agents.md) §8 · [`health_agent_own_table.md`](health_agent_own_table.md)(소유 테이블) · [`Health_Tool_명세.md`](Health_Tool_명세.md) · `설계_점검_2026-09-20.md`(저장소 밖)

| 추가 | 무엇 | AI 호출 |
| --- | --- | --- |
| 복약 기록 | "먹였어" 기록 · 다음 예정 시각 안내 (`medication_dose_log`) | 0 |
| **`care_handoff` 라벨 (신규)** | 기관 투약의뢰서 · 응급 카드 — 전달용 서류 생성 | **0** |

## 1. 이 Agent의 성격 — 먼저 읽어주세요

Health는 다섯 Agent 중 **가장 위험하고, 그래서 AI가 가장 적게 일하는** Agent입니다.

- **라벨 5개 중 3개는 AI를 부르지 않습니다.** 검진·접종 시기, 병원 찾기, 전달용 서류는 코드가 공식 기준표·공공 API·고정 서식으로 합니다.
- AI가 일하는 두 곳(진료 전 요약, 복약 등록)에서도 **AI는 보호자 기록을 옮겨 적기만** 합니다. 해석·추정·보정은 없습니다.
- 판정 문구는 **코드가 쓰고 AI가 고칠 수 없습니다**(`authored_by="code"`). AI가 다시 쓰다가 해석을 덧붙이는 일을 막습니다.

> **이 Agent가 하는 가장 강한 말은 "병원에서 확인해 보세요"입니다.** 그보다 강한 말은 하지 않습니다.

## 2. 연령 — Health가 쓰는 경계

공통 단계는 `life_stage()`(Food·Growth와 공유)에서 받고, Health는 **자기 내부 경계**를 추가로 씁니다.

| 경계 | 무엇이 바뀌나 | 근거 |
| --- | --- | --- |
| 월령 전체 | 검진 차수 · 접종 시기 | 건보공단 검진 주기 · 표준예방접종일정 |
| 조산아 | 24개월까지 교정연령 | `child.gestational_weeks` (선택 입력) |

## 3. 이 Agent가 받는 요청

| 라벨 | 이런 말이 들어오면 | 결과물 | AI 호출 |
| --- | --- | --- | --- |
| `visit_summary` (진료 준비) | "내일 소아과 가는데 정리해줘" · "요즘 열 얼마나 났지?" | 증상·식사·복약 타임라인 | 1 |
| `schedule_check` (검진·접종) | "검진 언제야?" · "이번 달 맞을 주사 있어?" | 현재·다음 검진 차수, 이 시기 권장 접종 | **0** |
| `place_lookup` (병원 찾기) | "지금 문 연 소아과" · "야간 진료" | 병원 목록 | **0** |
| `medication` (복약) | "항생제 하루 세 번 식후" · "약 끊었어" · "아까 약 먹였어" · "다음 약 언제야?" | 복약 일정 생성·수정(**초안 payload → 보호자 제출**)·중단(`status='stopped'`) · 복용 기록 · 다음 예정 시각 | 1 (기록·조회는 **0**) |
| **`care_handoff`** (전달용 서류) | "어린이집 투약의뢰서 써야 해" · "시터한테 알레르기 뭐라고 알려주지" | 투약의뢰서 · 응급 카드 (복사·공유용) | **0** |

### 이 Agent로 오지 않는 것

| 발화 | 어디로 | 왜 |
| --- | --- | --- |
| "숨을 못 쉬어" · "경련해" · "입술이 부었어" | **Supervisor 안전 사전검사 → 응급 안내** | Agent를 거치면 늦음 (§9) |
| "이거 폐렴이야?" · "해열제 더 먹여도 돼?" | Supervisor `guarded_diagnosis` → 고정 안내 | 진단·처방 문의 |
| "오늘 열 38도였어" | Memory (`observation_health`) | 기록 |
| "얼마나 컸어?" · "잘 크고 있어?" · "살찐 편이야?" | Growth `growth_review` | 신체 성장은 Growth만. 판정 없이 추이 + 검진 안내 |
| "다음 주 화요일 검진 예약했어" | Memory (`event`) | 확정 일정의 기록 |

### 경계 예시 (Supervisor 프롬프트에 필수)

```
"얼마나 컸어?"                    → growth / growth_review
"잘 크고 있어?"                   → growth / growth_review   (Health 아님)
"10cm 컸는데 많이 큰 거야?"        → growth / growth_review
"하루 세 번 항생제 먹여야 해"       → health / medication   (Memory 아님)
"열나서 병원 갔더니 항생제 먹이래"  → memory(관찰) + health / medication
"검진 언제 받아야 돼?"             → health / schedule_check
"검진 받았는데 키 95cm래"          → memory(child_growth_log)   ※ Health로 오지 않음
"아까 약 먹였어"                  → health / medication   (복약 기록은 Health 소유 테이블)
"어린이집 투약의뢰서 필요해"       → health / care_handoff
"열 언제부터 났더라"              → health / visit_summary  (열 타임라인)
```

애매하면 **판정·확인이 붙는 쪽(Health)** 으로 보냅니다.

## 4. 하는 일 / 하지 않는 일

### 하는 일
- **진료 준비** — 최근 증상·식사량·먹인 약·알레르기를 날짜순으로 정리. 모든 줄에 원 기록 링크
- **검진·접종 안내** — 월령으로 현재 검진 차수와 이 시기 권장 접종을 계산
- **병원 찾기** — 시간대에 맞춰 소아청소년과 · 달빛어린이병원 · 응급실
- **복약 일정 CRUD** — 생성·수정은 초안 payload를 내고 보호자가 제출할 때 백엔드가 저장, 중단은 soft delete
- **증상 반복 감지** — 같은 증상이 반복되면 병원 확인 안내
- **복약 기록** — "먹였어"를 남기고, 다음 예정 시각과 남은 횟수를 알려줌
- **전달용 서류** — 기관 투약의뢰서 · 시터·조부모에게 줄 응급 카드를 고정 서식으로 생성
- **열 경과 나열** — 기록된 체온과 복약 시각을 시간순으로. 계산만 하고 해석은 안 함
- **처방전 초안 확인** — OCR 파이프라인이 읽어 둔 값을 보여주고, 보호자가 고친 뒤 등록

### 하지 않는 일

| 안 함 | 이유 |
| --- | --- |
| 질환 추정·확진 ("장염 같아요") | 의료 행위 |
| 처방 · 약 제안 · 용량 변경 · "더 먹여도 돼요" | 의료 행위. NF-03 |
| 발화에 없는 약명·용량 채우기 · 단위 환산 | NF-03 |
| 증상만 보고 알레르기·질환을 Profile로 확정 | 보호자 확인 없이는 후보일 뿐 |
| "저체중" · "비만" · "저신장" 같은 **진단명 사용** | 판정은 검진·진료에서 |
| **성장 백분위·BMI 판정** | 제거됨(09-22). 신체 성장은 Growth가 추이만 정리 |
| 체중과 관련한 식이·운동 조언 | 어느 Agent도 하지 않음 |
| 발달 수준·장애 판단 | 발달 선별검사는 영유아 검진의 몫 |
| "접종을 빠뜨렸어요" 단정 | 실제 접종 기록을 보지 못함 (§6-2) |
| 병원 **예약·결제** | 경로 자체를 만들지 않음 |
| 약 이름에서 **성분·계열 추론** (아세트아미노펜/이부프로펜) | 의약품 DB 판단이고, 곧 교차투약 안내로 이어짐 |
| **"다음 투약 가능 시각"을 약 계열 최소 간격으로 계산** | 용법 지시. 보호자가 **등록한 일정**의 다음 예정 시각만 말함 |
| "지금 더 먹여도 돼요" 같은 **허가 문구** | 용량 판단. 반환값에 `can_take` 같은 필드를 두지 않음 |
| **발달 문항 자동 체크·문진표 대필** | 답을 고르는 순간 발달 판정. 검진의 선별 기능을 떨어뜨림 |
| 처방전·약봉투 **이미지 보관** | 추출 결과만 남기고 원본은 버림 |
| 보호자 발화에 없는 **복약 이유 추정** | `indication_text`는 복사만. 없으면 NULL |

## 5. 읽는 것 / 쓰는 것

> **근거를 고르는 방식이 다른 Agent와 다릅니다.** Food·Growth는 `rank_evidence`로 확정 관심 → 후보 관심 → 최근 관찰 순으로 줄을 세우지만, Health는 그러지 않습니다.
>
> `profile_affinity.domain`에 `health`가 없고 `observation_health`에는 `embedding`도 없습니다. **증상은 선호가 아니라서 쌓인다고 성향이 되지 않기 때문**입니다 — "열이 세 번 났다"는 "열을 좋아한다"가 아닙니다. 그래서 Health의 근거는 **항상 관찰 직접 참조**이고, 조회도 `symptom` 배열 + 기간으로만 합니다.
>
> `suggestion`을 만들지 않으므로 `suggestion_evidence`도 없습니다. 근거는 `Readout.source_refs`에 담기고, 타임라인은 **줄마다 `source_ref`가 있어야** 합니다(§6-3).

### 읽기

| 무엇 | 라벨 | 쓰는 이유 |
| --- | --- | --- |
| `observation_health` | visit_summary · (hook) | 증상 경과 · 반복 감지 · 알레르기 후보 |
| `observation_food` | visit_summary | 최근 3일 식사량 변화 |
| `health_safety` (state=active) | visit_summary · (hook) | 기존 알레르기·만성질환 |
| `medication_schedule` · `medication_dose` | visit_summary · medication · care_handoff | 먹이고 있는 약 |
| `medication_dose_log` | medication · visit_summary | 실제로 먹인 기록 |
| `prescription_draft` | medication | **OCR 파이프라인 산출물. 읽기만** — 값은 보호자가 확인한 뒤에만 쓰임 |
| `observation_routine` · `observation_education` | (검진 맥락 요약) | 기록 요약용. 판정 금지 |
| `child` (생년월일 · `gestational_weeks`) | schedule_check | 월령. **성별은 읽지 않음** |
| 공식 기준표 (코드 상수) | schedule_check | §11 |
| 공공 API | place_lookup | §11 |

### 쓰기

| 무엇 | 방식 |
| --- | --- |
| `medication_schedule` · `medication_dose` · **`medication_dose_log`** | **직접 CRUD** — 도메인 전용 테이블. 다른 Agent가 읽지 않음 ([`health_agent_own_table.md`](health_agent_own_table.md)). 단, 코스 **생성·수정은 직접 쓰지 않는다** — 초안 payload를 내고 보호자가 제출하면 백엔드가 쓴다. Agent가 직접 쓰는 것은 복용 기록(`medication_dose_log`)과 중단(`status='stopped'`)뿐 |
| `prescription_draft` | **쓰지 않음.** OCR 파이프라인이 쓰고 Health는 읽기만 |
| `health_safety` | **쓰지 않음.** 후보만 내고, 보호자 확인 후 앱이 보호자 권한으로 저장 |
| `event` | 쓰지 않음. 필요하면 `event_requests`로 Memory에 넘김 — **초안 payload로 나가고 보호자가 제출해야 저장된다** |
| `suggestion` | **쓰지 않음.** Health에는 추천이 없음 |

## 6. 라벨별 동작

### 6-1. ~~`growth_check`~~ — 제거됨 (2026-09-22)

성장 백분위·BMI 판정을 **시스템에서 빼기로 했습니다.** `growth_check` 라벨 · `assess_growth_percentile` · 성장도표 LMS 상수 · 판정 문구가 전부 사라집니다.

- 신체 성장 질문은 "잘 크고 있어?"까지 전부 **Growth `growth_review`** 로 갑니다. Growth는 측정 기록의 추이만 정리하고, 판정을 묻는 질문에는 "성장 평가는 영유아 건강검진에서 확인해 보세요"를 코드 템플릿으로 붙입니다.
- 체중과 관련한 식이·운동 조언은 여전히 **어느 Agent도 하지 않습니다.**
- Health는 `child.gender`와 `child_growth_log`를 읽지 않습니다. 성별은 시스템 어디에서도 쓰지 않습니다.

### 6-2. `schedule_check` — 검진·접종 (AI 0회)

코드 tool `compute_checkup_schedule` · `compute_vaccine_schedule`이 생년월일로 계산합니다. **저장하지 않습니다** — 생년월일에서 매번 결정되는 값이라 저장하면 생년월일 수정 때 어긋납니다.

**영유아 건강검진** (국민건강보험공단)

| 차수 | 일반검진 | 구강검진 |
| --- | --- | --- |
| 1 | 생후 14–35일 | – |
| 2 | 4–6개월 | – |
| 3 | 9–12개월 | – |
| 4 | 18–24개월 | 18–29개월 |
| 5 | 30–36개월 | 30–41개월 |
| 6 | 42–48개월 | 42–53개월 |
| 7 | 54–60개월 | 54–65개월 |
| 8 | 66–71개월 | – |

**예방접종** — 「국가예방접종 지침」의 표준예방접종일정을 **연도별 상수 파일**로 둡니다(`vaccine_schedule_2026.yaml`). 매년 지침이 나오면 교체합니다.

**하지 않는 것**: 실제 접종 여부를 모르므로 "빠뜨렸어요"라고 말하지 않습니다. 대신 "이 시기에 권장되는 접종이에요. 실제 접종 기록은 예방접종도우미에서 확인할 수 있어요."

**일정 알림** — 보호자가 "알림 받기"를 누르면 검진 기간 시작일로 `event_requests`(`category=health`)를 만듭니다. 이것도 **DB에 저장되지 않고 초안 payload로 나갑니다** — 복약 초안과 같은 방식이고, 보호자가 제출해야 `event` 행이 생깁니다. 확정된 예약 날짜는 보호자 발화로 Memory가 저장합니다.

**검진 맥락 요약** (`summarize_checkup_context`) — 검진 시기가 되면 "들고 갈 기록"을 한 장으로 정리합니다.

| 담는 것 | 담지 않는 것 |
| --- | --- |
| 최근 식사 경향 · 복용 중인 약 · 최근 아팠던 이력 | **발달 문항 답변·체크** |
| 등록된 알레르기·만성질환 | 문진표 항목 대필 |
| 마지막 측정값과 측정일 | 수면 시간 — **기록 구조가 없습니다** |

문진표는 보호자가 직접 작성합니다. 이 요약은 그때 **옆에 두고 보는 기록**이지 답안이 아닙니다.

### 6-3. `visit_summary` — 진료 준비 (AI 1회)

AI는 **정리 담당**입니다. 읽기 tool로 기록을 모으고, 출력 tool `compose_symptom_timeline`으로 타임라인을 냅니다.

| 구획 | 내용 | 기본 기간 |
| --- | --- | --- |
| 증상 경과 | 날짜 · 증상 · 정도 · 한 조치 | 최근 14일 |
| 먹은 것 | 식사량 변화 ("평소보다 적게") | 최근 3일 |
| 먹이는 약 | 약 이름 · 용량 — **등록된 원문 그대로** | 진행 중 |
| 알레르기·만성질환 | `health_safety` active | 전체 |

**모델이 받기 전에 코드가 묶습니다**
- `normalize_symptom_term` — "열나" · "미열" · "38도" → `fever` 표준 코드
- `group_symptom_episodes` — 같은 증상 코드가 48시간 이내로 이어지면 **한 에피소드**. "3/12–3/15 발열 (4일)"
- 이 묶기가 있어야 증상 반복 판정(3회)도 의미를 가집니다. 지금은 3일 연속 발열이 3회인지 1회인지 정의가 없습니다

**열 타임라인** (`build_fever_timeline`, AI 0회) — "열 언제부터 났지"에는 모델을 부르지 않습니다.

| 나가는 것 | 나가지 않는 것 |
| --- | --- |
| 최고·최저 체온과 시각 | 약 성분·계열 판정 |
| 마지막 복약 시각과 약 이름(원문) | 약 계열 최소 간격으로 계산한 "투약 가능 시각" |
| **등록된 일정상의** 다음 예정 시각 | "더 먹여도 돼요" |
| 체온 변화 나열 | "열이 잡히고 있어요" 같은 경과 해석 |

응급 신호(3개월 미만 발열 등)에 걸리면 타임라인보다 **병원 안내가 먼저** 나갑니다.

**출력 검사 (코드, 사후)**
- 모든 줄에 `source_ref` 필수 — 없는 줄은 삭제
- 약 이름·용량이 `medication_schedule` 원문과 글자 단위로 같은지 확인
- 해석 표현 금지어 필터 ("때문에", "의심", "같아요", "~염", "~증")

| --- | --- |
| 평일 주간 | 소아청소년과 의원 (심평원 병원정보) |

### 6-5. `medication` — 복약 CRUD (AI 1회)

상세 스키마는 [`health_agent_own_table.md`](health_agent_own_table.md).

**역할 분담**

| 누가 | 무엇을 |
| --- | --- |
| AI | 발화에서 약 이름 · 용량 · **시점 표현** · 기간 표현을 **원문 그대로 복사** |
| 코드 `resolve_dose_timing` | 시점 표현 → `(timing_anchor, offset_minutes)` — 표현 사전 |
| DB | `scheduled_time` 생성 컬럼 |
| 코드 | 결과 시각을 문장으로 → readout (`medication_notice`, `authored_by="code"`) |

**시점 표현 사전 (코드 상수, 발췌)**

| 표현 | anchor | offset |
| --- | --- | --- |
| "식후" · "밥 먹고" | 해당 식사 | +30 |
| "식후 바로" · "먹고 바로" | 해당 식사 | 0 |
| "식전" · "밥 먹기 전" | 해당 식사 | −30 |
| "자기 전" | `bedtime` | 0 |
| "일어나서" | `wake_up` | 0 |
| "오후 3시" | `fixed` | 15:00 |
| "하루 세 번 식후" | breakfast · lunch · dinner | 각 +30 |

- **사전에 없는 표현이나 시점이 빠진 경우("하루 세 번")는 추측하지 않고 되묻습니다.** "식사 전후 언제 먹이면 되나요?"
- AI는 `fixed`를 스스로 고를 수 없습니다. 발화에 시각이 있을 때만.

**승인 게이트** (2026-09-22) — 생성·수정은 **DB에 저장되지 않습니다.** Memory가 `event` 초안을 다루는 방식과 같게, 코스와 복용 시점을 **JSON 초안**으로 만들어 화면에 넘기고 보호자가 제출할 때 백엔드가 씁니다. 확인 모달에는 **실제 알림 시각**이 반드시 나갑니다 — 초안의 필수 필드라 빠지면 tool 호출이 실패합니다.

> "항생제 — 아침 08:30 · 점심 12:30 · 저녁 18:30에 알려드릴까요? (9/20 ~ 9/26)"  [등록] [취소]

- **`suggestion`과 다릅니다.** 추천은 만들자마자 `status='draft'` 행으로 저장되고 24시간 뒤 만료되지만, 복약은 **행이 있다는 것 자체가 승인의 증거**입니다. 승인 전 행을 두면 발송 잡이 그것을 걸러야 하고 만료 배치가 하나 더 붙습니다.
- **NOT NULL 칸이 비어 있으면 제출 버튼이 잠깁니다.** 초안에 비어 있는 칸 목록(`missing`)이 함께 실리고, 보호자가 채워서 보내야 저장됩니다. 처방전 카드의 "빈칸 + 등록 잠김"과 같은 규칙입니다.
- 수정은 `op="update"` 초안입니다. 제출 전까지 기존 알림은 그대로 울리고, 제출하면 **같은 행을 UPDATE**하고 dose를 다시 만듭니다. 코스를 지웠다 새로 만들지 않으므로 복용 기록이 남습니다.
- **취소하거나 화면을 떠나면 아무 일도 없습니다.** 초안은 run과 함께 사라집니다 — 만료라는 개념이 없습니다. 발송 잡은 `active` 코스만 읽습니다.

**중단** — "약 끊었어"는 `stop_medication_schedule` → `status='stopped'`(soft delete). 행이 남으므로 **먹인 기록이 보존됩니다.** 발송 잡은 `active`만 읽으니 알림은 즉시 멈춥니다. 되돌릴 수 없는 삭제가 아니라서 `event` 삭제와는 방식이 다릅니다 — event는 남길 기록이 없지만 복약은 있습니다.

**복약 이유** — `indication_text`에 보호자 발화를 **그대로 복사**합니다("중이염 때문에"). 발화에 없으면 NULL이고 추정하지 않습니다. `symptom_codes`는 코드가 사전으로 뽑습니다. 이 값은 **진단이 아니라 보호자 기록**이라 `health_safety`로 올라가지 않습니다.

**복용 기록** (AI 0회)

| tool | 동작 |
| --- | --- |
| `log_dose_taken` | "먹였어" → `medication_dose_log`에 시각 기록 (`status='taken'`) |
| `log_dose_skipped` | "못 먹였어" → `status='skipped'`로 기록. 부르지 않은 회차를 코드가 대신 채우지 않는다 |
| `get_next_dose` | "다음 예정 18:00 · 마지막 복용 13:00 · 오늘 2/3회" — **사실만** |

"지금 또 먹여도 돼?"는 용량 판단이라 답하지 않습니다. 대신 위의 사실을 돌려줍니다. 허가가 아니라 시각 안내입니다.

**처방전 초안** — 약봉투·처방전 이미지는 **OCR 파이프라인**이 처리해 `prescription_draft`에 넣습니다. Health는 그 행을 읽어 카드로 보여주기만 합니다.

- 필드별 신뢰도를 함께 표시하고, 흐리게 읽힌 칸은 **보호자가 채우기 전까지 등록 버튼이 잠깁니다**
- 읽히지 않은 값은 **빈칸으로 둡니다.** 추측해서 채우지 않습니다
- `create_medication_schedule`이 이 draft의 값으로 초안을 만들고(`source="prescription_ocr"`), 확인 카드에 **실제 알림 시각까지** 보여줍니다. "확인·등록"이 **제출을 겸합니다**(두 번 묻지 않음 — M-13)
- 약품명은 **대조하지 않습니다.** 일치 여부 표시도 하지 않습니다 — 표시를 붙이면 "비슷한 이름 제안"으로 번질 여지가 생깁니다. 바꿔 넣거나 빠진 용량을 채우는 것도 금지

### 6-6. `care_handoff` — 전달용 서류 (AI 0회)

남에게 아이를 맡길 때 매번 손으로 적는 정보를 앱이 이미 갖고 있습니다. **판단이 0이고 체감이 큰** 자리입니다.

**투약의뢰서** (`compose_daycare_med_notice`)

```
[투약 의뢰서]  2026-09-21
• 약 종류 : 항생제 시럽 (5ml)          ← 등록 원문
• 투약 시각 : 점심 식후 (12:30)         ← scheduled_time
• 보관 : 냉장                          ← storage
• 복용 이유 : 중이염 때문에             ← indication_text (보호자 기록)
• 특이사항 : (보호자 입력 원문)
보호자 확인 후 서명해 주세요.
```

- **고정 서식입니다. 모델이 문장을 다듬지 않습니다.** 기관이 원하는 건 정중한 편지가 아니라 항목이 채워진 양식이고, 모델이 손대면 복약 문구가 미세하게 바뀝니다.
- 저장하지 않고 **복사·공유만** 합니다(알림장 앱에 붙여넣기).
- 끝에 "보호자 확인 후 서명해 주세요"가 **항상** 붙습니다. 투약의뢰서는 보호자 책임 서류입니다.

**응급 카드** (`build_emergency_card`) — 알레르기 · 만성질환 · 복용 중인 약 · 아이 기본 정보 · 보호자 연락처를 한 장으로. 등록된 값의 **복사본**이라 새로 판단하는 것이 하나도 없습니다.

### 6-7. 코드 hook — 라벨과 무관하게 도는 것

Memory가 `observation_health`를 저장한 직후 **pipeline이 코드로 실행**합니다. Supervisor가 Health로 라우팅하지 않아도 돕니다. AI 0회.

| hook | 조건 | 출력 |
| --- | --- | --- |
| `check_symptom_repetition` | 같은 증상이 **14일 안에 3회 이상** (설정값) | readout: "최근 2주 동안 '발열'이 3번 기록됐어요. 병원에서 확인해 보시는 게 좋겠어요." + 병원 찾기 버튼 |

- hook은 `check_symptom_repetition` **하나뿐**입니다. 알레르기 후보 감지(`detect_allergy_candidate`)는 v1에서 뺐습니다 — 알레르기는 보호자가 앱에서 직접 등록하는 경로 하나만 둡니다.
- 반응이 심한 경우(호흡곤란 등)는 **Supervisor 응급 검사가 먼저** 잡습니다.

알레르기 후보 채널(`safety_confirmations`)은 **v1에서 뺐습니다.** 알레르기 등록은 보호자가 앱에서 직접 하는 경로 하나뿐입니다.

`medication_drafts`는 Memory의 `event` 초안과 같은 채널 모양입니다. run 단위 버퍼에 모였다가 한 번에 나가고, run이 끝나면 사라집니다. payload 스키마는 [`health_agent_own_table.md`](health_agent_own_table.md) §6.

```python
@dataclass(frozen=True)
class MedicationDraft:
    draft_id: str                  # 화면이 제출 요청에 되돌려 보내는 키
    op: Literal["create", "update"]
    source: Literal["utterance", "prescription_ocr"]
    schedule_id: str | None        # create면 None
    schedule: dict[str, Any]       # title · dosage · indication_text · storage · med_form · starts_on · ends_on
    doses: tuple[dict[str, Any], ...]
    notice_times: tuple[str, ...]  # 필수 — 실제로 울릴 시각
    missing: tuple[str, ...]       # 비어 있는 NOT NULL 칸 이름. 비지 않으면 제출 잠김
    before: dict[str, Any] | None = None   # update면 수정 전 원본
```

`suggestion`은 쓰지 않습니다. Health에는 "또래 기준 일반 추천"이 성립하지 않습니다.

## 9. 응급 — Health보다 먼저

응급 신호는 **Supervisor 안전 사전검사(규칙)** 가 Agent 라우팅보다 먼저 잡습니다. Health는 이 경로의 뒷단(응급실 찾기)만 제공합니다.

**응급 신호 후보** — 국가건강정보포털·대한소아청소년과학회 자료로 원문 대조 후 확정 (H-1)

- 숨쉬기 힘들어함 · 입술이 파래짐
- 입술·얼굴·목이 붓고 두드러기 (식후 급격히)
- 경련 · 부르거나 건드려도 반응이 없음 · 축 늘어짐
- 생후 3개월 미만의 발열
- 머리를 부딪힌 뒤 반복 구토·처짐
- 소변이 거의 없고 입이 마름 (탈수)

**출력 (코드 상수)**: "지금 바로 119에 연락하거나 가까운 응급실로 가세요." + 응급의료기관 목록. AI 호출 없음. 관찰 저장은 이후에.

## 12. 다른 팀이 알아야 할 것

### 기획·디자인
- 성장 대조 화면은 **없습니다**(09-22 제거). 신체 성장은 Growth 화면에서 추이만
- 알레르기 확인 카드는 **등록 / 아니요** 두 버튼. "아니요"는 같은 식품으로 다시 묻지 않음
- 복약 등록·수정 시 **확인 모달**이 뜨고, 모달에 **실제 알림 시각**이 반드시 나옴. 제출 전에는 저장도 알림도 없음
- 초안에 빈 필수 칸이 있으면 **제출 버튼이 잠김** (처방전 카드와 같은 규칙)
- 복약 중단은 soft delete(`status='stopped'`) — 알림은 즉시 멈추지만 먹인 기록은 남습니다
- 응급 안내 화면에는 다른 추천 카드를 같이 띄우지 않음

### 프론트엔드
- `authored_by="code"` readout은 문자열 그대로 렌더 (가공·요약 금지)
- 위치는 요청 시점에만 전달, 저장 안 함

### 백엔드
- Agent role: `medication_*` write 부여 · `health_safety` write **비부여**
- `health_safety` INSERT는 보호자 세션의 앱 API만 (`created_by = parent.id`)
- 기준표와 **고정 문구 전부** `reference/`에 버전 파일로, 테스트에서 글자 단위로 고정. Health에는 문서 테이블이 없다
- hook 두 개는 pipeline에서 Memory 저장 **직후** 동기 실행
- 선행 스키마: `child.gestational_weeks` · consent 조회 포트 (`child.gender` · `child_growth_log`는 Health와 무관해짐)
- **신규 소유 테이블**: `medication_dose_log` · `medication_schedule` 컬럼 4개 추가 → [`health_agent_own_table.md`](health_agent_own_table.md)
- **공유 테이블 변경 요청**: `observation_health.temperature` · `measured_at` (Memory 소유, Health는 읽기만)
- `prescription_draft`는 **OCR 파이프라인 소유**입니다. Health role에 write 권한을 주지 않습니다
- 처방전 원본 이미지는 파이프라인에서 파기합니다. Health는 추출 결과만 봅니다

### QA
- "잘 크고 있어?" → Health로 **오지 않고** Growth `growth_review`
- 출력 전체에 "저체중·비만·저신장·과체중·장염·폐렴" 등 **진단명 0건**
- "하루 세 번 먹여" (시점 없음) → 저장 0건, 되묻기
- "식후" → +30분으로 draft 저장, 확인 모달에 08:30 · 12:30 · 18:30 표시
- 제출 전에는 **DB에 행이 없음** (`medication_schedule` 0건) · 알림도 없음
- NOT NULL 칸이 빈 초안 → `missing`에 이름이 있고 제출이 막히는가
- 수정 → `op="update"` 초안, 제출 전까지 기존 알림 유지 · 제출 시 같은 행 UPDATE(복용 기록 유지)
- "약 끊었어" → `status='stopped'` · 발송 0건 · `medication_dose_log` 보존
- 14일 안 발열 3회 → 반복 readout / 15일 간격 3회 → 없음
- "숨을 못 쉬어" → Health까지 **가지 않고** 응급 안내
- 동의 철회 → Health 전 라벨 AI 0회
- 투약의뢰서·응급 카드 → AI 호출 **0회**, 서식이 상수와 글자 단위로 같음
- 투약의뢰서 끝에 "보호자 확인 후 서명" 문구가 **항상** 있는가
- 열 타임라인 출력에 **약 성분·계열 단어가 0건**인가 (아세트아미노펜·이부프로펜 등)
- "지금 또 먹여도 돼?" → 허가 문구 0건, 반환값에 `can_take` 필드 **없음**
- 3일 연속 발열 → 에피소드 **1건**으로 묶이는가 (반복 3회 오판정 방지)
- 처방전 초안에서 안 읽힌 칸 → 빈칸으로 남고 자동 채움 0건
- 검진 맥락 요약에 **발달 문항·체크·점수 0건**
- `indication_text` — 발화에 이유가 없으면 NULL (추정 저장 0건)
