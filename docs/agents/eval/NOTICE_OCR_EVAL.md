# 알림장 · 공지 OCR 프롬프트 평가

어린이집 · 유치원 공지(글자 · 사진)를 읽어 일정 · 할 일 · 안내 항목으로 나눈다. 날짜는 모델이 날짜 표현만 옮기고 계산은 코드가 한다. 표시 없이 틀린 날짜가 일정 초안에 오르면 틀린 날에 알림이 울린다.

프롬프트: `app/providers/notice/extractor.py` (`SYSTEM_PROMPT` · `IMAGE_ADDENDUM`)
tool spec · 응답 스키마: `app/providers/notice/extractor.py` (`_response_format` — `NoticeExtract` · `ImageNoticeExtract`)

지문은 `apps/api/app/agents/prompt_registry.py` 의 `all_fingerprints()["notice_ocr"]` 로 확인한다 (문서에는 앞 12자). 고정 입력으로 렌더링한 system 프롬프트 + user 메시지 틀 · 재시도 문구 + tool spec · 응답 스키마의 SHA-256 이다 — 모델 · effort 는 지문에 넣지 않고 `조건` 칸에 적는다. tool 이 돌려주는 실패 사유 문구는 Memory 것만 들어가고 나머지 Agent 는 아직 지문 밖이다.

## 1. 측정 이력

프롬프트나 tool spec 을 바꾸면 이 표에 행을 더한다 — 무엇을 왜 바꿨는지 한 줄씩. 마지막 행의 지문이 지금 프롬프트와 다르거나, 같은 `조건` 의 직전 행보다 C1 이 늘면 `tests/unit/agents/common/test_prompt_history.py` 가 실패한다.

| 버전 | 커밋 | 지문 | 조건 | 무엇을 왜 바꿨나 | C1 | 안정 오답 | 불안정 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| v0 | `3e0d3afc` | `f3239166b835` | 미측정 | 최초 기준선. 기존 수치는 표본이 달라 `a/b` 로 옮기지 않고 §0 에만 둠 | 미측정 | 미측정 | 미측정 |

- `커밋` 은 재 본 코드. 작업 트리가 더러웠으면 커밋 옆에 `dirty` 를 적는다 (`tests/eval/agents/live_run_meta.json` 의 `dirty`).
- `C1` 칸은 `a/b` (C1 사례 입력 수 / 전체 입력 수). `미측정` 은 v0 에만 쓴다.
- 프롬프트를 바꿀 때는 **같은 조건으로 잰 바꾸기 전 행** 이 있어야 한다. 기준선이 `미측정` 이면 바꾸기 전 프롬프트로 한 행, 바꾼 뒤로 한 행을 같은 조건으로 더한다.

## 2. C1 · 일반 실패 판정 기준

**C1 = 보호자가 출력을 그대로 믿고 따랐을 때 ① 아이가 다칠 수 있거나 ② 아이에 대한 틀린 판단이 남거나 ③ 되돌릴 수 없는 일이 생기는 출력.** 단순 응답 품질 저하와 구분하고, 실제 사용자에게 미칠 영향을 기준으로 판단한다.

**이 프롬프트의 C1**

- **표시(`needs_review`) 없이 틀린 일정 · 할 일 날짜** — 못 읽으면 보호자가 채우지만 틀리면 틀린 날에 알림이 울린다
- 기관이 보낸 건강 안내를 아이의 건강 판단(진단)으로 옮김 — 안내는 `info` 이고 `health_safety` 로 가지 않는다

**일반 실패**

- 표시 없이 빈 값 (보호자가 채운다)
- 분류 틀림 (calendar · todo · info)
- 항목 수가 흔들림 (한 문서에서 3개와 10개)

일반 실패는 단독으로 나오면 C1 이 아니다. 다만 C1 의 세 조건 중 하나를 만족하면 C1 을 먼저 적용한다. **근거 없는 개인화 표현 · 되묻기 2개 이상**은 루트 CLAUDE.md §2 절대 규칙이라 C1 은 아니어도 0건을 유지하고, 늘면 리뷰에서 막는다.

**반복 · 비교 규칙**

- 같은 입력을 R번 돌려 **한 번이라도 C1 이 나오면 그 입력은 C1 사례**다. 입력별 발생 횟수도 §3 에 적는다. 일부 실행에서만 나온 오류도 불안정하다는 이유로 빼지 않는다.
- 측정 이력의 `C1` 칸은 `a/b` — a = C1 사례인 입력 수, b = 전체 입력 수. `test_prompt_history.py` 가 같은 `조건` 의 직전 측정 행과 **비율 a/b** 를 비교해 늘었으면 실패시킨다 (평가셋이 커져 건수만 늘면 통과).
- 프롬프트를 바꾼 행은 **같은 조건으로 잰 바꾸기 전 행** 이 있어야 한다 — 없으면 실패. 기준선이 `미측정` 이면 바꾸기 전 프롬프트로 한 행, 바꾼 뒤로 한 행을 같은 조건으로 더한다.
- 조건(평가셋 · 모델/effort · 반복 횟수)을 바꿨으면 바꾸기 전 프롬프트를 새 조건으로 먼저 다시 재서 행을 더한다. 같은 지문으로 조건만 바꿔 다시 잰 행은 비교하지 않는다.

## 3. 반복해서 같은 오답 · 흔들리는 값

말뭉치가 저장소 밖에 있어 재측정은 가진 사람만 할 수 있다. 사람이 확정한 공지 정답셋이 먼저 필요하다.

## 4. 실행 방법

```powershell
# 말뭉치 · 결과는 저장소 밖. DB 는 실험용 DB 를 가리킨다
uv run python scripts/notice_corpus_eval.py llm <말뭉치> <결과 폴더> --max-calls 100
uv run python -m tests.eval.agents.run_meta scripts/notice_corpus_eval.py  # 메타
```

🚨 프롬프트 · 응답 스키마를 바꾸면 `extractor.PROMPT_VERSION`(저장된 행을 다시 뽑을지 고르는 캐시 키)도 올린다. 판을 안 올리면 `tests/unit/test_prompt_call_logs.py` 의 판 · 지문 표가 실패한다.

pytest 라이브 eval(`-m live`)은 끝나면 `tests/eval/agents/live_run_meta.json`(gitignore)에 커밋 · dirty · 모델 · effort · 반복 횟수 · 프롬프트 지문을 남긴다. pytest 가 아닌 스크립트는 위의 `run_meta` 명령으로 남긴다. 그 값으로 §1 에 행을 더한다. 라이브 eval 은 CI 에서 돌리지 않는다.
