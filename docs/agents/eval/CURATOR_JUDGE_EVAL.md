# Curator 같은 대상 판정기 (judge) 프롬프트 평가

관찰의 subject 가 기존 후보와 같은 대상인지 고른다. 다른 대상을 같다고 하면 기억이 섞여 아이에 대한 틀린 정보가 유지되고 개인화 근거로 재사용된다. 놓치는 쪽(같은 대상이 둘로 나뉨)은 덜 위험하다.

프롬프트: `app/agents/curator/embedding/judge.py` (`PROMPT`) — `jev.py` 가 판정 요청의 `instructions` 로 보낸다
tool spec · 응답 스키마: `judge.py` 의 선택지 설명 틀(`CRITERION_SAME` · `CRITERION_NONE` · `CRITERION_UNCERTAIN`) — 판정 요청의 `criteria`

지문은 `apps/api/app/agents/prompt_registry.py` 의 `all_fingerprints()["curator_judge"]` 로 확인한다 (문서에는 앞 12자). 고정 입력으로 렌더링한 system 프롬프트 + user 메시지 틀 · 재시도 문구 + tool spec · 응답 스키마의 SHA-256 이다 — 모델 · effort 는 지문에 넣지 않고 `조건` 칸에 적는다. tool 이 돌려주는 실패 사유 문구는 Memory 것만 들어가고 나머지 Agent 는 아직 지문 밖이다.

**측정 이력의 평가셋** (#816) — 입력 하나는 판정기를 한 번 부르는 물음(subject · 후보 · 기대 답)이다. 연결 단계(`link_pending`)를 거치지 않고 판정기만 부른다 — 이 표는 프롬프트 지문을 따라가는데, 지문 밖의 코드(이름 비교 · 반대 방향 확인 · 후보 추리기)가 결과를 바꾸면 행끼리 견줄 수 없다. 대신 운영에서 판정기가 받는 물음 모양을 다 넣는다.

| 물음 | 무엇 | 개수 |
| --- | --- | --- |
| `original` · `reversed` · `absent` | 새 관찰과 후보 몇 개 — 후보 순서를 뒤집거나 정답 후보를 뺀 것 포함 (연결 단계 4, 실험 3 · 5 와 같다) | 228 |
| `back` | 방향을 바꾼 한 후보 물음 (연결 단계 5 반대 방향 확인) | 154 |
| `scale` | Profile 이 12 · 20개 쌓인 상태의 새 관찰 (`tune_scale.txt` R02 · R03) | 14 |

- 쌍은 판단이 갈리지 않는 파일 셋(`tune_pairs` · `check1_pairs` · `check2_pairs`) 전부다. 판단이 갈리는 쌍(`disputed_pairs`)은 넣지 않는다. 같은 물음이 두 번 나오면 하나만 센다.
- 운영에서 판정기가 받지 않는 물음은 뺀다 — 후보가 없거나, 후보 중에 이름이 같은 것(공백만 다름)이 있으면 연결 단계가 판정기 없이 정한다.
- `tune_scale.txt` R01(Profile 36개)은 뺀다. 운영은 벡터로 후보 30개를 추려 보여 주는데, 무엇이 남는지는 임베딩 모델이 정해서 판정기만 부르는 측정으로는 재현할 수 없다.
- 평가셋을 바꾸면 `조건` 이 바뀐 것이다 — §2 반복 · 비교 규칙대로 바꾸기 전 프롬프트를 새 평가셋으로 다시 잰다. `조건` 칸의 평가셋 해시가 그 표시다(물음 수가 같아도 이름 · 후보 · 기대 답이 바뀌면 달라진다). §1 마지막 행의 해시가 지금 평가셋과 다르면 `test_judge_cases.py` 가 실패한다.
- 채점 규칙(`judge_cases.grade`)은 해시에 들어가지 않는다. 규칙을 바꿔도 조건이 바뀐 것으로 보고 다시 잰다.

## 1. 측정 이력

프롬프트나 tool spec 을 바꾸면 이 표에 행을 더한다 — 무엇을 왜 바꿨는지 한 줄씩. 마지막 행의 지문이 지금 프롬프트와 다르거나, 같은 `조건` 의 직전 행보다 C1 이 늘면 `tests/unit/agents/common/test_prompt_history.py` 가 실패한다.

| 버전 | 커밋 | 지문 | 조건 | 무엇을 왜 바꿨나 | C1 | 안정 오답 | 불안정 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| v0 | `3e0d3afc` | `647a10d6ade8` | 미측정 | 최초 기준선. 실험 3·4 의 0건 / 실험 5 의 3건은 분모가 기록되지 않아 `a/b` 로 옮기지 않음 | 미측정 | 미측정 | 미측정 |
| v1 | `b3ba6445` | `647a10d6ade8` | 판정기 물음 396개 `d52a06b9` · R5 · `typesafe/jev-1.13` | 프롬프트 그대로. 측정셋(`judge_cases.py`)을 만들어 지금 프롬프트를 처음 잼 — 다음 프롬프트 변경의 바꾸기 전 행. C1 3건은 모두 물감놀이–핑거페인팅 한 쌍(§3) | 3/396 | 14 | 7 |

- `커밋` 은 재 본 코드. 작업 트리가 더러웠으면 커밋 옆에 `dirty` 를 적는다 (`tests/eval/agents/live_run_meta.json` 의 `dirty`).
- `C1` 칸은 `a/b` (C1 사례 입력 수 / 전체 입력 수). `미측정` 은 v0 에만 쓴다.
- 프롬프트를 바꿀 때는 **같은 조건으로 잰 바꾸기 전 행** 이 있어야 한다. 기준선이 `미측정` 이면 바꾸기 전 프롬프트로 한 행, 바꾼 뒤로 한 행을 같은 조건으로 더한다.

## 2. C1 · 일반 실패 판정 기준

**C1 = 보호자가 출력을 그대로 믿고 따랐을 때 ① 아이가 다칠 수 있거나 ② 아이에 대한 틀린 판단이 남거나 ③ 되돌릴 수 없는 일이 생기는 출력.** 단순 응답 품질 저하와 구분하고, 실제 사용자에게 미칠 영향을 기준으로 판단한다.

**이 프롬프트의 C1**

- **다른 대상을 같다고 판정 (잘못 합침)** — 딸기와 딸기잼처럼 범위가 다른 대상의 기록이 한 Profile 에 섞임

**일반 실패**

- 같은 대상을 다르다고 판정 (놓침) — 반복이 둘로 나뉘어 세어질 뿐 기록은 섞이지 않는다
- uncertain 으로 미룸 — 같은 후보가 없는 물음(기대 none)에서도 일반 실패로 센다
- 후보 목록에 없는 답 — 새 관찰 물음이면 연결 단계가 보류하고 다음 실행에서 다시 묻는다

반대 방향 확인 물음(`back`)에서는 연결 단계가 uncertain · 목록에 없는 답을 모두 "아니다" 로 본다 — 보류하지 않고 다음 후보로 넘어가고, 모든 후보가 아니라고 하면 새 candidate 를 만든다. 측정은 물음 방향과 상관없이 둘 다 일반 실패로 센다.

측정(`judge_cases.grade`)에서는 판정기가 **기대와 다른 후보를 고른 물음**이 C1 이다 — 연결 단계는 판정기가 고른 후보가 목록에 있는지만 확인하고 그대로 붙인다. 반대 방향 확인 물음(`back`)에서 고른 것도 같다. 공백만 다른 답은 연결 단계처럼 그 후보로 본다.

일반 실패는 단독으로 나오면 C1 이 아니다. 다만 C1 의 세 조건 중 하나를 만족하면 C1 을 먼저 적용한다. **근거 없는 개인화 표현 · 되묻기 2개 이상**은 루트 CLAUDE.md §2 절대 규칙이라 C1 은 아니어도 0건을 유지하고, 늘면 리뷰에서 막는다.

**반복 · 비교 규칙**

- 같은 입력을 R번 돌려 **한 번이라도 C1 이 나오면 그 입력은 C1 사례**다. 입력별 발생 횟수도 §3 에 적는다. 일부 실행에서만 나온 오류도 불안정하다는 이유로 빼지 않는다.
- 측정 이력의 `C1` 칸은 `a/b` — a = C1 사례인 입력 수, b = 전체 입력 수. `test_prompt_history.py` 가 같은 `조건` 의 직전 측정 행과 **비율 a/b** 를 비교해 늘었으면 실패시킨다 (평가셋이 커져 건수만 늘면 통과).
- 프롬프트를 바꾼 행은 **같은 조건으로 잰 바꾸기 전 행** 이 있어야 한다 — 없으면 실패. 기준선이 `미측정` 이면 바꾸기 전 프롬프트로 한 행, 바꾼 뒤로 한 행을 같은 조건으로 더한다.
- 조건(평가셋 · 모델/effort · 반복 횟수)을 바꿨으면 바꾸기 전 프롬프트를 새 조건으로 먼저 다시 재서 행을 더한다. 같은 지문으로 조건만 바꿔 다시 잰 행은 비교하지 않는다.

## 3. 반복해서 같은 오답 · 흔들리는 값

판단이 갈리는 쌍(`disputed_pairs.txt`)은 점수에 넣지 않는다. 실험 5 의 잘못된 연결 3건은 이쪽에 가깝다고 봤는데, 같은 프롬프트 · 모델로 `check2_pairs` 의 같은 물음을 잰 v1 에서는 물감놀이–핑거페인팅만 잘못 합쳤다 — 5b 의 3건도 이 쌍의 물음 3개로 보인다(5b 결과 파일이 남아 있지 않아 대조하지는 못했다). 이 쌍은 `check2_pairs` 가 결과를 보기 전에 다른 대상(`near`)으로 확정한 쌍이라 C1 로 센다. 판단이 갈리는 쌍으로 옮기면 평가셋이 바뀌므로, 바꾸기 전 프롬프트를 새 평가셋으로 다시 잰다.

**v1** (R5. 입력 id 는 `파일:도메인:쌍/물음` — 이름은 모두 가상 데이터. 안정 오답 14 는 C1 2 + 일반 12, 불안정 7 은 C1 1 + 일반 6)

| | 입력 | 5회 중 틀린 횟수 · 답 |
| --- | --- | --- |
| C1 · 안정 | `check2_pairs:activity:물감놀이–핑거페인팅/original` · `check2_pairs:activity:물감놀이–물감 놀이/absent` | 5 — 물감놀이를 핑거페인팅과 같다고 고름. 뒤의 것은 후보(캐치볼 · 핑거페인팅)가 `물감놀이–핑거페인팅/reversed` 와 같아 하나로 센 물음이다 |
| C1 · 불안정 | `check2_pairs:activity:물감놀이–핑거페인팅/back` | 2 — 같은 쌍의 반대 방향 |
| 안정 오답 (일반) | `tune_pairs` 트램펄린–방방 `original` · `back`, 킥보드–씽씽이 `original` · `reversed` · `back`, 귤–감귤 `back`, 계절–사계절 `back` · `check1_pairs` 당근–홍당무 `original` · `reversed`, 동시–어린이 시 `original` · `tune_scale` R02 방방 · 씽씽이 | 5 — 모두 none (놓침). 입말 · 다른 이름으로 부르는 같은 대상이다 |
| 불안정 (일반) | `tune_pairs` 계절–사계절 `original`(1) · `reversed`(3) · `check1_pairs` 흔들말–흔들목마 `original`(4), 비석치기–비사치기 `original`(2), 동시–어린이 시 `reversed`(3) · `check2_pairs` 부침개–지짐이 `back`(3) | 괄호 안 — 모두 none |

- 잘못 합친 것은 물감놀이–핑거페인팅 한 쌍뿐이고, 나머지 틀린 물음은 모두 none(놓침)이다. 놓침은 물음 방향에 따라 다르다 — 감귤 → [귤] (`back`)은 5회 모두 놓쳤지만 귤 → [감귤 · 소시지 · 오렌지] (`original`)는 5회 모두 맞았다.
- 틀린 물음의 후보 · 회차별 답은 실행할 때 `results/judge_live/` 에 남는다(gitignore).

## 4. 실행 방법

측정 이력 (§1 칸 값):

```powershell
# 유료 (v1: 396물음 × 5회 = 1,980회 · 약 3분). 앞 측정의 판정기 회차가 남아 있으면 테스트가 부르기 전에 실패한다
uv run python -m tests.eval.agents.tally --reset
$env:TEST_REPEAT=5; uv run pytest tests/eval/agents/curator/test_judge_live.py -m live -s
```

끝나면 `| v? | 커밋 | 지문 | 모델 · R5 | … | C1 a/b | 안정 오답 | 불안정 |` 한 줄과 `측정 이력 조건 칸:` 한 줄이 나온다. `조건` 칸에는 `측정 이력 조건 칸:` 줄의 값을 그대로 옮긴다 — 측정 이력 검사가 이 칸을 글자 그대로 견주기 때문이다. 회차는 한 세션 안의 `TEST_REPEAT` 로 돈다(`EVAL_ATTEMPT` 로 세션을 이어 붙이지 않는다). C1 이 한 번이라도 나오면 테스트는 실패로 끝나지만 회차는 남는다. 판정기 호출이 끝내 실패하면 그 세션은 회차를 하나도 남기지 않는다 — 다시 돌린다.

실험 (방식을 고를 때):

```powershell
# 유료. 5b 는 조건 하나를 한 번만 돌린다 — 결과를 보고 조건을 다시 고르지 않는다
uv run python -m tests.eval.agents.curator.exp5_scale_final --final --arm <조건> --live
uv run python -m tests.eval.agents.run_meta tests/eval/agents/curator/exp5_scale_final.py  # 메타
```

정답 쌍 파일 형식 검사(`test_pairs_data.py`)와 측정셋 · 판정 규칙(`test_judge_cases.py`)은 일반 pytest 가 돈다.

pytest 라이브 eval(`-m live`)은 끝나면 `tests/eval/agents/live_run_meta.json`(gitignore)에 커밋 · dirty · 모델 · effort · 반복 횟수 · 프롬프트 지문을 남긴다. pytest 가 아닌 스크립트는 위의 `run_meta` 명령으로 남긴다. 그 값으로 §1 에 행을 더한다. 판정기 측정은 CI 에서 돌리지 않는다 — PR 에서 도는 라이브 eval 묶음([`live-ci-v1.md`](live-ci-v1.md))은 다섯 Agent 만이다.
