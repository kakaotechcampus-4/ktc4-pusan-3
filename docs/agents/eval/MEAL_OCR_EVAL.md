급식표 사진을 읽어 날짜 · 끼니 · 메뉴로 옮긴다. 읽은 메뉴가 그날 급식 정보가 되어 Food 의 근거가 된다.

프롬프트: `app/providers/meal_plan/image_ocr.py` (`SYSTEM_PROMPT`)
tool spec · 응답 스키마: `app/providers/meal_plan/image_ocr.py` (`RESPONSE_FORMAT`)

지문은 `apps/api/app/agents/prompt_registry.py` 의 `all_fingerprints()["meal_ocr"]` 로 확인한다 (문서에는 앞 12자). 고정 입력으로 렌더링한 system 프롬프트 + user 메시지 틀 · 재시도 문구 + tool spec · 응답 스키마의 SHA-256 이다 — 모델 · effort 는 지문에 넣지 않고 `조건` 칸에 적는다. tool 이 돌려주는 실패 사유 문구는 Memory 것만 들어가고 나머지 Agent 는 아직 지문 밖이다.

## 2. C1 · 일반 실패 판정 기준

**C1 = 보호자가 출력을 그대로 믿고 따랐을 때 ① 아이가 다칠 수 있거나 ② 아이에 대한 틀린 판단이 남거나 ③ 되돌릴 수 없는 일이 생기는 출력.** 단순 응답 품질 저하와 구분하고, 실제 사용자에게 미칠 영향을 기준으로 판단한다.

**이 프롬프트의 C1**

- 정답과 다른 메뉴가 그 날짜 · 끼니의 급식으로 읽힘 (메뉴 이름 · 날짜 · 끼니 불일치) — 저장되면 Food 가 그날 급식으로 믿고 쓰고, 보호자가 먹은 양을 기록하면 틀린 메뉴에 붙어 남는다 (②). 11-09 PM 확정
- 알레르기 번호 불일치는 C1 이 **아니다** — 10-09 부터 서비스가 번호를 읽지 않는다. 번호를 다시 읽는 쪽으로 바뀌면 C1 로 되돌린다 (그때 신체 위해 가능성 ①)

**일반 실패**

- 정답 메뉴를 빼먹기만 함 (틀린 메뉴는 안 들어감) — 화면에 덜 보일 뿐 틀린 메뉴가 기록에 붙지 않는다. 11-09 PM
- 이름 깨짐 — 맞는 메뉴인데 이름(`name`)에 한글이 아닌 찌꺼기가 붙음(`백김치(백깍두기 Riot`). 다른 음식으로 바뀐 것이 아니다. 저장되면 카탈로그에 없는 메뉴가 되어 알레르기 판정이 통과가 아니라 "확인 못 함" 으로 나온다(`food_safety.filter_food_safety` 5번) — 틀린 판단이 남지 않아 C1 이 아니다. 이름이 **다른 음식**을 말하면(원문 `현미밥` 에 이름 `흑미밥`) 위의 C1 이다. 11-10 결정
- 원문 글자 차이 (공백 · 기호)
- `unparsed` 칸이 늘어남 (모델이 못 읽겠다고 신고)

일반 실패는 단독으로 나오면 C1 이 아니다. 다만 C1 의 세 조건 중 하나를 만족하면 C1 을 먼저 적용한다. **근거 없는 개인화 표현 · 되묻기 2개 이상**은 루트 CLAUDE.md §2 절대 규칙이라 C1 은 아니어도 0건을 유지하고, 늘면 리뷰에서 막는다.

**반복 · 비교 규칙**

- 같은 입력을 R번 돌려 **한 번이라도 C1 이 나오면 그 입력은 C1 사례**다. 입력별 발생 횟수도 §3 에 적는다. 일부 실행에서만 나온 오류도 불안정하다는 이유로 빼지 않는다.
- 측정 이력의 `C1` 칸은 `a/b` — a = C1 사례인 입력 수, b = 전체 입력 수. `test_prompt_history.py` 가 같은 `조건` 의 직전 측정 행과 **비율 a/b** 를 비교해 늘었으면 실패시킨다 (평가셋이 커져 건수만 늘면 통과).
- 프롬프트를 바꾼 행은 **같은 조건으로 잰 바꾸기 전 행** 이 있어야 한다 — 없으면 실패. 기준선이 `미측정` 이면 바꾸기 전 프롬프트로 한 행, 바꾼 뒤로 한 행을 같은 조건으로 더한다.
- 조건(평가셋 · 모델/effort · 반복 횟수)을 바꿨으면 바꾸기 전 프롬프트를 새 조건으로 먼저 다시 재서 행을 더한다. 같은 지문으로 조건만 바꿔 다시 잰 행은 비교하지 않는다.

## 3. 반복해서 같은 오답 · 흔들리는 값

**채점 방법** (`scripts/meal_ocr_eval.py`)

- 입력 하나 = 끼니 하나(날짜 × 끼니). 분모 = 정답 끼니 69 + 어느 실행에서든 정답에 없는데 메뉴가 생긴 끼니(휴일에 급식이 생기는 날짜 밀림도 C1 이라 분모에 넣는다)
- 모델 출력은 운영이 싣는 끼니(점심 · 오전간식 · 오후간식)만 본다. 아침 · 저녁으로 간 메뉴는 저장되지 않아 틀린 메뉴가 남지 않고, 제 끼니에서 빼먹은 것(일반 실패)으로 잡힌다. 메뉴 이름이 없는 끼니(번호뿐)는 세지 않는다. 한 날짜에 같은 끼니가 두 번 나오면 이어 붙여 채점한다 — 운영은 둘 다 화면에 싣는다
- 메뉴 이름은 알레르기 번호를 떼고 괄호로 나눈 조각을 순서 없이 비교한다 — 공백 · ★ · 칸 끝 쉼표 · `백김치(백깍두기)` ↔ `백깍두기(백김치)` 는 같은 메뉴. 맞춤법 차이는 사람이 같은 음식이라고 확인한 것만 `SAME_MENU_SPELLING` 에 둔다(현미밥 / 흑미밥 처럼 한 글자만 달라도 다른 메뉴라 글자 거리로 묶지 않는다)
- 이 "같은 메뉴" 는 보호자가 화면에서 보는 이름 기준이다. 저장 키(`normalize_menu_key`, 괄호 안을 지운다)와는 다르다 — `빵(우유식빵)` · `빵(우유카스텔라)` 는 저장 키가 둘 다 `빵` 이지만 보이는 이름이 달라 C1 로 세고, `백김치(백깍두기)` · `백깍두기(백김치)` 는 저장 키가 다르지만(`백김치` · `백깍두기`) 같은 메뉴로 본다
- 항목은 원문(`raw`)과 이름(`name`)이 둘 다 맞아야 한다. 화면 제목과 저장 키는 원문이 아니라 이름으로 만든다(`photo_run._meal_entries`). 이름은 원문에서 번호 · 분량 · 대체 메뉴를 뺀 것이라 원문의 일부여도 맞다(`백김치9(백깍두기9)` 의 이름 `백김치`). 이름에 원문에 없는 낱말이 있을 때, 한글 낱말이면 다른 음식으로 보고 C1, 한글이 아닌 것뿐이면 이름 깨짐(일반 실패, §2)이다. 찌꺼기가 한글로 나오면 C1 로 잡힌다 — 헷갈릴 때 엄하게 세는 쪽이다
- 안정 오답 = 5번 다 실패한 끼니, 불안정 = 일부만 실패한 끼니. 실패 = C1 · 메뉴 빼먹음 · 이름 깨짐. 읽기에 실패한 회차는 모든 끼니를 빼먹은 것으로 센다(틀린 메뉴가 남지 않는다). 한 번도 못 읽으면 잰 것이 아니라서 종료 코드 1 로 끝나고 실행 메타를 남기지 않는다

## 4. 실행 방법

```powershell
uv run python -m scripts.meal_ocr_eval --check   # 접속 · 모델 목록만 (과금 없음)
uv run python -m scripts.meal_ocr_eval tests/fixtures/meal_plan_2025_01.jpg --repeat 5
```

같은 사진을 5번 읽어(한 번에 호출 2회, 11-09 기준 약 430원 · 7분) 끝에 `측정 이력 칸`(C1 `a/b` · 안정 오답 · 불안정)과 끼니별 실패 횟수를 출력하고, `tests/eval/agents/live_run_meta.json`(gitignore)에 커밋 · dirty · 모델 · effort · 반복 횟수 · 프롬프트 지문을 남긴다. 그 값으로 §1 에 행을 더한다. 모델 출력은 `--out`(기본 임시 폴더)에 실행마다 저장한다. 호출이 `--max-calls`(기본 20)를 넘으면 시작하지 않는다 — 예산을 넘기면 팀 키가 삭제된다. 라이브 eval 은 CI 에서 돌리지 않는다.
