## 1. 누구의, 어떤 문제인가

### 딱 한 사람

**김서연 / 34세 / IT 기업 맞벌이.** 남편은 출장이 잦아 집에 있는 날이 한 달에 일주일도 안 된다. 양가 부모님 도움도 어렵다. 5세 민준이의 하원 후부터 다음 날 등원까지는 전부 서연의 몫이다.

### 문제가 터지는 순간

> 오후 회의 중 어린이집에서 메시지가 온다. *"민준이가 점심을 많이 먹지 않았고 오후부터 컨디션이 좋지 않아요."*
동시에 내일 준비물 공지가 올라오고, 저녁 메뉴를 정해야 하고, 주말 계획도 아직 없다.
서연은 오늘 급식표 · 최근 먹은 음식 · 이전 컨디션 기록 · 병원 일정 · 학원 일정을 **각각 열어서 직접 연결해야** 한다.
> 

### 문제 한 문장

**일과 육아를 병행하는 양육자는** 알림장·일정·식사·행동·과거 경험 등 흩어진 정보를 **매번 직접 찾아 연결하고, 무엇이 지금 중요한지 판단한 뒤, 다음 행동까지 결정해야** 하는 **반복적인 육아 인지 노동**에 시달린다.

### 지금은 어떻게 버티고 있나 — 부모가 수동 Supervisor다

```
키즈노트 확인 → 캘린더로 옮기기 → 배우자에게 카톡 전달 → 맘카페 검색
→ 범용 AI에 아이 나이·취향·과거 상황 재설명 → 다른 보호자에게 인수인계
```

**근거 (Blind 게시글 3건, 서로 다른 사람·다른 시기·같은 불평)**

| 무슨 불평이었나 | 시사점 |
| --- | --- |
| 워킹맘 1년 4개월 — 어린이집 준비물을 깜빡할 때가 있다 (2022) | 공지를 **읽는 것**과 **행동으로 옮기는 것** 사이에서 누락이 난다 |
| 업무 중 키즈노트 알림 + 육아를 동시 처리하다 기저귀 재고를 놓침 (2025) | 부담의 정체는 정보 부족이 아니라 **동시에 기억·연결·처리하는 노동** |
| 일·육아 병행이 힘들어 퇴사 (2025) | 정보를 찾고 프롬프트를 정성껏 쓰는 것조차 **추가 노동**이 된다 |

> 🔑 4건 전부 "몰라서"가 아니라 **"연결해야 해서"** 힘들다고 말한다. 우리가 없앨 건 정보가 아니라 **연결 노동**이다.

## 2. 무엇을 바꾸는가

|  | 지금 | 우리 서비스 |
| --- | --- | --- |
| **흐름** | 알림 확인 → 기억 → 일정 옮기기 → 검색 → 과거정보 찾기 → 비교 → 배우자 전달 → 결정 | AI가 읽고 연결 → "오늘 신경 쓸 것"과 선택지 제시 → **보호자는 확인·선택** |
| **AI에 물을 때** | 매번 아이 나이·성향·과거 반응을 다시 붙여넣기 | 이미 아이 중심으로 쌓여 있음 |
| **유저가 바꿀 습관** | — | **새 습관 없음.** 이미 배우자에게 하던 말의 **수신처만** 바꾼다 |

### 포지셔닝

우리는 일·육아를 병행하는 양육자가 **매번 정보를 찾아 연결하고 AI에 아이를 다시 설명하는 과정**을, AI가 자동으로 구축하는 **Child Memory**와 전문 Agent의 **근거 기반 제안**을 통해 **'확인하고 선택하는 몇 번의 행동'**으로 줄이도록 돕는다.
단, 일정 등록·건강 기록 확정처럼 **되돌릴 수 없는 것은 항상 사람이 승인**한다.

> **목표는 부모가 육아에 덜 참여하게 만드는 것이 아니다.**
아이와 함께 있는 시간 **밖에서** 발생하는 '찾기·기억하기·연결하기·비교하기'를 줄이는 것이다.

## 3. 어떻게 동작하는가

### 이 한 줄이 다 보여줍니다

> 하원길에 서연이 앱에 한 줄 남긴다 —
**"오늘 농구하는 형들 계속 보더라. 저녁엔 또 계란말이 해달래, 5일째야."**
> 

```
① 분류        Supervisor — 안전 사전검사(규칙) + 의도 판정(기록형/요청형/혼합형)
     ↓         → "혼합형" 판정. 저장 먼저, 강제.

② 기록        Memory Agent + Curator — 한 줄이 관찰 2건으로 분리된다
     ↓         🏀 농구 관심   → 관찰 1회 · 확정 아님
               🍳 계란말이     → 반복 5회 · 오늘 급식에도 계란말이

③ 검색&행동   공통 컨텍스트 강제 주입(프로필·알레르기·오늘 급식·이번 주 일정)
     ↓         → Agent별 의미 검색 → 후보 생성 + 규칙 필터 + 근거 매핑
               ※ 방금 저장한 "5일째"가 검색 결과에 포함된 상태로 추천이 만들어진다

④ 승인        되돌릴 수 없는 것만 사람 앞으로
     ↓         ㉠ 캘린더 등록  ㉡ 알레르기 기록에 없는 재료 확인

⑤ 반영        선택·거절·Correction을 Memory로 되돌려 기록
               → 다음 입력의 맥락이 된다
```

### 화면으로는 이렇게 이어집니다 (끊김 없음)

```
첫 진입          이름·나이·알레르기만. 권한 요구 없음
   ↓
입력             하단 한 줄 입력창 "오늘 있었던 일, 말하듯 적어주세요" — 형식 요구 없음
   ↓
진행             체크리스트가 채워짐 ☑저장(2건) → ☑기록 찾음 → ▸후보 생성 중. 누를 것 없음
   ↓
저장 확인        한 줄 → 관찰 2건 분리 + `관찰 1회` `반복 5회` 라벨
   ↓
제안             후보 2~3개 + Why this / Why now + 사용한 기록 3건
   ↓
승인             여기만. 일정 등록 · 알레르기 확인
   ↓
기록 수정        `맞아요` `한 번 본 것뿐` `지금은 달라요` `잘못된 기록` → 즉시 재계산
```

### 자율성 경계 — AI는 어디까지, 사람은 어디서

|  |  |
| --- | --- |
| **AI가 하는 것** | 자연어에서 관찰 추출·라벨링(Fact/Observation/Inference), 의도 분류·라우팅, 식사·놀이·교육 후보 생성 |
| **코드(규칙)가 하는 것** | 날짜·나이 계산, 일정 충돌, **알레르기·금지식품 필터**, Memory 감쇠, 반복 승격, 승인 게이트 |
| **사람이 하는 것** | **되돌릴 수 없는 것만** — 일정 등록/변경, 알레르기·건강 기록 확정 |

| # | 항목 | 우리 답 |
| --- | --- | --- |
| ① | 모델 호출 횟수 | **최소 1회 · 최대 3회** (Supervisor 1 + 도메인 Agent 최대 2) |
| ② | 사람이 서는 칸 | 있음 — 승인 단계 **1곳** |

| ④ | 통과 판정 | ㉠결과가 맞나(eval 10개) ㉡**경로가 맞나(붙인 API를 실제로 불렀나)** |

> ⚠️ 전부에 승인을 붙이면 안전한 게 아니라 자동화가 무의미해진다. **2곳만** 붙였다.

## 4. 무엇을 만들고, 무엇을 안 만드는가

| ✅ Must | 🚫 Won't |
| --- | --- |
| **Child / Observation Memory** — 외부 기록·부모 발화를 아이 중심으로 연결 | 아이의 모든 대화·사진 무제한 수집 |
| **Curator** — 중복 병합·반복 집계·관찰 → 관심 승격 | 관찰 1회를 성향으로 확정 |
| **Child Supervisor** — 필요한 Agent만 선택 | 모든 Agent를 항상 실행 |
| **Food Agent** — 실제 섭취·급식·최근 상황 반영한 식사 아이디어 | 정확한 레시피 제공 |
| **Play / Interest Agent** — 최근 행동·몰입 기반 놀이 추천 | 승인 없이 예약·결제 |
| **Education Agent** — 기관 공지 구조화, 준비물·Action 추출 | 교사 평가 대체, 성적·지능 예측 |
| **Health Agent** — 기록 정리, 검진일·복약 알림, 진료 시 전달 보조 | **질환 확진, 처방 결정** |
| **근거 표시** — 모든 추천에 사용한 memory_id 첨부 | 근거 없이 나가는 추천 |
| **Correction UI** — 4버튼으로 잘못된 기억 수정 | 상품 추천, 대신 문자 발송 |

> **Won't를 먼저 못 박은 이유:** 10주 동안 스코프는 반드시 부푼다. 막는 게 아니라 **부푸는 걸 발견하는 장치**다.

## 5. 왜 우리여야 하는가

### 🎤 "그냥 챗봇으로 하면 왜 안 되나요?"

1. **스스로 판단해야 한다** — "지금 필요한 도움이 무엇인지"와 "수많은 기록 중 지금 관련 있는 것"
2. **도구를 써야 한다** — 공지 파싱 / 급식 조회 / Memory 저장·검색 / 캘린더 / 건강 기록
3. **최대 5단계를 밟는다**

### 🎤 "ChatGPT에 물어보면 나오는 거랑 뭐가 달라요?"

솔직히, **맥락을 부모가 손으로 다 붙여넣는 1회성 질문이라면** ChatGPT도 답의 80%는 낸다.
우리가 파는 건 그 1회성 답이 아니라 **그 맥락을 다시 입력하지 않아도 되게 만드는 것**이다. 나머지 20%는:

| # | 무엇 |
| --- | --- |
| ① | **부모가 다시 입력하지 않아도 되는 축적된 Child Memory** |
| ② | **Fact / Observation / Inference 분리** — "농구하는 형들 봤다"를 '농구를 좋아한다'로 확정하지 않는 규율 |
| ③ | **승격 로직과 감쇠** — 1회를 성향으로 굳히지 않고, 오래된 기억을 근거에서 뺀다 |
| ④ | **근거(memory_id) + Correction 루프** — 왜 그 답이 나왔는지 보이고, 고치면 다음 답이 바뀐다 |

### 남들이 동의하지 않는, 우리만 아는 진실

> 다들 육아 서비스가 안 풀리는 이유를 **"정보가 부족해서"**라고 생각한다. 그런데 정보는 이미 넘친다.
부족한 건 흩어진 정보를 **'우리 아이'에게 연결하는 판단**이고, 이 연결 노동은 **검색이 아무리 좋아져도 줄지 않는다.**
그리고 부모는 이미 매일 아이에 대해 말하고 있다 — 배우자에게, 카톡으로. **새 습관이 아니라 수신처만 바꾸면 된다.**

## 6. 안전 설계 — 여기가 제일 조심스러운 부분

### 🎤 "기술적으로 제일 겁나는 부분은?"

> 서로 다른 **출처·시점·신뢰도**를 가진 기록에서 **지금 관련 있는 기억만** 골라,
**사실과 AI의 해석을 혼동하지 않으면서** 안전하고 납득 가능한 다음 행동으로 연결하는 것.
> 

**왜 위험한가:** 개인화된 오답은 일반적인 오답보다 **더 쉽게 믿긴다.** "민준이를 오래 알고 있다"고 말하는 만큼, 틀렸을 때의 신뢰 손상이 크다. → **1~2주차에 가장 먼저 검증한다.**

### 가드레일

| # | 규칙 |
| --- | --- |
| ㉠ | 근거 Memory가 없으면 **추천을 만들지 않는다** ("기록이 부족해요") |
| ㉡ | 한 번의 관찰을 성향으로 확정하지 않는다 |
| ㉢ | **부모의 말은 아이의 Fact가 아니다** ("요즘 산만하다"는 보호자 Observation) |
| ㉣ | 6개월 이상 지난 관심 기록은 단독 근거로 쓰지 않는다 |
| ㉤ | **알레르기·검진 정보는 LLM이 생성·추론·수정하지 않는다** — 보호자 입력 또는 의료 기록만 |
| ㉥ | Health Agent는 **진단하지 않는다** (같은 증상 3회 → 추천 중단 + "병원 확인이 필요해 보여요" + 정리된 기록 전달) |
| ㉦ | 알레르기 필터·날짜 계산은 **모델이 아니라 규칙**이 막는다 |

### AI가 틀렸을 때 사용자 화면

| 상황 | 무엇이 보이나 |
| --- | --- |
| 결과 0건 | 억지 추천 금지. 쌓인 기록 건수를 그대로 보여주고 **최소 질문 1개**(탭 1회) 또는 또래 일반 추천 |
| 확신 낮음 | 숨기지 않고 `관찰 1회` `확정 아님` `추측` 라벨 + "~일 수 있어요". 같은 카드에 수정 버튼 |
| 틀린 답 | 사용한 기록을 전부 보여주고 4버튼으로 즉시 수정 → 그 자리에서 재계산 |
| 범위 밖 | 의료 판단·발달 평가·구매·예약은 **하지 않고** 필요한 정보만 정리해 건넨다 |

### 개인정보

이름·나이·알레르기 여부만 수집 · 로그엔 원문 대신 `memory_id` · 보관 범위·기간은 **9월 2주 최우선 확정** · 첫 커밋 날 보안 5종 체크 + 배포 전 AI 보안 리뷰

## 7. 잘 됐다는 걸 뭘로 아는가

### 성공 정의 한 문장

> **Agent가 실제 Child Memory를 근거로 판단했을 때의 보호자 채택률.**
> 

| 지표 | 목표 |
| --- | --- |
| 자체 테스트 10개 통과 수 | 9/10 |
| **근거 없는 추천 건수** | **0건 (하드 기준)** |
| 제안 → 24시간 내 실제 행동 전환율 | 70% |
| 잘못되거나 오래된 기억을 근거로 쓴 비율 | 0에 가깝게 |
| 블라인드 비교에서 우리 답 선택률 · 재방문율 | 미정 |

### 테스트 케이스 10개 — **실패 유도가 7개**

과해석 / 주체 혼동(부모 알레르기를 아이 것으로) / 기록 0건 / 무관 질문 / 오래된 기록 / 단정 금지 / 혼합형

## 8. 3개월 뒤에 남는 것 · 첫 100명

| 구분 | 우리 답 |
| --- | --- |
| **쌓이는 것 (유저 락인)** | 아이별 Child Memory와 그 위에 쌓인 **Correction 이력**. 떠나면 "우리 아이를 아는 상태"를 처음부터 다시 만들어야 하고, 그 비용이 **시간이라 돈으로 해결되지 않는다** |
| **못 사는 것 (데이터 해자)** | 개별 아이 데이터가 아니라 **패턴** — 라벨링 정답 쌍, 승격 임계값, 감쇠 기준, 오분류 케이스, 실제로 물어본 보호자 N명 |
| **책임 장벽** | **없다.** 진단·발달 평가를 하지 않기로 설계했다. 책임을 지지 않는 쪽을 골랐으니 그 대가로 진입장벽도 없다 |

### 순풍인가 역풍인가 → **순풍**

모델이 좋아질수록 관찰·의도·일정 추출이 정확해지고, 축적된 Memory를 활용한 개인화 품질도 함께 올라간다.
**현재 모델로는 정확도가 부족하다. 그래서 사람 확인 단계를 두고, 모델이 개선되면 그 단계를 줄이는 구조로 설계했다.**

### 첫 100명 — 채널 딱 1개

**부산대학교 부설어린이집 보람반·슬기반(5세, 40명),3~4세반(60명) 학부모 단톡방**

담임교사 협조 공지 → 시드 3~5명 실사용 → "알림장 정리가 줄었다" 후기를 단톡방에 직접 공유 → **폐쇄형 입소문으로 30명(75%)**
신규 채널을 늘리지 않고 **이 방 안에서 밀도를 먼저 채운 뒤** 다음 반으로 확장한다.
