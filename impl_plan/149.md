## 2. 최소 데이터 집합 — compute_profile_status 가 필요한 것

```
compute_profile_status(O, W, G, last_observed_on, today) -> ProfileState
```

| 입력 | 정의 | 출처 |
|------|------|------|
| **O** (int) | 같은 `affinity_id` 의 `status=active` 관찰 중 최근 **7일(승격 윈도우)** 안의 건수 | `observation_{food,education,activity}` 에서 `affinity_id = :pid AND status = 'active' AND observed_range && daterange(:today - 6, :today + 1, '[)')` |
| **W** (int) | 해당 profile 이 받은 `wrong` correction 수 (21일 윈도우) | `correction` 에서 `target_kind = 'profile_affinity' AND target_id = :pid AND verdict = 'wrong' AND created_at >= :today - 21` |
| **G** (bool) | 승격 보조 조건 — 윈도우 내 active 관찰 중 `strong_signals` 가 1개 이상 있는 것이 존재 | 같은 O 쿼리에 `strong_signals != '{}'` 필터 추가 |
| **last_observed_on** (date) | active 관찰의 최신 관찰일 | `ProfileAffinity.last_observed_on` (관찰 저장 시 갱신됨) |
| **today** (date) | 기준일. 호출부가 넘긴다 (`date.today()` 직접 호출 금지 — `rules/age.py` 선례) | 호출부 |

### O 계산 — 7일 윈도우의 정확한 범위

이슈: "최근 7일 안의 건수". 오늘이 9/26이면 9/20~9/26 포함 = 7일.
```sql
observed_range && daterange('2026-09-20', '2026-09-27', '[)')
-- = today - 6 ~ today + 1 (열린 상한)
```
→ 상수: `PROMOTION_WINDOW_DAYS = 7`, 범위 시작 = `today - timedelta(days=PROMOTION_WINDOW_DAYS - 1)`

### W 계산 — 21일 윈도우

이슈 [미정]: "하강 윈도우(21일) 안의 wrong 만 세는 쪽을 제안". 채택한다.
```sql
created_at >= now() - interval '21 days'
```

### G 계산 — Promotable 테이블만

`ObservationRoutine`은 `Promotable`을 상속하지 않아 `strong_signals` 컬럼이 없다.
→ O와 같은 3개 테이블(food, education, activity)에서만 체크.

## 3. 상태 전이 규칙 (이슈 그대로)

```
순서 1: today - last_observed_on > 21  →  archived
순서 2: O >= 3 + W  또는 (O >= 2 + W 그리고 G)  →  confirmed
순서 3: 그 외  →  candidate
```

- archived에 새 관찰 → 같은 공식으로 재계산
- 신규 profile 기본값 = candidate

## 4. strength 변화 규칙 (이슈 그대로)

```python
# correction
VERDICT_DECAY = {
    "wrong":                  0.93,  # 7% 감소
    "outdated":               0.95,  # 5% 감소
    "need_more_observation":  0.97,  # 3% 감소
}

# 상태 전이 (실제로 바뀐 경우에만 1회)
TRANSITION_BONUS = {
    ("candidate", "confirmed"): 1.10,  # 승격
    ("confirmed", "candidate"): 0.90,  # 강등
    ("confirmed", "archived"):  0.90,  # 강등
    ("candidate", "archived"):  0.90,  # 강등
    ("archived",  "candidate"): 1.00,  # 부활: 보너스 없음
    ("archived",  "confirmed"): 1.10,  # 부활+승격
}

STRENGTH_DEFAULT = 0.5
STRENGTH_MIN = 0.0
STRENGTH_MAX = 1.0
```

**멱등성 보장**: `apply_transition`은 `prev_state != next_state` 일 때만 적용. 같은 상태→같은 상태는 1.0 (변화 없음).

## 5. 구현상 예상 문제

### 5.1 strength 기본값 불일치
- **현재 모델**: `server_default="0.3"`
- **이슈 스펙**: default 0.5
- **결정**: 마이그레이션에서 기본값을 0.5로 변경. 기존 행의 0.3은 그대로 둔다 (이미 생성된 프로필의 strength를 일괄 변경하면 의미가 달라진다).

### 5.2 merge_key 에 polarity 포함
- **현재**: `merge_key`는 텍스트, `polarity`는 별도 컬럼
- **이슈**: "같은 정규화 대상이라도 +1 / -1 이면 서로 다른 키"
- **결정**: `merge_key` 생성 로직을 `{normalized_subject}::p{polarity}` 형식으로.
  단, merge_key 생성은 Memory Agent/Curator 쪽이다. 이번 이슈에서는 **정책만 명시**하고, 실제 생성 로직 변경은 AI Owner(이시하) 영역.
  profile 모델에 UNIQUE(child_id, merge_key) 제약이 없으므로 즉시 문제는 없다.

### 5.3 O 카운트의 테이블 분산
- active 관찰이 3개 테이블(food, education, activity)에 나뉘어 있다.
- profile의 `domain`으로 어느 테이블을 볼지 결정할 수 있지만, domain이 `education`이면 `observation_education`만 본다.
- **결정**: `MemoryDomain` → `observation_{domain}` 매핑으로 **해당 도메인 테이블 하나만** 카운트.

### 5.4 last_transition_at 추가
- 멱등성을 위해 "마지막으로 상태가 바뀐 시점"을 기록해야 한다.
- 전이 보너스가 이미 적용됐는지 판단하는 용도.
- **결정**: `last_transition_at` (DateTime, nullable) 컬럼 추가. 전이가 발생할 때만 갱신.
  + 추가로 `last_transition_from` (varchar, nullable) — 직전 상태. 재계산 시 "이전에 어떤 상태였는지" 알아야 보너스 적용 여부를 판단.

### 5.5 재계산 멱등성
- `compute_profile_status`는 순수 함수라 같은 입력이면 항상 같은 출력.
- 문제는 strength: 재계산을 여러 번 돌리면 transition bonus가 중복 적용될 수 있다.
- **해결**: 서비스 계층에서 `prev_state`를 현재 DB 값에서 읽고, `next_state = compute_profile_status(...)` 를 계산한 뒤, `prev_state != next_state` 일 때만 `apply_transition` 호출 + `last_transition_at` 갱신.
  → 두 번째 호출 시 prev_state == next_state이므로 bonus 없음.

### 5.6 correction 후 재계산 트리거
- observation correction(wrong→inactive): 해당 observation의 `affinity_id`가 가리키는 profile을 재계산
- profile correction(strength만 감소): 해당 profile 재계산
- **주의**: observation이 `affinity_id = NULL`이면 profile 재계산 불필요 (아직 승격 전)

### 5.7 `app/rules/` 레이어 경계
- 순수 함수(compute_profile_status, apply_correction, apply_transition)와 상수는 `app/rules/profile.py`
- DB 접근이 필요한 서비스 로직은 `app/domains/memory/profile/` 쪽
- `app/rules/`에서 sqlalchemy import 금지 (CLAUDE.md 레이어 경계)

        result = apply_correction(0.5, "outdated")

    def test_need_more_observation은_3퍼센트_감소(self):
        result = apply_correction(0.5, "need_more_observation")
        assert result == pytest.approx(0.5 * 0.97)

    def test_0_5에서_wrong_2회로_0_3_미만이_아니다(self):
        """완료 기준: 0.5 → wrong 2회 → 0.432... (0.3 미만 아님)"""
        s = apply_correction(apply_correction(0.5, "wrong"), "wrong")
        assert s >= 0.3
        assert s == pytest.approx(0.5 * 0.93 * 0.93)

    def test_0_5에서_wrong_8회면_0_3_미만(self):
        """완료 기준: 8회째 0.280"""
        s = 0.5
        for _ in range(8):
            s = apply_correction(s, "wrong")
        assert s < 0.3
        assert s == pytest.approx(0.5 * 0.93**8)

    def test_하한_클램프(self):
        s = 0.01
        result = apply_correction(s, "wrong")
        assert result >= STRENGTH_MIN

    def test_지원하지_않는_verdict면_ValueError(self):
        with pytest.raises(ValueError, match="verdict"):
            apply_correction(0.5, "once_only")  # observation 전용


# -- apply_transition --

class TestApplyTransition:
    """상태 전이 시 strength 보정. 실제로 바뀐 경우에만."""

    def test_candidate에서_confirmed로_승격(self):
        result = apply_transition(0.5, "candidate", "confirmed")
        assert result == pytest.approx(0.5 * 1.10)

    def test_confirmed에서_candidate로_강등(self):
        result = apply_transition(0.5, "confirmed", "candidate")
        assert result == pytest.approx(0.5 * 0.90)

    def test_confirmed에서_archived로_강등(self):
        result = apply_transition(0.5, "confirmed", "archived")
        assert result == pytest.approx(0.5 * 0.90)

    def test_archived에서_candidate로_부활은_보너스_없음(self):
        result = apply_transition(0.5, "archived", "candidate")
        assert result == pytest.approx(0.5)

    def test_같은_상태면_변화_없음(self):
        """재계산을 여러 번 돌려도 strength가 계속 오르내리지 않게"""
        assert apply_transition(0.5, "candidate", "candidate") == 0.5
        assert apply_transition(0.5, "confirmed", "confirmed") == 0.5
        assert apply_transition(0.5, "archived", "archived") == 0.5

    def test_상한_클램프(self):
        result = apply_transition(0.95, "candidate", "confirmed")
        assert result <= STRENGTH_MAX

    def test_하한_클램프(self):
        result = apply_transition(0.05, "confirmed", "archived")
        assert result >= STRENGTH_MIN

    def test_승격_후_재계산해도_중복_적용_안_됨(self):
        """candidate→confirmed 1회 적용 후, confirmed→confirmed는 변화 없음"""
        s1 = apply_transition(0.5, "candidate", "confirmed")  # 0.55
        s2 = apply_transition(s1, "confirmed", "confirmed")   # 0.55 그대로
        assert s2 == s1


# -- 통합 시나리오 (순수 함수 조합) --

class TestTransitionScenario:
    """상태 계산 + strength 변화를 조합한 시나리오."""
    TODAY = date(2026, 9, 26)

    def test_신규_profile_3회_관찰로_승격(self):
        """O=3, W=0, G=False → confirmed, strength 0.5 * 1.10 = 0.55"""
        status = compute_profile_status(O=3, W=0, G=False,
            last_observed_on=self.TODAY, today=self.TODAY)
        strength = apply_transition(STRENGTH_DEFAULT, "candidate", status.value)
        assert status == ProfileStatus.CONFIRMED
        assert strength == pytest.approx(0.55)

    def test_confirmed에서_wrong_받으면_candidate로_강등_가능(self):
        """wrong 1회 → W=1, O=3이면 3 < 3+1=4 → candidate"""
        strength = apply_correction(0.55, "wrong")  # 0.55 * 0.93
        status = compute_profile_status(O=3, W=1, G=False,
            last_observed_on=self.TODAY, today=self.TODAY)
        strength = apply_transition(strength, "confirmed", status.value)
        assert status == ProfileStatus.CANDIDATE
        assert strength == pytest.approx(0.55 * 0.93 * 0.90)

    def test_긍정_부정_관찰이_같은_대상이어도_profile_분리(self):
        """merge_key 에 polarity 포함 → 별개 profile.
        각각 독립적으로 상태 계산."""
        # 긍정 profile: O=3
        pos = compute_profile_status(O=3, W=0, G=False,
            last_observed_on=self.TODAY, today=self.TODAY)
        # 부정 profile: O=1
        neg = compute_profile_status(O=1, W=0, G=False,
            last_observed_on=self.TODAY, today=self.TODAY)
        assert pos == ProfileStatus.CONFIRMED
        assert neg == ProfileStatus.CANDIDATE
