# 약관 원고 — `policy_version` 에 들어가는 글

보호자가 동의 화면에서 읽는 글이다. 마이그레이션이 `<버전>/<scope>.md` 를 **한 글자도 바꾸지 않고**
`policy_version.content` 에 넣고, 동의 화면은 `GET /api/v1/policies` 로 그 글을 받는다.

체크박스 옆 **제목 · 법적 근거**는 같은 폴더의 `meta.json` 에 둔다. 본문처럼 그 버전의 글이라 버전마다
저장한다 — 코드 한 곳에 두면 제목을 바꾸는 순간 옛 동의 기록에도 새 제목이 붙는다 (#168 리뷰).

## 규칙

- 🚨 **등록한 원고는 고치지 않는다.** 누군가 이미 동의한 글이 바뀌면 동의 증빙이 증빙이 아니게 된다.
  마이그레이션이 파일 해시를 고정해 두고, 파일이 바뀌면 등록하지 않고 멈춘다.
  고치려면 **새 버전 폴더 + 새 마이그레이션**을 만든다 (옛 버전 행에는 `ended_at` 을 찍는다).
- 🚨 **운영자 주소 · 전화는 `{{운영자_주소}}` · `{{운영자_전화}}` 빈칸으로만 둔다.** 이 저장소는 public 이다.
  실제 값은 배포 서버의 `.env` 에만 두고, 배포용 등록 때 채운다 (#166).
- 파일은 보호자가 읽는 **본문만** 담는다. 누가 왜 이렇게 썼는지는 [`docs/safety/consent-texts-v1.md`](../../../../docs/safety/consent-texts-v1.md) 에 둔다.

## 버전 이름

| 단계 | 이름 | 예 |
| --- | --- | --- |
| 초안 (법률 검토 전) | `draft-N` — 본문이 바뀔 때마다 N 을 올린다 | `draft-1`, `draft-2` |
| 확정본 (법률 검토 후) | 확정한 날짜 `YYYY-MM-DD` | `2026-11-20` |

#91 은 처음부터 날짜로 쓰려 했지만, 초안 단계에서도 본문이 바뀔 때마다 버전을 올려야 동의 기록이
어느 글을 가리키는지 분명해서 초안은 `draft-N` 으로 쓴다 (#172).

`child_basic` · `child_health` 는 동의문 2·3 을 고치는 중이라 아직 `draft-0`(자리 표시 글)이다.

위치를 한 글로 합친 이유 — 위치정보법은 "약관에 적고 그 약관에 동의받기" 를 요구한다. 동의문 4 는
그 약관을 쉽게 풀어 쓴 요약이라, 요약을 위에 두고 약관 전문을 아래 붙여 체크박스 하나로 받는다
(카카오 · 당근도 약관 하나에 체크 하나다).
