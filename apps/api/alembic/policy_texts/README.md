# 약관 원고 — `policy_version` 에 들어가는 글

보호자가 동의 화면에서 읽는 글이다. 버전 폴더마다 scope 하나에 파일 두 개가 있다.

| 파일 | 무엇 | DB |
| --- | --- | --- |
| `<scope>.md` | 원고 (사람이 쓰고 고치는 것) | `policy_version.content` · `content_hash` |
| `<scope>.html` | 원고로 만든 **정본** — 보호자가 "전문 보기" 에서 보는 페이지 | `policy_version.content_html` |

마이그레이션이 두 파일을 **한 글자도 바꾸지 않고** 넣는다. 동의 화면은 `GET /api/v1/policies` 로 버전과
정본 주소(`html_path`)를 받고, "전문 보기" 는 `GET /api/v1/policies/{scope}/{version}` 을 **손대지 않고** 띄운다.
서버가 만든 완성본을 화면이 그대로 보여 줘야 "저장된 정본 = 보호자가 본 것" 이 된다 (멘토 #71-4).

## 새 버전을 만드는 순서

1. `<새 버전>/<scope>.md` 원고를 넣는다 (바탕화면 원고의 `본문 시작`~`본문 끝` 사이만)
2. `cd apps/api && uv run python -m scripts.render_policy_html <새 버전>` — 옆에 `.html` 이 생긴다
3. 두 파일의 해시를 고정하는 마이그레이션을 만든다 (`50ceeb7cedfe` · `bf14612a1d9c` 참고). 옛 버전 행에는 `ended_at`
4. 생성된 HTML 을 브라우저로 열어 한 번 읽어 본다 — 이게 보호자가 보는 그대로다

체크박스 옆 **제목 · 법적 근거**는 같은 폴더의 `meta.json` 에 둔다. 본문처럼 그 버전의 글이라 버전마다
저장한다 — 코드 한 곳에 두면 제목을 바꾸는 순간 옛 동의 기록에도 새 제목이 붙는다 (#168 리뷰).

## 규칙

- 🚨 **등록한 원고는 고치지 않는다.** 누군가 이미 동의한 글이 바뀌면 동의 증빙이 증빙이 아니게 된다.
  마이그레이션이 파일 해시를 고정해 두고, 파일이 바뀌면 등록하지 않고 멈춘다.
  고치려면 **새 버전 폴더 + 새 마이그레이션**을 만든다 (옛 버전 행에는 `ended_at` 을 찍는다).
- 🚨 **개인정보의 항목 · 목적 · 보내는 곳이 늘거나 보관 기간이 길어지는 개정이면, 기존 회원에게 다시 묻는 장치부터 만든다.**
  이용약관 제3조 ⑥ 과 개인정보 보호법 제15조 ② 가 요구한다. 지금 서버는 "한 번이라도 동의했는가" 만 보고
  버전을 보지 않는다 (`missing_account_scopes`) — 그대로 새 버전을 등록하면 기존 회원은 옛 글에 동의한 채로 남는다.
  문장만 다듬는 개정은 다시 묻지 않아도 된다.
- 🚨 **운영자 주소 · 전화는 `{{운영자_주소}}` · `{{운영자_전화}}` 빈칸으로만 둔다.** 이 저장소는 public 이다.
  실제 값은 배포 서버의 `.env` 에만 두고, 배포용 등록 때 채운다 (#166).
  ⚠️ 그래서 `draft-1` 은 **개발 DB 용**이다 — 빈칸이 그대로 들어가 있고 해시로 고정돼 있어 나중에 채울 수 없다.
  배포 DB 에는 빈칸을 채운 버전이 따로 등록돼야 한다. 그 방법을 정하는 것까지 #166 이다.
- 파일은 보호자가 읽는 **본문만** 담는다. 누가 왜 이렇게 썼는지는 [`docs/safety/consent-texts-v1.md`](../../../../docs/safety/consent-texts-v1.md) 에 둔다.

## 버전 이름

| 단계 | 이름 | 예 |
| --- | --- | --- |
| 초안 (법률 검토 전) | `draft-N` — 본문이 바뀔 때마다 N 을 올린다 | `draft-1`, `draft-2` |
| 확정본 (법률 검토 후) | 확정한 날짜 `YYYY-MM-DD` | `2026-11-20` |

#91 은 처음부터 날짜로 쓰려 했지만, 초안 단계에서도 본문이 바뀔 때마다 버전을 올려야 동의 기록이
어느 글을 가리키는지 분명해서 초안은 `draft-N` 으로 쓴다 (#172).

## 지금 있는 것

| 버전 | scope | 원고 |
| --- | --- | --- |
| `draft-1` | `service_terms` | 서비스 이용약관 초안 v5 |
| `draft-1` | `privacy_account` | 동의문 1 (보호자 개인정보) 초안 v2 |
| `draft-1` | `location` | 동의문 4 요약 + 위치기반서비스 이용약관 초안 v1 — **체크박스 하나에 글 하나** |

`child_basic` · `child_health` 는 동의문 2·3 을 고치는 중이라 아직 `draft-0`(자리 표시 글)이다.

위치를 한 글로 합친 이유 — 위치정보법은 "약관에 적고 그 약관에 동의받기" 를 요구한다. 동의문 4 는
그 약관을 쉽게 풀어 쓴 요약이라, 요약을 위에 두고 약관 전문을 아래 붙여 체크박스 하나로 받는다
(카카오 · 당근도 약관 하나에 체크 하나다).
